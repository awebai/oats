## Captured instance: home, source and work

**Your instance home** is the specific OATS instance directory supplied as
`OATS_INSTANCE_HOME`, not your user home, source repository or work target.
`instance.json.executionBinding` names the explicit captured **deployment and
resolution**. Home-bound actions must also match this owned home's incarnation
and recorded custody. Do not invent, copy or rewrite those identifiers to make
another home or composition appear authorized.

- **Home holds composed instructions and instance state.** `AGENTS.md` is the
  canonical composed instruction file; `CLAUDE.md -> AGENTS.md` is its relative
  compatibility alias, not a second instruction source. Preserve the generated
  instructions, aliases and metadata; do not hand-edit them to change authority.
  Task material and provider-managed state belong where their owning contract
  specifies. The selected capabilities define any knowledge or memory protocol.
- **Your soul is retained source, not your edit surface.** The home carries no
  soul link: the composed `AGENTS.md` already holds your soul's instructions,
  and nothing you read depends on the publisher's current checkout. Never modify
  retained artifacts. If a task authorizes source changes, use its explicitly
  authorized tracked work surface and review path instead.
- **`./work` is the task's work surface.** The work-mode instructions determine
  whether it is an owned directory or another permitted repository view. Make
  task edits only on that authorized surface, not in deployment stores or a
  convenient source checkout. Reading an external input is not permission to
  modify it or its owner.

For supported captured commands, keep the explicit `--deployment` and
`--resolution` pair from the recorded binding; supply the exact owned home when
an action requires one. Running from home preserves the invocation's working
location, but **cwd and a recorded `repo` path never select configuration or
execution authority**. Source location, deployment, work target and team
membership are separate facts. Do not fill missing inputs from a config cascade,
a current lock, an alias match or another instance's environment.

Load **oats-portable** for the running kernel's supported captured operations.
A no-launch scaffold or `launchPending` receipt is not a running agent. Where
captured launch, start/restart/wake/retire or recovery is unsupported, stop and
report the limitation; do not strip selectors or use a legacy command as a
workaround. Preserve work, knowledge, native history, identities and outstanding
cleanup receipts. Missing authority is a hold, never permission to erase state.
