# Live evidence requires owned native resources

## Admit a safe probe before launching

Confirm operator permission, tested source/artifact, host and runtime prerequisites, and exact cleanup ownership. Use a dedicated fixture workspace and isolated session backend. For tmux use a private socket through the supported saved-socket path; never run resource tests on the operator's default server. A separate Electron user-data profile alone does not isolate ports, tmux, processes or credentials.

Keep the probe off the operator's screen. A test or preview Desktop runs on a virtual display, never in the operator's graphical session. On Linux that is Xvfb, with X11 forced so Electron cannot pick the operator's Wayland compositor, and tmux pointed at a private directory because the Desktop sweeps its default tmux server at start and quit (inside an agent's tmux session, `TMUX` names the operator's), and a private home for OATS (next paragraph): `xvfb-run -a -s "-screen 0 1920x1080x24" env -u WAYLAND_DISPLAY -u TMUX HOME=<private dir> OATS_HOME_DIR=<private dir> TMUX_TMPDIR=<private dir> OATS_DESKTOP_DIR=<fixture deployment> OATS_DESKTOP_OATS_BIN=<absolute oats> <electron argv> --ozone-platform=x11`. Without `-s`, xvfb-run's screen is 640x480. Drive and screenshot it over CDP. Window-manager placement is not a substitute: a test Desktop launched with a silent-workspace rule still mapped on the operator's workspace. Right after the launch, confirm no probe window reached the operator's session (on Hyprland, none in `hyprctl clients -j`); if one did, close it at once and tell the operator. Where no virtual display is available (Xvfb not installed, or macOS), do not launch one and do not install one yourself: ask the operator first, and say in the hand-over that the live tier was not run. Give the probe its own user-data profile: a launch that shares the operator's is handed to their running Desktop, which shows and focuses a window in their view. Close the probe's Desktop and its virtual display after the check. A test TUI (`oats tui`) keeps off the operator's screen the same way: it runs in a detached session on a private tmux socket, never in a new terminal window or on the operator's tmux server.

Keep the probe off the operator's sessions too. A Desktop or a TUI runs the kernel's machine sweep (`oats session resume --json`) when it opens and again when a roster shows a local lost session, and the sweep restarts the lost homes it may resume on every deployment in this computer's deployments list. Under the operator's own `HOME` and `OATS_HOME_DIR` that is the operator's list: a home of theirs lost since the last sweep, after a reboot or while the probe runs, would be restarted by the probe, on its private tmux server, out of their sight. The list, the kernel's record of which homes it saw running and the sweep's lock all live under `OATS_HOME_DIR` (default `~/.oats`), and the list's first use imports `$HOME/Agents`, so a private `OATS_HOME_DIR` alone is not enough: give the probe a private `HOME`, `OATS_HOME_DIR` and `TMUX_TMPDIR` (one empty directory each, or one for all three), in its ledger. Run every command that builds, starts or reads the fixture (onboard, spawn, start, status) with the same three: a kernel command run in a deployment adds it to that environment's list, so one run from the operator's shell puts the fixture on their list, where their next sweep restarts its homes on their tmux server. Open only the fixture deployment (`OATS_DESKTOP_DIR` or `--dir`), never the operator's: a deployment the probe opens joins its list. The probe's sweeps then see only its fixture, so a fixture home the probe saw running and then lost is still resumed, and a resume check still works. A private `HOME` changes what a login shell or a version manager finds, and the Desktop puts the login shell's `PATH` first: name the CLI by absolute path, make sure the `node` it runs is reached without `HOME`, and confirm in the Desktop's log which CLI it accepted. The fixture's agents get the private `HOME` too, so use a stand-in harness that needs no login, and seed under the private `OATS_HOME_DIR` only what the check needs (launch configurations, servers). A test TUI takes the same `HOME`, `OATS_HOME_DIR` and `TMUX_TMPDIR`, set on the command its private session runs: its kernel calls find the tmux server through `TMUX_TMPDIR`, not through the socket that hosts the TUI. At cleanup, stop the fixture's instances with `oats instance stop` before its tmux server goes, and check that the operator's `oats deployments --json` does not list the fixture. Never run the sweep under the operator's environment to see what it would do, `--plan` included: the probe reads only its own machine state.

Read the current `packages/desktop/package.json`, `main.mjs`, backend target modules and `scripts/dist-smoke.mjs` before choosing launch arguments. Record the exact argv and resource ledger. Do not invent a fixture flag or launch another application against live operator work. Bind any debugging endpoint to loopback with a dedicated port and close it afterwards; CDP is privileged control, not a public service.

## Prove the boundary

1. Record fixture source/viewer window and pane identity, host/socket, process IDs and baseline resource counts. Use only generated probe data.
2. Drive the rendered UI to the exact fixture instance. Use native input or CDP `Input.dispatchMouseEvent` for wheel events, not JavaScript-created DOM events. Locate the active terminal bounds before sending input.
3. Independently query the session owner. For tmux, record exact window/pane identity, copy mode, history and scroll position before/after wheel-up and wheel-down. Visual scrolling alone is insufficient.
4. Test stale target refusal and source loss without allowing a sibling to appear. Test navigation restrictions while preserving scrollback. Remote targets must be tested through their own supported seam; local tmux success is not evidence for them.
5. Close the viewer and prove its ephemeral resources disappear while the durable fixture source survives. Exercise reuse/cap rejection in the owning process, not only UI dedupe.
6. Clean up only resources proven to be created by the probe, on the exact socket/host. Recheck the baseline; uncertain cleanup is a reported failure, not permission for broad process-name killing or profile deletion.

## Evidence tiers

- Unit/DOM: policy and controlled completion order.
- Packaged smoke: artifact inventory, ABI and signature where applicable.
- Live GUI/native input: actual operator interaction and external session observations.
- Real agent task: runtime/learning acceptance, separately assigned.

Report tiers separately. `OATS_SMOKE_SKIP_LAUNCH=1 OATS_SMOKE_BUILD_VERIFY=1 npm run dist:smoke` from the Desktop package is build verification only. Strict ad-hoc signature checks do not prove notarization, and CI without an interactive desktop does not prove GUI usability. Keep screenshots and raw probe logs outside reusable knowledge after redaction review.
