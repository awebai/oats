## The release PR (item 5)
1. Version 0.30.0 in EVERY package that carries it (root, pi, desktop).
2. The `oats.core` / `oats.setup` compat floors AND the check-knowledge-theory floor at `>=0.30.0`,
   in the same commit as the bump.
3. The framework v1.4.0 pins (the tag is cut at release).
4. The oats.aweb 1.17.1 and oats.okf 4.0.4 mirrors (trees == the tags) and pins. Until those tags
   exist, use placeholders; the PR stays a draft.
5. Re-pin the REAL bundled binding-check test to 1.17.1's actual answer (no hand-written payload).
6. The Desktop's supported band: `<0.31`.
7. Release notes:
   - the team model v2 migration and the flag day, with every setup step as
     `oats aweb setup --soul <soul>`;
   - the teams you control (BYOT) line: a lost team is left automatically on hosted teams; on a team
     you control, the leave is reported with an `aweb-team-leave-failed` event, and the owner
     removes the member;
   - launch preferences (soul `launch:`, `souls.launch`, the frozen record, `--reselect-launch`);
   - automations.trust, if it merged in time: a behaviour change for hosts that ran automations;
   - fixed: second-team joins usable, okf readiness answered, launch warnings shown;
   - the 0.29.4 catalog note (`OATS_PACKAGE_CATALOG`).
   - **Known in 0.30.0** (so nobody is surprised): with no teams configured, spawn refuses through
     the provider (`E_SPAWN_FAILED`), not `E_TEAM_UNCONFIGURED`; capability operator commands run
     from a deployment need `--soul <soul>`; retire of homes whose session is gone (if it misses the
     tag). Each is fixed in 0.30.1.
8. A check of the PACKED tarball: its `package-catalog.json` carries oats.engineering 1.1.0,
   oats.aweb 1.17.1 and oats.okf 4.0.4.
