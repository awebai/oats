# Captured-only instance and directory boundaries

## IC1 resource correction and ownership

New resources:

- `injects/portable-instance-boundary.md`
- `injects/portable-work-directory.md`

These are captured-only variants, not replacements for the legacy files. The
resource owner creates/tests the new text; the lifecycle owner selects it in
captured preparation and verifies the complete retained curriculum. This change
alone does **not** wire the new resources into active compositions.

Both variants preserve instance-home/work separation, canonical
`AGENTS.md`/relative `CLAUDE.md` alias, generated instruction/metadata custody,
read-only retained soul links, authorized edit surfaces and preservation of
nonempty work/receipts. Authority is explicit captured deployment/resolution and
matching owned-home incarnation—not cwd, a `repo` path, a config cascade or an
alias. External reads do not authorize edits.

The directory variant describes an owned execution directory, not a source or
work-target checkout. It creates no policy requiring a knowledge layout,
harvester, publication mechanism or storage backend. Capabilities define any
knowledge/memory functionality. No-launch/launch-pending state is not a running
runtime, and unsupported captured launch/start/restart/wake/retire/recovery has no
legacy fallback or promised automatic recovery.
