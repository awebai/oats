The npm tarball's `gitHead` is `c923d81b`; the version-bump commit lands after the tag (PR #58). A from-the-tag verifier should expect `gitHead == c923d81b`. ## Kernel

- **`oats instance git <instance> [--home] [--dir] [--json]`** and
  **`oats instance diff <instance> --file <id> --revision <rev> [--index-revision <idx>] [--json]`** (K1) —
  read-only Git observation of one instance's work tree. Truth from the tree:
  the branch the tree is on (the spawn-recorded branch is reported as
  `recorded` with a `drift` flag). Porcelain v2 NUL status with renames keeping
  both paths; **upstream and default-branch merge-base as two separate
  comparisons** — no upstream is `null`, never 0/0. Opaque file ids minted
  under (HEAD, index); a diff is taken against the *captured* revision oid and
  refuses `E_STALE_OBSERVATION` (fresh observation attached) if HEAD, index or
  the file's content moved, before **or during** the read. Bounded (256 KiB,
  binary flagged). Qualified addressing: several homes with one name refuse
  `E_AMBIGUOUS_INSTANCE` with candidates; retired/unmaterialized tree is
  `E_NO_WORKTREE`.
  **Hardened after a consumer-side adversarial probe**: the observed tree is
  worked in by an agent, so its repo config is input — external diff, textconv,
  fsmonitor and hooks are disabled, the caller's Git environment and global/
  system config are not inherited, optional locks are off (no index refresh),
  and the index revision is a hash of `ls-files --stage` (no `write-tree`, no
  object written). The response states it: `readOnly: {helpers, optionalLocks, objectsWritten}`.
- **`oats inspect --json` souls carry their declarations** (K4, `soulsApi: 1`):
  `declarations` (requires/defaults/knowledge/teams/resources, parsed
  kernel-side, `null` when absent), `provenance` (recorded by `oats onboard`
  from now on; `null` = *unrecorded*, never inferred), `readiness` (declared
  sources joined against the same payload's capability inventory — separate
  from launchability and adoption; never a green "Ready"), and
  `result.sources` — the scope's portable source context, with an honest
  `none-recorded` state.
- **No hollow agents.** `oats create` declares `oats.core` by default; composition
  honours the declaration by suppressing the kernel's legacy skills — but nothing
  on that path activates the replacement, so a `spawn` produced an agent with
  **no operational curriculum and no warning** (second-operator finding on 0.24.6).
  Now `spawn` refuses `E_REQUIREMENT_INACTIVE` before creating anything, with
  the remedy (`oats install oats.framework` if needed, then
  `oats use oats.core --soul <name>`) and the opt-out (remove the declaration).
  `create` states the activation step up front (`next-step` note,
  `declaredCapabilities` in `--json`). `create` stays declaration, not acquisition.

## Desktop (parity slices 1b, 2a, 3, 4, 6a, 7a)

- **1b** shared contextual right panel (Instance · Git & GitHub · Soul), collapsed
  rail, per-workspace preferences, temporary focus mode.
- **2a** Git & GitHub panel on K1: worktree/branch/drift, upstream and base named
  separately, real file counts and rename paths, bounded read-only diff; stale
  → re-observe, never rendered. The legacy background `gitState` collector —
  which ran Git against every instance tree on every roster poll without helper
  controls and substituted healthy zeros on failure — is **removed**. Desktop
  Git reads are the K1 route only. GitHub/PR card is *unavailable* pending the
  `oats.git` decision.
- **3** Souls + Sources on K4: declarations, recorded provenance (`null` renders
  *Unrecorded*, never *Local*), "Not declared" vs "Not reported" distinguished,
  sources-installed ≠ Ready.
- **4** Capabilities: official catalog via `oats catalog` (0.24.6+) plus the
  deployment's classic inventory; aliases are mappings not exports, refs are refs,
  override catalogs conspicuously labelled; "Add capability" copies the schema's
  exact `oats install <package>` argv and never executes it.
- **6a** Spawn modal to the redesign on existing seams: two-column layout,
  grouped soul chooser, provider/model with reported-vs-assumed provenance,
  launch configuration restored (an already-supported property the renderer had
  regressed out of), fields that need K6 rendered disabled with their seam named.
- **7a** Active overview (frame 07) on the roster: anonymous count-labelled
  relation groups (the roster reports no group names), activity `unknown` until K7.

Desktop CLI floor for the new views is **0.24.7** (`instanceGitApi`/`soulsApi`
gates); an older CLI renders those views as *unavailable*, never as empty-healthy.
