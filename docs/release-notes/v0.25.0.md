# OATS v0.25.0 — the workspace model (breaking)

Kernel/Pi **0.25.0**. Consumers gate on `oats version --json` `features[]`
names and API integers, never on the version.

**This is a new deployment model, not a patch to the old one.** 0.24.x keeps
spawning 0.24.x deployments; there is no converter, and a 0.24 deployment is
rebuilt on the new model. Design:
[simplified workspace model](https://github.com/awebai/oats/blob/7838d3ca70772f63854b198601fbc45437c2e999/docs/design/2026-09-23-simplified-workspace-model.md);
module contracts:
[workspace module contracts](../design/2026-09-23-workspace-module-contracts.md).

## The one idea

An organisation has **one workspace**: a Git repo hosting `oats-workspace.yaml`
that lists its **member repositories**, pins its **packages**, names its
**teams** and declares **defaults**. Every member carries an
`oats-membership.yaml` back-link, confirmed over the Git remotes in the
operator's own access context: **membership is the trust**. A member exports
**souls** (`souls/<name>/soul.yaml`) and **capabilities**
(`capabilities/<name>/oats.json`); a soul says where each capability comes
from (`from: <member repo> | here | package`). Packages are consumed only
through `packages:` + `oats-lock.json` v3, with per-version executable
approval. A spawn resolves the soul and materializes every capability whole
into the instance (`<home>/.oats/modules/<cap>/`, skills under
`<home>/.agents/skills/<cap>/`). Nothing is installed anywhere.

## Kernel — `workspace-v2` (`workspaceApi: 2`), `instance-modules`, `spawn-provider-payload`

- **Declarations** (`docs/*.schema.json`, `schemaVersion: 2`):
  `oats-workspace.yaml`, `oats-membership.yaml`, `soul.yaml` v2 and
  `oats-local.yaml`, the only per-machine file (`workspace:` or `standalone:`
  ref, `clones`, `settings.<cap>`, `souls.disabled`). See
  [workspaces.md](../workspaces.md#the-files).
- **`oats sync`** discovers members, confirms membership, resolves packages
  and writes `oats-lock.json` v3; unapproved executables exit `2` non-TTY or
  prompt on a TTY. New: `oats package add|remove`, `oats workspace status`,
  `oats capabilities`, `oats souls`.
- **`oats spawn`** resolves over the remotes, fetches the soul from its member
  repo, materializes and launches. `--preview` reports `modules[]`, `team`,
  `resolution`, `workspace` and `soulFetched`; the decision binds the
  resolution revision (`E_DECISION_STALE` if a member moved). `--provider <cap>
  k=v` records a per-spawn provider payload, the third payload home after the
  soul and `oats-local.yaml` `settings`.
- **`instance.json`** carries `modules{}`, `providers{}`, `workspace{}` and
  `capabilities[]`; **`oats status`** shows per-instance drift.
- **`oats onboard [<dir>] --workspace <ref>`** writes `oats-local.yaml`, runs
  the sync path and prints the layout and the hosting rule for mixed
  public/private organisations (`onboardApi: 2`). It creates no soul and
  spawns nothing.
- **Standalone case:** a member whose workspace cannot be read (access
  failure only) still offers its souls with `from: here` capabilities plus
  `oats.core` from the official catalog, marked `standalone: true`.
- **Teams** are labels; per-team provider payload is
  `messaging.byTeam.<label>`. A store names a repository.
- **Scheduled spawns** on a workspace deployment materialize exactly like
  `oats spawn`.
- **Security:** remote tree names are checked (no traversal), a tag naming a
  blob is refused as a commit, symlinks in fetched trees are refused except
  the soul's `CLAUDE.md → AGENTS.md` alias, `__proto__` / `constructor` /
  `prototype` are refused in every payload layer, `byTeam` is reserved outside
  `workspace.messaging`, and staging is atomic with full rollback.

## Removed

`oats init`, `use`, `install`, `trust`, `list`, `remove`, `migrate`,
`catalog`, `update`, `config` and `inject` answer `E_UNKNOWN_COMMAND` naming
the replacement. `oats-config.yaml` is no longer read as configuration (a
leftover one is harmless). Also gone: the `installed/` tier, `oats.yaml`,
`lockfileVersion` 2, per-soul `source: git:…` lines, `stores.inherit`,
`imports`, and the `catalog` feature name. `docs/configuration.md` now
describes `oats-local.yaml` only.

## Desktop

The Desktop server's `oats catalog` reader surfaces `E_USAGE` (the verb is
removed). Everything else in the Desktop is unchanged.

## Known limitations

- A deployment without `oats-local.yaml` still spawns through the classic
  (pre-workspace) compose path.
