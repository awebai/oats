# OATS 0.49.0

Unreleased

## Added

- **Remote roster groups carry each host's kernel features, feature
  `server-probe-features`.** `oats status --json` now has a top-level
  `features`: the running kernel's own list, the same array as
  `oats version --json` `features` (emitted at output time, never from a
  reused `--max-age` observation; the human output is unchanged). `oats server
  roster --json` relays it from the status answer it already pulls, as each
  group's `probe.features`, so the Desktop can tell what a host supports
  without probing it: no extra ssh, no `version --json`, nothing stored. The
  host's answer is untrusted and is relayed only as an array of at most 256
  entries, each a string of at most 64 characters matching
  `^[a-z0-9]+(?:-[a-z0-9]+)*$`, in the host's order, duplicates kept;
  anything else, even one bad entry, is `null` (never a filtered list). `null`
  means unknown; `[]` is a valid answer, not unknown. A failed probe stays
  `{ok: false, error}` with no `features` key. A host before 0.49.0 answers no
  `features`, so its group reads `null`: a false negative for a host running
  0.46.0 to 0.48.0, whose `version --json` does advertise, for example,
  `soul-composed-instructions`. Its features are unknown until it runs
  0.49.0.

## Fixed

- **A home's session receipt is found whatever the letter case of its path
  (#780).** On a case-insensitive filesystem (the macOS default),
  `.../agents/...` and `.../Agents/...` are one directory, but the receipt was
  keyed by the path as the caller spelled it. So a healthy home addressed with
  a different case was refused with `E_RUNTIME_ENDPOINT_UNKNOWN` by
  `session inspect`, `start`, `restart` and `stop`. Retire then read it as a
  home of unknown provenance, and a directory-work home was refused with
  `E_WORK_INSPECTION_FAILED`. A spawn now keys the receipt and records its home
  by the on-disk spelling, and every reader compares spellings on disk. A
  receipt a kernel before 0.49.0 wrote keeps working where it is (nothing is
  moved or rewritten). It is found from the spelling its spawn used, and from
  the on-disk spelling when the two are the same. Any other spelling of such a
  home still misses it: address the home as `oats status` prints it. The
  missing-receipt message names the on-disk receipt path, and the older path
  for the caller's spelling when that differs. Case-sensitive filesystems are
  unchanged: two spellings there are two directories.

- **Retire sees a session working in a home whatever the letter case of its
  path (#789).** Before it removes a home without a usable session receipt
  (and on a lost tmux server, or for a home opened in Herdr), retire checks
  that no tmux pane and no process works there. tmux and lsof report those
  working directories in their on-disk spelling, which was compared with the
  caller's spelling of the home. On a case-insensitive filesystem (the macOS
  default), a home addressed in another letter case therefore looked empty
  while a session still worked in it, and retire went on to remove it. Both
  checks now compare on-disk spellings. So do the checks that find a home's
  `.work-*` extra trees: under another spelling they were missed, so a
  detached extra tree's own commits could be left reachable from no ref.
  Such a tree is now kept as a worktree, as under the home's own spelling.

## Added

- **Desktop: a soul's page shows its instructions.** A new **Instructions**
  section, after Capabilities, reads the soul's own `AGENTS.md` the way a
  capability's page reads its injected instructions: a navigation tree, then
  the file with its front matter as a table, its Markdown rendered strictly and
  its code highlighted. The path shown is the file's place in the soul's
  repository. It comes from the page's existing inspection (no new CLI call),
  and **Refresh** keeps the selection, focus and scroll position. The capability
  page's Contents and this section now share one reader and one keyboard model.
  With OATS 0.46.0 or later, the section also shows the soul's composed
  `AGENTS.md`, what a new instance spawned here would be given: the soul's own
  text, then each part OATS and its capabilities inject, each headed with where
  it comes from and its file, with **Open capability** on a capability's part
  and **Copy composed AGENTS.md** for the exact file. The page asks for it
  (`oats inspect --soul … --instructions`) only when the installed OATS
  supports it. For a soul on another machine (a server workspace), the page
  asks only when that server supports it, as the server reports in the remote
  roster (`probe.features`, feature `server-probe-features`): a server that
  reports nothing (older than 0.49.0, or not reached) shows only the soul's own
  `AGENTS.md`. The Desktop decides from the roster it already reads; it never
  probes a server for this.

## Changed

- **Desktop: identity marks show two letters.** Soul, capability and workspace
  marks used the name's first letter, so every `oats-…` soul read "O". A mark
  now drops a package qualifier and, from three words, a leading namespace
  word, then takes two words' initials or a one-word name's first two letters:
  `oats-desktop-expert` is DE, `oats-okf--knowledge-harvester` KH, `oats.aweb`
  OA. Colours are unchanged, and the mark stays decorative beside the name.
  Where marks stack (a capability's *Used by*, a team's members), they now
  overlap by 1px, so no letter hides under the next mark.
- **A capability that declares a hook event this kernel does not run still
  composes (lfx-oats-workspace#22).** Until now an unknown event in `hooks`
  dropped the whole capability from discovery, and every soul composing it
  stopped on that host. From 0.49.0, an unknown event declared as a command,
  `{ command }` or `{ command, required: false }` is ignored and never runs;
  the capability composes and carries the warning `hook-event-unsupported`
  (`capability <id> declares hook "<event>", which this kernel does not
  run`). The warning appears, in JSON and in text, in `oats sync`, `oats
  workspace status`, `oats capabilities show`, `oats inspect`, `oats
  readiness` and `oats doctor`, each in a `warnings` array (new, and always
  present, in `capabilities show`, `inspect` and `readiness`; new in
  `doctor --json`), and as its message in the `warnings` strings of `oats
  spawn --preview` and `oats spawn`. Doctor without `--soul` reads the
  deployment's capabilities from this machine's cache, and names what it
  could not check (`hook-events-unchecked`). `oats capabilities` lists only
  the hook events this kernel runs. An unknown event declared
  `required: true` is still refused, exactly as before, since skipping a hook
  its author declared essential would fail open. The tolerance covers the
  event's name only: a malformed declaration (no or empty command, an unknown
  key, a non-boolean `required`, a script outside the capability) is refused
  as for a known event. Approved events are unchanged.
  `docs/capability-manifest.schema.json` accepts additional `hooks` keys with
  the same value shape. The limit: it helps from this release on only.
  Kernels before 0.49.0 still refuse every unknown event, so a capability
  that must load on them declares only the events they run.
