# OATS 0.30.2

## Changed

- **Desktop: a faster, calmer load.** The backend reads a deployment's status
  and workspace status in parallel, holds the souls and capabilities catalogs
  and soul inspections server-side (re-read when the workspace state or a
  Desktop mutation moves, or when viewed after 60 s), and slows its cycle
  from 5 s to 30 s while no window is focused. Returning to the window no longer
  re-reads the capabilities list or cancels the observation in flight. When
  the installed CLI supports `--max-age`, background reads accept the kernel's
  recent observation; `/api/panel`, `/api/agents`, `/api/workspace-sync` and
  `/api/capabilities` inspect now report `observedAt` and `refreshing`.
- **Desktop: Where it works shows the work folder.** The Instance tab's Where
  it works card adds a Folder row, `<home>/work`, between Branch and Home, with
  a copy button; in checkout, attached and workspace mode a muted "shared" tag
  says it links to the tree other instances share.

- **Desktop: consistent loading states.** The sidebar roster, the hierarchy,
  the soul inspector and readiness now run on one state model: skeletons
  shaped like the final content instead of false empty lists,
  content and focus kept while refreshing, stale data labelled with its
  observation's age and a Retry, and the actions that need current state held
  with an accessible reason until a good read.

- **Desktop: the Workspace view and the instance panel join the loading-state
  model.** The Souls grid, the Capabilities tab and its capability pages, and
  the instance panel's Soul and Messaging sections show skeletons at the real
  row and card size instead of empty claims, keep their content (and a held
  table) through a refresh or a failed re-read, and name a stale observation's
  age with a Retry; the spawn dialog's harness, model and launch hints describe
  the preview for the choices on screen only.
- **The spawn preview says why each module is there.** Every `modules[]` row
  of `oats spawn … --preview --json` carries `composedFrom`: `"soul"` when the
  soul declares the capability (a package soul's `from: here` and every module
  of a standalone view included), `"workspace"` when a workspace default
  (`defaults.<slot>` or `defaults.capabilities`) gave it. It is the value
  `oats inspect --soul` already reports as `capabilities[].composedFrom`.
  Provenance only: `resolution`, `declRevision`, `payloadRevision` and the
  spawn decision are unchanged, so a previewed decision still binds its apply.
  Gate on the new feature `preview-composed-from`
  ([Desktop CLI API](../desktop-cli-api.md#the-preview)).

## Fixed

- **Instance skills are flat again, so Claude Code finds them.** Since the
  workspace model (0.25.0) spawn copied each module's skills grouped by
  capability, `<home>/.agents/skills/<capability>/<skill>/SKILL.md`. Claude
  Code discovers skills one level deep (`.claude/skills/<skill>/SKILL.md`), so
  no capability skill resolved there: `/oats-operate`, `/oats-aweb`,
  `/okf-consultation` and the rest were missing from the session although the
  composed `AGENTS.md` tells the agent to load them. (pi's loader recurses, so
  pi instances were not affected.) Spawn now copies every skill, the soul's
  own and every module's, flat to `<home>/.agents/skills/<skill>/`, the
  layout the Agent Skills convention and every harness expect;
  `.claude/skills → ../.agents/skills` is unchanged. `instance.json` records
  the flat paths (`capabilities[].skills`; a module's skill tree in
  `composition.expected[].resolved` is the skills root).
- **One skill name, one directory.** Every composed skill shares the flat
  directory, so names are unique across the soul and its modules, compared
  case-insensitively: a soul's own skill named like a module's skill, or two
  names differing only in case, is `E_SKILL_DUPLICATE` at spawn and the home
  is removed. A soul skill named like a *capability* (`oats.okf`) is no
  longer a collision. No soul in this repository is affected.
- **oats.framework 1.4.1** (oats.core 2.2.1): the `oats-operate` skill shows
  the flat layout.

**Existing Claude Code instances keep their grouped layout and still do not
see their capability skills: respawn them to pick up the fix.** Nothing
rewrites an existing home: a running instance never changes under itself, and
moving its skills would contradict what its `instance.json` recorded. Until
it is respawned, an agent can read a skill by path,
`.agents/skills/<capability>/<skill>/SKILL.md`.
