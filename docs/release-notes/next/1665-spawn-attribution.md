## Added

- **The kernel records who spawned each instance, and status rows show the human an instance's identity is attributed to.** The feature probe is `spawn-attribution`. Everything here is additive: a home, provider or client without these fields behaves as before.
  - **`spawnedBy`.** A new instance records `spawnedBy: {instance, home}` in `instance.json` and in the `spawned` event, or `null`, and status rows carry the same value. The caller is the instance that the `spawnOrigin` check confirms, so `spawnedBy` non-null implies `spawnOrigin: "instance"`. `spawnOrigin: "instance"` with `spawnedBy: null` means the spawner's session was found gone. A spawner whose session can't be read (tmux unreadable, its session receipt unusable) is kept, and the spawn is never refused. A person's shell, the Desktop, an automation and another deployment's home give `null`, and so does a `--server` spawn whose caller is not a live home on that host. `spawnedBy` is separate from `parentInstance` and `relation`, so an instance's `--relation unrelated` spawn still has a spawner. It is written once, at spawn: retire's lineage repair doesn't touch it, and it can name a home that no longer exists.
  - **`OATS_SPAWNER_HOME`.** Spawn hooks get the spawner's absolute home in this new reserved variable, unset when the spawner is `null`. It selects who signs the new identity. An inherited value is dropped from hooks, from launch and tmux start environments and from scheduled jobs; a harness's pane does not unset one. A capability should treat a missing value as a person's spawn only when the kernel lists `spawn-attribution`. The kernel reads the caller from its environment only, so a harness that strips its session's environment reads as a person's spawn.
  - **`attributedHuman`.** Status rows, local and remote, gain `attributedHuman`. It is the label of the human that the messaging capability attributed its served identity to, through an optional `identity.attribution` (`{mode, human: {id, label}|null, parent: {id}|null}`). Otherwise it is `null`. Only the messaging-layer capability's identity counts. The label is untrusted text, held to a waiting claim's message rule: one line of 1 to 200 characters with no refused character, else `null`. A malformed `attribution` reads as absent and never fails a row. `oats inspect` passes the identity through unchanged.
  - `spawnedBy` and `attribution` report: no kernel decision reads them.

  See [awebai/oats#1665](https://github.com/awebai/oats/issues/1665), [Spawned by](../desktop-cli-api.md#spawned-by), [Attributed human](../desktop-cli-api.md#attributed-human) and [Commands and hooks](../capabilities.md#commands-and-hooks).
