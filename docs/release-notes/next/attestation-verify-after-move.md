## Fixed

- **`oats-getting-started` installs the Desktop again after the repository moved to `oats-project`.** After the transfer, `gh attestation verify <file> --repo awebai/oats` resolves to `oats-project/oats`. The attestations of releases up to 0.69.12 stayed with the `awebai` organisation, so the verify got `HTTP 404`, step 3 never printed `VERIFIED`, and no new onboarding installed the Desktop. Step 3 now downloads from `oats-project/oats` and verifies with `--repo oats-project/oats`. For versions up to 0.69.12 only, it falls back to `--owner awebai`. Each form accepts only its own repository's release workflow, run for the release's tag (`--signer-workflow`, `--source-ref`). The two forms are grouped, so a failed download or checksum still never prints `VERIFIED`. The checksum now also fails when `SHA256SUMS.txt` has no line for the file: on macOS, `sha256sum` passed empty input ([The Desktop](../desktop.md)).
