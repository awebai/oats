## Fixed

- **`oats-getting-started` installs the Desktop again after the repository moved to `oats-project`.** After the transfer, `gh attestation verify <file> --repo awebai/oats` resolves to `oats-project/oats`. The attestations of releases up to 0.69.12 stayed with the `awebai` organisation, so the verify got `HTTP 404`, step 3 never printed `VERIFIED`, and no new onboarding installed the Desktop. Step 3 now downloads from `oats-project/oats`, then verifies with `--repo oats-project/oats` and, failing that, `--owner awebai`. Each form accepts only its own repository's release workflow as the signer (`--signer-workflow`). The two forms are grouped, so a failed download or checksum still never prints `VERIFIED` ([The Desktop](../desktop.md)).
