## Changed

- **Getting started: a new workspace reaches a running setup expert in under two minutes on a warm machine.** `oats-getting-started` now installs OATS, OATS Desktop and the messaging CLI first (`aw`, with no soul), then has the person sign in to their own aweb account in their browser (`aw auth login`) and creates the workspace's team with one call that installs its root in the deployment (`aw team ensure --workspace-key <host repo key> --label <workspace> --expect-account <account>`): the team is owned by their aweb account. It asks where the workspace lives (inside a monorepo, a dedicated private host, or a first new repository), writes the skeleton with the team id from that answer (one framework pin, no soul of its own, no `tasks:` default), spawns `oats.framework`'s `oats-setup-expert` with `oats onboard`'s `next.spawn` and opens the Desktop on the workspace. It needs `oats.framework` 1.18.0 and stops on an older catalog. It also stops when Node is under 22, naming the minimum and the version found, and recommends Git 2.45 or later (older Git works, with whole-tree fetches); on Linux, x64 or arm64, it installs Node 22 from NodeSource and, on Ubuntu, Git from the git-core PPA. SSH, signing and the DCO sign-off leave the main path (`/oats-git-setup`, optional); GitHub stays where the flow needs it: the Desktop's download, the host repository and its push. Its messaging gate is the soul's messaging capability and its readiness, with aweb as the default ([awebai/oats#1665](https://github.com/awebai/oats/issues/1665)).
