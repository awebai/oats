## Fixed

- **A turn that ends in a provider error now shows on the instance.** A refusal, an exhausted rate limit or a dead credential ended the turn with the error in the pane and nothing anywhere else, so an instance could sit idle for days while whoever waited on it heard nothing. On Claude Code 2.1.78 and later (oats.core 2.10.0, its `StopFailure` hook) and on pi (`@awebai/oats-pi`), the instance now sets a needs-input claim, `Turn failed: <the error>`, on `oats status`, Desktop and the terminal UI. It shows only once the harness has stopped retrying, so a transient error it recovers from raises nothing, and it clears on the instance's next turn. The claim uses the existing `oats instance waiting` path with no contract change; pi's producer id is `oats.pi`. Codex still reports nothing: a provider error fires neither its `Stop` hook nor `notify`, so no hook can see it. A pi before 0.80.4 reports nothing either, and neither does a Claude Code before 2.1.78, which oats.core detects at each start because that version refuses a settings file naming the hook ([awebai/oats#1667](https://github.com/awebai/oats/issues/1667)).
