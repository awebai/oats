## Fixed

- **A turn that ends in a provider error now shows on the instance.** A refusal, an exhausted rate limit or a dead credential ended the turn with the error in the pane and nothing anywhere else, so an instance could sit idle for days while whoever waited on it heard nothing. On Claude Code 2.1.78 and later (oats.core 2.10.0, its `StopFailure` hook) and on pi (`@awebai/oats-pi`), the instance now sets a needs-input claim, `Turn failed: <the error>`, on `oats status`, Desktop and the terminal UI. It shows only once the harness has stopped retrying, so a transient error it recovers from raises nothing, and it clears on the instance's next turn. The claim uses the existing `oats instance waiting` path; pi's producer id is `oats.pi`. Codex still reports nothing: a provider error fires neither its `Stop` hook nor `notify`, so no hook can see it. A pi before 0.80.4 reports nothing either, and neither does a Claude Code before 2.1.78: that version refuses a settings file naming the hook, so oats.core asks the executable the launch will run and writes the hook only on a clear answer of 2.1.78 or later ([awebai/oats#1667](https://github.com/awebai/oats/issues/1667)).

## Added

- **Spawn and launch hooks get `OATS_HARNESS_EXECUTABLE`.** This is additive, for every harness: the absolute real path of the executable the pane will run, found the way the pane finds it, and set the same way in a preview. It is reserved, so a launch configuration's `env` or a trigger cannot set it, and it is absent where that lookup has no answer, including a bare harness name on a spawn with `--no-launch`. A bare name can still be replaced on the session the launch gets, and a symlink can move under any path; that launch warns, in its answer and as a `launch-warning` event in the home, naming both real paths. oats.core uses it for the Claude Code version check above, so on a kernel without it Claude's failed turns stay unreported ([awebai/oats#1667](https://github.com/awebai/oats/issues/1667)).
