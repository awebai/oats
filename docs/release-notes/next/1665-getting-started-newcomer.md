## Changed

- **Getting started speaks to a newcomer and asks less.** These changes come from newcomer test runs of `oats-getting-started` on fresh machines.
  - **Wording:** the skill talks in everyday words (projects, code, folders, "the setup assistant") and keeps file paths, commands, error codes and raw output to itself.
  - **Step 1** first runs step 2's read-only checks, then asks three things: what the agents should help with, which projects, and whether this is a fresh start or joining someone's setup. It proposes everything else as defaults: the name (from the project's), where the shared setup lives and under which GitHub owner (from the project's repositories or the login), the messaging account, the folder where the agents live (default `<home>/Agents/<workspace>`) and the Desktop. It doesn't ask for the harness. When an answer changes a default, the skill derives them again and shows the final values.
  - **One confirmation covers every change to the person's computer** that the checks found needed: the installs, the PATH line, the Claude channel plugin, folder trust, the Desktop and any missing system package. The list names each change by what and where, Git's own settings included. A new private GitHub repository for a new workspace goes on the same list, and so does the name on the first commit when Git has none, so neither is asked again later. The skill never runs `sudo` for anything outside that list. When the agent's own permission check refuses a step, the skill never runs it another way: it asks the person once, by name, retries once, and otherwise says what is missing. The person never types a command with `!`, and types one in a terminal only for a password or login when no window can be opened for them.
  - **The Desktop downloads in the background** right after the GitHub login, with its checksum and attestation, while the CLI installs. It is installed only once all three have passed.
  - **Linux:** the Desktop's system libraries are checked before the install. A missing ALSA is a system package to confirm; a missing FUSE 2 installs nothing, and the Desktop starts with `--appimage-extract-and-run`.
  - **An existing workspace** names its setup expert and the machine's messaging root after the machine's short hostname, with a machine-id suffix for hostnames many machines share. From `oats.aweb` 1.33.1 the invite answer's `awebUrl` is the service URL the join needs; without it the join takes the service from the invite, and stops if it can't.
  - **The hand-off** tells the person to switch to the Desktop and click the setup assistant, since it has already started and will ask them its first question there. Attaching the person to the workspace's messaging account happens later in the setup, with the setup expert ([awebai/oats#1665](https://github.com/awebai/oats/issues/1665)).
