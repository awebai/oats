## Fixed

- **The Desktop and the TUI now say that nothing was started when a stop, an upgrade, a retire or unfinished cleanup refuses a start or restart.** A kernel answers `E_LIFECYCLE_BUSY` beside a stop or an upgrade, and `E_INSTANCE_RETIRING` beside a retire or for a home with cleanup to finish. Both clients read those answers as uncertain, though the kernel gives them before any launch and before a restart's stop. They now read them as refused and word them for a start, with the kernel's own line under the sentence. A restart says that nothing was stopped or started. Only a holder that is running is offered waiting. This needs the answering kernel to list `lifecycle-claim-start`: a local kernel or a server's host without it, or a host whose features aren't known, keeps the uncertain reading ([awebai/oats#1666](https://github.com/awebai/oats/issues/1666); [Commands that meet on one home](../desktop-cli-api.md#lifecycle-pairs)).
