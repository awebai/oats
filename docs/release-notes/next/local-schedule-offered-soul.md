## Fixed

- **A local spawn schedule accepts any soul the workspace offers.** `oats schedule add` and `update` refused a local spawn job whose `agent` is a member or package soul this deployment had never spawned (`agent: no soul named "<soul>" under <root>/agents`, `E_SCHEDULE_INVALID`), although `oats spawn` resolves it, and a run always resolves its soul as `oats spawn` does. A name is now checked by `oats spawn <agent> --preview`: one spawn would refuse is still refused with `E_SCHEDULE_INVALID`, field `agent`, now carrying spawn's own message and its code in `details.code`; a soul already spawned here is accepted without that check, as before. `oats schedule test` reports such a soul as resolving, and the job runs at its due minutes and through `run-now` ([Kinds](../schedules.md#kinds)).
