# OATS 0.46.0

## Added

- **`oats inspect --soul <soul> --instructions` shows the instructions a new
  instance would get.** `souls[0].composedInstructions` is the AGENTS.md a
  spawn of that soul here would write: the soul's own text, then the
  instance-boundary and work-mode blocks and each capability's inject,
  produced by spawn's own composition, with nothing written to the
  deployment. The soul's text and each block are given as ranges into the
  text, named like an instance's `instructions.sources`, so the Desktop can
  show which part comes from where. Without `--instructions` nothing extra is
  composed; with `--home` it is refused. Feature `soul-composed-instructions`.
  `oats doctor --soul` uses the same composition, and its capability markers
  now name the inject home-relative instead of a deleted temporary path.
  Routed with `--server <id>`, a host whose probe does not advertise
  `soul-composed-instructions` is refused with `E_REMOTE_INCOMPATIBLE`, and
  nothing is sent.

## Fixed

- **Interim subscription completion extension:** the qualified Claude 2.1.289
  darwin-arm64 110x35 empty Opus 5.5 / auto / medium frames additionally accept
  exactly Claude Max, Pro, Team and Enterprise billing labels. These variants
  are source-derived synthetic frames, not captured subscription sessions.
  The exact Enter-authorizing prompt, explicit home consent and all launch
  guards are unchanged. Completion closes input authority and proves no
  account/channel readiness. This is **not the #754 onboarding fix**: #754
  remains open for task-filled and bypass-permissions completion recognition.
  Other unqualified frames still retain a blocked result after a submitted
  answer; there is no automatic retry.

- **`oats doctor --soul` lists every inject block of a capability that
  declares several.** Its `instructionBlocks` kept only the first block of
  such a capability, though its composed text had them all; it now lists
  each one, as a spawn records them.

## Changed

- **oats.framework 1.7.0: oats.setup 2.4.0 and oats.core 2.4.2.** Instruction
  text only; no kernel, schema or provider contract changes.
  - **oats.setup 2.4.0: team setup instructions are executable from one
    authorized intake.** The onboarding and teams skills carry one
    authorized intake through team configuration, operator composition
    checks and first-task verification; they link the provider-owned
    identity and delivery procedures, distinguish unsupported paths, and keep
    project operator advice independent of central knowledge identities. An
    instruction change, not a new team or provider primitive
    ([#709](https://github.com/awebai/oats/issues/709), #721). The setup
    inject and `oats-automations` keep configuration repairs proportional to
    the requested outcome (#689, #692) and describe schedule and trigger
    descriptions, retained-attempt reconciliation and supervisor cleanup as
    the kernel now does them (#684, #591, #592, #593).
  - **oats.core 2.4.2:** `oats-operate` covers the extra work trees a
    work-mode briefing allows and their retirement (#678), and what
    `oats session input` does and does not prove (#595).

- Add explicit host-local `oats harness trust --plan` and bare apply for one
  canonical deployment-root Claude/Codex trust entry. Edits preserve unrelated
  native bytes and record a durable `.agents/harness-trust.jsonl` audit. Partial
  failures are retained with `E_HARNESS_TRUST_INCOMPLETE`; no rollback is claimed.
  Spawn/start/retire do not write native trust. Claude ancestor qualification is
  bounded to2.1.289 darwin-arm64/no-Git paths; Codex format qualification is separate.
  Nested Git boundaries and unsupported native formats still refuse or warn.
