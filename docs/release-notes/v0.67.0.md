# OATS 0.67.0

Unreleased

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says: a 0.66 Desktop refuses a 0.67.0 CLI. The
  0.67.0 Desktop accepts OATS CLIs `>=0.26.0 <0.68.0`.

- **Coming from 0.65 or earlier:** do 0.66.0's Upgrade steps too (`oats
  tui`'s key file moves to `~/.oats/config/tui.json`, and `oats server
  connect` needs `--dir`), and 0.62.0's when coming from 0.61 or earlier.

- **One package move:** the official catalog pins oats.framework 1.13.5
  (Provider updates, below). A deployment that pins it takes it with `oats
  sync`, and only new spawns use it. No floor changes.

- **The leader moves to Ctrl+X** in OATS Desktop and in `oats tui`, on every
  platform (Changed, below). A Desktop rebind of the leader and an
  `open.detachKey` in `tui.json` are kept. To keep Alt+O or ⌃\, bind it
  again: `"open": {"detachKey": "M-o"}` (or `"C-\\"`) in `tui.json`, the
  shortcuts editor in the Desktop. **A `tui.json` that gives `ctrl+x` to an
  action and names no leader stops `oats tui` from starting:** its line on
  stderr names the action; give that action another key, or name a leader
  in `open.detachKey` ([Change the keys](../tui.md#change-the-keys-tuijson)).

- **The shortcuts move on Linux and Windows** (Changed, below): the shared
  chords are Ctrl+Alt now, not Ctrl+Shift, in OATS Desktop as in `oats tui`.
  A shortcut you rebound in 0.66 is kept. If your terminal passes Ctrl+Shift
  apart from Ctrl (foot, Alacritty), choose the Ctrl+Shift option instead
  (Added, below). The Alt+Shift arrows no longer reach an agent in its
  terminal.

## Added

- **An instance has a colour** (feature `instance-color`, awebai/oats#1421).
  `oats instance color <instance> (<colour> | --clear)` sets or clears it,
  from the palette `sand`, `sage`, `slate`, `mauve`, `clay`, `olive`; it is
  addressed as `oats instance stop` addresses an instance, and routed with
  `--server`. The colour is presentation only: anyone may change it, and it
  is never an address. It is kept in the home's own record,
  `.oats-color.json`, which a start or restart never rewrites and a retire
  does not count as a change to the home. `oats status --json` rows,
  `oats server roster --json` rows and `oats inspect --home` carry `color`
  ([An instance's colour](../desktop-cli-api.md#an-instances-colour-oats-instance-color)).

- **`oats inspect --soul <soul> --composed-skills` lists every skill a spawn
  of the soul gives its instance** (feature `soul-composed-skills`,
  awebai/oats#1421): its own skills and each capability's, each with its
  `source` (`soul` or `module:<capability>`) and each file's text, from the
  same scratch composition as `--instructions`. A collision a spawn would
  refuse makes the field `null` with spawn's own message. It is opt-in, takes
  `--soul` only, and a routed host without the feature refuses it
  ([`oats inspect`](../desktop-cli-api.md#oats-inspect---home-----soul----dir----json--operationsapi-2)).

- **`oats spawn <soul> --preview --suggest-name` names the instance from its
  task** (feature `spawn-suggest-name`, awebai/oats#1421). The soul's own
  harness gives a few descriptive words in one call, and the preview answers
  for `--name <descriptive>-<role>`, with the same decision an apply with
  `--expect-decision` matches. The call starts none of the user's MCP
  servers, hooks, plugins or extensions, and no tool on either harness: the
  prompt goes on stdin, from an empty temporary directory, in its own process
  group, within the preview's 20 s preflight budget, after its harness checks.
  - **Supported harnesses: claude (model `haiku`) and pi (the instance's
    model)**, proven on Linux with claude 2.1.288 and pi 1.3.0
    (`scripts/naming-isolation-proof.mjs`).
  - **Three stated exceptions:** Claude Code's own built-in plugins
    (`cc-plugin-*@builtin`) load as they always do, `--bare` included; hooks
    in the host's managed policy still apply; and pi runs its own credential
    commands (`!command` keys and headers in models.json), as every pi launch
    does. A claude login through `apiKeyHelper` is not read, so such a user
    gets `harness-failed` and a numbered name.
  - **codex is not supported yet:** a codex soul's preview is numbered, with
    `naming.reason: "unsupported-harness"`.
  - **A failure is never an error.** The preview numbers the instance as
    before and says why in `naming.reason`: `no-task`, `unsupported-harness`,
    `timeout`, `harness-failed` or `invalid-reply`.
  - Routed with `--server`, the host must advertise the feature
    ([The suggested name](../desktop-cli-api.md#the-suggested-name-feature-spawn-suggest-name)).

- **One chord for each everyday action, the same in `oats tui` and OATS
  Desktop, from every focus, an agent's terminal too, with no leader first**
  ([Chords](../tui.md#chords);
  [desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md)).
  On Linux and Windows:
  - `Ctrl+Alt+O` opens the switcher.
  - `Alt+Shift+Up` and `Alt+Shift+Down` open the terminal of the previous
    or next instance.
  - `Ctrl+Alt+1` to `Ctrl+Alt+8` show the first to eighth tab, and
    `Ctrl+Alt+9` the last one.
  - `Ctrl+Alt+Z` zooms the shown terminal.
  - `Ctrl+Alt+A` goes to the other split group.

  The Desktop's macOS chords are `⌘⌥O`, `⌘⌥↑`, `⌘⌥↓`, `⌘⌥1` to `⌘⌥9`, `⌘⌥Z`
  and `⌘⌥A`. Help, the views, and stop, restart, start and retire stay on
  the leader, which still works everywhere.
  - **In `oats tui` the Ctrl+Alt chords need the kitty keyboard protocol,**
    as the 0.66 chords did. The Alt+Shift arrows work in every terminal on
    Linux and Windows, GNOME Terminal included. On macOS `oats tui` has no
    chords: the leader does it all there.
  - **While the terminal confirms the protocol, the help and the cheat sheet
    lead with the chords,** each with its leader key beside it. The leader
    keeps its own section.
  - **A character typed with AltGr stays a character.** On Windows `AltGr`
    is `Ctrl+Alt`: where it types a character (Spanish `€`, `@` and `#`,
    Polish `ą`, `ę`, `ó` and `ż`), that key types it in both clients, and
    the leader does what the chord would.
  - **Windows Terminal takes `Ctrl+Alt+1` to `Ctrl+Alt+9`** for its own tabs,
    and the Alt+Shift arrows while its panes are split.
    [The matrix](../tui.md#which-terminals-let-the-chords-through) lists
    what each terminal takes.

- **A Ctrl+Shift option for the shared chords, in `oats tui` and OATS
  Desktop at once,** on Linux and Windows
  ([Switch to Ctrl+Shift](../tui.md#switch-to-ctrlshift);
  [desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md)).
  It is for a terminal that lets Ctrl+Shift letters through to `oats tui`:
  foot and Alacritty
  ([Which family for my terminal](../tui.md#which-family-for-my-terminal)).
  Ctrl+Alt stays the default.
  - **Seven chords move:** `Ctrl+Shift+K` the palette, `Ctrl+Shift+P` a
    spawn (the Desktop's Quick Open), `Ctrl+Shift+S` the switcher,
    `Ctrl+Shift+M` zoom, `Ctrl+Shift+W` close the tab, `Ctrl+Shift+E` split
    right and `Ctrl+Shift+D` split down.
  - **The others keep their keys:** `Ctrl+Alt+A` the other group,
    `Ctrl+Alt+F` the filter, the Alt+Shift arrows, `Ctrl+Alt+1` to
    `Ctrl+Alt+9`, and in the Desktop `Ctrl+Alt+R`, an instance's name and
    colour.
  - **To switch,** choose **Ctrl+Shift (foot, Alacritty)** under
    **Shortcut family, shared with oats tui** on the Desktop's Shortcuts page, or write
    `{ "chords": "ctrl+shift" }` to `~/.oats/config/keys.json`
    (`$OATS_HOME_DIR/config/keys.json` when that is set). The Desktop
    switches at once; `oats tui` reads the file at its next start. A
    missing or broken file means Ctrl+Alt, and the help says why.
  - **The help names the family in force:** `?` in `oats tui`, the
    Shortcuts page in the Desktop.
  - **Your own keys still win, row by row:** `tui.json`'s `keys`, and the
    Desktop's shortcuts editor, which shows a clash with a key the option
    takes.
  - **In `oats tui` it needs the kitty keyboard protocol;** the leader
    works without it. With the option on, the seven are taken from an
    agent's terminal too: pi's `Ctrl+Shift+P` (previous model) spawns
    instead.
  - macOS has no option.

- **Jump to the next or previous group in the palette,** in `oats tui` and
  OATS Desktop ([The palette](../tui.md#the-palette);
  [desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md)).
  While the palette is open, `Alt+Shift+Down` moves the selection to the
  first row of the next group, and `Alt+Shift+Up` to the previous one's;
  both wrap. On macOS the Desktop's keys are `⌘N` and `⌥⌘N` (`⌘⇧N` stays
  File → New Window).
  - **The keys are the palette's while it is open.** There `⌘N` doesn't
    choose a soul, and the Alt+Shift arrows don't open the next or previous
    instance. With the palette closed, they do what they did before.
  - **`oats tui`'s palette now groups its instances** as the sidebar and the
    Desktop's palette do: by relation, with the group last used first. A dim
    label names each group, and the selection skips it. The souls,
    capabilities, views, acts and commands after them are a group each.
  - Both palettes name the keys: the Desktop's in a line under the list,
    `oats tui`'s in its cheat sheet. On macOS `oats tui` has no group key:
    a terminal never passes ⌘.

- **Desktop: the soul page lists every skill an instance gets.** With OATS
  0.67.0 or later, **Composed for an instance › Skills** lists the soul's own
  skills and the ones its capabilities add, each saying where it comes from
  (**From this soul** or **From** the capability), and the "newer OATS" note
  goes. A capability's skill file opens under its place in the instance home,
  with **Open capability** above it. For a soul on a server, the server's OATS
  must list them too. ([Desktop](../desktop.md))

- **Desktop: an instance's colour.** Each instance's dot (the sidebar, its
  terminal tab, the command palette, the overview) shows the colour set for
  it: filled while running, a ring while stopped. **Instance: name and
  colour…** in the command palette, or Ctrl+Alt+R (⌥⌘R on macOS), opens a
  small dialog for the focused instance: its name, and **None** plus the six
  palette colours, applied at once through `oats instance color`. Needs OATS
  0.67.0 or later here, and on a server for its instances. The TUI leaves
  Ctrl+Alt+R to the agent. ([Desktop](../desktop.md))

- **Desktop: an instance named from its task.** With an OATS that suggests
  names (`spawn-suggest-name`), the spawn dialog asks for a name once the
  Opening instruction holds three words and you pause typing. The soul's
  harness replies with a short name for the work, and the role is added as
  its suffix. It shows as the empty Name field's placeholder, "will be named
  release-notes-manager", and in **What will be created**, and Spawn uses
  it. Typing a name replaces it and stops suggestions for that dialog.
  Spawning with Name empty and no suggestion yet shows **Naming…** and asks
  once. When the instance can't be named from its task, it is numbered, and
  a notification says why ("Named oats-desktop-expert-3: naming took longer
  than 20 seconds."). Nothing is asked before you type, nor on a timer.
  Spawns on a server keep their purpose. ([Desktop](../desktop.md))

- **The TUI draws an instance's mark in its colour**, its shape still saying
  its state ([tui.md](../tui.md#what-it-shows)).

## Changed

- **The leader is Ctrl+X in both clients and on every platform**
  (awebai/oats#1433), as Emacs' prefix key: it was Alt+O on Linux and
  Windows and ⌃\ on macOS. The keys after it do not change. Without the
  kitty keyboard protocol Ctrl+X is one byte, 0x18, in every terminal, so it
  needs no protocol and no timing; under the protocol `oats tui` reads it
  too, and Ctrl+Shift+X and Ctrl+Alt+X are not the leader
  ([The leader](../tui.md#the-leader)).
  - **Ctrl+X twice sends Ctrl+X to the program,** as the leader twice
    always has. The shell's Ctrl+X Ctrl+E is now Ctrl+X twice, then Ctrl+E,
    and nano exits with Ctrl+X twice.
  - **In the Desktop, Cut keeps Ctrl+X** in a text field (an input, a text
    area, an editable region) that is not a terminal, on Linux and Windows.
    On macOS Cut is ⌘X, so the leader works there too
    ([desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md#the-leader)).
  - **Alt+O and ⌃\ go back to the programs:** on Linux and Windows an agent
    gets Alt+O as Esc then `o` (on macOS Option+O types its character, `ø`
    on a US layout, unless the terminal sends Option as Meta), and ⌃\ as it
    is typed, unless you bind either as the leader again.

- **The shared chords move from Ctrl+Shift to Ctrl+Alt on Linux and
  Windows,** in both clients. kitty, Ghostty, WezTerm, Konsole and Windows
  Terminal take most Ctrl+Shift chords for themselves, so in `oats tui`
  most of 0.66's chords never arrived. Old → new:

  | Action | Was | Now |
  |---|---|---|
  | the palette | `Ctrl+Shift+K` | `Ctrl+Alt+K` |
  | Quick Open in the Desktop, a spawn in `oats tui` | `Ctrl+Shift+P` | `Ctrl+Alt+P` |
  | close the tab | `Ctrl+Shift+W` | `Ctrl+Alt+W` |
  | the filter | `Ctrl+Shift+F` | `Ctrl+Alt+F` |
  | split right | `Ctrl+Shift+E` | `Ctrl+Alt+E` |
  | split down | `Ctrl+Shift+O` | `Ctrl+Alt+Shift+E` |
  | next and previous tab in `oats tui` | `Ctrl+Tab`, `Ctrl+Shift+Tab` | `Alt+Shift+Right`, `Alt+Shift+Left` |
  | the Desktop's second next and previous tab chords | `Ctrl+PgDn`, `Ctrl+PgUp` (outside a terminal) | `Alt+Shift+Right`, `Alt+Shift+Left` (everywhere) |
  | the Desktop's go to tab 1–9 | `Alt+1` to `Alt+9` (outside a terminal) | `Ctrl+Alt+1` to `Ctrl+Alt+9` (everywhere) |

  - **The Alt+Shift arrows no longer reach the agent in its terminal:** in
    both clients they are the chords, there as everywhere else.
  - The Desktop keeps `Ctrl+Tab` and `Ctrl+Shift+Tab`, and its other
    Ctrl+Shift chords (sidebar, instance panel, spawn, theme picker, copy).
  - On macOS the Desktop gains `⌘⌥→` and `⌘⌥←` for the next and previous
    tab, beside `⌃Tab`.
  - A binding you set yourself in the Desktop's shortcuts editor is kept,
    a macOS ⌘⌥ one that 0.66 saved by the character ⌥ typed (`⌥⌘Ø`) too.
    When it is a chord a default now takes, the editor shows the clash.

- **In OATS Desktop, a key you bound yourself now wins over a default on
  every key two actions share,** not only on the seven keys of the
  Ctrl+Shift option
  ([desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md)).
  Before, a default of a narrower context (the tabs, the sidebar, a stage)
  could win over a global key of yours. The shortcuts editor lists every
  such clash, and now says which of the two runs: "Ctrl+Shift+K runs
  “Sidebar: show or hide” (yours) where both apply; “Command palette” has
  it by default."

- **`.oats-color` is a kernel-owned home name**: a capability's
  `retirement.disposable.home` cannot declare it
  ([capabilities.md](../capabilities.md)).

- **Desktop: the soul page's Instructions has two sections.** **Defined in
  this soul** holds the soul's own `AGENTS.md` and its skills. **Composed for
  an instance** holds the composed `AGENTS.md` and the skills an instance
  gets, each saying where it comes from (**From this soul**). Until OATS lists
  the skills that capabilities add, a note says a newer OATS lists them. The
  boundary is a named group for assistive technology too, and the tree is
  still one tab stop. ([Desktop](../desktop.md))

- **Desktop: the spawn dialog's name is optional and its last field.**
  **Name · optional** now comes last, before **Developer settings**. The soul-name
  prefix and its **Prefix with the soul name** switch are gone. Left empty,
  the kernel numbers the instance. The Desktop's spawn dialog adds the role
  to a typed name (the last word of the soul's name) and uses the name in
  lowercase: `desktop-improvements` for `oats-desktop-expert` spawns as
  `desktop-improvements-expert`, and a name that already ends in the role
  gets no second one. On a CLI without
  `spawn-name`, and for a spawn on a server, a typed name is still a purpose
  named `<soul>-<purpose>`. The dialog opens on the Opening instruction;
  Ctrl+1 / ⌘1 still goes to Name. ([Desktop](../desktop.md),
  [souls and instances](../souls-and-instances.md))

- **Desktop: the spawn dialog starts with the Opening instruction.** It is the
  form's first field, and the dialog opens with the cursor in it, after a
  restored instruction's text. In a narrow window, **What will be created** now comes after the form's last
  field instead of above the form. ([Desktop](../desktop.md))

- **Desktop: the sidebar's footer no longer has a "commands" button.** The
  leader's chord works as before. The keyboard shortcuts editor lists the
  keys that follow it: open it from the footer's shortcuts button, with
  Ctrl+, / ⌘, or from the palette.

- **Desktop: "Needs input" shows on an instance's second line.** The name
  line keeps the whole name. The mark, or "N below" on a collapsed parent,
  replaces the repository, pull request and branch, which stay in the hover
  card. A home that is being retired or set up keeps its state on that line.

- **Desktop: the sidebar's dotted sibling links sit a little further from
  the lines to children.**

- **`oats tui`'s switcher lists one row per workspace, whichever machines
  it is on.** A deployment on this computer's list that the run has not
  opened is read for its workspace (`oats status --dir <path> --json`, one at
  a time, 30 seconds each and 60 in all, at the start and when the switcher
  opens or is refreshed). It then joins its workspace's row instead of
  standing apart under `On this machine, not opened`. Under each workspace a
  dim line per deployment names its machine and, when it is not live, its
  state (`not opened`, `not observed`, `not reached`, ...). `Enter` on a
  workspace opens its deployments of this machine too, so the view holds
  them and the other machines' at once. A read that fails or times out
  leaves the deployment as its own row, saying why. The cheat sheet of the
  list of instances names `w workspaces`.
  ([The switcher](../tui.md#the-switcher))

- **`oats tui`'s terminal panel has a tab bar like a terminal's.** Its top
  row is always the tab bar, with one tab or many. Each tab is the agent's
  name, with `· <machine>` for another machine's agent, and tabs are divided
  by `│` (`|` in ASCII). The shown tab is bracketed, `[name]`, and bold, in
  reverse video while the terminal has the focus. The other tabs are dim.
  ([Tabs](../tui.md#tabs))

- **`oats tui` marks a row that needs input with a tag in words.** Where it
  drew a bare `!` at the right of the row, it now draws the Desktop's words
  in reverse video in the waiting colour: `Needs input`, and on a folded row
  with waiting instances under it, `3 below` (`99+ below` past 99). On the
  selected row the tag is the waiting colour not reversed, so it stands
  apart from the selection's bar, and under `NO_COLOR` the reverse video
  alone carries it. On a row too narrow for the whole name beside the
  words, the tag shrinks to `!` or the count alone, still reversed, and the
  name keeps every cell it had. ([What it shows](../tui.md#what-it-shows))

- **The `oats-getting-started` skill covers two Linux snags from a rehearsal.**
  With NodeSource's Node under `/usr`, it sets a per-user npm prefix and now
  also puts `~/.local/bin` on PATH for its own later commands and asks the
  person to add it to their shell's startup file. Without FUSE (Ubuntu 22.04
  and later), it names `libfuse2` (`libfuse2t64` on Ubuntu 24.04) as the
  install, beside the `--appimage-extract-and-run` fallback.

## Fixed

- **`oats spawn --preview` names each capability skill as the spawn copies
  it.** A manifest whose `skills` entry is a directory of skills (the
  documented `"skills": ["skills"]`) showed as one skill named `skills`, and
  a manifest with no `skills` showed none of the `skills/` directories the
  spawn copies. The preview now lists each of them, as `--composed-skills`
  does ([The preview](../desktop-cli-api.md#the-preview)).

## Provider updates

- **oats.framework 1.13.5: oats.core 2.6.6, oats.support 1.0.1.** Text
  only: neither floor (`compatibility.oats`) changes.
  - **Instances are named for their work, with the soul's role last.**
    `/oats-operate` and `/oats-souls` (oats.core) teach
    `--name <descriptive>-<role>`, the role being the last word of the soul's
    name: `--name desktop-improvements-expert` for an `oats-desktop-expert`,
    not `oats-desktop-expert-desktop-improvements`. `--purpose` still derives
    `<soul>-<purpose>`, for automations and scripts that know only the soul.
    [Souls and instances](../souls-and-instances.md) states the convention
    ([#1421](https://github.com/awebai/oats/issues/1421)).
  - **Agents set needs-input whenever they need anything from a human.** The
    oats.core inject and `/oats-operate` make `oats instance attention`
    mandatory, under an IMPORTANT lead, for any question, decision,
    approval, credential or other input an instance waits on, not only when
    it cannot go on without the answer, so the wait shows on `oats status`
    and in the Desktop. It stays out of FYIs and progress reports.
    oats.support's hand-off skill says the same, and `/oats-operate` says
    which questions the Claude Code emitter already reports
    ([oats.core: needs input](../capabilities.md#oatscore-needs-input)).
