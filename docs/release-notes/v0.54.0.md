# OATS 0.54.0

2026-10-13

## Upgrade

- **Nothing is required.** Install the Desktop first and the CLI second, as
  [Upgrading](../upgrading.md) says: a 0.53.0 Desktop refuses a 0.54.0 CLI.

- **To get the skill `/oats-token-saving`,** pin `oats.framework: v1.10.0`
  in your workspace and run `oats sync`. Instances already running keep the
  briefing and the skills they were spawned with; new spawns get the new
  ones. See Added and Provider updates.

- **A script that reads a refusal about a repository reference** (its
  message, or `details.ref`, `details.url`, `details.value`) now reads a
  display form: user information is never in it; a refused value made only
  of letters, digits, spaces and `._/+-:` is shown as written; any other
  value that cannot be rebuilt from its parts is replaced whole by a fixed
  text. See Changed and Fixed
  ([#1077](https://github.com/awebai/oats/issues/1077)). Codes and field
  shapes are unchanged, and so is the reference Git itself is given.

- **The official catalog's versions in this release** are oats.framework
  1.10.0, oats.okf 5.0.3, oats.aweb 1.27.1 and oats.engineering 1.9.1: see
  Provider updates. Pin what your workspace uses, then run `oats sync`.

## Added

- **`oats.core`: the skill `/oats-token-saving`, and three lines of its
  briefing** ([#1103](https://github.com/awebai/oats/issues/1103)). A message
  between instances costs twice: the sender writes it, and the receiver is
  woken, reads it with its whole context and often answers. The skill gives
  one test before sending, "who will do something different because of this,
  and what?", and the rules that follow from it:
  - **to whom:** only the instance that will act on it, with no copies and no
    sending to every holder of a role;
  - **what not to send:** acknowledgements and courtesy, progress and status,
    what a shared record already shows, someone else's words passed along, and
    the story of how the sender got there. A message that needs a confirmation
    says so and gets one line back;
  - **don't ask for what you can read,** and never ask for progress reports or
    set a helper up to send them;
  - **what a message holds:** first what the receiver must do, exact
    references, one topic, one message per task boundary. A spec, a brief or a
    review's findings is the long message, sent once as a file or a link;
  - **what is never cut:** what moves work, what a role owes, and what is owed
    on a record (a verdict on the pull request, a decision on its issue, the
    evidence of a hand-over, the report of a fault or of one's own mistake).

  The skill is provider-neutral: it names no messaging capability, and how to
  send stays with that capability's own skill. The `oats.core` briefing, which
  every instance with `oats.core` reads, gains the test in three lines, so it
  applies before the skill is loaded. An instance spawned before the release
  that carries this keeps its briefing; new spawns get it
  ([`oats.core`](../souls-and-instances.md)).

## Changed

- **The Desktop accepts OATS CLIs `>=0.25.8 <0.55.0`.** The compatibility band
  admits 0.54. Upgrade the CLI and the Desktop together: a 0.53.0 Desktop
  refuses a 0.54.0 CLI. No new gate on the band. `oats tui` runs the kernel it
  ships with and is held to the same band.

- **Diagnostic messages, details, provenance and workspace `cannot-read` values
  now preserve bounded plain refused values, construct displays that omit user
  information (including SSH users), or withhold the reference, while the seven
  rejected argument fields share the bounded plain rule and Git lines are shown
  only for unchanged original operation references
  and no literal `@` in the original line, replacing
  [#1075](https://github.com/awebai/oats/issues/1075)'s scrubbed-line behavior
  ([#1077](https://github.com/awebai/oats/issues/1077)).**

## Fixed

- **Repository diagnostics no longer copy user information from selected
  references ([#1077](https://github.com/awebai/oats/issues/1077)).** Messages,
  reference-bearing details and provenance, schema problems and workspace
  `cannot-read` fields use a display constructed from recognised host and path
  components, with a verbatim exception for original refused values of 1–256
  ASCII letters, digits, spaces or `._/+-:` characters. The same predicate
  serves the seven selected rejected arguments; it never trims or decodes an
  input. Malformed or mixed values outside that rule are withheld whole,
  including harmless text, while known declaration files and key locations
  remain available. Raw derived fragments qualify for the plain exception only
  through their original selected source, never from a nonplain source. Plain
  recognition is not a secret detector: credential-like text within the
  permitted alphabet remains visible.
  Git's own line is shown only when all original operation references are
  proved unchanged by display construction and the original line contains no
  `@`; otherwise the whole line becomes a fixed notice directing the operator
  to run the operation by hand. No substring is recovered. This replaces the
  quoted-line disclosure behavior shipped for unknown Git failures.
  See the [diagnostic display contract](../workspaces.md#repository-references-in-diagnostics).
  Standalone file/path meanings, command-consumed values and Git's original
  transport reference are unchanged.
  Explicit pinned-source diagnostics keep a constructed reference and its
  validated commit, or withhold the whole source without a plain fallback.
  Rejected argument values use the contract's bounded plain-value rule and
  neutral withholding notice; valid operational arguments are unchanged. Unknown Git failures quote only
  stderr: empty stderr adds no line unless output overflow needs a kernel budget notice.

- **Repository and package refusals explain an omitted reference without
  exposing it ([#1077](https://github.com/awebai/oats/issues/1077)).** The
  originating refusal explains withholding or user-information omission once;
  existing message slots keep the explanation when forwarding it. HTTP(S)
  userinfo refusals keep their specific cause and credential-helper advice,
  and package refusals keep their own reason. Admission, codes and field shapes
  are unchanged.

- `oats souls` and `oats capabilities` now show every catalog discovery
  problem below their text tables, including unreadable locked package
  souls. Diagnostics stay on stdout in JSON order, with the kernel's code
  and message; partial listings still exit 0
  ([#1098](https://github.com/awebai/oats/issues/1098)).

## Provider updates

- **oats.framework 1.10.0: oats.core 2.6.0.** One new skill and three lines
  of instruction text in oats.core; no hook, command, schema or provider
  contract changes, and the capability floors are unchanged (oats.core
  `>=0.40.0`).
  - oats.core gains the skill `/oats-token-saving` and names it in its
    briefing, as the entry under Added says
    ([#1103](https://github.com/awebai/oats/issues/1103)). The two commands
    the skill tells an instance to read before asking, `oats status` and
    `oats instance events <instance>`, exist in every kernel oats.core
    admits.
  - A deployment gets it by pinning `oats.framework: v1.10.0` and running
    `oats sync`. Instances already running keep the briefing and the skills
    they were spawned with; new spawns get the new ones.

## Documentation

- **Upgrading: the Desktop goes before the CLI
  ([#1107](https://github.com/awebai/oats/issues/1107)).**
  [Upgrading OATS on a host](../upgrading.md) now says so, and why: a
  Desktop refuses a CLI of a newer minor version, so with the CLI moved
  first it lists no instance until it is replaced. The Upgrade section of
  the [0.53.0 notes](v0.53.0.md#upgrade) gained that step, and one for a
  host that comes from 0.51 or earlier: 0.52.0's steps first, the aw client
  among them, before `oats sync`.
