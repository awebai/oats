# OATS v0.22.12

The same reviewed content as the unpublished v0.22.11 tag, whose hosted
run failed in test fixtures before anything was published; those fixtures
are fixed here.

Schedules: cron-driven agent work that runs on the execution host, from
the CLI and from Desktop, including while the GUI is closed.

## Schedules (kernel)

`oats schedule` keeps a per-workspace `oats-schedules.json` of jobs of three
kinds: **spawn** launches a soul as a fresh disposable instance with a task,
**command** runs an `oats` command in a directory (a harvest, for example),
and **wake** starts a stopped instance if needed and sends it a message
through its terminal. Cron expressions are five-field with an IANA time
zone, evaluated by croner; missed minutes are skipped, never caught up.

One host timer (`oats schedule host install`: a launchd agent or a systemd
user timer) ticks every registered workspace once a minute under a shared
limit on concurrent scheduled launches. A remote workspace's schedules live
and run on that server; `--server` routes every subcommand there.
`oats spawn --wake-file <json>` binds a wake schedule to the new home.

Outcomes are what the kernel observed, not a claim that a task succeeded:
launched, active, ended, stopped, launch-failed, delivered, started,
skipped, and unknown. A launch whose effects the kernel cannot confirm (a
timed-out or envelope-less command, an incomplete rollback) keeps its slot
as unknown until `oats schedule reconcile <id>` adopts a named receipt or
the operator clears it with `--clear`. A wake's launch slot follows the
runtime through the session start receipt, so a persistent home whose
process exited frees the slot. Locks are never reclaimed automatically;
an unreadable or dead owner names the directory to remove.
`oats version --json` advertises feature `schedule` and `scheduleApi: 1`.
See docs/schedules.md.

## Schedules (Desktop)

A **Schedules** view per workspace: create, edit, pause, run now, check run
state and delete jobs through a single JSON spec; the Soul roster's
**Schedule…** preselects the soul; the spawn dialog offers a recurring wake
for the new agent, forwarded inline to a remote server. Mutations require
an explicit workspace. The reconcile result and its recovery instructions
stay visible across polling. **Enable host scheduler** installs the timer
and registers the workspace. See docs/desktop.md.

## Tests

The kernel adds `test/schedule.test.mjs` (fixture homes, injected
spawn/start/input, dummy commands, fixture-only host unit paths) and
`test/schedule-session.test.mjs`, which drives a real private tmux socket
to prove literal delivery, same-minute deduplication and slot release when
a runtime stops. Nothing in the suites touches a live timer.
