# OATS 0.25.6

Decision 27 — per-spawn identity choice (local | global) — lands its kernel half.
No new CLI flags; three provider-neutral additions and one manifest attribute.

## Added

- **`decision.effective.providers`** — the spawn decision now binds the merged
  per-module payloads the providers will receive (exactly the preview's
  `settings.<cap>`), so a confirmed apply covers every provider fact by value.
- **`hostOnly` settings keys** — a capability manifest may mark a settings key
  `hostOnly: true`; the resolver accepts it only from the deployment's
  `oats-local.yaml settings.<cap>` and refuses it in the workspace file, `byTeam`
  payloads, a soul's slot payload and `--provider` flags (`E_WORKSPACE_SCHEMA`,
  reason `host-only-key`). Closes the documented hole where a committed file
  could point a messaging provider at a custody root.
- **Served identity on the roster** — `oats status --json instances[].identity`,
  the text roster's `identity:` line and `oats inspect --home … selected.identity`
  carry the principal an instance acts as, copied from its messaging provider's
  hook meta (`{ mode, alias, team, address, resident, grant?, provider }`).
- `oats version --json` `features[]` gains `served-identity`.

## For providers

oats.aweb 1.12.1 can now declare `residents` `hostOnly`. Any messaging provider
that emits `identity` in its spawn/launch meta appears on the roster.
