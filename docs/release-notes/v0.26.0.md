# OATS 0.26.0

## Removed

- **Package approval** (human decision, 2026-09-24). People install a package
  only when they trust it: declaring it in the workspace's `packages:` IS the
  trust decision, so there is no second, per-version approval step.
  - `oats sync` resolves, fetches, verifies integrity, writes the lock and exits
    `0` on success. No exit `2` for pending approvals, no interactive prompt, no
    `approvalNeeded` in the report and no `approvalNeeded` on `changes[]` rows.
    `oats sync --approve …` is `E_BAD_ARGS` naming the decision.
  - `oats onboard` has no approval-pending outcome and no "approve first" hint.
  - The lock (v3) drops the per-entry `approved` record. A lock that still carries
    it is read with the field ignored, and the next write drops it. The lock
    still pins each package to its exact commit and content integrity; a moved
    tag or drifted content is `E_PACKAGE_INTEGRITY` — reproducibility, not
    approval.
  - Spawn, `--preview`, operator dispatch and package capability agents never
    raise `E_PACKAGE_UNAPPROVED`; the executables-digest gate is gone. At spawn
    the lock's capability list must still match what the package declares at
    the locked commit (`E_PACKAGE_INTEGRITY { why: "capabilities" }`).
  - `oats workspace status` loses its `approval` object and column; `oats
    capabilities` package rows lose `approved`; `oats doctor` prints each locked
    package's integrity instead of its approval.
  - `oats version --json` advertises `packages-no-approval`; the Desktop gates
    its (removed) approval flow on it.
