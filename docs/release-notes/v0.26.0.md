# OATS 0.26.0

The workspace model is the only model the kernel knows. The 0.24-era classic
path is removed, not flagged: a 0.24.x kernel keeps running 0.24.x
deployments, and a 0.25.x deployment is already on the workspace model. See
[Upgrading from 0.25](#upgrading-from-025).

## Removed

- **The captured/portable path** (`oats prepare`, captured resolutions,
  `--deployment --resolution` dispatch, the pi SDK host, versioned schedules).
  What is left are typed refusals:
  - The selectors `--deployment`, `--resolution`, `--artifact-set` and an
    inherited `OATS_DEPLOYMENT` / `OATS_RESOLUTION` are `E_UNSUPPORTED_MODE`
    for every command but `version`. `oats prepare` and `oats inspect
    --request` are `E_UNKNOWN_COMMAND`, naming `oats onboard` / `oats sync` and
    `oats spawn <soul> --preview`.
  - **Captured homes** are reported as the problem `legacy-captured-home` and
    refused by start, restart, `--home` reads and in-home commands. `oats
    retire` works but runs no captured retire hook; its `warnings[]` name the
    capabilities whose identities to revoke with the provider's tooling.
  - **Captured schedule keys** are refused by `schedule add|update`
    (`E_SCHEDULE_INVALID`); a stored captured job or lock never runs until
    `oats schedule remove --force <id>` clears it.
  - Manifest keys `helperInjection` and hook `inputs` are accepted and
    ignored. `oats version --json` drops `capturedDispatchApi` and
    `capturedDispatchActions`. The captured/portable core exports, the
    installed-tier and lock v2 helpers, and their schemas (including
    `oats-lock` lockfileVersion 2 and `provider-check-input`) are removed.
- **Kernel skills, injects and the operational block.** The kernel's `oats`,
  `oats-config`, `oats-packages` and portable skills, and its "You run on
  OATS" and portable injects, are deleted. `oats.core` (the `oats.framework`
  package, the workspace default) ships the operating skills and briefing,
  `oats.setup` the setup skills. A soul without them gets no OATS operating
  instructions (`oats doctor --soul` says so). The kernel keeps
  `instance-boundary`, the `work-*` briefings and `oats-getting-started`.
- **Package approval.** Declaring a package in `packages:` is the trust
  decision. `oats sync` exits `0` on success (no exit `2`, prompt or
  `approvalNeeded`; `--approve` is `E_BAD_ARGS`), and `oats onboard` has no
  approval step. `E_PACKAGE_UNAPPROVED` is gone. Lock v3 drops `approved`
  (ignored on read, dropped on write). **A kernel before 0.26.0 cannot read a
  lock 0.26.0 wrote** (`E_LOCK_SCHEMA`): keep every kernel of a deployment on
  0.26.0 or later. The lock still pins commit and content integrity
  (`E_PACKAGE_INTEGRITY`); a package no longer declared is `E_PACKAGE_MISSING`
  at spawn until `oats sync`. The `approval`/`approved` fields leave `oats
  workspace status` and `oats capabilities`. Gate on the feature
  `packages-no-approval`; the API integers are not bumped.
- **The `soul` link in instance homes.** `instance.json` records `soulDir`,
  handed as `OATS_SOUL` to every spawn, launch and retire hook and to in-home
  capability commands (launch and retire hooks and in-home commands had none
  before). A command with no recorded soul gets no `OATS_SOUL`. Homes spawned
  before 0.26.0 keep their link; their launch hooks and in-home commands get no
  `OATS_SOUL` (oats.okf 2.1.5 refuses with `E_OATS_SOUL_MISSING`): re-spawn
  them.
- **Local souls and `local-agents/`.** A soul is a member repository's
  `souls/<name>`. `oats create` is `E_UNKNOWN_COMMAND`, and `oats spawn
  --instructions-file` / `--def-file` are `E_BAD_ARGS`, naming the
  replacement (author the soul in a member repository, then `oats sync`).
  `soul-scaffold` hooks no longer run. Capability-defined agents home at
  `<deployment>/agents/<agent>/instances/<name>`; the agents root is the
  closest `agents/` (or `PI_AGENTS_ROOT`).
- **Classic verbs.** `oats type`, `oats soul set` and `oats session recompose`
  are `E_UNKNOWN_COMMAND` (edit the soul in its repository; re-spawn to
  refresh). `oats status --team` is `E_BAD_ARGS`.
- **`oats-config.yaml` and the scope configuration chain.** One found between
  a command's directory and its deployment is `E_CONFIG_BROKEN` (`reason:
  "legacy-config"`); with no `oats-local.yaml` in reach, `E_LOCAL_MISSING`
  names it. Where each key went:

  | 0.25 key | 0.26.0 |
  | --- | --- |
  | `capabilities:`, `agent-types:` | `oats-workspace.yaml` `defaults:` and `soul.yaml`, then `oats sync` |
  | `team:` | `oats-workspace.yaml` `teams:` and a soul's `team:` |
  | `work-modes:` | a soul's `work:` and spawn flags; a worktree `setup:` script no longer runs |
  | `yolo:` | `--yolo`, or a launch configuration's `yolo` |
  | `launch-configs:` | `oats-local.yaml` (see Changed) |
  | `agents-md-injection:`, `skill-overrides:`, `injection-override:` | removed; a duplicate skill is `E_SKILL_DUPLICATE` |

  Hooks get the team facts `OATS_TEAM_SCOPE`, `OATS_TEAM_ID`,
  `OATS_TEAM_LABEL`, `OATS_WORKSPACE_NAME` and `OATS_WORKSPACE_KEY`
  (`OATS_TEAM_NAME` is always empty). A classic deployment rooted at a checkout
  of the OATS repository can spawn nothing from that root once it pulls this
  release (its root `oats-config.yaml` is gone); rebuild it with `oats
  onboard`.
- **v1 soul fields** (`runtime`, `model`, `backend`, `repo`, `yolo`,
  `launch-config`, `children`, `requires:`) are not read; use spawn flags,
  launch configurations and `--allow-child-spawns` / `--no-child-spawns`.
- **Classic answers and scopes.** With no `oats-local.yaml` and no `--home`,
  `oats inspect`, `readiness`, `operation run`, `doctor`, `spawn` and
  `schedule` answer `E_LOCAL_MISSING` (`E_NO_DEPLOYMENT` now means only a
  missing `agents/` root); an unreadable `--home` is `E_SESSION_UNKNOWN`.
  `--verify-signatures` is always `E_BAD_ARGS`. A
  deployment has one agents root; cross-repository team roots are gone.
- **Homes from an earlier kernel** (no `modules` in `instance.json`) answer
  `E_UNSUPPORTED_MODE` to start, restart, `--home` reads and capability
  commands; `oats retire` still works, runs no retire hook and says so. `oats
  launch-config preview --home` under a selection answers `E_LAUNCH_LEGACY`.
- **Scheduling a capability agent by name.** A `kind: "spawn"` schedule names
  a soul; schedule the capability's command (`kind: "command"`, for example
  `oats okf harvest --soul <soul>`) or operation instead.
- **Leftovers:** the OAS scope probes, the installed tier, the v1 catalog
  migration helpers, and the classic-era guides (including the 0.24 → 0.25
  rebuild guide). The catalog-pinned workspace example is in
  [packages.md](../packages.md#declaring-packages); the official list is the
  [official catalog](../official-catalog.md), no longer "marketplace".

## Known limitations

- **A scheduled wake's session start uses the spawn-time teams**
  (`OATS_TEAMS_SOURCE=recorded`), so its launch hook leaves no team. The next
  operator start, restart or messaging command is live.
- **The bundled oats.aweb 1.13.1 joins no team beyond the personal one** (the
  aweb root's active team, or `settings.oats.aweb.team`), though the kernel
  hands it `OATS_TEAMS`.
- **"Personal" is the person's active aweb team,** shared across that
  person's workspaces.

## Upgrading from 0.25

- **Retire classic instances with 0.25, then onboard with 0.26.** With 0.26.0,
  write `oats-local.yaml` (`oats onboard`), move what `oats-config.yaml`
  declared into `oats-workspace.yaml` and each `soul.yaml`, delete it, and run
  `oats sync`. Homes left behind retire under 0.26.0 with no retire hook, so
  revoke their messaging identities by hand.
- **Retire instances under `local-agents/` first.** 0.26.0 does not manage
  them; `oats status` and `oats doctor` report the problem
  `legacy-local-agents` until the directory is deleted.
- **Wake needs aw 1.36.5 or later** (verified on 1.36.8), and a restart of the
  host's wake daemon.
- **Captured homes and schedules:** retire each home, revoke the identities
  its retire warnings name, and re-spawn the soul. Remove each captured
  schedule (`oats schedule remove --force <id>`) and re-add it without the
  captured keys.

## Added

- **Private capabilities are listed as repo-owned** (`private: true` rows,
  still usable only by their own repository's souls). Feature
  `capabilities-private`.
- **`oats spawn <soul> --name <slug>`**: an explicit, unprefixed instance
  name, never rewritten; exclusive with `--purpose`. Refusals:
  `E_INSTANCE_NAME_INVALID`, `E_INSTANCE_NAME_TAKEN`. Feature `spawn-name`.
- **Instance names are at most 64 characters**, never truncated; a spawn
  schedule whose run names would exceed 64 is refused when saved.
- **The retire summary names what a recovery copied** (`outputs`, `bytes`).
- **`oats inspect --json` says where each layer's capability came from**
  (`layers.<layer>.from`: `soul`, `workspace` or `team:<label>`). Feature
  `layers-from`.

## Changed

- **Souls have no private mode.** `private:` in `soul.yaml` is accepted but
  ignored, with a `soul-private-ignored` warning.
- **A capability whose `compatibility.oats` the kernel does not satisfy is
  refused** (`E_CAPABILITY_INCOMPATIBLE`); an existing home reports
  `capability-incompatible` instead.
- **Catalog:** oats.authoring 1.0.3; oats.jira, oats.linear and oats.dev
  1.0.1 (require OATS >=0.26.0, settings only from the workspace model);
  oats.review 1.2.1.
- **A soul may name several team labels**; the first is the primary. Each
  label's `defaults.byTeam` applies (`E_TEAM_CONFLICT` on a clash). The
  messaging provider's settings no longer merge `byTeam[<label>]`; the
  per-label payloads travel in `OATS_TEAMS`, beside `OATS_TEAM_LABELS` and
  `OATS_TEAMS_SOURCE`, and a soul whose primary label is mapped gets a new
  `payloadRevision`. Feature `teams`. See the
  [teams contract](https://github.com/awebai/oats/blob/7838d3ca70772f63854b198601fbc45437c2e999/docs/design/2026-09-25-teams-contract.md).
- **Launch configurations move to `oats-local.yaml`** (`launch-configs:`).
  Move the block, or re-declare each entry with `oats launch-config set`. See
  [configuration.md](../configuration.md#launch-configurations).
- **The capability manifest contract applies to member and package
  capabilities** (`E_WORKSPACE_SCHEMA` / `E_PACKAGE_MANIFEST`), and a payload
  value outside `settings.<key>.values` is refused.
- **A capability agent composes only its providing module**, with no
  knowledge, messaging or tasks module.
- **`oats inspect`, `oats readiness` and `oats operation run` read the
  workspace model** (`operationsApi: 2`, `soulsApi: 2`, `readinessApi: 2`).
  Readiness checks are `installed | configured | member | providers`. See
  [desktop-cli-api.md](../desktop-cli-api.md#inspect-readiness-and-operation-run-on-the-workspace-model-operationsapi-2-soulsapi-2-readinessapi-2-oats-0260).
- **Manifest setting defaults reach workspace spawns** as the lowest payload
  layer; the preview's `settingsOrigins` says where each value came from
  (feature `settings-origins`).
- Spawn previews and `oats inspect` report each module's declared setting keys
  (feature `settings-declared`); `instance.json` records module skills and
  `workspace.name` / `workspace.deployment`.

## Fixed

- Every team label's messaging payload is validated, not only the primary's.
- Launch and retire hooks get the primary `OATS_TEAM_LABEL` and
  `OATS_TEAM_ID` (they were empty).
- Session start and restart of a workspace-model home no longer refuse with
  `E_LAUNCH_PREPARATION`.
- A spawn preview writes nothing to the deployment, the first one included.
- `oats retire <unknown>` is `E_SESSION_UNKNOWN`.
- Derived instance names are unique across the deployment.
- `oats status` reads a `schemaVersion: 2` soul.yaml correctly.
- `oats doctor --soul <name>` includes module injects.
- Capability commands recognise `OATS_INSTANCE_HOME`.
- `E_LAUNCH_PREPARATION` remedies no longer name removed verbs.
