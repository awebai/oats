# OATS 0.26.0

The workspace model is the only model the kernel knows ("v2 becomes the
classic"). The 0.24-era classic path is removed, not flagged: a 0.24.x kernel
keeps running 0.24.x deployments, and a 0.25.x deployment is already v2
([rebuild-to-v2.md](../rebuild-to-v2.md)).

## Removed

- **Package approval** (human decision, 2026-09-24). People install a package
  only when they trust it: declaring it in the workspace's `packages:` IS the
  trust decision, so there is no second, per-version approval step.
  - `oats sync` resolves, fetches, verifies integrity, writes the lock and exits
    `0` on success. No exit `2` for pending approvals, no interactive prompt, no
    `approvalNeeded` in the report and none on `changes[]` rows.
    `oats sync --approve …` is `E_BAD_ARGS` naming the decision.
  - `oats onboard` has no approval-pending outcome and no "approve first" hint.
  - The lock (v3) drops the per-entry `approved` record. A lock that still
    carries it is read with the field ignored, and the next write drops it.
    **A kernel before 0.26.0 cannot read a lock 0.26.0 wrote** (`E_LOCK_SCHEMA`
    on the missing `approved`): keep every kernel that reads one deployment on
    0.26.0 or later.
  - The lock still pins each package to its exact commit and content integrity.
    `oats sync` refuses a moved tag, drifted content and a lock whose capability
    list no longer matches the package (`E_PACKAGE_INTEGRITY`) —
    reproducibility, not approval.
    **Where integrity is checked:** `oats sync` recomputes each package's
    content digest and refuses drift. At spawn, the kernel checks the lock's
    capability list against the package and trusts the locked commit plus
    materialize's fetch-versus-copy self-check. The lock's integrity is
    recorded in each module's `from`, not recomputed per spawn. (The removed
    per-spawn executables-digest check was an approval binding, not an
    integrity guarantee.)
  - Spawn, `--preview` and operator dispatch never raise `E_PACKAGE_UNAPPROVED`;
    the executables-digest gate is gone. At spawn a package capability must come
    from a package the workspace **still declares** (a stale lock entry for a
    package removed from `packages:` is `E_PACKAGE_MISSING { reason:
    "undeclared" }` until `oats sync`), and the lock's capability list must match
    what the package declares at the locked commit (`E_PACKAGE_INTEGRITY { why:
    "capabilities" }`). A package capability agent is found only in a declared
    package.
  - `oats workspace status` loses its `approval` object and column; `oats
    capabilities` package rows lose `approved`; `oats doctor` prints each locked
    package's integrity instead of its approval.
  - `oats version --json` advertises `packages-no-approval`. `syncApi`,
    `workspaceStatusApi` and `capabilitiesApi` are NOT bumped: a consumer that
    reads the removed fields gates on this feature string.
- **The `soul` link in instance homes.** A home no longer carries
  `<home>/soul`: its composed `AGENTS.md` already holds the soul's
  instructions. The soul directory an instance incarnates is recorded as
  `instance.json` `soulDir` (a workspace soul's per-commit copy
  `<deployment>/agents/<soul>/souls/<commit12>`, or the read-only soul inside a
  capability package) and is handed to every classic lifecycle hook — spawn,
  launch, retire — and to every capability command dispatched inside a home as
  `OATS_SOUL` (captured lifecycle hooks set no `OATS_SOUL`, unchanged). Launch
  and retire hooks, and in-home commands such as `oats okf harvest`, previously
  received no `OATS_SOUL`; `oats operation run`
  previously handed the swappable `agents/<soul>/soul` pointer. Captured
  (portable) scaffolds no longer create the link either; their curriculum check
  compares the retained `AGENTS.md` and skills as before. `oats session
  recompose` reads the recorded `soulDir`. A spawn that is rolled back into
  quarantine records the soul in its cleanup descriptor, so a retried retire
  hook sees the spawn's soul. A capability command dispatched with no recorded
  soul gets no `OATS_SOUL`, never one inherited from the invoking process.
  - **Homes spawned before 0.26.0** record no `soulDir`. They keep their
    existing `soul` link (0.26.0 neither reads nor removes it). Their retire
    hooks get the soul pointer `agents/<soul>/soul` (today's soul, not
    necessarily the spawn's commit). They are degraded: their launch hooks and
    in-home commands get no `OATS_SOUL` (a provider that requires it, such as
    oats.okf 2.1.5, refuses with `E_OATS_SOUL_MISSING`), and `oats session
    recompose` refuses them (`E_SOUL_UNKNOWN`). Re-spawn to get a recorded
    `soulDir`.

- **Local souls and `local-agents/`.** A soul is a member repository's
  `souls/<name>` (`soul.yaml` + `AGENTS.md`); there are no machine-local souls.
  - **`oats create` is removed**: `E_UNKNOWN_COMMAND` naming the replacement
    (author `souls/<name>/soul.yaml` + `AGENTS.md` in a member repository, then
    `oats sync`). `--local`, `--type` and the `.gitignore` injection went with it.
  - **`oats spawn --instructions-file` and `--def-file`** (which wrote a local
    soul, including from a `.claude/agents` definition) are refused with
    `E_BAD_ARGS` naming the same replacement. `oats status` no longer lists
    importable definitions.
  - The kernel no longer composes the local-soul instruction block.
  - **`soul-scaffold` hooks are no longer run** (souls are authored in member
    repositories); manifests may still declare it until providers drop it.
  - **Capability-defined agents** (a package's or member module's `agents/`,
    such as the OKF harvester) now home at
    `<deployment>/agents/<agent>/instances/<name>`, like souls. That directory
    holds only `instances/`. A name that is both a workspace soul and a
    capability agent stays `E_SOUL_AMBIGUOUS`.
  - The agents root is found only as the closest `agents/` (or
    `PI_AGENTS_ROOT`); a `local-agents/` beside it no longer locates one.
- **OAS scope probes.** `oats doctor` no longer looks for un-migrated OAS
  scope files, and the dead `docs/migration-from-oas.md` links went with the
  probe.
- **The installed tier.** `oats doctor` loses its installed-packages section.
  The restore, remove, lock-migration and installed config-template readers
  are deleted with it.
- **Classic verbs** (lead decision 3). Each answers a typed refusal naming
  its replacement:
  - `oats type` and `oats soul set` are removed verbs (`E_UNKNOWN_COMMAND`).
    A soul is edited in its member repository (`soul.yaml` + `AGENTS.md`),
    then `oats sync`; per-spawn choices are spawn flags or a launch
    configuration. `soul` no longer routes with `--server`.
  - `oats session recompose` is `E_UNKNOWN_COMMAND`, and the
    `session-recompose` feature is no longer advertised. The refresh path is
    a re-spawn: an instance never changes under itself.
  - `oats status --team` is `E_BAD_ARGS`: `oats status` in the deployment
    lists every instance, and `oats workspace status` shows the members.
- **The classic answers of `oats inspect`, `oats readiness` and `oats
  operation run`** (lead decision 4). There is no v1 shape any more. With no
  `oats-local.yaml` in reach and no `--home` they answer `E_LOCAL_MISSING`; a
  `--home` whose `instance.json` records no `modules` (spawned by an earlier
  kernel) answers `E_UNSUPPORTED_MODE` (re-spawn it from the deployment); an
  unreadable `--home` answers `E_SESSION_UNKNOWN`. `--verify-signatures` is
  always `E_BAD_ARGS`, and the signature verifier is deleted.

## Upgrading from 0.25

- **Retire capability-agent instances before upgrading.** Instances homed
  under `<deployment>/local-agents/` (running knowledge harvesters, for
  example) are not managed by 0.26.0: it never reads, spawns into or retires
  from that directory, and only detects it (onboarding refuses into a
  directory that holds one). Retire them with the 0.25 kernel first, or accept that
  they are orphaned. While the directory exists, `oats status` and
  `oats doctor` report it once as the problem **`legacy-local-agents`** (JSON
  `problems[]`), naming the instances found there. Delete the directory once
  they are stopped.

## Added

- **`oats spawn <soul> --name <slug>`** (human decision, 2026-09-24): an
  explicit, unprefixed instance name. The name is exactly `<slug>`, with no
  `<soul>-` prefix. Derived naming (`--purpose`, `<soul>-<n>`) stays the
  default.
  - `--name` and `--purpose` are mutually exclusive (`E_BAD_ARGS`).
  - The name is never rewritten: a non-slug, or a soul name of the deployment,
    is `E_INSTANCE_NAME_INVALID`.
  - A name that any soul of the deployment already holds, or that a live tmux
    window carries, is `E_INSTANCE_NAME_TAKEN`; never a silent `-2`.
  - `--preview` reports the final name and the same refusals, and
    `--expect-decision` binds the name.
  - Feature `spawn-name`.
- **Instance names are at most 64 characters**, explicit and derived (the
  messaging alias allows 1–64). A longer name is `E_INSTANCE_NAME_INVALID` in
  preview and apply, and is never truncated. A derived name that would exceed
  64 (a long purpose, or the `-2` suffix on a long one) is refused, naming the
  purpose to shorten. A spawn schedule whose run names
  (`<agent>-<purpose|id>-<YYYYMMDDHHMM>`) would exceed 64 is refused when it is
  saved (`E_SCHEDULE_INVALID`). Previously such a name passed the kernel and
  failed only at the messaging join.

## Changed

- **Launch configurations move to `oats-local.yaml`** (lead decision 2: a
  spawn-time host choice). The deployment's `oats-local.yaml` gains a
  `launch-configs:` key with the same entries (`runtime`, `executable`, `args`,
  `env`, `model`, `yolo`); `oats launch-config set | remove` rewrite only that
  block, and `list` / `preview`, `--launch-config` on `oats spawn` and on
  `oats session start | restart`, and the `launch-config` feature are unchanged.
  There is one host file and no scope chain: `list` rows keep `source` (the
  deployment directory) and an always-empty `shadows`. A relative `executable`
  resolves against the deployment directory. A home's launch configurations
  are its deployment's, found walking up from the home.
  - **Upgrading:** a scope's `oats-config.yaml` that still declares
    `launch-configs:` is refused (its readers, and the `launch-config`
    commands, name the move). Move the block into `oats-local.yaml`, or
    re-declare each entry with `oats launch-config set <name> --file <json>`
    from the deployment. `set` with no `oats-local.yaml` in reach is
    `E_LOCAL_MISSING`.
- **The capability manifest contract is checked where a workspace reads the
  manifest.** The rules the kernel enforced only on classic capabilities now
  apply to member and package capabilities too, before anything runs:
  - a launch `environment` name inside the capability's vendor namespace (or an
    `environmentNamespaces` prefix that is not reserved), never a core or
    process bootstrap variable;
  - hooks: an approved event, a command string or `{ command, required,
    inputs }`, `required: true` only on the spawn hook, and a script path inside
    the capability directory;
  - hooks and launch environment only on a dotted id (`acme.tool`): an
    undotted id has no vendor namespace to claim.

  A member capability that breaks one is a discovery problem
  (`E_WORKSPACE_SCHEMA` at `capabilities/<dir>/oats.json#<pointer>`, shown by
  `oats workspace status`) and is not listed; a soul that declares it is
  refused with that problem (`reason: "manifest-contract"`), not "missing". A
  package capability that breaks one is `E_PACKAGE_MANIFEST` at `oats sync`.
  - **A provider payload value outside the manifest's `settings.<key>.values`
    is refused** (`E_WORKSPACE_SCHEMA`, `reason: "setting-value"`, naming where
    it was set: a `--provider` flag, `oats-local.yaml` settings, the soul or the
    workspace). A misspelled value used to be recorded and skip every
    conditional `requires` row that reads it.
- **A capability agent is a workspace-model spawn of its providing module
  only** (lead decision c3 Q1). `oats spawn <agent>` for a capability's
  `agents:` soul (OKF's `memory-harvest`, `oats.review`'s `reviewer`) records
  `modules`/`providers`/`workspace` like any v2 home, and composes exactly one
  module: the capability that declares the agent. The module comes from the
  `--parent`/`--relative-to` instance's verified copy (pinned to its recorded
  digest, with its recorded payload), else from a home that carries it, else
  from a confirmed member capability or a locked package that declares the
  agent (the source instance may be gone). A capability agent gets no
  knowledge, messaging or tasks module and runs no provider hook, its providing
  module's included: a harvester never registers as a knowledge source or gets
  a messaging identity. A knowledge-layer provider's inject is left out.
- **`instance.json` records `workspace.name` and `workspace.deployment`**
  (M5/3a). `oats inspect --home` reports the recorded workspace name without
  discovery, and `oats operation run --home` hands it to the provider as
  `OATS_WORKSPACE_NAME`. Homes spawned before 0.26.0 have neither.

- **`oats inspect`, `oats readiness` and `oats operation run` read the
  workspace model** on a workspace deployment and for every home whose
  `instance.json` records `modules`. They never read the classic config chain.
  The probe integers are the gate: `operationsApi: 2`, `soulsApi: 2` (the
  inspect soul rows) and `readinessApi: 2`. `oats souls --json` keeps
  `soulsApi: 1`, since its shape is unchanged. Shapes and examples are in
  [desktop-cli-api.md](../desktop-cli-api.md#inspect-readiness-and-operation-run-on-the-workspace-model-operationsapi-2-soulsapi-2-readinessapi-2-oats-0260).
  - The subject is an instance (`--home`: `{kind:"instance", instance, home,
    soul}`) or a soul (`--soul`: `{kind:"soul", soul, repoKey, commit,
    team}`). A workspace deployment with neither is `E_BAD_ARGS`; the
    scope-wide lists are `oats souls` and `oats capabilities`.
  - Payloads lose `scope` (`chain`, `team`, `agentsRoots`), config `levels`,
    `activation`, `currentConfig`, `snapshot`, `health.trusted` and the
    portable `sources`. A capability's origin is its module's `from`; its
    settings are the merged provider payload.
  - Readiness checks are `installed | configured | member | providers`:
    - `trusted` is removed, and `--verify-signatures` is `E_BAD_ARGS`.
    - `enrolled` is now `member`: the soul's member repository confirmed in
      the workspace (`oats-membership.yaml`), never `oats.yaml`.
    - `providers` is new: each bound provider's own binding check, relayed
      verbatim as `{status, problems, warnings}`. The status maps to the item:
      - `ready` → pass;
      - `needs-configuration` or `authorization-required` → fail;
      - `unavailable` → unknown.

      `warnings` is optional in the provider's answer and always present in
      the relay (`[]` when absent). It never changes the status: a ready
      binding with a warning still passes. The answer is decoded by the
      binding wire's rules (exit 0, one strict JSON document, the envelope
      echo, no problems on `ready`); anything else is `unknown`. All provider
      checks share one 60 s budget per read. Provider authors: the request,
      environment and answer are specified in
      [capabilities.md](../capabilities.md#readiness-check-bindingcheck).
    - A soul whose packages the lock does not provide fails `installed` with
      the typed code and an `oats sync` remedy.
  - The probe's integers say the kernel can answer the v2 shapes. Dispatch
    on each payload's own integer; the v1 shapes are removed (see Removed).
  - The `readiness-verify` feature is no longer advertised.
  - A v2 home's deployment is derived from its path
    (`<deployment>/agents/<soul>/instances/<name>`), and
    `<deployment>/oats-local.yaml` must exist exactly there (`E_HOME_MISMATCH`
    otherwise). A v2 spawn ignores an ambient `PI_AGENTS_ROOT` / `OATS_ROOT`.
  - A module tree in the deployment's store (used by readiness `--soul`,
    `operation run --soul` and `oats <ns>` dispatch) runs only while it
    matches the digest verified when it was fetched at the locked commit. A
    drifted tree is fetched again; a fetch that does not verify is
    `E_PACKAGE_INTEGRITY`.
  - `readiness --policy` is kept, with the same shape. The selector echo moves
    from `subject.selector` to a top-level `selector`.
  - `oats operation run` runs the module that fills the layer for the home or
    the soul. There is no trust gate, and the result carries
    `operationsApi: 2`. Remote routing accepts a destination advertising
    `operationsApi` 1 or 2.

- **Manifest setting defaults reach workspace spawns** (addendum 5). A
  capability's declared `settings.<key>.default` (for example oats.aweb's
  `identity: { mode: local }`) is now the lowest layer of the merged provider
  payload on `oats spawn`, `--preview` and `oats inspect --soul`, below the
  workspace, team, soul, host and `--provider` layers. The provider receives it
  in `OATS_SETTINGS` and `instance.json` `providers.<cap>` records it. The
  preview's new `settingsOrigins.<cap>` says where each leaf came from
  (`manifest-default`, `workspace`, `workspace-team`, `soul`, `host`,
  `spawn`; feature `settings-origins`), so a Desktop shows "Default" without
  hardcoding it. The decision
  binds the payload by value, defaults included. An instance spawned before
  0.26.0 keeps the payload it recorded, without the defaults.

## Fixed

- **Session start and restart of a workspace-model home.** Every start or
  restart of a home that records `modules` and a launch recipe refused with
  `E_LAUNCH_PREPARATION` ("… is no longer installed in the scope"): the
  launch providers' manifests were looked up from the home's recorded work
  repository instead of the home's own module copies. A module home now reads
  them from `<home>/.oats/modules`, and is never re-resolved against the scope;
  a module copy that is missing is its own refusal naming the directory.

- **A spawn preview writes nothing, the first one included.** The first
  `oats spawn <soul> --preview` of a workspace soul (or of a new member commit)
  used to fill the deployment's soul cache (`agents/<soul>/souls/<commit>/`)
  and move the `agents/<soul>/soul` pointer. A preview now reads the cache when
  a spawn already filled it, else fetches the soul to a temporary copy outside
  the deployment and removes it; `soulFetched: true` still says it fetched. The
  deployment is byte-identical after any preview, as `spawnPreviewApi 2`
  promises (docs/desktop-cli-api.md).

- **`oats retire <unknown>` is a typed refusal.** An instance name with no home
  under the agents root used to escape as an untyped error with a stack trace
  (no `--json` envelope). It is now `E_SESSION_UNKNOWN` (`no instance named
  "<name>"`), the code every lookup by instance name answers, exit 1, one
  envelope under `--json`.

- **Instance names are unique across the deployment.** A derived name used to
  de-duplicate only within its own soul's `instances/`, so soul `a` with
  `--purpose b-c` and soul `a-b` with `--purpose c` both got `a-b-c`. Derived
  names now skip every instance and soul name in the deployment (`-2`, `-3`, …).
