# OATS 0.30.1

## Added

- **Faster read verbs, and `--max-age <s>` to reuse recent remote heads** (feature `observe-max-age`): `status`, `workspace status`, `souls`, `capabilities` and `inspect` start far fewer git processes and cache what they parse by commit, and with `--max-age` they reuse a head observed in the last `<s>` seconds and report `observation {observedAt, reused, localRevision}` (`localRevision` changes whenever the local configuration read for the answer does) ([Observation reuse](../desktop-cli-api.md#observation-reuse-feature-observe-max-age-oats-0301)).

## Fixes

- **`oats --help` piped into another program is no longer cut off at 8 KB.** The top-level usage (about 20 KB) now arrives whole, including the "Observation reuse" section; exit codes are unchanged.
- **Desktop: an instance-less soul no longer takes the whole roster down.**
  `oats status --json` reports an agent row's `key` as `null` when no instance
  records a workspace soul, as the roster contract documents. That happens for a
  soul directory with no instances: after a spawn preview of a soul that has
  never been spawned, or after its last instance is retired. The 0.30.0 Desktop
  accepted only a string there, so one such row rejected the whole observation
  with `E_CLI_PROTOCOL` ("The installed OATS CLI returned an invalid deployment
  observation"). The Desktop now accepts `null` and still refuses any other
  type.
- **Knowledge readiness answers, fast.** With oats.okf 4.0.5, `oats readiness`
  answers the knowledge check from okf's cache in the knowledge `stateDir`, well
  inside the kernel's 30 s cap, instead of cloning every base and timing out as
  `unknown` (measured: 7 s against 35 s and `unknown` before). A base that is
  not cached yet, out of date or unreachable is reported as a named warning or
  problem, never `unknown`. A spawn with harvest off fills the cache, spending at
  most 20 s per base, and still refuses a soul that names a node its base does
  not have.
- **Desktop: a stored workspace selection the server no longer serves** (a
  deleted deployment) locked the Desktop out: every roster refresh refused the
  server's reply as "belongs to a different workspace", and the switcher
  already showed the served workspace as active. A selection that is not
  among the served workspaces is now treated like an empty one: both rosters
  adopt the served workspace and the stored selection is replaced. A
  selection the server does serve, answered with another workspace, is still
  refused.
- **Desktop: terminal tabs are back to native geometry.** 13px system
  monospace, xterm's default line height, and 32px side gutters with no
  vertical inset, as before Redesign v3. The block cursor is one cell tall
  again. A font size you chose yourself is kept.
- **Desktop: the spawn dialog could stay on "Reading defaults…" forever.**
  A routine roster refresh restarted the spawn preview while it was still
  being read, so on a machine where the preview takes several seconds it
  never finished. The dialog now re-reads only when a fact the preview
  depends on changes.

## Packages

- **oats.okf 4.0.5** (was 4.0.4 in 0.30.0): the knowledge readiness fix above.
- **oats.engineering 1.3.0** (was 1.1.0 in 0.30.0).
  - 1.2.0: the packaged `code-reviewer` launches on Codex with `gpt-6-astra` by default, a different model family from the developers it reviews. A machine without the `codex` binary gets `E_HARNESS_UNAVAILABLE` when it spawns `code-reviewer`, until it installs Codex or overrides the preference (`oats-local.yaml` `souls.launch`, or `--harness`/`--model` at spawn).
  - 1.3.0: review happens on local branches, before the PR. The developer runs its adversarial loop with the `code-reviewer` on its local branch and hands the reviewed branch to its expert. The expert reviews that branch, and only when it accepts is a PR opened. A returned branch's delta goes back through the same reviewer first.

## Changed

- **Desktop: calmer selection, focus and search fields.** A selected segment
  (Group by, List/Graph and similar) now uses the brand tint instead of
  white-on-grey. Clicking a button, tab or row no longer draws a focus ring.
  Keyboard focus stays visible as the tint plus a thin accent edge, not a
  2px ring. Search and filter fields have a single border that turns accent
  on focus, with no inner ring.
  Sidebar instance rows are more compact, with a gap between highlighted rows,
  and an instance's pull request number sits before its branch name instead of
  on its own line.
- **The official workspace lists each package capability once.** The `oats`
  repository kept byte mirrors of the official packages' capabilities
  (`oats.okf`, `oats.aweb`, `oats.jira`, …) under `capabilities/`, so `oats
  capabilities` in the official workspace also listed each of them as a member
  capability of `github.com/awebai/oats`, beside its package. The mirrors now
  live in `mirrors/`, which member discovery does not read, and the npm
  package no longer carries them (nothing read them at runtime: capabilities
  resolve from Git at the locked commit). No operator action.
- **Desktop: clearer Workspace views, and Spawn goes straight to the soul.**
  Soul cards label their facts ("Team oats", "No instances" instead of a
  bare "none"), group by repo by default, and keep a compact Spawn on the
  instances line. Capabilities are compact one-line row cards with a
  kind-coloured tile, their source and who uses them; a row opens the
  capability page with the full description. Teams show one card per team,
  split into shared and this-computer sections. Spawn on a soul card or the
  soul page opens the spawn dialog for that soul, with a "What will be
  created" preview (core capabilities and capabilities with their sources);
  "Change soul" returns to the picker.
- **Two Desktop souls.** The `oats-desktop-designer` soul is removed.
  `oats-desktop-expert` now owns Desktop's UX and design direction as well as
  its product rationale, and `oats-desktop-developer` builds all of
  `packages/desktop`, including renderer views, styles, themes and copy.
  Running designer instances keep working until they are retired; `oats
  status` reports their soul as no longer present.
- **The legacy Desktop soul trees are removed.** `agents/oats-desktop-engineer`
  and `agents/ux-designer` were no longer offered souls. The
  `oats-desktop-expert` knowledge node carries their durable rationale.
- **The remaining legacy soul trees are removed.** `agents/cli-dev`,
  `dev-coordinator`, `docs-expert`, `integrations-expert`, `lead`,
  `oats-coordinator` and `oats-expert` were pre-v2 soul bundles, not offered
  souls; the offered souls live in `souls/` and the packages. Their bundled
  knowledge gate (`npm run validate:okf`) goes with them: the souls' knowledge
  lives in the central knowledge base, which validates itself.
- **Desktop: a calmer instance panel.** The summary bar under the terminal
  (harness, tmux target, team marks, Details, Focus mode) is gone, and the
  terminal gets its height. A panel toggle at the end of the tab bar shows or
  hides the instance panel (⌥⌘B, Ctrl+Alt+B on Linux and Windows; also in the
  command palette). Focus mode stays in the palette; in focus mode the panel
  toggle and the sidebar's edge button stay visible and leave it. The Instance
  tab drops Built from and Details. When the kernel reports drift, its header
  shows an "older build" chip whose tooltip says what changed and that
  re-spawning picks up the new state. Where it works is one card: the work mode
  in plain words, then repo, branch and home. Messaging is a compact list of
  teams, with an icon refresh and the identity address on its own line. The Git
  & GitHub tab is now the Developer tab; it shows branch, changes and pull
  request cards; the branch line says how far it is from main and, when it has
  an upstream, how many commits are unpushed. An instance without Git by design
  (directory or workspace mode) gets a calm "No Git for this instance" note
  instead of a red error; a worktree that has gone missing still reports its
  error.
- **The official workspace's souls declare launch preferences.** Its experts,
  developers and setup admin prefer Claude Code with Opus 5.5 (`launch:` in
  each `soul.yaml`); each machine can override them in `oats-local.yaml`
  `souls.launch`, and spawn flags win over both.

## Still known in 0.30.1

The 0.30.0 notes said the first two below would be fixed in 0.30.1. They are
not in this release, and are planned for 0.30.2.

- With no teams configured, a spawn is refused by the provider
  (`E_SPAWN_FAILED`, relaying "no teams configured: run `oats aweb setup`"),
  not by the kernel's `E_TEAM_UNCONFIGURED`.
- A capability operator command run from a deployment needs `--soul <soul>`.
- On a team you control (BYOT), retire cannot revoke membership; the retire
  prints the owner's `aw id team remove-member` command, as in 0.30.0.
