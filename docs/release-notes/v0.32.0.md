# OATS 0.32.0 (unreleased)

## Added

- **Every instance a server reports is first-class in the Desktop, whoever
  spawned it.** A remote row opens its terminal, starts, restarts, stops and
  retires, and shows its readiness, activity, Git and diffs, just like a local
  one; only its pull request is not read here, since the forge reads this
  computer's clones. Stop and Remove keep their confirmations: the plan and
  its guarded apply run on the instance's machine. Every command goes to the
  server by the instance's home (`--server <id> --home <path>`), never by a
  bare name, so two instances with the same name stay apart. While a read is
  in flight, the view says "Reading from <server>…". When the server refuses,
  it shows the server's code and message under a headline that usually names
  the server; it never falls back to a local read. A remote stop or remove
  that loses its link reads as an unknown outcome, never a failure, and the
  server's roster is read again at once
  ([desktop.md](../desktop.md#instances-on-servers)).
- **A row that can't be opened says why, on the row.** The roster shows a short
  reason where it said "state unknown": Herdr no longer supported, gone from
  <server>, not reachable on <server>, or <server> not reached. The full
  sentence stays in the row's tooltip and its actions menu. For an instance a
  server no longer lists, it names the command that removes it from this
  computer (`oats server forget <server> --instance <name>`).
- **This computer's OATS 0.31 decides which server rows can be used.** The
  Desktop accepts OATS CLIs up to 0.32.x. With a local OATS before 0.31, which
  does not report that fact, an instance spawned from this computer stays
  usable through its saved route, as before; its routed reads and plans ask you
  to update OATS here.
- **A team card lists its members wherever they run.** On a local workspace's
  Teams page, each team with a provider id lists every instance in it: this
  workspace's, and every registered server's whose messaging identity is in
  that team. They are grouped by machine ("This computer" first), with each
  one's state in words. A member's name shows its roster row, where every
  action lives; **Terminal** opens a running member there. A server whose
  last roster read failed keeps its last-known members under "<server> · not
  reached"; servers with nothing to show are named under the page head. The
  card's count reads "N members · M on other machines". The Desktop reads
  this from what it already holds and runs nothing new
  ([desktop-teams.md](../../packages/desktop/docs/desktop-teams.md#team-members)).
- **The spawn dialog asks "Where to run" up front** (it was "Run on", under
  Developer settings). "This computer" comes first, then each registered
  server. A server is disabled, with the reason, when it wasn't reached or
  the roster knows only an older registration of it. With a server chosen,
  the dialog says where the instance will run, and the relationship picker
  lists only that server's instances: a relation never crosses machines. When
  the server refuses the spawn (a soul it doesn't offer, for example), the
  dialog says so in the server's own words.
- **The Desktop keeps and sets a harness's default launch configuration.**
  Editing a configuration marked `default: true` saves it with its default
  intact, and with an OATS that has `launch-config-default` the editor offers
  "Default for <harness> on this machine" for this computer's own
  configurations. A remote host's default survives editing too, but is set on
  that host. A second default for the same harness is refused in OATS's own
  words; unset the old one first.

## Fixed

- **A remote spawn with an empty opening instruction starts it waiting**, as
  the dialog says. It was refused ("--task needs a value").
- **Focus stays put on the Workspace's Teams, Capabilities and Setup pages.**
  Every roster poll rebuilt the page, since the workspace status it compared
  carries a fresh observation time each time, so keyboard focus (and the
  caret in the add-team form) fell back to the page every few seconds.
- **A click on a Desktop instance's actions menu does what it says.** With the
  pointer over the open menu, the row no longer counted as hovered, so its
  tools, the menu included, went hidden and a click on an item did nothing;
  the keyboard still worked.
- **The Stop and Remove confirmations show only their own choices.** Stop
  showed Remove's "delete the worktree" and "delete the local branch" options
  (enabled, and ignored), and Remove showed Stop's "include recorded children".
