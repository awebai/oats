# OATS 0.68.0

Unreleased

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says: a 0.67 Desktop refuses a 0.68.0 CLI. The
  0.68.0 Desktop accepts OATS CLIs `>=0.26.0 <0.69.0`.

- **One package move:** the official catalog pins oats.framework 1.14.0
  (Provider updates, below). A deployment that pins it takes it with `oats
  sync`; new spawns use it, and existing homes move with the step below. No
  floor changes.

- After bumping a package pin and running `oats sync`, stop each existing home
  that should adopt it and review `oats instance upgrade <instance> --plan`.
  Apply with the plan revision and an idempotency key, then start the session.
  Providers with state must support the `upgrade` adoption hook; a provider
  refusal names the remedy. oats.aweb's hook ships after this release, in
  oats.aweb 1.32.0: until a deployment pins that, a plan that moves oats.aweb
  refuses and names respawn. See [the deploy step](../upgrading.md#moving-existing-homes-to-locked-package-versions).
  This command requires a kernel advertising `instance-upgrade`; older
  kernels keep their existing spawn-only behavior.

## Added

- `oats instance upgrade` moves a stopped local home's package modules to the
  deployment lock, recomposing skills, instructions and hooks while keeping
  the recorded soul and member modules. Plans show provider adoption and
  composition changes and whether the home changed since spawn. Dirty homes
  retain their original retirement baseline for recovery, including with older
  kernels; work-tree baselines never change. Apply checks the revision and supports idempotent
  retries. Undo verifies the latest saved state and asks the restored version
  to adopt it. Before commit, a partial upgrade after a successful provider
  hook or an interrupted hook with an uncertain outcome finishes forward
  with the same key and blocks start with
  `E_UPGRADE_PARTIAL`. After commit, a cleanup failure permits start with a
  warning and the same-key retry finishes event publication and cleanup; another move waits
  until cleanup finishes.
- Start and restart report package drift and the command to move those
  modules. Their JSON includes `drift`; they keep the recorded copies. An
  unreadable lock yields one warning and no `drift`, without blocking launch.
  `modules.<cap>.previous` records the latest move, and `modules-upgraded`
  records its completion in instance events. Desktop tolerates the additive
  `previous` field and labels the new event.

## Changed

- **The `oats-getting-started` agent does more of the setup itself,
  instead of handing it to the person**
  ([#1314](https://github.com/awebai/oats/issues/1314)). A clean-machine trial of the skill
  showed it handing back work at the end. Now:
  - It adds `~/.local/bin` to the shell's startup file when it set a
    per-user npm folder.
  - It opens the GitHub device page in the browser.
  - It opens the person's terminal with the exact command in it, for each
    step that needs a password or token typed there (a `sudo` or Homebrew
    password, an aweb invite token) and for the TUI. The person types only
    the secret.
  - On Linux it starts OATS Desktop on the new deployment through the
    session manager (`systemd-run --user`), so it gets the desktop session's
    environment rather than the agent's. It checks that it is running.
  - It quits a running Desktop before installing over it.
  - Without FUSE it uses `--appimage-extract-and-run`, which needs no
    `sudo`.

- **Desktop: an instance's card on the Deployments page has two buttons.**
  Clicking an instance shows what it reports, as before, and two buttons:
  - **Go to instance** opens the instance's terminal tab. For a stopped
    instance, which has no terminal, it reads **Start…** and opens the Start
    dialog. Double-click, Enter and `T` do the same.
  - **Go to soul** opens the soul the instance was spawned from on the
    Workspace page: that exact soul, never another of the same name. When it
    can't be told exactly, the button is disabled and says why, for example
    when the soul is no longer among the deployment's souls, or the instance
    is on a deployment other than the one the Workspace page shows.

  The card's Git, Restart with…, Brain and Workspace buttons are gone, and so
  is the `B` key there, which only said Brain was unavailable. Restart with…
  is in the instance's menu and its panel, Git on the panel's Developer page,
  and Workspace in the rail and on `S`
  ([desktop.md](../desktop.md),
  [desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md)).

- **Desktop and TUI: pressing the leader (Ctrl+X) shows nothing.** The panel
  of keys at the bottom of the Desktop's main area, and the TUI's leader hint
  in place of its cheat sheet, are gone. The leader still waits for its key
  exactly as before. Its table is in the Desktop's shortcuts editor (`?` after
  the leader, or ⌘, / Ctrl+,) and in the TUI's help (`?`). In the Desktop, a
  screen reader still hears that a key is awaited, and a key that cannot act
  still says why in one quiet line
  ([desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md),
  [TUI](../tui.md)).

- **Desktop: the spawn dialog's section keys follow the form.** The Opening
  instruction, the form's first field, is now ⌘1 / Ctrl+1, and Name, its last
  before **Developer settings**, ⌘6 / Ctrl+6 (they were the other way round).
  ⌘2–⌘5 and ⌘7 are unchanged. A shortcut you rebound is kept, and where one of
  yours now shares a key with a section's new default, yours is the one that
  runs, as the shortcuts editor says
  ([desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md)).
- **Desktop: the instance name is proposed sooner.** Once the Opening
  instruction holds seven words, the Desktop asks OATS for a name as you type
  (it waited for three words and a pause of about a second and a half). The
  Name field's placeholder shows the proposed name alone, without "will be
  named". ([Desktop](../desktop.md))

- **TUI: each workspace keeps its tabs, layout and place across a switch.**
  - Opening another workspace still closes the open terminals' viewers (the
    agents keep running), but coming back opens them again: the tabs in their
    order and groups, the split, each group's shown tab, and where the focus
    was, zoom included.
  - A tab whose instance is gone or stopped is dropped; another machine's tab
    is asked first again.
  - The selection, the scroll and, new, the filter come back with their
    workspace. Before, the filter was dropped on every switch, and a filter
    still being typed in is kept as `Enter` keeps it.
  - The palette (Ctrl+X then `k`) keeps each workspace's own recency, its last
    50 instances, so working in another workspace leaves it as it was.
  - Nothing is kept after the TUI exits ([TUI](../tui.md)).

## Fixed

- `oats worktree remove` completes Git's partial deletion of a clean extra
  tree containing read-only ignored output, such as a Go module cache. A
  retry of an unregistered tree with a dangling `.git` file verifies its
  surviving files against the recorded branch before deletion, refusing
  modified or nonignored untracked paths even when tracked `.gitignore`
  files were deleted. Permission changes stay within the tree and never
  follow symlinks. Cleanup preserves `.git` until other entries are gone.
  Incomplete removal keeps the record and reports partial deletion
  accurately, with a manual recovery step when Git removed `.git` too.

- **Desktop: the tab and instance keys no longer skip a press.**
  - In a split, the tab keys (Ctrl+Tab, Alt+Shift+←/→, ⌥⌘←/→, the leader's
    ←/→ and ⌥⌘1–9 / Ctrl+Alt+1–9) went through every tab in the order they
    were opened, across both groups. They now stay in the focused group, in
    the order its strip shows.
  - Moving to the previous or next instance (the leader's ↑/↓,
    Alt+Shift+↑/↓, ⌥⌘↑/↓) could re-open the instance already being opened
    when pressed again before its terminal arrived. Each press now moves one
    instance on.

## Provider updates

- **oats.framework 1.14.0: oats.core 2.7.0, oats.setup 2.9.0.** Text only:
  neither floor (`compatibility.oats`) changes.
  - **`/oats-upgrade` reaches deployments.** oats.setup carries the skill
    for "upgrade OATS" and "update to the latest": it reads the upgrade page
    and release notes at the latest release's tag, not the installed copy,
    and the setup inject lists it. `/oats-setup-model` points at it for an
    upgrade ([#1440](https://github.com/awebai/oats/issues/1440)).
  - **`/oats-operate` teaches moving a stopped home's package modules.** A
    new section covers `oats instance upgrade`: stop, plan, apply with the
    plan's revision and an idempotency key, then start; a partial move that
    must finish forward; and `--undo` for the latest move. Its lines name
    their version, "from OATS 0.68.0"
    ([#1450](https://github.com/awebai/oats/issues/1450)).
  - **`/oats-operate` on a half-done `oats worktree remove`.** From OATS
    0.68.0, `remove` finishes a deletion Git left half done on read-only
    ignored output, and checks an unregistered residue against its branch
    before removing it ([#1451](https://github.com/awebai/oats/issues/1451)).
