# OATS 0.69.2

Unreleased

0.69.2 fixes a retire that a session resume could undo, and adds background
instances, the same-work flag, the TUI's session resume and a composed
`AGENTS.md` in the soul's capability order. OATS Desktop and `oats tui` no
longer say anything about a resume.

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says. The 0.69.2 Desktop accepts OATS CLIs
  `>=0.26.0 <0.70.0`, so a 0.69.1 Desktop also works with this CLI.
- **The retire fix is in the CLI.** With the 0.69.2 CLI installed, a resume
  started by any Desktop, `oats tui` or `oats session resume` no longer brings
  back a home OATS is retiring or stopping (Fixed, below). Until a host has
  it, quit OATS Desktop while you retire a batch of instances.
- **Package moves:** the official catalog pins oats.framework 1.16.1 and
  oats.okf 5.5.0 (Provider updates, below). A deployment takes them with
  `oats sync`. New spawns use them, and a stopped home moves to them with
  `oats instance upgrade`.
- **oats.okf 5.5.0 before 5.5.0 sources harvest.** A harvester on oats.okf
  5.4.0 or older refuses the `, incarnation` suffix 5.5.0 adds to a proposal's
  `Source:` line, so sync each deployment before its instances on 5.5.0 write
  proposals.
- **A soul's `background: true`** is refused by kernels before 0.69.2: commit
  it only once every deployment of the workspace runs 0.69.2 or later.
- **Existing homes keep their `AGENTS.md`.** The new composition order and
  the shorter instructions reach new spawns, and a stopped home that
  `oats instance upgrade` moves.

## Added

- **TUI: lost sessions are resumed when `oats tui` opens**
  ([#1559](https://github.com/awebai/oats/issues/1559)). After a shutdown, a
  reboot or a crash, `oats tui` asks OATS to resume every instance whose
  session was lost, on every deployment on this computer, without holding up
  its first screen. It asks again whenever a read shows a session lost while
  it is open, at most every 30 seconds. `oats tui` says nothing about a
  resume: the list is read again after each one, so a resumed instance shows
  running. `oats session resume --plan --json` shows what a resume would do,
  and `oats session resume` run by hand says why an instance could not be
  resumed. Quitting while the sessions are being resumed does not cut that
  short. There is no setting: stop an instance with OATS to keep it down.
  `S` and `R` are unchanged and never resume a conversation. See
  [Resuming lost sessions](../tui.md#resuming-lost-sessions).

- **An instance can record that it does the same work as its parent**
  (feature `instance-same-work`,
  [#1577](https://github.com/awebai/oats/issues/1577)). Clients draw the
  parent→child line for an instance that carries the flag.
  `oats spawn … --same-work` sets it on the new instance, bound to the
  parent the new home records (a child, a sibling of an anchor with a
  parent, a `--relation parent` over an anchor with a parent, an attached
  spawn); a spawn that would record no parent is refused with `E_BAD_ARGS`
  before anything is created. `oats instance same-work <instance> on|off`
  sets or clears it on an existing instance, addressed as
  `oats instance color` addresses one; `on` needs a recorded parent, and
  the answer is `{instance, sameWork}`. The flag is kept in the home's own
  record, `.oats-same-work.json`, naming the parent it was set against: it
  survives a restart, a stop and a start, a resume and
  `oats instance upgrade`, and only `off` or retirement clears it. It is on
  only while that parent is still the home's recorded `parentInstance`, so
  after a reparent (a retire's lineage splice, a `--relation parent` spawn
  re-pointing its anchor) it reads off until `on` rebinds it.
  `oats status --json` rows and `oats server roster --json` rows carry
  `sameWork: true` while it is on, and no `sameWork` key otherwise. Both the
  flag and the verb are routed with `--server`; a host without the feature
  is refused with `E_REMOTE_INCOMPATIBLE` and nothing is sent
  ([Same work as the parent](../desktop-cli-api.md#same-work-as-the-parent-oats-instance-same-work)).

- **Background instances** ([#1579](https://github.com/awebai/oats/issues/1579),
  feature `instance-background`). An instance can be recorded as background,
  so that clients list it under a Background section of its own. Like the
  colour, it is presentation only: a background instance spawns, starts,
  takes input, messages and retires like any other.
  - A soul gives the default with `background: true` in `soul.yaml`. Add it to
    a committed soul only once every deployment that reads it runs this
    release, because earlier kernels refuse the key.
  - `oats spawn … --background` or `--no-background` wins over the soul. The
    preview and the result carry `background` and `backgroundFrom` (`flag` or
    `soul`). A routed spawn sends either flag only to a host that has the
    feature.
  - `oats instance background <instance> on|off` changes it later, locally or
    with `--server`, under the same rules as `oats instance color`.
  - The home keeps it in `.oats-background.json` through restart, stop, resume
    and `oats instance upgrade`. A later edit of the soul moves no existing
    instance, and retire never counts the file as work.
  - `background: true` appears on `oats status --json` rows, remote roster
    rows, `oats inspect --home` and the soul rows of `oats souls --json`. The
    `oats status` text marks a row `[background]`.

  See
  [Background instances](../desktop-cli-api.md#background-instances-oats-instance-background).

- **Desktop and TUI: background instances are listed apart, under one
  closed Background heading** ([#1579](https://github.com/awebai/oats/issues/1579)).
  - An instance whose `background` is on (`oats instance background`, or
    a soul's `background: true` at spawn) leaves the main tree, and so do
    the instances below it. They are listed under a **Background** heading
    at the end of the sidebar's list, with how many there are. The heading
    starts closed in every new Desktop window and TUI session.
  - Inside, the rows form their own tree, with the machine headings of a
    workspace of two or more machines. No line joins the section to the main
    tree.
  - While a background instance waits on you, the heading says **Needs
    input**, open or closed, and the workspace's mark counts it.
  - The command palette still lists every instance. The previous and next
    instance keys pass over a closed section, and opening an instance's tab
    leaves the section as it was.
  - Desktop: the **Spawn** dialog's **Run in background** switch starts
    from the soul's default, and a row's context menu offers **Move to
    background** and **Move out of background**.
  - It needs OATS with the `instance-background` feature, on the server too
    for a server's instance. With an older OATS nothing changes. See
    [Background instances](../desktop.md#background-instances) and
    [the TUI's list](../tui.md#what-it-shows).

## Changed

- **Desktop: no notice about resumed sessions**
  ([#1559](https://github.com/awebai/oats/issues/1559)). OATS Desktop still
  asks OATS to resume lost sessions when it opens and when a roster shows one
  lost, exactly as before, but it no longer shows a notice about what was
  resumed, started fresh, left waiting or could not be resumed. A resumed
  instance shows running in the roster. A sweep that fails still writes one
  line with its code to Desktop's log. `oats tui` says nothing about a resume
  either. See
  [When Desktop opens](../desktop-instance-start.md#when-desktop-opens).

- **`.oats-same-work` is a kernel-owned home name**: a capability's
  `retirement.disposable.home` cannot declare it
  ([capabilities.md](../capabilities.md)).

- **Desktop and TUI: a parent's line joins only the children that do its
  work.** With an OATS that has the `instance-same-work` feature, the
  Desktop's sidebar and command palette draw a parent's line only to a child
  flagged as doing the same work (`sameWork: true`), and list those children
  first under their parent; the TUI, which draws no lines, lists them first
  too. The tree keeps its rows, indent and groups. So once the clients read the
  feature, the lines go away until flags are set: experts with live developers
  set them with the CLI, `oats instance same-work <instance> on`. Nothing is
  migrated automatically. A host without the feature keeps today's lines
  ([desktop.md](../desktop.md#the-sidebars-instance-tree),
  [tui.md](../tui.md#what-it-shows)).

- **A composed `AGENTS.md` puts the capabilities in the soul's order, and the
  kernel's blocks last.** It is the soul's own `AGENTS.md`, then the inject
  of each capability the soul lists, in its `capabilities:` order, then the
  workspace defaults the soul does not list, in the order the workspace's
  `defaults:` lists them, then the instance-boundary and work-mode blocks.
  Before, the kernel's blocks came right after the soul's body and the
  injects followed in capability-name order. A soul entry that re-lists a
  workspace default sits at the soul's place; a standalone soul's kernel
  default, `oats.core`, follows the capabilities it lists. A capability
  name made only of digits comes first in its list. Spawn, `instance.json`
  `instructions` and `composition.expected`, `oats inspect --soul
  --instructions` and `oats doctor --soul` all list the blocks in the new
  order; no JSON shape changes. Modules, skills and hooks keep their name
  order, and the resolution's revisions do not move, so no instance reports
  drift. An existing home keeps the `AGENTS.md` it has; `oats instance
  upgrade` recomposes it in the capability order it recorded, with the
  kernel's blocks last
  ([capabilities.md](../capabilities.md#what-an-instance-receives)).

- **Shorter always-loaded instructions.** The kernel's instance-boundary and
  work-mode blocks are about half their former size. The oats.core "You run
  on OATS" block is shorter too, despite the new rule below. They keep
  their behaviour rules, the pinned home/work boundary sentences among them,
  in emphatic form, and name which skill to load and when for the detail
  (`/oats-operate`, `/oats-souls`, `/oats-token-saving`). The instance-boundary
  block opens with "ALWAYS FOLLOW THESE INSTRUCTIONS FOR WORKING". The
  extra-trees commands are unchanged. Existing instances keep the AGENTS.md
  they were spawned with; new spawns get the new text.
- **oats.core: needs-input through the parent.** When a human talks to an
  instance's parent rather than to the instance, the instance sends its
  question to the parent, which sets its own needs-input claim naming the
  child and relays the answer ([capabilities.md](../capabilities.md)).
- **oats.core: an instance acts on other instances or the deployment also
  when its soul's capabilities say so,** besides its task or its human
  (`/oats-operate`, and the "You run on OATS" block).

## Fixed

- **The sweep could bring back a home that was being retired**
  ([#1559](https://github.com/awebai/oats/issues/1559)). A retire ended its
  instance's session without recording the stop, so for a moment the home read
  as lost, and a sweep that ran then (OATS Desktop or `oats tui` opening, or
  `oats session resume`) started it again in the home that the retire then
  removed. Now a home OATS is stopping, upgrading or retiring, or whose retire
  did not finish, is never resumed:
  - `oats session start --resume` holds the home's lifecycle claim for the whole
    start, as a retire, a stop and an upgrade do. Beside a retire it answers
    `E_INSTANCE_RETIRING`; beside a stop, an upgrade or another resume it
    answers `E_LIFECYCLE_BUSY`. A retire, stop or upgrade that meets a resume
    answers `E_LIFECYCLE_BUSY`, and the claim names `action: "resume"`.
  - The sweep reports such a home `skipped`, with the new reason
    `lifecycle-busy`, and starts nothing. What OATS was doing decides what the
    home is next, and a later sweep reads it again.
  - A retire records the stop before it ends the window. A home it was retiring
    reads `stopped`, never `lost`, also when the retire fails afterwards. The
    exception is a stop record that cannot be written (a full disk) followed by
    a retire that fails as well: that home reads `lost`, as before 0.69.2.

  The new reason and the new `action` value are additive. A client that does
  not know them treats the row as skipped and the claim as busy. See
  [Resume after a shutdown](../execution-targets.md#resume-after-a-shutdown).

- **Desktop: the terminal font size belongs to its face**
  ([#1571](https://github.com/awebai/oats/issues/1571)). Omarchy's font in the
  terminals used a size chosen for Inconsolata, which in the wider face is a
  fifth larger. Each face now keeps its own size and default: Omarchy's font
  13px, Inconsolata (System font, macOS, and Omarchy's font where it shows
  System font's faces) 15px, on every computer. A size stored before keeps
  applying to Inconsolata; Omarchy's font starts at its default. Changing the
  size (⌘= / ⌘-, the palette, Settings → Terminal) or resetting it (⌘0,
  **Terminal: reset typography**, Settings' **Reset to default**) changes the
  face in use only. A font change gives open terminals that face's size in
  place, and Settings shows its default (**Theme and font**, under
  [Workspaces](../desktop.md#workspaces)).

## Provider updates

- **oats.framework 1.16.1: oats.core 2.9.0 and oats.setup 2.9.3.** oats.core
  carries three changes:
  - its shorter "You run on OATS" inject (#1580);
  - the needs-input rule for a child whose human talks to its parent: the
    child asks its parent, which sets its own claim naming the child and
    relays the answer (#1580);
  - the skill lines for background instances (#1579). `oats-operate` shows
    `oats spawn … --background`, and `oats-souls` shows a soul's
    `background: true`. Both name OATS 0.69.2, the release that adds them,
    and say an earlier kernel refuses the key and the flags.

  oats.setup's `/oats-onboarding` pins `oats.okf: v5.5.0` in its knowledge
  section (text only). 1.16.0 carried the oats.core changes alone; 1.16.1
  adds the onboarding pin. The floors are unchanged, and the other
  capabilities are unchanged.
- **Upgrade:** `oats sync` locks it once the workspace or the catalog pins
  `oats.framework: v1.16.1`. New spawns get it, and a stopped home moves with
  `oats instance upgrade`, from OATS 0.68.0.
- **oats.okf 5.5.0: proposals name the source's incarnation; a shorter
  inject.** The catalog and this workspace pin `oats.okf: v5.5.0`, from
  5.3.0 (floor unchanged, OATS >=0.49.0). It carries 5.4.0 too.
  - 5.4.0: `oats instance upgrade` (OATS 0.68.0 and later) can move a stopped
    5.x home (oats-okf#106). A home spawned under 4.x is refused, with the
    remedy to retire and respawn it.
  - A proposal's `Source:` line ends `, incarnation <createdAt>`, copied from
    the source's `instance.json`, so a live source whose name was used
    before can harvest (oats-okf#111). A line without it still works for an
    unambiguous source.
  - The always-loaded inject is shorter; it loads the consultation and
    instance-knowledge skills at task start and after compaction. An
    instance runs its final checkpoint before it reports its work done, and
    says in the report whether a harvest still waits (oats-okf#112).
- **Upgrade:** a harvester on 5.4.0 or older refuses the new `Source:` line.
  Run `oats sync` to 5.5.0 before instances on 5.5.0 write proposals: the
  harvester is spawned from the lock.
