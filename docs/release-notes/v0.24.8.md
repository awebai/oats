# OATS v0.24.8 — lifecycle plans, readiness, spawn preview, instance events, and guarded Stop/Remove in the Desktop

Kernel/Pi/Desktop **0.24.8** (PR #69). Every new contract is advertised:
consumers gate on `oats version --json` `features[]` names and API integers,
never on the version number. Full shapes are in the
[Desktop CLI API](../desktop-cli-api.md).

## Kernel

- **Lifecycle plans** (`lifecycleApi: 1`, feature `lifecycle-plans`):
  `oats instance stop <i> --plan|--apply` and `oats retire <i> --plan`, then
  the guarded apply `oats retire <i> --plan-revision <rev> --idempotency-key
  <key> [--discard-worktree] [--delete-branch]`. A plan states the facts
  (ordered targets, session and work facts, recorded children) under a
  `planRevision`; apply refuses `E_PLAN_STALE` when they moved. A repeated key
  replays its receipt instead of acting twice.
  - **Retention by default** (feature `retire-retention`): a plain retire moves
    the worktree to `<workspace>/.agents/worktrees/<repo>/<branch>` instead of
    deleting it; `--discard-worktree` removes it; `--delete-branch` deletes the
    branch the tree is verified to be on and implies discard. A failed move is
    `E_WORK_PRESERVATION_FAILED` with the home kept.
  - **Children first.** A guarded retire stops the plan's recorded children
    (bounded SIGTERM, never escalated); a child still running refuses the whole
    retirement with `E_CHILDREN_RUNNING`.
  - Branch deletion is re-verified after hooks; a mismatch deletes nothing and
    reports `branchDeletionSkipped`. Ambiguous parentage is reported, never
    acted on.
  - An older CLI does not understand `--plan` and would retire on it, so
    consumers must gate on the feature.
- **Readiness** (`readinessApi: 1`): `oats readiness [--soul] [--home]
  [--verify-signatures] [--policy] --json` reports installed, trusted,
  configured and enrolled, each `pass|fail|unknown|not-applicable`, with items
  and remedies. Signatures are `unknown` unless `--verify-signatures` is given.
- **Child spawn policy**: soul `children: {spawn: bool}` and spawn
  `--allow-child-spawns|--no-child-spawns`, recorded in `instance.json`; a spawn
  with `--parent` under a disabled policy refuses `E_CHILD_SPAWNS_DISABLED`.
- **Spawn preview** (`spawnPreviewApi: 1`): `oats spawn … --preview --json`
  states the instance name, home, worktree, branch, base, runtime, model, launch
  configuration, work mode and policy without creating anything. `--base <ref>`
  picks the base; `@native-default` names the runtime's default.
- **Instance events** (`eventsApi: 1`, feature `instance-events`):
  `oats instance events <i> [--limit] [--since] --json` returns typed lifecycle
  events (spawned, launched, restarted, stopped, retired, worktree-retained,
  branch-deleted, recomposed and others); truncation and unreadable lines are
  visible.
- **Schedule run history** (`scheduleApi: 2`, feature `schedule-history`):
  schedules report up to 50 settled `recentRuns`.
- **Instruction refresh** (feature `session-recompose`): `oats session recompose
  --home <abs> [--dry-run] --json` recomposes a live home's `AGENTS.md` from its
  current soul, keeps the previous text beside it, and restarts nothing.
- `oats instance git|diff` reach remote instances through the saved route.

## Desktop

- **Connections**: Settings → Connections with "Connect GitHub" (device flow
  through `gh`, which keeps the credential). The Git & GitHub panel gains an
  informational PR card tied to the observed revision and branch.
- **Stop and Remove**: the instance menu offers *Stop…* and *Remove
  instance…*, each with a plan-backed confirmation showing the kernel's targets,
  children, session and work facts, the real branch and the retention choices.
  Lost responses show an unknown outcome; stale plans need a new confirmation.
  The old unguarded retire route answers `E_PLAN_REQUIRED`.
- Each control is unavailable when the installed CLI does not advertise its
  feature.

## Upgrade

`npm i -g @awebai/oats@0.24.8`, then `oats doctor`. Desktops on an older CLI
keep working; new controls appear as the CLI advertises their features.
