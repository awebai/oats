# OATS v0.24.10 — confirmed, idempotent spawn (apply contract) and the Desktop Review → Confirm spawn flow

Kernel/Pi/Desktop **0.24.10**. Consumers gate on `oats version --json`
`features[]` names and API integers, never on the version. Shapes are in the
[Desktop CLI API](../desktop-cli-api.md).

## Kernel: the spawn apply contract

A person can review exactly what a spawn will do and then confirm it; the
kernel guarantees that what runs is what was reviewed, and that a lost
response never spawns twice.

- **`spawn-apply-2`** (`spawnApplyApi: 1`): the previewed `decision` binds the
  effective launch facts (repo, work mode, runtime, model, launch config,
  yolo, backend, child policy, relation) as well as placement; an inherited
  default edited between preview and apply refuses `E_DECISION_STALE`. No
  backend starts before the decision check. The home is reserved with an
  exclusive `mkdir`, so two concurrent applies produce one home and the other
  refuses `E_PLACEMENT_TAKEN` having touched nothing.
- **`spawn-idempotency-2`**: `spawn --expect-decision <rev> --idempotency-key
  <key>` records both in the new home. A same-key retry replays the recorded
  receipt (found by key, not name) before any placement check. Same key with a
  different decision refuses `E_IDEMPOTENCY_CONFLICT`. A home whose spawn did
  not finish refuses `E_SPAWN_INCOMPLETE`, never a replayed success. The wake
  outcome is recorded and returned on replay (`wake {requested, saved,
  error}`).
- Decision-bound receipts echo the full decision, and a fresh keyed home
  retires clean. Known issue: bytes the agent writes to its home early after
  launch may not be recovered at retirement; fixed in [v0.24.11](v0.24.11.md).

## Desktop

- **Review spawn → Confirm spawn**: the spawn modal prepares an immutable
  intent (soul, root, choices, task, wake and the kernel's decision) and
  applies it by reference, keeping one idempotency key per intent. A lost
  response shows **unknown** with *Check result* (a same-key replay), never a
  second spawn. Stale or conflicting decisions require a fresh review. A raw
  local spawn request on a fully capable CLI is refused (`E_PLAN_REQUIRED`);
  older or remote CLIs keep ordinary spawn. A submitted intent does not survive
  a Desktop restart.
