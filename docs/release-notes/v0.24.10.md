# OATS v0.24.10 — confirmed, idempotent spawn (apply contract) and the Desktop Review → Confirm spawn flow

Kernel/Pi/Desktop **0.24.10**. Tag `v0.24.10` → the commit carrying these
notes; the version-bump commit lands after the tag. Consumers gate on
`oats version --json` `features[]` names and API integers — never on the version.

## Kernel — the spawn apply contract (K6c–K6f)

A Desktop can now let a person **review** exactly what a spawn will do and then
**confirm** it, with the kernel guaranteeing that what runs is what was
reviewed — and that a lost response never spawns twice.

- **`spawn-apply-2`** (`spawnApplyApi: 1`): the previewed `decision` binds
  **effective launch facts** (`repo, work, runtime, model, launchConfig, yolo,
  backend, childSpawns, relation/anchor`) as well as placement; an inherited
  default edited between preview and apply → `E_DECISION_STALE`. No backend
  (Herdr) is started before the decision fence. The home is reserved with an
  **exclusive** non-recursive `mkdir` right after the check: two concurrent
  applies of one decision produce exactly one home; the loser refuses
  `E_PLACEMENT_TAKEN` having touched nothing.
- **`spawn-idempotency-2`**: `spawn --expect-decision <rev> --idempotency-key
  <key>` records both in the new home. A **same-key retry replays** the
  recorded receipt (found by key, never by name — the planned name may have
  been auto-suffixed past it), runs **before** any placement/branch/base check
  (so a spawn that created its explicit branch still replays), and re-saves no
  wake. Same key + different decision → `E_IDEMPOTENCY_CONFLICT`. A home whose
  spawn did not finish (crash between metadata and launch) → `E_SPAWN_INCOMPLETE`,
  never a replayed success. The wake outcome is recorded and returned on replay
  (`wake {requested, saved, error}`; `saved:null` = not recorded).
- Decision-bound receipts echo the **full** bound decision; the kernel's own
  post-spawn writes (completion marker, wake record) re-stamp the retirement
  baseline so a fresh keyed home retires clean.
- Every one of these came from the Desktop engineer's pre-wiring reads of the
  merged producer, several proved in an inert VM; each is a new advertised name
  because a strengthened guarantee must be distinguishable from the installed
  CLI that lacks it.

## Desktop

- **Review spawn → Confirm spawn**: the spawn modal prepares a server-owned,
  immutable intent (soul, root, choices, task, wake, the kernel's decision) and
  applies only by reference; the idempotency key is minted at the first
  confirmation and kept for that intent's retries. A lost response shows
  **unknown** with an explicit *Check result* (a same-key kernel replay), never
  a second spawn or a guessed terminal. Stale/conflict refusals require a fresh
  review and a new confirmation. `E_SPAWN_INCOMPLETE` points at the session
  surface; an unrecorded wake outcome says so ("check Schedules"). A raw local
  spawn request on a fully capable CLI is refused (`E_PLAN_REQUIRED`); older or
  remote CLIs keep ordinary spawn with the new choices unavailable. No
  persistent task journal: after a Desktop restart a submitted intent is
  unavailable/unknown and mints nothing.
