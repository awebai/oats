# OATS v0.22.8

Two fixes an operator meets directly: picking a remote workspace in Desktop
now works, and the bundled catalog pin for the knowledge package catches up
with what is published.

## Desktop: selecting a discovered remote workspace

A registered SSH server's workspaces are discovered after the app starts, so
the main process's record of what the backend advertises could be seeded
before that discovery finished. Clicking the remote workspace in the menu then
looked like nothing happened: the request carried a workspace id the record
did not recognize, and an unrecognized selection is deliberately pinned back
to the verified local scope. The workaround was to open Add workspace and
cancel, whose own refresh repaired the record as a side effect.

The main process now learns that record from the successful `/api/panel`
responses it is already making, which are the same server-owned choices the
menu is built from, so a workspace that appears late is selectable as soon as
the menu can show it. No request is added, including for a selection that
stays unrecognized. Only a successful panel response teaches it: error
replies and other endpoints cannot. Nothing learned from an outgoing backend
can survive its replacement: a request that begins while the backend is being
replaced never teaches, and one that began earlier is refused if a replacement
started before its reply arrived, so the workspaces a stopped server
advertised cannot come back. Off-origin resolution is still rejected before
anything is fetched, and a selection the backend does not advertise is still
pinned to the local scope.

## Bundled: oats.okf 1.5.2 pin

The catalog shipped with the kernel now pins oats.okf v1.5.2, so
`oats update oats.okf` resolves it without an explicit selector. Until now a
bare update resolved the pin baked into the installed kernel, which was
v1.5.1, and reaching 1.5.2 needed `oats update oats.okf --to v1.5.2`.
Deployments that moved early with the explicit selector are already on the
same payload and need nothing. 1.5.2 makes a failed harvest exit non-zero,
stops `okf harvest --help` from running a harvest, and reclaims a leftover
`memory-harvest/<slug>` branch whose promotion is already merged into the
base, including when the base is a remote main ahead of the local one.
