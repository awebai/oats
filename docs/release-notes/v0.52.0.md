# OATS 0.52.0

Unreleased

## Changed

- **Desktop: the kernel readers moved to `packages/client/`.** The modules
  through which the Desktop reads the kernel's JSON (the CLI adapters and the
  contract decoders) now live in `packages/client/`, where a second client can
  import them. The Desktop behaves as before. In the installed app they are in
  `client/` beside `app.asar`, not inside it: `Contents/Resources/client/` in
  the macOS bundle, covered by its signature, and `resources/client/` on
  Linux. Installer CI now launches the packaged window on the Linux leg.
- **Desktop: the instance menu is built from one shared decision.** Which
  acts a roster row offers (inspect, start or restart, stop, retire) and why
  one is unavailable is now decided in `packages/client/`, where a second
  client can import it, with the roster's tree and its sections; the Desktop
  draws its menu from that answer. One thing differs: a remote row whose
  server does not report it as reachable has a menu with no items. That menu
  could not be opened before either (its button is disabled and says why), so
  the items it held were never reachable. A root test,
  `test/client-boundary.test.mjs`, pins what `packages/client/` may import
  and which of its modules and exports a second client may take.

## Documentation

- **`/oats-onboarding` names `oats aweb resident create` for a GLOBAL
  resident (oats.framework).** The "Fresh/reused GLOBAL resident and grant
  seat" route points at the one command from oats.aweb 1.26.0
  (aw >= 1.36.33), run with the dashboard's line, `--plan` first. Card 7's
  GLOBAL options are the exact `--provider oats.aweb identity.mode=global
  --provider oats.aweb identity.resident=<name>` that command prints.
- **`/oats-onboarding` describes oats.okf 5.x harvest (#901).** The skill
  pins `oats.okf` v5.0.2 and states the 5.x model. Souls propose at
  checkpoints and the harvester opens one pull request per proposal. There is
  no host or spawn switch. The one control enforced in code is the soul's own
  `knowledge: { harvest: off }`, per soul, and the exclusions (personal data
  included) are instructions only. The section also gives the move from 4.x:
  settle first, `oats okf setup --remove-legacy-settings` with `--plan`
  first, and respawn 4.x homes.
