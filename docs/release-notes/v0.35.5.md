# OATS 0.35.5

## Fixed

- **Adding a workspace never drops a saved deployment that is missing at
  that moment** (awebai/oats#472). A saved deployment on a volume that was
  not mounted yet stayed saved at launch, but adding another workspace then
  saved only the deployments that validated, and it was gone for good. The
  same happened when the Desktop was launched on a new deployment. Now the
  server is still started only with the deployments that are there, while
  `workspace-open.json` keeps every saved one; the next launch serves it again
  once it is back. Only an explicit remove drops a saved deployment (the
  Desktop has no remove action yet).

- **A pi instance launched with a task runs it, once, after the @awebai/pi
  welcome** (awebai/oats#469). pi's interactive mode sends `@TASK.md` as the
  session's first prompt with no streamingBehavior (pi 0.85.1
  `interactive-mode.js:816`), so pi refused it ("Agent is already
  processing…") when the @awebai/pi welcome turn was running or started
  while the task was being sent, leaving the instance idle with no task.
  With the bridge, the opening task now runs exactly once, after any turn
  another extension starts, exactly as pi's input processing made it: the
  bridge holds it on pi's own path until no turn is active, and never
  sends, re-sends or alters a message. One exception remains: an extension
  loaded behind the bridge that starts a turn (or awaits I/O while one
  starts) inside its own input or before_agent_start handling of the
  opening prompt can still make pi refuse the task, as before. The bridge
  with @awebai/pi has no such handler and is fully covered. Tested against
  pi 0.85.1; pi before 0.80.4, which has no `agent_settled` event, is
  covered by a model of its behaviour only. The fix ships in
  `@awebai/oats-pi` 0.35.5: a pi deployment must update the bridge to get it
  (`oats update` updates an installed bridge; without one, `pi install
  npm:@awebai/oats-pi`), then restart its pi sessions. The kernel alone does
  not fix it. Claude and Codex launches are unchanged.
