# OATS 0.35.5

## Fixed

- **Adding a workspace never drops a saved deployment that is missing at
  that moment** (awebai/oats#472). A saved deployment on a volume that was
  not mounted yet stayed saved at launch, but adding another workspace then
  saved only the deployments that validated, and it was gone for good. The
  same happened when the Desktop was launched on a new deployment. Now the
  server is still started only with the deployments that are there, while
  `workspace-open.json` keeps every saved one; the next launch serves it again
  once it is back. Only an explicit remove drops a saved deployment (the
  Desktop has no remove action yet).

- **A pi instance launched with a task always runs it** (awebai/oats#469).
  pi sends `@TASK.md` as the session's first prompt and refused it when the
  @awebai/pi welcome turn was running, or started at the same moment ("Agent
  is already processing…"), leaving the instance idle with no task. The pi
  bridge now queues the task behind that turn, and sends it again, once, if
  the turn made pi refuse it; it enters the conversation exactly once. When
  the turn starts at the same moment, pi still shows its refusal line
  briefly before the task runs after the welcome. Verified with pi 0.85.1;
  that resend relies on pi's `agent_settled` event (pi 0.80.4 and later),
  and on an older pi only the welcome-first order is fixed. The fix ships in
  `@awebai/oats-pi` 0.35.5: a pi deployment must update the bridge to get it
  (`oats update` updates an installed bridge; without one, `pi install
  npm:@awebai/oats-pi`), then restart its pi sessions. The kernel alone does
  not fix it. Claude and Codex launches are unchanged.
