# OATS 0.58.0

2026-10-15

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says: a 0.57 Desktop refuses a 0.58.0 CLI. The
  0.58.0 Desktop accepts OATS CLIs `>=0.26.0 <0.59.0`.

- **On a Mac, upgrade the CLI before the next reboot.** Up to 0.57.1, every
  directory-mode instance refused `oats session start` after a macOS reboot
  ("directory home was exchanged"). With 0.58.0 those homes start again, with
  no edit, including homes spawned before the upgrade. A host that is already
  stuck needs only the new CLI. See Fixed
  ([#1261](https://github.com/awebai/oats/issues/1261)).

- **A client that drives `oats spawn` itself** may pass `--max-age` on an
  apply bound by `--expect-decision`, when `oats version --json` lists
  `spawn-apply-max-age`. An older kernel refuses the flag (`E_BAD_ARGS`). See
  Added ([#1246](https://github.com/awebai/oats/issues/1246)).

- **The official catalog's versions are unchanged in this release:**
  oats.framework 1.12.0, oats.okf 5.2.0, oats.aweb 1.27.3, oats.engineering
  1.10.0, oats.cloning 1.0.1, oats.authoring 1.0.3, oats.jira 1.0.1,
  oats.linear 1.0.1 and oats.apps 1.0.0.

## Added

- **`oats spawn … --expect-decision <revision> --max-age <seconds>`: a
  confirmed spawn reuses its preview's observations** (feature
  `spawn-apply-max-age`, [#1246](https://github.com/awebai/oats/issues/1246)).
  An apply bound by `--expect-decision` now takes `--max-age`, as
  `spawn --preview` already did: it reuses member heads this machine observed
  at most that many seconds ago instead of asking each remote again, which
  saves the apply's `git ls-remote` round (about 0.3–0.45 s). The decision is
  computed from those heads, and one that differs from the confirmed revision
  is still `E_DECISION_STALE`, with nothing created. `--max-age 0` is live, as
  without the flag. The apply's answer is unchanged: it carries no
  `observation` block. A spawn apply without `--expect-decision` still refuses
  the flag (`E_BAD_ARGS`), now with a message that says so, and `--server`
  still refuses it. A client passes the flag on an apply only when
  `oats version --json` lists `spawn-apply-max-age`: an older kernel refuses
  it ([Apply](../desktop-cli-api.md#apply)).

## Changed

- **Desktop: a spawn no longer re-reads every member repository at the
  press** ([#1246](https://github.com/awebai/oats/issues/1246)). With a
  kernel that can reuse them, the Desktop's spawn lets the kernel use the
  member repositories' heads it observed in the last minute instead of
  reading each one again when you press Spawn. If the kernel then works out
  a different spawn from what the dialog showed, the spawn is still refused
  as before ("Something changed before the spawn went through…") and the
  values are read again.

- **Desktop: a spawn reaches its terminal sooner**
  ([#1246](https://github.com/awebai/oats/issues/1246)). Pressing Spawn no
  longer runs a second spawn preview when the dialog has been open more than
  a minute: the press uses the preview on screen for up to five minutes, and
  if anything changed meanwhile the spawn is refused as before ("Something
  changed before the spawn went through…") and the values are read again.
  Once the spawn is created, the Desktop reads that one workspace at once
  instead of waiting for its next full refresh, so the new instance's row and
  terminal appear without the extra second or more.

- **Spawn preview and apply are about 0.4 s faster on Claude souls whose
  capabilities require a Claude plugin**
  ([#1246](https://github.com/awebai/oats/issues/1246)). The harness-package
  check's probe, `claude plugin list --json`, now runs with
  `DISABLE_TELEMETRY=1` set for its own run, so Claude no longer flushes
  telemetry before it exits. The probe's answer, and so the check, is
  unchanged; the launch, the install steps and every other probe run as
  before ([The checks read the pane](../execution-targets.md#the-checks-read-the-pane)).

- **The Desktop accepts OATS CLIs `>=0.26.0 <0.59.0`**
  ([#1261](https://github.com/awebai/oats/issues/1261)). The compatibility band
  admits 0.58; a 0.57 Desktop refuses a 0.58 CLI. No new gate on the band.
  `oats tui` runs the kernel it ships with and is held to the same band.

## Fixed

- **A directory-mode instance starts again after a macOS reboot**
  ([#1261](https://github.com/awebai/oats/issues/1261)). macOS gives a volume a
  new device number each time it is mounted, so after every reboot
  `oats session start` refused every directory-mode home with "directory home
  was exchanged; restore the owned root before retrying start", although its
  home and `work/` were the same directories. On macOS a start now accepts a
  root whose inode matches the one the spawn recorded, and whose birth time
  matches too when one was recorded. A spawn now records each root's birth
  time; homes spawned earlier, whose baselines hold none, start with no edit.
  A real exchange, another directory renamed into the home's or `work/`'s
  place, is still refused with the same error, and Linux keeps comparing
  device and inode. Captured Pi sessions on macOS had the same problem at the
  next start after a reboot ("original Pi session directory was replaced");
  the same rule now applies to their session directory
  ([`directory` — independent execution](../souls-and-instances.md#directory--independent-execution)).

- **`oats tui`: an agent's terminal that ends says why again.** On tmux 3.2 to
  3.4, a terminal whose viewer ended at once, for example because the agent's
  window had just gone, could close with the line that the viewer "ended
  without saying why", and without the viewer's error output under it. The
  cause: tmux reports a pane as dead a moment before it has the exit status.
  The panel now waits for that status, for at most 10 seconds (2.5 seconds
  on tmux 3.2), so the line and the viewer's error output show again
  ([#855](https://github.com/awebai/oats/issues/855); see
  [`oats tui`](../tui.md)).
