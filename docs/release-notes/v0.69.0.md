# OATS 0.69.0

Unreleased

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says: a 0.68 Desktop refuses a 0.69.0 CLI. The
  0.69.0 Desktop accepts OATS CLIs `>=0.26.0 <0.70.0`.

- **Package moves:** the official catalog pins oats.aweb 1.32.0,
  oats.framework 1.15.0 and oats.engineering 1.15.0 (Provider updates, below).
  oats.aweb 1.32.0 requires OATS >=0.68.0: every host that shares a
  workspace runs OATS 0.68.0 or later before any of them syncs to it. A
  deployment then takes them with `oats sync`; new spawns use them, and a
  stopped home moves to them with `oats instance upgrade`.

- A broken machine file (unreadable, not YAML, empty, another top-level key,
  an invalid entry) refuses every launch that reads launch configurations,
  with `E_LAUNCH_CONFIG_INVALID` naming the file. A missing file changes
  nothing.

## Added

- **`Shift+PageUp` scrolls back in `oats session attach`**
  ([#1476](https://github.com/awebai/oats/issues/1476)). Every viewer binds
  it to tmux's copy mode, a page up, with or without `--detach-key`. Under an
  agent that takes the mouse, as Claude Code does, the wheel goes to the agent,
  and a viewer had no way to scroll back. In copy mode `PageUp` and `PageDown`
  move and `q` leaves it. See
  [Inspect, input and attach](../execution-targets.md#inspect-input-and-attach).

- **Desktop: scroll back in a terminal with the keyboard.** Shift+PgUp, or
  Ctrl+B then `[`, scrolls back through an agent's output, as the wheel does,
  in every terminal tab on this computer, and on another computer running
  OATS 0.69.0 or later. Ctrl+B followed by any other key still reaches the
  agent as both keys. Ctrl+B `[` needs tmux 3.3 or later on the computer the
  agent runs on. The shortcuts window lists the three under Tabs
  ([desktop.md](../desktop.md#copy-from-a-terminal),
  [desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md)).

- **Desktop: the shortcuts window's Most useful names how to scroll back in a
  terminal** ([#1502](https://github.com/awebai/oats/issues/1502)): "Wheel
  up, Shift+PgUp or Ctrl+B then `[`", as the Tabs group's row does. The Tabs
  row's tooltip also says that on another computer the two keys need OATS
  0.69.0 or later there. On Linux and Windows, when a shortcut that works in
  a terminal is bound to Ctrl+B, both rows leave Ctrl+B `[` out and the
  tooltip names the shortcut
  ([desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md)).

- **Desktop: an agent's question shows over its terminal.** While an instance
  waits on you, each terminal tab that shows it has a row over the terminal.
  The row says **Needs input** and how long it has waited, and under that the
  agent's question, as plain text. When the agent left no text, the row gives
  the reason in words, for example "Waiting for a tool approval". The question
  wraps to at most three lines, never takes more than a quarter of the pane,
  and ends with "…" when it is longer. The terminal resizes only when the wait
  starts, ends or its text changes, never as the age ticks over. In a split,
  each group has its own row
  ([desktop.md](../desktop.md#when-an-agent-waits-on-you)).

- **TUI: the cheat sheet names a terminal's scroll keys**
  ([#1502](https://github.com/awebai/oats/issues/1502)). While a terminal
  has the focus, the cheat sheet and, where it has room, a zoomed
  terminal's title row name the viewer's own keys: `Shift+PageUp or
  Ctrl+B [`, then `scroll back` (`Ctrl+B [` alone where the row holds one
  key). In the Alt family a zoomed terminal 120 columns wide or less has no
  room for them: its chords keep the row.
  - The keys are the ones the tab's host's kernel says its viewer takes:
    `Shift+PageUp` where it lists `session-attach-prefix-scroll`, and
    `Ctrl+B [` too where its `sessionViewer.prefixScroll` is true. That is
    this machine's `oats version --json` for a local tab, and the roster
    probe of its server for a remote one. A host without the feature gets
    no scroll keys named. `Ctrl+B [` is never named when the leader is
    `Ctrl+B` (`open.detachKey: "C-b"`), which takes that key first.
  - Each tab's viewer runs without its own status line where the kernel
    has `--no-status-line`: the cheat sheet says it instead.
  - See [the TUI's tabs](../tui.md#tabs).

- **TUI: an open agent that waits on you says what it waits on, above its
  terminal** ([#1502](https://github.com/awebai/oats/issues/1502)).
  - While the shown tab's agent has a live claim, a row stands under its
    tab bar: `Needs input`, how long it has waited, and the claim's
    message.
  - A claim with no message says what it waits on, for example
    `waiting on a permission prompt`.
  - The message wraps to at most 3 rows, and to a quarter of the group's
    height at most.
  - The agent's pane is resized only when the claim starts, clears or
    changes its text. Before, the question showed only in the agent's
    detail, which an open terminal covers. See
    [Tabs](../tui.md#tabs).

- **`C-b [` scrolls back in `oats session attach`, and the viewer says how**
  ([#1502](https://github.com/awebai/oats/issues/1502)). Not every keyboard
  has a PageUp.
  - **`C-b [`:** a viewer without `--detach-key` takes it to enter tmux's copy
    mode, as a tmux prefix does. It is the viewer's only `C-b` key. Any other
    key after `C-b` still reaches the agent as both keys (`C-b n`, `C-b c`,
    `C-b C-b`), with no timeout. It needs tmux 3.3 or later, whose
    `send-keys` can re-send the key after `C-b`. On an older tmux the viewer
    has no `C-b` key, and the line names `Shift+PgUp` alone.
  - **The status line:** the viewer shows one line under the agent,
    `Shift+PgUp or C-b [ to scroll back`. It takes the terminal's last row.
  - **`--no-status-line`** (feature `session-attach-no-status-line`) drops
    the line, for a caller that shows the keys itself.
  - **`sessionViewer.prefixScroll`** (feature `session-attach-prefix-scroll`)
    on `oats version --json` and `oats status --json`, relayed as each
    roster group's `probe.sessionViewer`: whether that host's viewer takes
    `C-b [`, read from its tmux afresh at each run. A caller that names the
    keys itself reads it per host.
  - **Copy mode is the agent pane's.** While one viewer scrolls back, every
    other viewer of that agent shows the same frozen screen.
  - **Each viewer reads key tables of its own**, named as its session and
    removed with it. Before, every viewer without a detach key shared one
    server-wide table, `oatsview-locked`.
  - **A tmux limitation:** a `C-b` pressed in the instant another viewer of
    the same tmux server opens is dropped. tmux resets every client's key
    table when any session sets `key-table`. The key after it reaches the
    agent alone.
  - See
    [Inspect, input and attach](../execution-targets.md#inspect-input-and-attach).

- This machine's launch configurations: `~/.oats/config/launch-configs.yaml`
  (`$OATS_HOME_DIR/config/` when set) declares launch configurations for every
  deployment on the machine. Its one key is `launch-configs:`, with the
  deployment block's schema. A deployment entry with the same name replaces
  the machine's whole and lists the machine file in `shadows`. A deployment's
  `default: true` for a harness wins over the machine's. With no deployment
  in reach, the machine's entries alone apply. A relative `executable`
  resolves against `~/.oats/config`. The person or an installer writes the
  file; `oats launch-config set|remove` keep writing only `oats-local.yaml`.
  See [This machine's launch configurations](../configuration.md#this-machines-launch-configurations).
- `oats launch-config list` gives each entry's `source` and `shadows`, and its
  text marks machine entries. `oats spawn --preview` names the machine file
  when it supplied the configuration, and its `--json` carries
  `launchConfigSource`, the declaring file's directory. `oats doctor` reports the file, and its
  `--json` carries `machineLaunchConfigs` (`file`, `present`, `ok`,
  `configurations`, `error`).

- **Desktop: a font picker.** **Font…** in the settings cog's menu, or
  **Font: choose…** in the command palette (no default shortcut; give it one
  in the shortcuts editor), chooses between
  **Omarchy's font** and **System font**. The choice is kept on this computer
  and applies at once: open terminals switch font in place and keep their
  session. The terminal font size and zoom are unchanged (**Theme and
  font**, under [Workspaces](../desktop.md#workspaces)).

- **`oats.machine` is an official package** at `v0.1.1`
  ([official catalog](../official-catalog.md)). It brings a steward for one
  computer, `oats.machine/steward`, and a technician that handles one machine
  problem at a time; both use the `oats.machine-care` capability, which the
  catalog aliases to the package. A workspace pins it as
  `oats.machine: v0.1.1`.

## Changed

- On Linux, on the unified cgroup hierarchy, each agent's harness now runs in
  a systemd scope of its own, `oats-agent-<hash>-<random>.scope` in the user
  manager's default slice, at every launch (spawn, session start and restart),
  wherever the OATS tmux server runs: systemd-oomd, which ends a whole cgroup
  under memory pressure, then ends one agent, never the server or the others.
  The harness stays the pane's direct child, and nothing recorded changes (the
  home's command, its launch recipe, receipts, `oats spawn --preview`). Before
  it wraps, a launch checks with `systemd-run --user --scope -- true`, in the
  pane's environment, that a scope can be created. When it cannot on a host
  booted with systemd (no user manager or bus in the pane, no `systemd-run`),
  the harness is launched as before, and the answer's `warnings` say `the agent's harness runs in the OATS
  tmux server's cgroup, not a scope of its own: <reason>`, as does a
  `launch-warning` event once the launch is recorded (a start refused after
  the check leaves none). Off Linux, on a Linux host not booted with systemd
  (a container's own init, another init system) and on the old or hybrid
  hierarchy, nothing changes and nothing is said (#1559).
- The OATS tmux server is now started in a scope of its own from inside any
  unit of the user manager, not only a service: a client launched from a
  desktop session (OATS Desktop or `oats tui` in its `app-*.scope`), a
  terminal's scope, an agent's scope. A login session's `session-N.scope` (an
  ssh or tty login) starts the server as before. A server that already runs
  keeps the cgroup it has (#1559). See
  [Where sessions run](../execution-targets.md#where-sessions-run-the-servers-scope-and-each-agents).

- **Desktop: the command that opens Workspace › Souls is named for what it
  does.** ⌘N / Ctrl+Shift+N, in the command palette and the shortcuts editor,
  now reads **Souls: choose a soul to spawn (Workspace › Souls)**, where it
  read **Spawn instance: choose a soul in Workspace**, so it is not mistaken
  for the sidebar's **Spawn instance** button, which opens Quick Open. Its
  keys are unchanged
  ([Keyboard shortcuts](../../packages/desktop/docs/desktop-keyboard.md)).

- **Desktop: on Omarchy, the font is Omarchy's by default.** On a computer
  that runs Omarchy, the window and its terminals use the computer's
  monospace font, the one `omarchy font set` changes (fontconfig's
  `monospace`), and the terminal's default size is 13px (JetBrains Mono,
  Omarchy's default face, at 13px; 15px elsewhere). In Omarchy's font,
  instance names in the sidebar and on tabs are 12px, a little smaller than
  System font's 12.5px. Everywhere else the
  default stays **System font**, the previous faces; **Omarchy's font** can be
  chosen there too (on Windows the system's monospace font; on macOS JetBrains
  Mono, with the terminals keeping Inconsolata). A chosen font or terminal size
  always wins. A terminal font family set with **Terminal: set font
  family…** still wins. Where the computer's monospace font does not draw at
  a fixed width (none installed, or a bitmap font), Omarchy's font shows
  System font's faces and its row in the picker says so.

- **Desktop: the sidebar's rows sit closer to the window's left edge.** The
  workspace and instance rows, their headings and the foot's OATS mark all
  move 4px left and stay in one column. The right side is unchanged.

- **Desktop: switching back to a workspace puts the keyboard back where you
  left it.** The terminal you were typing in has the focus again, ready to
  type, with no click; so does the instance's row in the list of instances
  (once the list is read), the tab, or the page's control. Picking a workspace
  from the list of workspaces, a move (Alt+↑ / ↓, ⌥↑ / ↓, the leader's
  ↑ / ↓) and a window falling back after another window took its workspace
  over all do it. A move made from the list of workspaces leaves the focus on
  the list. A tab that closed meanwhile gives the focus to the tab active in
  its place, or to the page
  ([desktop.md](../desktop.md#one-window-per-workspace)).

- **Desktop: the workspace moves wrap around.** Alt+↓ (⌥↓ on macOS, the
  leader's ↓) on the last workspace of the list shows the first, and Alt+↑
  on the first shows the last, instead of saying "No workspace below this
  one." / "No workspace above this one." With only one workspace to show,
  nothing moves and one line says "No other workspace to show." The TUI's
  moves wrap too
  ([desktop.md](../desktop.md#workspaces)).

- **`oats-getting-started` sets up a machine's steward with a global
  address** when its prompt hands it a machine found-list (a found-list with
  `machine.platform` set, as oats-omarchy's installer writes):
  - Step 1 is the machine's own round. It asks once, with a default for
    every value: the workspace and the namespace (both the machine's
    hostname, normalised), the steward's name (`steward`), the deployment
    directory, and the harness when the found-list names none. Enter
    accepts them all. No question comes after that round: a step that would
    ask tells the person what happened and stops.
  - The person's harness is recorded as the steward's launch preference
    (`oats soul launch set`), so harness trust, readiness and the spawn all
    use it.
  - The new workspace is the machine's own. It pins `oats.machine`, and its
    setup soul is `oats.machine/steward`; no `<workspace>-oats-setup-expert`
    soul is written.
  - Once messaging is set up, the agent creates the steward's resident with
    `oats aweb resident create <name> --team-label <label>`: first with
    `--plan`, then for real. It runs with no `AWEB_API_KEY`, using the team
    root that signup made. The agent then spawns the steward with the grant-seat
    options the provider prints. The steward's address is contacts-only:
    `<namespace>/<name>`.
  - With oats.aweb below 1.33.0, aw below 1.36.48, a machine that joined an
    existing workspace by invite, or a plan that does not take the root route,
    the steward gets a local team identity instead. The person is told so in
    one line, with no question asked. oats.aweb 1.33.0 is not released yet,
    so for now every steward gets the local team identity.

- **TUI: the workspace moves wrap around, as the Desktop's do.** The
  leader then `Down` (or `Alt+Down` in the Alt family and on macOS) on the
  last workspace of the list of workspaces opens the
  first, and the leader then `Up` on the first opens the last, instead of
  saying "No workspace below this one." / "No workspace above this one."
  With only one workspace to open, nothing moves and one line says "No
  other workspace to show." The list's own `Up` and `Down`, while it has
  the focus, still stop at its ends
  ([tui.md](../tui.md#the-list-of-workspaces)).

## Fixed

- **Desktop: a waiting instance's row says why, in words.** A message of
  only spaces showed as a blank line; it now reads as no message, so the
  row, the tab's tooltip and the sidebar's card give the reason in words.
  An instance waiting for a reason Desktop doesn't know read "Needs input"
  twice in its terminal's row, its tab's tooltip and an unavailable sidebar
  row's tooltip; they now say it once
  ([desktop.md](../desktop.md#when-an-agent-waits-on-you)).

- **A question to the person is no longer hidden by a later claim with no
  text** ([#1502](https://github.com/awebai/oats/issues/1502)). On a new
  user's machine the steward's yes/no question sat unseen for 2.5 days: a
  later `oats.core` permission claim with `message: null` replaced it in
  `waitingOnYou`.
  - `waitingOnYou` in `oats status`, `oats session inspect` and
    `oats instance events` now shows the newest claim that has a message. A
    text-less claim only fills in the reason when the shown claim has none.
    With no message anywhere, the newest claim is shown, as before.
  - **oats.core 2.8.0: Claude Code's waiting claims carry the prompt's
    text.** An `AskUserQuestion` gives the question's own words. A permission
    prompt gives Claude's "Claude needs your permission to use <tool>". See
    [the Claude Code emitter](../capabilities.md). It reaches deployments
    with the next oats.framework release.

- **Add a machine (`oats server connect`) finds an OATS and npm that only the
  host's login files put on PATH**
  ([#1517](https://github.com/awebai/oats/issues/1517)). Without `--path`, connect
  asks the host user's own login shell (bash, zsh or fish, run `-l -i`) for its
  PATH once. It records that PATH as the registration's `path`, and the oats it
  finds there as `oatsPath`, so installing, onboarding, readiness and every later
  `--server` command use the same environment. When the shell cannot be read,
  the `ssh` step's detail says why and connect uses ssh's own PATH. When even the
  login shell has no npm, the remedy names the PATH it searched and a command
  that checks it on the host, and you act on it by checking again, in Desktop
  too. An explicit `--path` is used as given. A machine registered before keeps
  its `path` and `oatsPath`; connect fills in only the ones it lacks.

- **`oats instance upgrade` moves a home whose oats.framework changes**
  ([#1549](https://github.com/awebai/oats/issues/1549)). oats.core has spawn
  and launch hooks but declared no `upgrade` hook, so the upgrade refused every
  home that carries it ("oats.core does not declare an upgrade hook; respawn
  the instance to change it").
  - **oats.core 2.8.0 declares a non-required `upgrade` hook.** The hook that
    runs is the destination's, so homes spawned on any earlier oats.core are
    covered, including framework 1.4.1, 1.8.0 and 1.14.1 homes.
  - `plan` adopts when the home records no oats.core metadata (no oats.core
    ever wrote any), `{}`, or a falsy value (`null`, `false`, `0`, `""`),
    which the kernel passes as `{}`. Any other recorded value is refused with
    the remedy `respawn the instance: oats retire <instance>, then oats spawn`.
  - `apply` carries the empty metadata unchanged. Neither phase reads the home
    or calls the host. The next start's launch hook rewrites the Claude Code
    waiting hooks for the moved module copy.
  - **oats.core's kernel floor rises from 0.40.0 to 0.49.0.** A kernel before
    0.49.0 drops a capability that declares a hook event it does not know, so
    it would lose oats.core on every soul. From 0.49.0 the kernel ignores the
    hook; only OATS 0.68.0 and later (`oats instance upgrade`) run it.
  - Known effect: after the move, the record holds
    `capabilityMeta["oats.core"]: {}`, as oats.aweb-tasks' adoption leaves it.
  - See [oats.core across `oats instance upgrade`](../capabilities.md#oatscore-needs-input).
    It reaches deployments with the next oats.framework release.

- **An instance with a file over 2 GiB in its work retires**
  ([#617](https://github.com/awebai/oats/issues/617)). The retire refused such
  an instance before doing anything, with `E_WORK_INSPECTION_FAILED: ... File
  size (...) is greater than 2 GiB`. A Git clone with a large pack in a
  directory instance's `work/` was enough. The retire's digests now read
  every file in pieces of 1 MiB, and so does the verification of its recovery
  copy. A home's `instance.json`, whose stored digest leaves out the fields
  the kernel writes after spawn, is read whole up to 16 MiB; a larger one is
  hashed as it is. Otherwise a digest is the same as before for the same
  bytes, so spawn baselines stay valid. A file that shrinks while the retire
  reads it refuses the retire with `E_WORK_INSPECTION_FAILED`, `<path>
  changed while it was read`. Retry once nothing writes to it. See
  [souls-and-instances.md](../souls-and-instances.md).

## Provider updates

- **oats.aweb 1.32.0: stopped seats upgrade in place, and joined teams mint
  only from a member root.** The catalog and this workspace pin
  `oats.aweb: v1.32.0`. It requires OATS >=0.68.0; the aw floor is unchanged.
  - **`oats instance upgrade` moves a stopped seat** (local, global grant or
    retained, including 1.17.1 metadata) to the locked package. Plan is
    read-only. Apply keeps the identity and grant, and makes no host
    registration or `aw` call. The next start re-registers the home and, where
    configured, renews the grant before revoking the old one. That ends the
    lost wakes after an upgrade or a restart: a grant seat's new grant home is
    registered first, and a local Codex seat recorded under `delivery: channel`
    registers `<home>/.aw` as a session home. `oats.aweb-tasks` adopts with it.
  - **A team other than the default** is joined at spawn, and its roster read,
    only from `roots[team]` or `root`, and only when `aw team list --json`
    there lists the team. The cwd, `OATS_WORKSPACE` and the home's own `.aw`
    never mint for it. A missing or non-member root refuses, naming the team,
    the root tried and the remedy (`oats aweb setup --join <label>
    --invite-stdin`, then a respawn). `oats aweb join --labels L --plan`
    shows the root a join would use, without inviting.
  - **Claude channel:** a start clears a cached aweb-channel failure, which
    made every Claude started in the next 15 minutes skip the channel, and
    readiness reads Claude's MCP log to prove a home registered on the channel
    (`channel-not-connected`, with the restart remedy).
- **Upgrade:** every host sharing the workspace runs OATS >=0.68.0 first.
  Then `oats sync` locks it; new spawns get it, or a stopped home moved with
  `oats instance upgrade`.

- **oats.engineering 1.14.0: maintainers per human, and shorter instructions.**
  The catalog and this workspace now pin 1.15.0, which carries it (below);
  the floor is unchanged.
  - **What a lane is.** A lane is a standing area of work: areas of the
    repository, a kind of work, or one human's requests. Work that would be
    finished when one goal lands is an effort in an existing lane. Any
    maintainer opens a lane with nobody's sign-off.
  - **One maintainer per human in each project lane.** The release lane stays
    one maintainer for the whole project, with the final say on merges and
    releases. A lane's maintainer owns its lane: it doesn't report to the
    maintainer that spawned it. By default a lane merges its own PRs once the
    release lane has signed off at that head.
  - **The lane map shows who holds each seat and what each maintainer is
    on.** Each maintainer keeps an entry of its own on it. Your messaging
    layer's presence says which maintainers are running.
  - **Experts find their maintainer.** An expert that no maintainer launched
    finds its human's maintainer in its lane. If there is none, it spawns
    one.
  - **Shorter injects.** The maintainer, expert and developer injects open
    with a short block of IMPORTANT, ALWAYS and NEVER rules, and run about
    half as long. The skills are about a fifth shorter, and no rule was
    dropped.
- **Upgrade:**
  - `oats sync` locks it. New spawns get it, and a stopped home moves to it
    with `oats instance upgrade`.
  - Maintainers add their entry to the lane map at their next intake.

- **oats.engineering 1.15.0: maintainers trust what experts relay from their
  human.** The catalog and this workspace pin `oats.engineering: v1.15.0`,
  which carries 1.14.0 (above); the floor is unchanged.
  - **A decision is trusted.** When an expert reports a decision it made
    with its own human, the maintainer takes it as that human's decision
    without asking them again. That covers an architecture, a design, a
    scope or a product call, and the same holds for a peer maintainer
    relaying its own human. The maintainer still gates it on soundness, the
    roadmap, the product direction and the architecture.
  - **A relay says "Decided with <human>: <decision>"** and where it is
    recorded. Anything else is a proposal.
  - **Authority is still confirmed with the human directly.** That covers a
    merge without its second reader, a hold or freeze exception, a tag or
    publication, a deploy, a destructive or outward-facing act, and marking
    another maintainer `left`.
- **Upgrade:** `oats sync` locks it. New spawns get it, and a stopped home
  moves to it with `oats instance upgrade`. Experts relay their human's
  decisions in the "Decided with" form.

- **oats.framework 1.15.0: oats.core 2.8.0.** oats.core's floor
  (`compatibility.oats`) rises from 0.40.0 to 0.49.0. The other three
  capabilities are unchanged.
  - **`oats instance upgrade` moves a home's oats.framework.** oats.core
    declares a non-required `upgrade` hook
    ([#1549](https://github.com/awebai/oats/issues/1549)), so a
    stopped home is upgraded in place instead of refused with "respawn". A
    kernel before 0.49.0 would drop a capability that declares a hook event it
    does not know, so oats.core now refuses such a kernel with the kernel's own
    compatibility message. Only OATS 0.68.0 and later run the hook.
  - **A waiting question carries its text**
    ([#1502](https://github.com/awebai/oats/issues/1502)). oats.core's Claude Code
    emitter puts the prompt's own words on its needs-input claim: the
    question, or Claude's "needs your permission to use <tool>". A claim with
    text is shown over one without. `/oats-operate` says so, from oats.core
    2.8.0.
- **Upgrade:** `oats sync` locks it once the workspace or the catalog pins
  `oats.framework: v1.15.0`. New spawns get it; a stopped home moves with
  `oats instance upgrade`, from OATS 0.68.0. Every host that shares the
  workspace runs OATS 0.49.0 or later first.
