# OATS 0.25.5

Patch release: one lifecycle-contract defect fixed; catalog pins may follow in
the same or a later patch as their tags are cut.

## Fixed

- **Launch-hook `meta` was collected and discarded.** A capability's `launch`
  hook may return `meta` like the spawn hook does, but the start/restart path
  consumed only its `launch` arguments and `env`, so `instance.json.capabilityMeta`
  kept the spawn-time value forever. A provider that re-issues a credential at
  every start (e.g. a renewed messaging session grant) would have left the
  ORIGINAL id on record, and retire — which reads that record as `OATS_META` —
  would have revoked the wrong one while the live one ran to its TTL. After a
  successful start the kernel now merges each capability's launch `meta` over
  its entry; a hook answering without `meta` keeps its prior entry; a failed
  launch preparation changes nothing. Regression test in
  `test/session-restart.test.mjs`; contract paragraph in `docs/capabilities.md`.

No new flags, fields or hook events. `oats version --json` unchanged apart from
the version.
