# OATS 0.25.5

Patch release: one lifecycle-contract defect fixed; two provider releases
pinned in the official catalog.

## Fixed

- **Launch-hook `meta` was collected and discarded.** A capability's `launch`
  hook may return `meta` like the spawn hook does, but the start/restart path
  consumed only its `launch` arguments and `env`, so `instance.json.capabilityMeta`
  kept the spawn-time value forever. A provider that re-issues a credential at
  every start (e.g. a renewed messaging session grant) would have left the
  ORIGINAL id on record, and retire — which reads that record as `OATS_META` —
  would have revoked the wrong one while the live one ran to its TTL. After a
  successful start the kernel now merges each capability's launch `meta` over
  its entry; a hook answering without `meta` keeps its prior entry; a failed
  launch preparation changes nothing. Regression test in
  `test/session-restart.test.mjs`; contract paragraph in `docs/capabilities.md`.

No new flags, fields or hook events. `oats version --json` unchanged apart from
the version.

## Catalog

- **oats.okf → v2.1.4** (mirror in `capabilities/oats-okf` synced, published
  tag `2af47ad3`): sparse staging to `base.root` from a single-branch partial
  clone with streamed object reads (large repositories and large files outside
  the knowledge base no longer matter), `git-timeout` binding key (600 s for
  remote operations), migration record hygiene + `oats okf migrate --forget`,
  owners keyed by `OATS_SOUL_ID` with a one-time rewrite of same-name path pins
  (closes the `E_OWNER`-after-member-commit regression; needs kernel ≥ 0.25.3),
  and retire removes a drained source's `okf-<id>` scheduler job.
- **oats.aweb → v1.12.0** (byte-identical to `capabilities/oats-aweb`):
  resident identity session grants — `identity.mode: local | global`, `team`
  read from the payload (so `messaging.byTeam.<label>.team` is now the per-label
  identity), host-only `residents` map, and the messaging-layer meta key
  `identity` on every spawn. Known limitation: sending mail/chat through a
  grant is rejected by the aweb server as of aw 1.36.1 (client bug; receive,
  wake and whoami work). Guide truths in `docs/workspaces.md` and
  `docs/rebuild-to-v2.md` updated from "1.11.2 ignores `team`" to what 1.12.0
  does.
