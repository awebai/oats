# OATS 0.35.3

## Fixed

- **A Desktop opened from Finder or the Dock finds the CLI's node**
  (awebai/oats#468). Such a launch inherits launchd's PATH
  (`/usr/bin:/bin:/usr/sbin:/sbin`). Discovery found the CLI through the
  login shell, but the probe and every later call ran it with that PATH, so
  its `#!/usr/bin/env node` failed on a Homebrew or nvm host, and every
  workspace showed `E_CLI_UNAVAILABLE`. At startup the Desktop now runs the
  login shell once (3 s timeout) and puts its PATH in front of the
  inherited one, for the backend, every `oats` call, the probe, a CLI picked
  with **Choose oats…**, and the tmux server it starts. Only PATH is taken,
  never the rest of the shell's environment. If the shell fails, the
  inherited PATH stays, and `/api/cli` says so (`pathSource`, `pathError`,
  `probePath`). An already-running tmux server is left as it is.
