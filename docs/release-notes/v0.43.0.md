# OATS 0.43.0

## Added

- **A one-line summary for every schedule and trigger** (feature
  `automation-descriptions`). One rule covers every kind and level. A
  `description` is one line of 1 to 200 characters with no control characters
  (no `\p{Cc}`, U+2028 or U+2029). Before this, only local schedules could
  carry one.
  - **Local triggers take `description`.** Out of the rule it is refused as
    `E_TRIGGER_INVALID {field: "description"}`. `oats trigger list` and `show`
    used to send `null` for every local trigger; they now show it.
  - **Package trigger templates may carry `definition.description`.** It is
    validated like any trigger's. `oats trigger add --from` copies it, and
    `--description=<text>` overrides it. A workspace trigger made `from:` a
    template shows its file header's description, or the template's when the
    header has none. A kernel before 0.43.0 refuses the key, so a package
    whose template sets it needs `compatibility.oats: ">=0.43.0"`.
  - **`--description=<text>` on `oats schedule add` and `oats trigger add`**
    sets the description, or overrides the one in the spec. `--description=`
    with an empty value leaves it out. With `--workspace`, the description goes
    to the file header, never into the body.
  - **Change only the description:**

    ```sh
    oats schedule update <id> --description=<text>   # without --file/--spec-json
    oats trigger update <id> --description=<text>
    ```

    `--description=` clears it. Both work on local schedules and triggers
    only; a workspace one is changed in Git (`E_AUTOMATION_WORKSPACE`). A
    schedule's description may change while the job runs or has an unresolved
    attempt, and the update runs under the same locks as any other. A
    trigger's fired and pending events are untouched. `oats trigger update`
    takes no other flag for now (`E_BAD_ARGS`): a full trigger update is still
    a remove and an add. `oats schedule … --server <id>` with `--description`
    needs the destination to advertise `automation-descriptions`
    (`E_REMOTE_INCOMPATIBLE` otherwise).

  The Desktop gates its summary writes on the feature. See
  [schedules](../schedules.md#kinds) and the
  [Desktop CLI API](../desktop-cli-api.md#automations-shared-rows).

### Desktop

- **Schedules and Triggers show each item's summary.** A row shows the item's
  name beside its origin tag (`local`, or the member), in place of
  `local/<id>`, and its summary under it. Without a summary, the row shows the
  first non-empty line of the task or wake message in muted italics, titled "No
  summary set — first line of the prompt". A command or operation row without
  one shows "No summary": the Desktop never makes a label from argv.
- **A detail page shows everything an item does**
  ([#545](https://github.com/awebai/oats/issues/545)). The title is the name,
  with the qualified id under it, and then the summary or "No summary".
  - **What it sends, in full:** a spawn's or trigger's task; a wake's whole
    message and the home it wakes (before, a wake said "No prompt"); a
    command's argv exactly as written, one argument per chip, and its working
    directory; an operation and the home it runs in.
  - **Spawns** also shows a spawn schedule's purpose (never shown before),
    harness and model, launch configuration, permissions, session backend, and
    the spawn's own recurring wake.
  - **Run state** shows a schedule that is running and since when. It also
    shows a run whose state is unknown and since when, with its exit facts,
    whether it still holds a host slot, *Check run state* and the
    `oats schedule reconcile <id> [--clear]` command to paste. A held job lock
    no longer hides an unknown run. It also shows a wake waiting to be delivered.
  - **An Invalid or Unreadable item** gets a card with its code, field and
    message. Before, they appeared only in a tag's tooltip.
  - **Comes from** adds the package template an item was made from (package,
    version, commit) and a local item's created and updated times.
- **Set a summary from the Desktop** (needs a CLI with
  `automation-descriptions`). The schedule form has an optional **Summary**
  field. **Edit summary** sets or clears the summary of any local schedule
  (command ones included) or local trigger, from the detail page or the row
  menu; it runs `oats <kind> update <id> --description=<text>`. The text is
  saved as typed, and an empty value removes it. A workspace item's summary is
  its file's `description:` in Git. With an older CLI, the Desktop shows the
  summaries it reports and the form keeps a stored summary unchanged.

## Changed

- **A workspace file header whose `description` breaks the rule is a warning,
  not a refusal.** Before, a non-string header description stopped the entry
  (`E_AUTOMATION_SCHEMA`), and any other value was accepted unchecked. Now the
  entry still loads and runs, with `description: null`, and the snapshot
  reports an `E_AUTOMATION_SCHEMA` problem at `<path>#/description`:
  "description: one line of 1 to 200 characters without control characters —
  shorten it or remove it; the automation keeps running without one". A label
  never stops a job. `oats trigger|schedule add --workspace` refuses an
  out-of-rule description before it writes the file.
- **The Desktop accepts OATS CLIs `>=0.25.8 <0.44.0`**, so it runs against
  this release's kernel; the Desktop 0.42.x refuses a 0.43 CLI. Upgrade the
  Desktop and the CLI together.
