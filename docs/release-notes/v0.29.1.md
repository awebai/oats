# OATS 0.29.1

## Added

- **Per-file line counts in `oats instance git`.** Each tracked file entry has
  `additions` and `deletions` (integers) and `binary`, so the Desktop can show
  `+84 −3` beside a changed file. They come from one `git diff --numstat`
  against the observed commit, counting staged and unstaged changes together,
  which is the same baseline as the status letters and `oats instance diff`.
  - A binary file has `additions: null, deletions: null, binary: true`.
  - An untracked file or a submodule has all three `null`.
  - A rename is counted on its new path.
  - `instanceGitApi` stays 1: the fields are additive. The text output shows
    `+N -M` after each path. See
    [desktop-cli-api.md](../desktop-cli-api.md#instance-git-state-oats-instance-gitdiff-instancegitapi-1-oats-0247).

## Changed

- **The `oats-setup-admin` soul is never harvested.** Its `soul.yaml` opts out
  of OKF harvest with `knowledge: { harvest: off }`: its sessions work on the
  deployment's own config and carry deployment specifics that must not reach
  the shared knowledge base. oats.okf 4.0.0 makes a soul's opt-out absolute, so
  a deployment that switches harvest on (`settings.oats.okf.harvest: on`)
  still registers no source, captures nothing and takes no custody for its
  instances. `oats okf harvest-status` in one of its homes reports
  `harvest: off` with the soul's reason.

## Desktop

The Desktop now shows the kernel's 0.29 Desktop facts and the Workspace v4
design's Git & GitHub section. On an older kernel, each fact is absent and its
view shows nothing new.

- **Souls say when a spawn here would refuse** (#228, #231). A soul the kernel
  reports as not spawnable shows "Can't spawn here" with the kernel's reason on
  its card and page, and its Spawn and Schedule… are disabled with that reason.
  A soul page offers Open file for a hosted soul file, and shows the file's path
  when it has no web address.
- **The server passes the kernel's Desktop facts through** (#230). Its souls,
  capabilities, workspace status and instance projections keep those fields,
  bounded, instead of dropping them. A soul's spawn default is nested as
  `spawnDefault`, so it is never read as the soul's own harness or model.
- **Capability pages** (#232) show the description, what the capability
  provides (skills, commands and hooks by name, or "Not listable"), its file and
  its fingerprint.
- **Setup names the files and this computer's state** (#233). It names the
  workspace and membership files, and links them when they are hosted. A member
  panel has Open repository and its clone on this computer. This computer lists
  the lock file, disabled souls and each member's clone, or "not cloned here".
  Packages with a newer version say "X available".
- **Setup shows the workspace defaults** (#237): each slot and its source ("not
  set" or "none" when empty), the default capabilities, and what each team adds
  or turns off.
- **The instance page** (#235) says when the session started, where its model
  came from (the soul, the spawn, the start, the launch configuration or the
  harness default), and its messaging address.
- **Each local instance's pull request on its roster row** (#234, #236). A new
  `POST /api/forge-roster` maps each instance to its member's clone from the
  kernel's workspace status and reads the branch's PR with `gh`, cached for a
  minute. The row shows `#N`, with draft, merged or closed in words. Remote
  instances, and hosts without a signed-in `gh`, show no badge.
- **W6 Git & GitHub** (#239, #240, #241, #242, #243). The instance's Git panel
  follows the design:
  - **Branch** shows the work mode, the distance from the default branch and
    whether the tree is clean, with the rest behind Details.
  - **Changes** is a list of status letters and paths, with Open diff.
  - **Pull request** shows the title and state, the issues it closes and the
    checks: failing first, with how long each took. It also shows the review
    decision with the count of unresolved review threads, and has Open on
    GitHub.
  - Check marks are icons. The thread count is read only for the open
    instance's PR, never for the roster.
- **Automations through the app proxy** (#224). `/api/automations` has its own
  proxy route, pinned to the verified workspace like the other workspace
  endpoints. It has a 90 s deadline, so `trigger test` (which polls the forge)
  is no longer cut off in the packaged app. The automations docs describe the
  API and the proxy.
- **Docs** (#227): the documented Desktop band is `>=0.25.8 <0.30.0`.
- The Desktop still accepts OATS CLIs `>=0.25.8 <0.30.0`.
