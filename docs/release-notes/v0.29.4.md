# OATS 0.29.4

## Fixed

- **Security: an automation's `model` could inject spawn options.** A trigger's
  `spawn.model` or a schedule's `model` such as `--task-file=<path>` was passed
  to the child `oats spawn` as a flag of its own. It could make any readable
  file the instance's `TASK.md`, or add `--work` or `--allow-child-spawns`,
  past the automation schema. Three changes close it:
  - `model` must be a model id; a schedule's `agent` and `repo` may not start
    with `-`;
  - every value reaches the child as one `--flag=value` token;
  - the CLI refuses an inline value that is itself an option (`--model=--yolo`
    is `E_BAD_ARGS`).
- **A package soul's command could get another soul's `OATS_SOUL`.** A command
  run from the deployment with `--soul <package>/<soul>` read the soul's copy
  under the bare name's agent directory. It ran without `OATS_SOUL`, or with a
  same-named member soul's copy. It now reads `agents/<package>--<soul>/`.
- **Upgrading from 0.28 re-fired every open pull request.** Trigger state kept
  under a local trigger's bare id (0.28) is now carried to `local/<id>`, so
  nothing re-fires. Homes that 0.28 spawned still count toward the trigger's
  concurrency.
- **A member repository named `local`** collided with this host's own
  triggers and schedules (`local/<id>`): their state, live counts and CLI
  edits. Such a member is now `E_AUTOMATION_DUPLICATE`, and its automations
  are not listed.
- Also fixed:
  - a workspace command's `cwd` may no longer leave the deployment (`..` or a
    symlink);
  - a newer push supersedes a pending `synchronize` for an older head;
  - a workspace trigger's `owner` and `on.repo` must be on the same GitHub
    host.

## Added

- **`triggersMaxConcurrent`** in the host registry
  (`~/.oats/schedules/registry.json`) caps trigger-spawned live instances
  across the host's scopes. It is absent by default, which means no host cap:
  each trigger's own `concurrency.max` applies. It is separate from the
  schedules' `maxConcurrent`: neither counts the other's instances.
