# OATS 0.29.4

## Security

- **An automation's `model` could inject spawn options** (#255). A trigger's
  `spawn.model` or a schedule's `model` such as `--task-file=<path>` was passed
  to the child `oats spawn` as a flag of its own. It could make any readable
  file the instance's `TASK.md`, or add `--work` or `--allow-child-spawns`,
  past the automation schema. Three changes close it:
  - `model` must be a model id; a schedule's `agent` and `repo` may not start
    with `-`;
  - every value reaches the child as one `--flag=value` token;
  - the CLI refuses an inline value that is itself an option (`--model=--yolo`
    is `E_BAD_ARGS`).
- **oats.okf 4.0.1: a crafted Git base could write files anywhere the user
  can write** (okf 3.0.0 and 4.0.0). Every tree entry of a base's accepted
  commit is now contained, and a bad entry refuses the whole base with
  `E_PATH`. Upgrade the pin; details under oats.okf 4.0.1 below.

## Fixed

- **A member repository named `local`** collided with this host's own
  triggers and schedules (`local/<id>`): their state, live counts and CLI
  edits. Such a member is now `E_AUTOMATION_DUPLICATE`, and its automations
  are not listed (#256).
- **A workspace command's `cwd` may no longer leave the deployment**, through
  `..` or a symlink (#256).
- **A newer push supersedes a pending `synchronize`** for an older head of the
  same pull request (#256).
- **A workspace trigger's `owner` and `on.repo` must be on the same GitHub
  host** (#256).
- **Upgrading from 0.28 re-fired every open pull request.** Trigger state kept
  under a local trigger's bare id (0.28) is now carried to `local/<id>`, so
  nothing re-fires. Homes that 0.28 spawned still count toward the trigger's
  concurrency (#256).
- **A package soul's command could get another soul's `OATS_SOUL`.** A command
  run from the deployment with `--soul <package>/<soul>` read the soul's copy
  under the bare name's agent directory. It ran without `OATS_SOUL`, or with a
  same-named member soul's copy. It now reads `agents/<package>--<soul>/`
  (#256).

## Changed

- **`helperInjection` is marked deprecated in the capability manifest
  schema** (#257). It has been ignored since 0.26 and is still accepted, so
  old manifests validate. oats.core 2.1.2 and oats.setup 2.1.3 no longer
  declare it; the catalog and this repo's workspace pin `oats.framework` to
  `oats-framework/v1.3.2`, which ships them.
- **`triggersMaxConcurrent`** in the host registry
  (`~/.oats/schedules/registry.json`) caps trigger-spawned live instances
  across the host's scopes (#256). It is absent by default, which means no
  host cap: each trigger's own `concurrency.max` applies. It is separate from
  the schedules' `maxConcurrent`: neither counts the other's instances.

## oats.okf 4.0.1 (catalog pin and bundled mirror)

The catalog and this repo's workspace pin `oats.okf` to `v4.0.1`. The three
bundled capabilities (`oats.okf`, `oats.okf-harvest`, `oats.okf-maintenance`)
are the tag's trees. The kernel floor stays `>=0.29.0`.

- **Security: a crafted Git base could write files anywhere the user can
  write.** This affects okf 3.0.0 and 4.0.0: upgrade.
  - Validating a Git base's accepted commit copied every tree entry into a
    scratch directory with no containment check. Git accepts literal `..`
    entries.
  - The first `oats okf bases`, or a spawn against a crafted accepted commit,
    could create any file that did not yet exist, with attacker content.
  - Every entry is now checked against the canonical path rules, and its
    target must stay inside the scratch. All entries are checked before
    anything is written, and the first bad entry refuses the whole base with
    `E_PATH`. The staging materializer asserts the same.
  - GitHub probably blocks such a push; local and self-hosted bases do not.
- **Credentials are never shown to agents.** A repository URL with a user or
  token in it is refused at binding: use a Git credential helper or an SSH
  key. Every repository in `bases` output and in errors is redacted,
  including Git's own failure text.
- **Knowledge review trusts only the accepted base.**
  `review-context --checkout` takes node ownership from the base's accepted
  `okf-base.json`, never from the PR. It lists the nodes a PR claims but the
  source does not own, and flags any change to `okf-base.json`.
- **A merge is tied to the reviewed head**
  (`gh pr merge --match-head-commit`). **`okf-needs-human` is a hard stop**
  for every PR event, until a human removes the label.
- **Turning harvest off takes effect at once.** `run-source` and `retire`
  re-read the harvest switch, including the soul's. A soul or deployment that
  turns harvest off after spawn stops capture at the next run. Retire then
  takes no final capture; inputs already in custody stay.
- **`OATS_SETTINGS_ORIGINS` is an extra signal:** a harvest value that comes
  from the soul never switches harvest on. `soul.yaml` stays the authority for
  the absolute opt-out.
