# OATS v0.24.2 — `oats onboard`, official capabilities in a soul's definition, aweb 1.11.0 pairing

Kernel/Pi/Desktop **0.24.2**. Publication is not deployment: every operator still installs, approves and qualifies locally.

## What changed

- **`oats onboard [--dir <deployment>] [--workspace <git:source[@rev]>] [--force-existing] [--json]`** bootstraps a deployment with an **`oats-setup-expert`** soul that holds `oats.core` and `oats.setup`. It acquires the official `oats.framework` package (no catalog auto-trust), activates exactly those two capabilities for that soul, pins both at the acquired commit, and **prints** the spawn command; it never launches a model. `oats setup` (record capture setup) is unchanged.
- **Soul creation declares `oats.core` explicitly.** `oats create` writes `requires.capabilities.oats.core` resolved from the official catalog; `--no-oats-core` opts out. A soul that declares `oats.core` or `oats.setup` no longer receives the legacy kernel skills (`oats`, `oats-config`, `oats-packages`) or the `kernel:oats` injection; the capability's skills replace them. Other souls keep the legacy behavior, and `oats doctor` prints an informational line.
- **Official capabilities.** `oats.framework` **1.1.1** (tag `oats-framework/v1.1.1`) exports `oats.core` (`oats-operate`, `oats-souls`, the "you run on OATS" briefing), `oats.setup` (`oats-config`, `oats-packages`, `oats-workspace-setup`) and `oats.knowledge-theory`, listed in the official catalog with capability aliases.
- **Retained inspection reports `launchSelection`** (`{runtime, model}` or `null`) for the primary, and provider binding codecs receive `OATS_CLI_BIN`.
- **aweb 1.11.0 pairing.** The catalog and the framework soul editions pin `oats.aweb@v1.11.0`, which adds the portable binding interface (floor `>=0.24.2`). Its `check` qualifies only an explicit private team with `delivery: session` and an input-capable Claude or Codex primary; a strict-Pi print primary reports `needs-configuration`.
- **Six framework soul editions** are exported and imported by `oats-workspace.yaml`: `oats-expert`, `oats-kernel-expert`, `oats-desktop-expert`, `market-research-expert`, `oats-assistant` and `oats-setup-expert`, all declaring `oats.core`.

## Known limits

- The first-contact seams in `inspect` and `prepare` (request-file mismatch, raw `ENOENT` on an absent deployment, `oats trust --dir` rejecting lock v3, `--artifact-set` missing from help, unattributed provider problems) are fixed in [v0.24.3](v0.24.3.md).
- Pi primaries do not support session input.
