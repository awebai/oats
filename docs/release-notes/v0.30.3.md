# OATS 0.30.3

## Changed

- **Desktop: the whole app works from the keyboard, with a Linux-sane keymap.**
  Changed Linux and Windows defaults: the command palette is now Ctrl+Shift+P
  on Linux and Windows; close tab Ctrl+Shift+W; split Ctrl+Shift+E /
  Ctrl+Shift+O (close the split Ctrl+Shift+Alt+W); Spawn instance
  Ctrl+Shift+N; the theme cycle has no default chord (on macOS too; the palette
  keeps it). No default chord takes a key a program in the terminal reads:
  plain Ctrl+W, Ctrl+K, Ctrl+\, Ctrl+P and Ctrl+B, F6, Alt+digit and
  Ctrl+PgUp/PgDn (and ⌃digits on macOS) always reach the program, and nothing
  binds Super. New: go to tab (⌥⌘1–⌥⌘9 / Alt+1–Alt+9), Ctrl+PgDn / Ctrl+PgUp,
  ⌘3 / Ctrl+3 for Automations, and F6 / Shift+F6 to move between the sidebar,
  the instances, the main area and the instance panel; from a terminal,
  ⇧⌘F6 / Ctrl+Shift+F6 leaves it for the next region. Your own rebinds are
  kept; one that now clashes with another shortcut is flagged in the shortcuts
  editor, never changed for you. Quick Open (⌘P / Ctrl+P)
  now opens the spawn dialog for the soul you pick, and Esc takes you back to
  where you were; ⌘↵ / Ctrl+Enter spawns from any field, and Tab walks the
  form in the order you see it. Keyboard gaps found in an audit are closed:
  roster rows of unknown state, Independent nodes in the Active overview, the
  Automations row menu, the schedule form and focus lost after switching tabs
  or views. The keymap and the audit are in
  `packages/desktop/docs/desktop-keyboard.md`.
- **Desktop: the spawn dialog says why each capability is there.** In "What
  will be created", each Capabilities row shows a muted reason tag beside its
  source: **Soul**, **Workspace default**, or, for a workspace default that
  fills a core slot, **Workspace default · messaging** (knowledge, messaging or
  tasks). It is the preview's `composedFrom`, read only from a CLI that reports
  `preview-composed-from`; with an older CLI the rows show no tag, never a
  guess. The Core capabilities table is unchanged.
- **Desktop: clearer overview lines, a centred rail, pinned Workspace controls.**
  The Active overview draws parent links as smooth curves from a parent's
  bottom to its child's top, with dashed arcs between siblings, in a colour
  that is visible in every theme. The collapsed instance panel's icons sit
  on its centre line. In Workspace, the Capabilities section pills and search
  and the Teams header stay in view while the content scrolls, and scrolling
  to the end of a list no longer moves the whole window.

## Fixes

- **Plain `oats` inside an instance is the kernel that launched it.** On a
  machine with two kernels side by side (a global 0.24 for classic
  deployments and a 0.30 prefix install), an agent typing `oats` got whatever
  `PATH` found first: `oats aweb teams` answered `E_UNKNOWN_COMMAND` in a 0.30
  home. Every launch (spawn, `session start`, `session restart`) now writes
  `<home>/.oats/bin/oats`, a link to the launching kernel, and runs the harness
  with `<home>/.oats/bin` first on `PATH`. A restart by another kernel
  re-points it. The recipe records the target as `launch.kernelBin`, and
  `oats status` shows it (`kernel:`) when it is not the running `oats`. A
  launch that cannot write the link fails with `E_LAUNCH_SHIM`. Existing homes
  get the link at their next start or restart.
- **`oats spawn` refuses an argument it does not read.** A positional after
  the soul, or a flag spawn does not know, is `E_BAD_ARGS` naming it, before
  anything is resolved or created. `oats spawn <soul> join=oats` used to be
  accepted and the bare `join=oats` ignored, so the instance joined nothing;
  the refusal now names the form that was meant, `--provider <capability>
  key=value`. A routed spawn (`--server`) is refused on this machine, before
  the server is contacted.
- **Herdr 0.9 spawns work.** A new Herdr session was always opened at protocol
  20, so `oats spawn --backend herdr` against Herdr 0.9, which speaks protocol
  22, failed with "Herdr snapshot does not match selected protocol 20". A new
  session now records the protocol its server reports when it is one OATS
  supports (20 or 22), and refuses any other by name. A recorded session is
  still checked against its recorded protocol on every call and is never
  renegotiated. The Desktop attaches to protocol-22 sessions too; it accepted
  only protocol 20 before. An instance recorded at protocol 20 is unreachable
  after an in-place Herdr 0.8 → 0.9 upgrade until it is respawned.
- **A Herdr launch no longer arrives cut.** OATS typed the launch command into
  the new pane before its shell had started. The terminal's line buffer
  (1024 bytes on macOS) dropped the rest of the longer command, so the harness
  never started: the shell waited on an unclosed quote. On Herdr 0.9, 0 of 5
  fresh panes ran a 2000-character command intact. A launch now waits, up to
  10 s, until the pane has drawn its prompt, then types; 5 of 5 ran intact.
