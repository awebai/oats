# OATS 0.43.3

## Added

- A dispatched capability command (`oats <namespace> <command>`) now gets
  `OATS_AGENT` and `OATS_SOUL_ID`, with the values its soul's lifecycle hooks
  get: the soul's agents-root name and its stable id (`<repoKey>#<soul>`, or
  `package:<id>#<soul>`). The same soul gives the same values from an
  instance home, from the deployment with `--soul` or as the default soul,
  and in its hooks
  ([#688](https://github.com/awebai/oats/issues/688)). From the deployment,
  `OATS_SOUL` is a per-commit or temporary copy of the soul, so a provider
  keys durable state on `OATS_SOUL_ID` instead: `oats okf harvest` needs this
  to keep its owner across runs
  ([oats-okf#54](https://github.com/awebai/oats-okf/issues/54)).
  See [Commands and hooks](../capabilities.md#commands-and-hooks).

## Changed

- An `OATS_AGENT` or `OATS_SOUL_ID` in the caller's environment no longer
  reaches a dispatched command, as an ambient `OATS_SOUL` already did not: it
  named another soul.

- Setup skills now carry one authorized intake through team configuration,
  operator composition checks and first-task verification. Onboarding and
  teams link provider-owned identity and delivery procedures, distinguish
  unsupported paths, and keep project operator advice independent of central
  knowledge identities. This is an instruction change, not a new team or
  provider primitive ([#709](https://github.com/awebai/oats/issues/709)).
