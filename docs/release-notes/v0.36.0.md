# OATS 0.36.0

## Added

- **A deployment reports its workspace identity** (feature
  `workspace-identity`, awebai/oats#482). `oats status --json`'s `workspace`
  object now also carries `key` (the workspace host's canonical repository
  key, so every spelling of one repository matches, and the host's key when
  `oats-local.yaml` names a member whose backlink is known), `ref` (the
  reference exactly as `oats-local.yaml` writes it, for display), `keyFrom`
  (`"workspace"`, or `"member"` while a member's host is not known),
  `standalone`, `defaultTeam` (`{label, team}`),
  `teams` (`{<label>: <provider team id> | null}`) and `teamsFrom`. They are
  read offline, so they are there whether the workspace is reachable or not.
  Shared teams come from the workspace file the run read
  (`teamsFrom: "observed"`), else this machine's cached copy at the host
  commit it last observed (`"cache"`, no git process), else nowhere
  (`"local"`: local teams only). `oats server roster --json` relays each
  host's `workspace` object verbatim on its group (from a host before
  0.36.0, the reachability-only object), or `null` from a host that reports
  none. The rule for matching teams across machines (when a
  `null` team is unmapped and when it is unknown) is in
  docs/desktop-cli-api.md, under Workspace identity. A deployment without
  `oats-local.yaml` still has no `workspace` object, and the human-readable
  `oats status` is unchanged. After upgrading, run `oats sync` on each remote
  host (and on any deployment with no instances): the parsed cache belongs to
  the running kernel, so until the deployment observes its workspace again,
  a status that does not read the workspace itself reports
  `teamsFrom: "local"` and its shared default team shows as unknown.
- **The Desktop shows a workspace's deployments on every machine**
  (awebai/oats#482). The switcher lists each workspace once: its deployments
  on this Mac and on registered servers are matched by the workspace each
  reports (its key and default team, by the kernel's rules in
  docs/desktop-cli-api.md), and named by machine. The Active overview becomes
  **Deployments**: **All** shows the overview trees split by deployment ("This
  Mac · ~/Agents/oats", "altair · ~/Agents/tsm"), then each deployment has its
  own tab. Every action is still addressed to the row's own deployment. A
  deployment that isn't shown live says why in a few words, with **How to fix**
  under it (ssh needs a prompt or a host key, timed out, the host's OATS is too
  old, its workspace reference needs `oats sync` or fixing), and one that can't
  be matched is listed in the switcher under "Not matched to a workspace". The
  Desktop remembers the last workspace each remote reported, so an
  unreachable server stays under its workspace, marked "remembered". With two
  or more deployments the sidebar groups instances by machine, and the Spawn
  dialog asks first which deployment to spawn in; the Teams board shows only
  the workspace's own deployments, grouped by deployment.
  Saved selections and tabs move to the workspace that holds their
  deployment. It needs the CLI's `workspace-identity` feature; without it
  each deployment keeps its own entry, as before.

## Changed

- **The Desktop follows a spawn to its new instance.** After **Spawn** the
  dialog closes at once and the pending row is revealed in the roster, without
  taking focus. When the instance is running, the Desktop opens its terminal
  tab and selects its row: arriving there is the confirmation, so a successful
  spawn no longer posts a toast. It never pulls the operator away from
  something they did since the press: typing (a lone modifier does not count),
  pasting, moving focus, opening another tab or view, or an open dialog or
  overlay. Then they stay where they are, and the row says **New** until it or
  its tab is first opened. Either way, assistive technology hears "*name*
  spawned". Partial, refused, failed and unknown outcomes keep their
  notifications
  ([desktop-spawn-preview.md](../../packages/desktop/docs/desktop-spawn-preview.md)).

- **The Desktop's spawn dialog opens on Name and jumps between its sections.**
  Name is focused whenever the dialog opens for a chosen soul, Quick Open
  included, with the caret after a restored name. **⌘1–⌘7** (Ctrl+1–7
  elsewhere) jump to Name, Harness, Model, Relationship, Teams and the Opening
  instruction; ⌘7 opens or closes Developer settings. Quiet hints show the
  keys; the shortcuts editor lists them under *Spawn dialog*, where they can
  be rebound, and the shell's own ⌘1–9 do not fire behind the dialog
  ([desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md)).
  In "Works in", a directory instance now reads "own folder · free to work
  across repos".

- **The Active overview no longer has a Spawn button.** Spawn from the
  canvas with **S**, from the sidebar's **Spawn instance** (⌘N), from Quick
  Open or from a soul card.

- **The Desktop accepts OATS CLIs `>=0.25.8 <0.37.0`**, so it runs against
  this release's kernel. Install the CLI and the Desktop 0.36.0 together: the
  Desktop 0.35.x refuses a 0.36 CLI.
