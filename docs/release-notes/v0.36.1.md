# OATS 0.36.1

## Changed

- **oats.okf 4.1.1** (catalog and workspace pin, and the bundled mirrors):
  three fixes to harvest completion and `harvest --once`.
  - `oats okf complete` on an amended PR that is still open
    (awebai/oats-okf#36). After the knowledge-maintainer pushed an amendment
    on top of the delivered commit, `complete --run <id>` failed with `E_PR:
    publication branch has unexpected commit; never force push`. The run is
    now reported `delivered` when the known PR is open at the branch's tip
    and Git shows that tip descends from the delivered commit; the answer
    names the amended head. A tip that does not contain the delivered commit
    is still refused with `E_PR`, and nothing is ever force-pushed. Ancestry
    is read from the commit objects alone, so a checkout's grafts or
    commit-graph file cannot fake it.
  - `harvest --once`: one-shots of a seat no longer race
    (awebai/oats-okf#39). The overlap checks and the install run under one
    seat lock, so of two overlapping one-shots started together one installs
    and the other gets `E_ONCE_OVERLAP`.
  - `harvest --once`: a note edited between runs no longer strands a
    draining one-shot (awebai/oats-okf#40). A rerun with the same manifest
    continues from custody without reading the listed notes. Another
    manifest listing a note a one-shot already holds is refused with
    `E_ONCE_OVERLAP`, naming that one-shot, instead of a `sha256 mismatch`.
