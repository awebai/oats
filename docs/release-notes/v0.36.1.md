# OATS 0.36.1

## Changed

- **oats.okf 4.1.1** (catalog and workspace pin, and the bundled mirrors):
  three fixes to harvest completion and `harvest --once`.
  - `oats okf complete` on an amended PR that is still open
    (awebai/oats-okf#36). After the knowledge-maintainer pushed an amendment
    on top of the delivered commit, `complete --run <id>` failed with `E_PR:
    publication branch has unexpected commit; never force push`. The run is
    now reported `delivered` when the known PR is open at the branch's tip
    and Git shows that tip descends from the delivered commit; the answer
    names the amended head. A tip that does not contain the delivered commit
    is still refused with `E_PR`, and nothing is ever force-pushed. Ancestry
    is read from the commit objects alone, so a checkout's grafts or
    commit-graph file cannot fake it.
  - `harvest --once`: one-shots of a seat no longer race
    (awebai/oats-okf#39). The overlap checks and the install run under one
    seat lock, so of two overlapping one-shots started together one installs
    and the other gets `E_ONCE_OVERLAP`.
  - `harvest --once`: a note edited between runs no longer strands a
    draining one-shot (awebai/oats-okf#40). A rerun with the same manifest
    continues from custody without reading the listed notes. Another
    manifest listing a note a one-shot already holds is refused with
    `E_ONCE_OVERLAP`, naming that one-shot, instead of a `sha256 mismatch`.
- **Preparing for team model 3** (awebai/oats#485). OATS 0.37.0 commits the
  teams an organisation's souls may join, and their default team, in the
  workspace file, closed by default (awebai/oats#484), so the organisation's
  intended team set is visible and reviewable in its git and a deployment's
  `oats-local.yaml` no longer adds a team by accident. 0.36.1 lets every workspace and
  deployment migrate before 0.37.0 refuses the old shape:
  - `oats-workspace.yaml` accepts `defaultTeam`, `localTeams` and `souls:`,
    and validates them: every label they name must be a shared team in
    `teams:` of the same file (`E_WORKSPACE_SCHEMA` otherwise, when the file
    is read). 0.36.1 does **not** apply them: a soul's teams and default are
    still resolved from `oats-local.yaml`. Earlier releases refuse these keys,
    so add them only once everyone who reads the workspace runs 0.36.1 or
    later.
  - A new readiness warning, `team-model-3-migration` (never blocking), names
    what 0.37.0 will refuse. `oats teams`, `oats readiness` (and so the
    Desktop's readiness view) and `oats doctor` show it. Its `condition` is
    `local-soul-teams` when `oats-local.yaml` has `souls.teams` or
    `souls.default`, and `local-teams-closed` when `oats-local.yaml` declares
    `teams` or `defaultTeam` and the workspace file does not say
    `localTeams: true` (never in the standalone view). `oats doctor` stays
    offline: it checks `local-teams-closed` against the workspace file this
    machine last observed, and says so when there is none yet (`oats sync`
    fixes that). The shapes are in docs/desktop-cli-api.md, under Team
    readiness items.

## What 0.37.0 will change

- **`souls:` in `oats-workspace.yaml` decides which teams a soul may join**
  besides its default: the most specific key wins (`<member|package>/<soul>`,
  then `<member|package>/*`, then `"*"`); `teams` is a list of shared labels
  or `any`. A soul no key matches joins its default only. This applies to
  package souls too: a workspace opens a package explicitly.
- **A soul's default team**, in order: its `souls:` `default`; else the
  deployment's `defaultTeam`, only when the workspace says
  `localTeams: true`; else the workspace's `defaultTeam`.
- **`oats-local.yaml` `souls.teams` and `souls.default` are refused**
  (`E_WORKSPACE_SCHEMA`, reason `removed-key`), and so are `oats soul teams
  --add/--remove/--default/--clear-default`.
- **Local `teams` and `defaultTeam` are refused unless the workspace says
  `localTeams: true`**, and so are `oats teams add/remove/default`. The
  standalone view still allows them.

## Upgrade

Nothing is required for 0.36.1 itself. To be ready for 0.37.0
(`oats teams` lists each deployment's `team-model-3-migration` warnings):

1. **Now**, once everyone who reads the workspace runs 0.36.1 or later,
   commit in `oats-workspace.yaml` the choices each deployment makes locally:
   - a `souls:` entry for what `souls.teams` says (`"*": { teams: [...] }`
     for every soul, `<member|package>/<soul>: { teams: [...] }` for one;
     local keys are bare soul names, workspace keys are qualified by the
     member or package, as in `souls.disabled`), with a `default:` for what
     `souls.default` says;
   - for local teams and a local `defaultTeam`, choose one: (a) keep them
     personal, and add `localTeams: true`, which clears `local-teams-closed`
     at once; or (b) commit the teams in `teams:` and the default as
     `defaultTeam:`.
2. **When the deployment moves to 0.37.0**, remove from its `oats-local.yaml`
   `souls.teams`, `souls.default` and, under (b), the local `teams` and
   `defaultTeam`. Not before: 0.36.1 does not apply the workspace keys, so
   those local keys are still what decides a soul's teams and default until
   then, and their warnings stay until they go. 0.37.0 refuses them, naming
   the replacement.
