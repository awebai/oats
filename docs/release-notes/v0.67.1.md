# OATS 0.67.1

Unreleased

**0.67.1 is the first published 0.67 release.** v0.67.0 was tagged but never
published: its release run stopped before npm and the Desktop Release, on
Desktop tests that failed on macOS (Fixed, below). Everything in
[0.67.0's notes](v0.67.0.md) ships in 0.67.1.

## Upgrade

- **Do [0.67.0's Upgrade steps](v0.67.0.md#upgrade):** they are this
  release's. Install the Desktop first and the CLI second: a 0.66 Desktop
  refuses a 0.67.1 CLI. The 0.67.1 Desktop accepts OATS CLIs
  `>=0.26.0 <0.68.0`. The leader moves to Ctrl+X, and the shortcuts on Linux
  and Windows move to Ctrl+Alt; the official catalog pins oats.framework
  1.13.5.

- **Coming from 0.65 or earlier:** do 0.66.0's Upgrade steps too, and
  0.62.0's when coming from 0.61 or earlier.

## Added

- **`/oats-upgrade`, an oats.setup skill for "upgrade OATS" and "update to
  the latest".** It takes the latest version from
  `npm view @awebai/oats version`, reads [Upgrading](../upgrading.md) and
  the `## Upgrade` section of every release after the installed one at the
  tag `v<latest>`, never the copy in the installed CLI, and walks the person
  through each release's own steps, the Desktop, the CLI, the pi bridges in
  every deployment and `oats doctor`, one step on each yes. On a tag whose page does not
  open with the latest version yet (up to v0.67.0), it takes the order from
  the page and the version and the Desktop's CLIs from the latest release's
  notes. `/oats-setup-model` points at it instead of the installed copy. It
  ships with the next oats.framework release
  ([#1440](https://github.com/awebai/oats/issues/1440)).

## Fixed

- **The spawn dialog's name suggestion refuses an oversized request before
  it reads it.** The Desktop's spawn-preview proxy now refuses a body past
  its limit before parsing it; a parsed body that is not a suggestion read
  keeps a preview's 16 KiB limit (follow-up to
  [#1438](https://github.com/awebai/oats/pull/1438)).

- **Three Desktop keymap tests assumed the Linux keys,** so they failed on
  macOS, and one of them kept `node --test` from ending; the v0.67.0 release
  run stopped there. They now pin the platform they test. No shipped code
  changes ([#1433](https://github.com/awebai/oats/issues/1433)).

## Documentation

- **[Upgrading](../upgrading.md) opens with "Upgrading to the latest
  version":** the latest version, the CLIs its Desktop accepts and the
  steps. What each older release asks of a host that comes from it is under
  "Coming from an older version", one line per release, newest first, each
  linking its notes; the capture service's release order is there too. The
  page states only the latest Desktop's CLIs; the earlier ones stay in
  their notes ([#1440](https://github.com/awebai/oats/issues/1440)).
- **The release-prep pull request updates that section with the notes**
  ([Release lane](../release-lane.md#for-the-tag-owner)), and
  `test/release-packaging.test.mjs` checks that it names the version the
  manifests carry, and no other.
