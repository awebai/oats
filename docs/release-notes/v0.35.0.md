# OATS 0.35.0

## Added

- **oats.okf 4.1.0** (catalog and workspace pin, and the bundled mirrors):
  `oats okf harvest --once`, a one-shot reviewed harvest of one seat from an
  explicit record set (awebai/oats-okf#37). A seat that moved (classic to v2)
  or was spawned with harvest off had no way to get its notes into the
  knowledge base. The operator now runs, from the deployment:

  ```sh
  oats okf harvest --once --home <seat home> --records <manifest> --soul <its soul> [--override-opt-out]
  ```

  - The manifest lists note files, each with its sha256, in the seat's home
    or a listed archive directory. Each file is checked against the bytes
    used, with no symlinks, directories or globbing. A bad entry refuses
    everything before anything is stored.
  - The harvester judges and opens a PR that the knowledge-maintainer
    reviews, as for every harvest. It writes only to the soul's own nodes.
  - Nothing is registered: no schedule and no capture. Rerunning the same
    command continues a large set run by run (each run says how many inputs
    remain), or answers `already-delivered`.
  - A soul's opt-out is refused unless `--override-opt-out`, which the PR
    records. The host's harvest switch does not apply.
  - Archived session records come in a later oats.okf, through `oats capture
    --file` (below).

- **`oats capture --file <path> --format cc|pi|codex --home <instance home> [--json]`**
  (feature `capture-file`). It captures one session file, such as an
  archived session the `--home` sweep can no longer find, exactly as
  `--home` capture of that instance would. It is for oats.okf's one-shot
  reviewed harvest of archived sessions (awebai/oats-okf#37).
  - The owner is explicit (`--owner` or `TURN_RECORD_OWNER`, never the
    hostname), and `--home` must be an instance home.
  - The stream identity is the one `--home` capture writes, so capturing the
    same session either way, or again, appends nothing.
  - The format is stated and checked against the file's session header,
    never sniffed.
  - Only one regular file is read, once, from its descriptor: a symlink,
    FIFO or directory is refused.
  - The receipt binds to the bytes: `{thread, firstTurnId, lastTurnId,
    turns, ignored, sha256, ...}`.
  - An outcome that binds nothing is an error code: `E_IGNORED`,
    `E_NO_TURNS`, `E_FORMAT`, `E_NOT_REGULAR_FILE`, `E_FILE_UNREADABLE`,
    `E_USAGE`, and `E_CAPTURE_FAILED` for a pass that failed (`appended:
    null`). See packages/record/README.md.

## Changed

- **The Desktop accepts OATS CLIs `>=0.25.8 <0.36.0`**, so it runs against
  this release's kernel. Install the CLI and the Desktop 0.35.0 together: the
  Desktop 0.34.x refuses a 0.35 CLI.
