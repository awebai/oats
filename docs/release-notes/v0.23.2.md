# OATS v0.23.2 — Desktop Workspace redesign

This release refreshes OATS Desktop around souls, instances and reported
capabilities, while keeping lifecycle operations behind the installed OATS CLI.
It builds on the released 0.23.1 kernel and knowledge contracts; it does not
implement the proposed Portable Souls architecture.

## Workspace and visual polish

- A cleaner sidebar, aligned toolbar and soul cards, with a side inspector for
  explicit Launch, Files and Schedule actions.
- Workspace sections for **Souls**, **Capabilities** and **Sources**. Capability
  health, installation, trust and activation are reported facts; Sources shows
  provenance, not a new remote discovery or repository-admission feature.
- **White** is the default theme, alongside explicit **Solarized** and **Dark**
  choices. Existing valid theme preferences are retained.
- Orange accents distinct from errors, quieter split controls, roomier instance
  selection, darker navigation and colored marks for reported runtimes.
- Stable muted soul marks. Optional local `soul.yaml` display metadata accepts
  `color: sand`, `sage`, `slate`, `mauve`, `clay` or `olive`. Unknown values use a
  deterministic identity-based fallback. Current remote CLI rosters do not report
  this metadata; colors are decorative, never identity or status authority.

## Working with instances and files

- Workspace switches retain session-local tabs, selected panels and split sizes.
- Closing a tab preserves its empty panel. Selecting that panel and reopening an
  instance uses the selected destination; reusing an open terminal does not create
  another attachment. Close split remains an explicit layout action.
- **File: open read-only…** / **Mod+O** opens a native file chooser for sanitized
  Markdown, highlighted code or plain text, alongside ordinary workspace tabs.
  Files are read-only with a 2 MiB limit; no absolute-path guessing, sibling-file
  access, editing or save workflow is introduced.
- Soul Spawn no longer presents launch-configuration controls; the CLI's inherited
  defaults remain authoritative. Quick Open inspects; Launch is always explicit.
- Improved picker/shortcut focus handoffs and stale-selection protection across
  workspace changes, roster refreshes and delayed operations.

## Compatibility and boundaries

Desktop supports the reviewed OATS 0.22.x and 0.23.x CLI contracts. Without a
compatible installation it remains observation-only, with persistent recovery
controls across Workspace sections. The root npm package still contains no
Electron dependencies; Desktop remains a private, separately packaged app.

New Knowledge/Tasks views, portable-soul membership/discovery and an agent-facing
file-open CLI command are not part of this release. Workspace layout memory is
session-local, not restart persistence. macOS assets retain the existing ad-hoc
signing model; this release does not introduce Developer ID notarization.
