# OATS 0.68.1

Unreleased

## Upgrade

- **From 0.68.0:** [the steps](../upgrading.md#the-steps), the Desktop
  first and the CLI second. The 0.68.1 Desktop accepts OATS CLIs
  `>=0.26.0 <0.69.0`. The official catalog pins oats.engineering 1.13.0
  (Provider updates, below) in place of 0.68.0's 1.11.0.

- **From 0.67 or earlier:** do [0.68.0's Upgrade steps](v0.68.0.md#upgrade)
  first: a 0.67 Desktop refuses a 0.68 CLI. From 0.66 or earlier, do 0.67.0's
  too, and the older ones [Upgrading](../upgrading.md#coming-from-an-older-version)
  names.

## Added

- **Desktop: a resizable sidebar, a little wider by default.** The sidebar
  is 288px wide (it was 264px), and its right edge is a handle: drag it
  between 240px and 480px (at most 45% of the window, so the terminals keep
  the rest), or Tab to it and use ← and → (Shift for bigger steps), Home and
  End. A double-click on it, Enter, or the palette's **Sidebar: reset width**
  put it back to 288px. The width is remembered on this computer and kept
  while the sidebar is hidden. Terminals refit as it moves and tell their
  programs the new size once, at the end.
  ([desktop.md](../desktop.md#workspaces),
  [desktop-keyboard.md](../../packages/desktop/docs/desktop-keyboard.md#keyboard-audit))

## Changed

- **Desktop: the sidebar shows an instance's name as words.** Each `-` is a
  space, and the first letter is a capital: `oats-expert-maintainer-lanes`
  reads "Oats expert maintainer lanes", on nested rows and on a spawn's
  pending row too. Only the row's label changes. The hover card, the command
  palette's search, terminal tabs, a screen reader and the CLI keep the real
  name ([OATS Desktop](../desktop.md#the-sidebars-instance-tree)).

- **Desktop: an instance that needs input shows it on its dot.** In the
  sidebar's instance tree, the row's dot becomes the needs-input mark, the
  amber disc with a "!" that the terminal tab and the workspace list already
  show, and the row's "Needs input" label is gone: its second line keeps the
  soul and the repository. A screen reader still hears "Needs input" after the
  name, the hover card keeps the reason and how long it has waited, and a
  collapsed parent still shows "! N below" for the rows it hides
  ([OATS Desktop](../desktop.md#the-sidebars-instance-tree)).
- **Desktop: yellow now means needs input only.** Unknown state has its own
  look, a grey ring with a small grey centre, in the sidebar, the command
  palette, Quick Open, the overview and a team's member list. The keyboard
  shortcut clash dot, the Workspace page's Setup and Teams attention dot and
  the Automations problem dots are red.

- **TUI: an instance's row shows its name as words**, as the Desktop's
  sidebar does: each `-` a space and the first letter upper-case, so
  `oats-expert-lead` reads `Oats expert lead`, nested rows included. Only
  the row changes: the detail, the filter (`oats-expert` still finds the
  row), the palette, the tabs, the confirmations and everything sent to
  OATS keep the instance's name, and a row is cut as before. See
  [What it shows](../tui.md#what-it-shows).

- **TUI: an instance that needs input shows it by its mark, not a tag in
  words.** Its row draws `!` in place of its state mark, bold, in reverse
  video in yellow (not reversed on the selected row, a gap in the
  selection's bar), whatever its state and its colour; the row's
  `Needs input` tag is gone, and its name is cut as before. Under
  `NO_COLOR` the reverse video and the `!` carry it, and in ASCII it is the
  same `!`. A folded row keeps its `N below` tag for the waiting instances
  it folds away, whether or not it waits itself. The detail still says it
  in words, with the reason and how long it has waited, and the help lists
  the mark. Yellow now means needs input only: a state unknown (`?`) is
  dim in the terminal's foreground, and the warnings of the Souls and
  Capabilities views (a failed read, `Can't spawn here`, `· N on an older
  version`) are bold red, and a `sand` instance or soul is in the
  terminal's foreground colour.
  ([tui.md](../tui.md#what-it-shows))

## Provider updates

- **oats.engineering 1.13.0: one release lane, and one lane per project.**
  The catalog and this workspace pin `oats.engineering: v1.13.0` (floor
  unchanged). It carries 1.12.0 and 1.13.0 together, and supersedes 1.11.0's
  "a maintainer the map doesn't name asks for a lane before it acts":
  - **The release lane** does the final review and the merge of what the
    other lanes hand it, owns and tags every release, and keeps the lane map.
  - **Every other lane is a project lane.** A maintainer defines one, or
    claims one with no active maintainer, when it holds none or its human
    asks, and adds itself to the map; several maintainers may share a lane.
    A project lane reviews its own work and hands each approved PR to the
    release lane. The map may record another arrangement for a lane, agreed
    with the release lane.
  - **A human's high-level picture is the maintainer's intake.** The
    maintainer writes the brief and launches the expert, which writes the
    spec and plan. A lead launched for work in a lane the maintainer holds is
    its child (`--parent`); work for another lane goes to that lane's
    maintainer, or to a maintainer spawned for it, and the human is told who
    has it.
  - Also taught: splitting a lane, the owning lane's second read on a
    cross-lane PR, confirming a relayed human decision directly, cleaning up
    a cancelled effort, and a failed publication (re-run from the same tag).
- **Upgrade:** `oats sync` locks it; new spawns get it, or a stopped home
  moved with `oats instance upgrade`. Peer maintainers record their lanes,
  and any non-default arrangement, in their lane map.
