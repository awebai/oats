# OATS 0.55.1

2026-10-14

A patch release: the oats.aweb 1.27.3 pin, and one fix in the record's `recall --show`.

## Upgrade

- **Either order of Desktop and CLI works:** a 0.55.0 Desktop accepts a
  0.55.1 CLI, and the other way round.

- **Pin `oats.aweb: v1.27.3` in your workspace, then run `oats sync`.** The
  catalog in this release names it. On 1.27.2, readiness reports
  `unavailable` for every home that the host wake broker serves (Codex,
  `delivery: session`, joined teams with `receive: native`) while delivery
  works. Running instances keep the provider they were spawned with. Such an
  instance reads `unavailable` until it is re-spawned; spawns after the sync
  get 1.27.3. See Provider updates.

## Fixed

- `oats recall --show` now refuses session turns hidden by their author's
  tombstone, including claims in another stream. It reports the turn as
  tombstoned with exit status 1 and emits no payload. Record-owner authority
  resolution and index authority changes remain separate work under
  [#1125](https://github.com/awebai/oats/issues/1125)
  ([#1127](https://github.com/awebai/oats/pull/1127)).

## Provider updates

- **oats.aweb 1.27.3:** fixes false `wake-status-stale` / `unavailable`
  readiness on Codex, `delivery: session`, and joined-team broker routes
  ([oats-aweb#116](https://github.com/awebai/oats-aweb/issues/116),
  [provider fix](https://github.com/awebai/oats-aweb/pull/117)). Broker
  timestamps are judged against a clock read after `aw wake status` returns,
  not the readiness phase's start. No skew allowance is added: invalid and
  genuinely future timestamps still fail, and inspection ordering and
  observation-age warnings remain intact. The catalog, reference workspace,
  docs and generated mirror now take published `v1.27.3`.
  Both floors remain OATS >=0.52.0 and aw >=1.36.33; this fix needs no new aw
  upgrade or service restart. Keep the existing upgrade order: meet the
  kernel/aw floors (restart custody services and the wake daemon after an aw
  upgrade), update the provider pin, then `oats sync`. New compositions take
  the fixed provider; existing homes keep their captured module bytes.
  Readiness does not prove actual message delivery.
