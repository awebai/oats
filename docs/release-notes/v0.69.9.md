# OATS 0.69.9

0.69.9 moves the official catalog to three package releases: `oats.framework`
1.19.0 (the setup expert attaches a person to a messaging account created for
the workspace), `oats.aweb` 1.33.0 (a workspace set up without a browser
sign-in, and setup no longer writes aw's rules into `AGENTS.md` or
`CLAUDE.md`) and `oats.engineering` 1.18.0 (a waiting agent sets a checkpoint,
so a stalled child no longer stalls it). Plain `oats status` shows how long a
needs-input claim has waited, and the Desktop says when an older Claude home
can't report its dialogs.

## Upgrade

- **Either order of the Desktop and the CLI works.**
  [Upgrading](../upgrading.md) installs the Desktop first, and a host that
  installed the CLI first is fine too: the 0.69.9 Desktop accepts OATS CLIs
  `>=0.26.0 <0.70.0`, and so does the 0.69.8 Desktop.
- **Package moves:** the official catalog pins oats.framework 1.19.0,
  oats.aweb 1.33.0 and oats.engineering 1.18.0, with no change to their OATS
  floors (oats.aweb keeps aw >=1.36.33). A deployment takes each by raising its
  own pin (`/oats-package-pins`), then `oats sync`. Running instances keep the
  modules they were spawned with: new spawns get the new ones, and a stopped
  home moves with `oats instance upgrade`.
- **A stop doesn't hold while a checkpoint is pending.** With oats.engineering
  1.18.0, an instance stopped while it waits comes back when its checkpoint
  fires, because a wake job starts a stopped home. To keep it stopped, run
  `oats schedule disable <id>`, or retire it. A checkpoint fires only on a host
  whose schedule timer is installed (`oats schedule host install`).
- **A deployment set up by an earlier `oats aweb setup` may still carry aw's
  rules** in `AGENTS.md` or `CLAUDE.md`. Nothing in OATS reads them; the
  oats.aweb 1.33.0 CHANGELOG says how to remove them.

## Changed

- **`oats.aweb` 1.33.0.** `oats aweb setup --username` creates a workspace's
  account and team without a browser sign-in, and `/oats-aweb`'s new section
  "attach yourself to the account" has the setup expert run `aw claim-human`
  with the address the person gives; the account is theirs once they click the
  link aw mails them. **On aweb Cloud today that link fails** for an account
  that `--username` created ("Verification failed"): aweb's fix ships in its
  next Cloud release. Until then, sign in to your own account instead, as
  getting started in this release does. Setup's `aw init` no longer writes
  aw's rules into the deployment. A shorter always-loaded inject, the approved route as the
  guidance for unattended Claude homes, joined teams read at task boundaries on
  Claude homes, and an opt-in attention flag for unread mail with a persisting
  broker error (it needs aw's `mail inbox --count-only`) are in it too
  ([CHANGELOG](https://github.com/awebai/oats-aweb/blob/v1.33.0/CHANGELOG.md);
  [awebai/oats#1665](https://github.com/awebai/oats/issues/1665)).

- **`oats.engineering` 1.18.0: a stalled child no longer stalls its waiter.**
  Before a developer, expert or maintainer ends a turn to wait on a child, it
  sets a checkpoint: a wake job on its own home, due when the result is
  overdue. When it fires, the waiter inspects the child, then unblocks it or
  asks it one precise question; a second overdue checkpoint with no movement
  replaces the child. A waiter sets one only where `wakeHold` reads `on-claims`
  or `not-exposed`, and otherwise hands the wait up. The package's own CI now
  checks layer neutrality, and a reviewer reports a failure that stops its
  round ([CHANGELOG](https://github.com/awebai/oats-engineering/blob/v1.18.0/CHANGELOG.md)).

- Plain `oats status` now shows when a running instance's needs-input claim
  started, in the CLI machine's local time, and how long it has waited
  (`under a minute`, minutes, hours or days). A start in the future shows
  only its time; an unparseable start keeps the previous line without time.
  JSON output is unchanged.

- **`oats.core` 2.12.1, in `oats.framework` 1.19.0:** `/oats-operate` gives the needs-input line that plain `oats status` prints from OATS 0.69.9, with when the claim started and how long it has waited.

- **`oats.framework` 1.19.0: the setup expert attaches the person to a messaging account created for the workspace.** `oats.onboarding` 1.1.0's `/oats-tailor-workspace` gains a normal step 3, before the deployment-agent step: when getting started created the workspace's account without the person's sign-in, the setup expert attaches the person through the messaging capability's own step (with aweb, `/oats-aweb`'s "attach yourself to the account", from the `oats.aweb` release that ships it), and skips it when the person signed in to their own account. When the answer waits on the person's email, the account is theirs only once they click its link, and a refusal leaves it unattached; the briefing reports which. Until it is theirs, the skill and `oats.setup` 2.10.1's `/oats-setup-expert` say the team is on an account created for the workspace, never that it is the person's ([awebai/oats#1665](https://github.com/awebai/oats/issues/1665)).

- **Getting started: a new workspace ends with the Desktop open on it and its setup expert running.** `oats-getting-started` now installs OATS, OATS Desktop and the messaging CLI first (`aw`, with no soul), then has the person sign in to their own aweb account in their browser (`aw auth login`) and creates the workspace's team with one call that installs its root in the deployment (`aw team ensure --workspace-key <host repo key> --label <workspace> --expect-account <account>`): the team is owned by their aweb account. It asks where the workspace lives (inside a monorepo, a dedicated private host, or a first new repository), writes the skeleton with the team id from that answer (one framework pin, no soul of its own, no `tasks:` default), spawns `oats.framework`'s `oats-setup-expert` with `oats onboard`'s `next.spawn` and opens the Desktop on the workspace with the setup expert selected (`--instance`; an older Desktop ignores it). It needs `oats.framework` 1.18.0 and stops on an older catalog. It also stops when Node is under 22, naming the minimum and the version found, and recommends Git 2.45 or later (older Git works, with whole-tree fetches); on Linux, x64 or arm64, it installs Node 22 from NodeSource and, on Ubuntu, Git from the git-core PPA. SSH, signing and the DCO sign-off leave the main path (`/oats-git-setup`, optional); GitHub stays where the flow needs it: the Desktop's download, the host repository and its push. Its messaging gate is the soul's messaging capability and its readiness, with aweb as the default ([awebai/oats#1665](https://github.com/awebai/oats/issues/1665)).

- **Getting started stops when this machine's messaging root is not a member of the workspace's team.** In step 9, when `oats aweb setup --check-only` answers `"member": false` for a new workspace whose team step 5 created, the skill spawns nothing and names the fix; a machine found-list's first check, before its signup, still goes on to it. With no root (`"root": null`), step 5's team creation did not finish in the deployment's `.aw`, and its line for an interrupted run continues it. With a root, the workspace file's team id is not step 5's `canonical_team_id`, so it is corrected, committed and synced. After a found-list signup or an invited join, it stops and reports what the check shows, without rerunning them ([awebai/oats#1665](https://github.com/awebai/oats/issues/1665)).

## Fixed

- **Desktop explains when an older Claude home's questions and permission requests aren't reported
  as needs input.** Its roster hover card and the instance panel's Session card say when its recorded
  oats.core comes from oats.framework before 1.6.0 (oats.core 2.4.0), and the panel suggests upgrading
  or respawning it to report those dialogs. The explanation clears when the home's recorded version
  supports reporting. It works for local and remote rows; missing or unknown version evidence shows
  nothing. The live "Needs input" marker is unchanged, and an agent's own attention claim can appear
  alongside the dialog reporting explanation.
