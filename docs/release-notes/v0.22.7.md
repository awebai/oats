# OATS v0.22.7

Two resource fixes: index reconciliation streams journals instead of
reading each one whole, so a full capture pass fits in memory on a store
with very large session journals, and the packaged Desktop backend runs as
Node rather than a second Electron runtime.

## Record index: streamed reconciliation

`RecordIndex.update()` used to materialize every journal as a buffer plus a
parsed array before consulting its per-stream cursor; on a real store with
an 887 MiB journal the indexing phase peaked above 2.3 GiB and had to be
stopped. The store now offers `iterateStream()`, which reads 64 KiB chunks
and yields one turn at a time with the same rules as `readStream()`:
whitespace lines are skipped, an unparseable or `null` interior line is a
corruption error carrying its absolute byte offset, and an unterminated
final fragment is a torn tail left for the owner's append repair. The
cursor, the single transaction and its rollback on corruption are
unchanged. Measured on the same store: a full pass completes in 42 s with a
peak of about 810 MiB under a 256 MB Node old-space budget.

`readStream()` is unchanged for callers that need arrays.

## Desktop backend runs as Node

The packaged Desktop app spawns its backend server with its own
executable, which is Electron. The child now runs with
`ELECTRON_RUN_AS_NODE=1`, so the backend and the collector processes it
starts run as plain Node instead of relaunching the app (verified headless
against the signed 0.22.6 executable: the backend served `/api/version` at
about 70 MiB). This does not explain the earlier GUI memory incident, whose
snapshot held no Desktop process; it removes one way to multiply app
runtimes.
