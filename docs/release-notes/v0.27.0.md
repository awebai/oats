# OATS 0.27.0

What starts an instance (pi, claude or codex) is now called its **harness**
everywhere the kernel used to say `runtime`: in flags, configuration, records,
JSON and error codes. Nothing already written stops working. The rule is read
either, write new: every spelling from before 0.27.0 is still read, and the
next write records the new one. A command that reads an old spelling answers
one `deprecated-runtime-name` warning, and a later release drops the old
spellings. See [Upgrading from 0.26](#upgrading-from-026).

## Changed

- **runtime → harness.** [The Desktop CLI API](../desktop-cli-api.md#the-harness-rename-feature-harness-oats-0270)
  has the complete table. In short:
  - Flags: `--harness` replaces `--runtime` on `spawn` (and `--preview`),
    `session start|restart` and `launch-config preview`, including their
    `--server` forms. `--runtime` is still accepted, with the warning. The
    two given with different values are refused (`E_BAD_ARGS`).
  - `oats-local.yaml`: a launch configuration names `harness:`. `runtime:` is
    still read, with the warning. Both, disagreeing, is a schema error
    (`E_WORKSPACE_SCHEMA`). `oats launch-config set` writes `harness`.
  - Schedules: a spawn job names `harness`. A job stored with `runtime` is
    read as `harness`, with the warning, and saved in the new name next time.
    Both, disagreeing, makes that job invalid (`E_SCHEDULE_INVALID`).
    `lastRun`/`recentRuns` record `startedHarness` (was `startedRuntime`).
  - Homes: `instance.json` records `harness`, and the launch recipe is version
    **2** (`harness`; version 1 said `runtime`). A home spawned by 0.26.0 is
    read in the new names, with the warning naming the home. It inspects,
    starts, restarts and retires as before, and its next start or restart
    records the new names.
  - `soul.yaml` names `harness:`. `runtime:` is still read, **without** a
    warning, because released capabilities ship it (oats.aweb 1.13.1's agents)
    and an operator cannot fix a provider's file. Both, disagreeing:
    `E_BAD_MANIFEST`. The same holds for a capability manifest's
    `requires[]` harness package (`harness`, or `runtime`, never both).
  - Hooks get `OATS_HARNESS` and `OATS_PREVIOUS_HARNESS` beside
    `OATS_RUNTIME` and `OATS_PREVIOUS_RUNTIME`, with the same values.
  - JSON outputs speak only the new names:
    - `oats version --json` lists `harnesses` (no `runtimes`) and the feature
      `harness`;
    - `harness` replaces `runtime` in the status, inspect, spawn, preview,
      session, launch-config, schedule and event documents;
    - `harnessPackages` and `harnessPosture` replace `runtimePackages` and
      `runtimePosture` in `composition.materialized`;
    - the launch plan's package check (`launch-config preview` `problems[]`)
      is `harness-packages`, and package verification's `loadedBy` is
      `harness-discovery`.
  - Error codes: `E_UNSUPPORTED_HARNESS`, `E_HARNESS_PACKAGE` and
    `E_HARNESS_RESOURCE_MISSING` replace `E_UNSUPPORTED_RUNTIME`,
    `E_RUNTIME_PACKAGE` and `E_RUNTIME_RESOURCE_MISSING`.
  - JSON envelopes may carry `warnings: [...]`, only when there is something
    to say. `oats status --json` carries it beside `problems`. In text mode,
    a warning is one `oats: warning: …` line on stderr.
  - Routed commands (`--server`) speak each host's own vocabulary. A host
    without the `harness` feature (0.26.x and older) is sent `--runtime` and
    `runtime` keys, and its `runtimes` list and `runtime` roster rows are read
    as harnesses.
  - A spawn decision previewed by a 0.26 kernel is `E_DECISION_STALE` at a
    0.27 apply (the revision covers the key names), with the fresh decision
    attached.
  - Unchanged, because they do not name the harness: the session endpoint's
    `runtimeAuthority`, `runtimeState` and `runtimeError`, the
    `E_RUNTIME_ENDPOINT_*`, `E_RUNTIME_AUTHORITY_MISMATCH` and
    `E_RUNTIME_QUIESCE_FAILED` codes, `capabilityRuntime`, the retirement
    baseline, and oats.okf's `harvest-runtime` setting.

## Desktop

- **The Desktop speaks the harness names** on a kernel that declares feature
  `harness` (`--harness`, `harness`/`harnesses`), and the old names on released
  0.25.8–0.26.x kernels. It reads either spelling everywhere, shows only the
  harness the kernel reports (no `pi` default for an instance that doesn't say),
  and accepts kernels `>=0.25.8 <0.28.0`.
- **Core capabilities name their origin** (soul, workspace or team) on the soul
  page and the instance sidebar, on a kernel with feature `layers-from`.
- The unused "the workspace's team settings" origin label is gone (0.26.0's
  teams amendment K stopped emitting it).

## Fixed

- **0.26.0's notes said per-workspace personal teams need undeployed aweb
  server support.** The aweb service (0.8.13 and later) and CLI (1.36.8 and
  later) already carry personal enrollment; what remains is oats.aweb 1.15
  adopting it. The bundled oats.aweb is still 1.13.1 (the personal team only);
  the team verbs come with oats.aweb 1.14.1 in a 0.27.x patch.

## Upgrading from 0.26

Nothing to do. Old spellings keep working with a `deprecated-runtime-name`
warning, and a later release drops them. To stop the warning:

- write `harness:` for `runtime:` in `oats-local.yaml` launch configurations
  (or re-save them with `oats launch-config set`);
- pass `--harness` for `--runtime` in scripts;
- re-save any schedule the warning names (`oats schedule update`). A stored
  job is also rewritten on its next save.

A 0.26.0 home stops warning after its next start or restart. A Desktop that
gates on the `harness` feature reads the new names; an older Desktop reads
`runtimes` and `runtime` and needs its update.
