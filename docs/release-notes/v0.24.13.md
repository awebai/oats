# OATS v0.24.13 — schedule history API 3 and the Desktop schedules table

Kernel/Pi/Desktop **0.24.13**. Tag `v0.24.13` → the commit carrying these
notes; the version-bump commit lands after the tag. Consumers gate on
`oats version --json` `features[]` names and API integers — never on the version.

## Kernel — `schedule-read-2` (`scheduleHistoryApi: 3`; `scheduleApi` stays 2)

`oats schedule list|show` history had four defects found by the Desktop
engineer's exact-source review; each is closed under a new advertised name.

- **A run's identity is when it was scheduled and started, never its outcome.**
  `runId = sha256(scheduledFor|startedAt|attemptId)[0:24]`; a run's later facts
  update its one row; `transitions[]` keeps the outcome sequence
  (`["started","unknown","ended"]` is one run, not three); `settled`,
  `recordedAt`. Pre-API-3 rows are returned `legacy: true` with `runId: null`
  and are never merged.
- **Bounded, descriptor-safe state.** Both scope files are `lstat`ed (regular
  file only), opened `O_NOFOLLOW|O_NONBLOCK`, `fstat`-verified (dev+ino) and
  read whole **only within a 1 MiB budget** — over budget is a typed
  `E_SCHEDULE_STATE_OVERSIZE` refusal, never truncated JSON. `list` carries
  `integrity.sources[]`; history is capped at 50 rows at read
  (`history: {status, stored, truncated}`); one job's corrupt history or bad
  identity is its own row and never fails the others.
- **Subject truth.** `list`/`show` echo the resolved `scope` and canonical `id`;
  a definition whose own `id` differs from its key → `E_SCHEDULE_IDENTITY`; ids
  are validated before any read. Typed refusal details travel through the CLI's
  JSON failure.
- **Session provenance, never a transcript.** The `transcript` pointer named a
  reader that does not exist and is gone. Every run carries
  `session: {instance|null, home|null, incarnation|null, server|null, delivery}`
  — what the recorder knew at write time. A read-only transcript verb is a
  separate seam (K12), not implied by this API.

## Desktop

- **Schedules** view: the compact table (enabled, schedule, target, cadence,
  next run, last reported outcome, actions) with **Recent runs** for the
  workspace (≤50), read once on entry and on explicit Refresh — no polling.
  History enables nothing; `ended` is not success and `delivered` is not
  consumption; missing time facts are shown as unreported. Session provenance
  is displayed with a precise unavailable reason — no transcript, terminal or
  link. Remote history and editing a captured wake are shown as honest
  limitations. Gated on `scheduleHistoryApi === 3` and `schedule-read-2`.
- **Security**: the command-running `GET /api/schedules` is removed (405, no
  command, no default workspace); legacy POST `list|show` aliases run through
  the same strict admission, budgets and two coalesced read slots.
