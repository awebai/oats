# OATS 0.47.1

## Fixed

- **Every `oats retire` stops recorded children first, as its plan says
  (#778).** `oats retire <name> --plan` has always said that recorded child
  instances "are stopped first (bounded SIGTERM, never escalated) and
  retained" and that "a child still running after the grace refuses the
  retirement", but before 0.47.1 only the guarded apply (`--plan-revision`
  with `--idempotency-key`, what the Desktop sends) did it. A plain
  `oats retire <name>` and a `--self` retirement left the children running,
  attached ones on a work tree that had just been removed, with no stop
  event.
  - **Behavior change.** A plain `oats retire` and `--self` now stop recorded
    children first and keep them. They refuse, retiring nothing, when one
    won't stop or its session can't be established: `E_CHILDREN_RUNNING
    {childrenStopped}`, exit 1, and the text names each child and its code
    (`children still running: <name> (<code>); nothing retired`). `--force`
    does not bypass it: end the child's session yourself (the receipt's
    `stillRunning` names its processes), then retry.
  - The receipt lists the children as `childrenStopped[]` (absent when there
    are none), and the text prints `child <name>: stopped` or
    `already idle` for each.
  - `--self` stops the children recorded when the retirement was scheduled
    (skipping any retired since), in its detached completion before it stops
    the caller. A refusal leaves the caller's window and home in place and
    writes `E_CHILDREN_RUNNING` with `childrenStopped` and the `retry` command
    to the result file that `oats status` reports.
  - The guarded apply is unchanged for the Desktop. It now stops children
    only after the retire's own read-only refusals, so a retire refused
    there leaves its children running.
