# OATS 0.65.0

Unreleased

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says: a 0.64 Desktop refuses a 0.65.0 CLI. The
  0.65.0 Desktop accepts OATS CLIs `>=0.26.0 <0.66.0`. With an older CLI its
  switcher shows the saved workspaces only and says "Update oats".

- **No package moves.** The official catalog keeps oats.framework 1.13.3; no
  `oats sync` is needed for this release.

- **This computer's deployments list fills itself.** Nothing to run: the
  first kernel command in a deployment lists it, `oats onboard` lists what it
  creates, the first command that touches the list imports `~/Agents` once,
  and the 0.65.0 Desktop's first launch imports its own saved and recent
  workspaces. `oats deployments` shows the list, and `oats deployments remove`
  takes off a row you don't want.

- **Coming from 0.61 or earlier:** do 0.62.0's Upgrade steps too (the capture
  service's `oats setup`, once per user on each host, from that user's shell).

## Added

- **One list of this computer's deployments, `~/.oats/config/deployments.json`,
  and `oats deployments`** to read and change it
  ([#1390](https://github.com/awebai/oats/issues/1390);
  [This computer's deployments](../workspaces.md#this-computers-deployments)).
  The clients read it to offer the deployments that are not open. It holds
  this computer's deployments only; other machines stay in the server
  registry.
  - **`oats deployments [list] [--json]`** shows each deployment's path, its
    state (`ok`, `missing`, `not-a-deployment` or `unreadable`, from
    existence checks only) and how it was listed. `add [<dir>]` lists the
    deployment at or above `<dir>`; `remove <path>` takes a row off the list
    and touches nothing on disk; `import --from desktop <path>...` is the
    Desktop's one-time import of its own lists. The JSON is in the
    [Desktop CLI API](../desktop-cli-api.md#this-computers-deployments-oats-deployments),
    under the feature `deployments-list`.
  - **The list fills itself.** `oats onboard` lists what it creates (`listed`
    in its result; a failed add never fails the onboard). Any kernel command
    that resolves a deployment that is not listed yet (`status`, `spawn`,
    `sync`, `doctor` and the others that read a deployment) lists it,
    silently. A deployment inside a linked Git worktree or submodule is
    listed by the first command that resolves its instance root (`status`,
    `spawn`, `session` and the like), not by `sync`, `doctor` and the other
    configuration commands. Once it is listed, a command reads the list and
    nothing more: no lock, no write, no process (at most about
    0.5 ms a command); another spelling of it, a link for example, adds
    one realpath. A busy lock never delays a command, and a command routed
    with `--server` lists nothing.
  - **A removed deployment stays removed.** Nothing automatic lists a path
    `oats deployments remove` took out; `oats deployments add` or
    `oats onboard` brings it back.
  - **`~/Agents` is imported once.** The first command that touches the list
    lists the deployments directly inside `~/Agents` (at most 200 entries, no
    link followed) and records that it did. Nothing reads `~/Agents` again.
  - **Five new codes:** `E_DEPLOYMENTS_INVALID`, `E_DEPLOYMENTS_VERSION`,
    `E_DEPLOYMENTS_BUSY`, `E_DEPLOYMENTS_WRITE` and `E_DEPLOYMENTS_IMPORT`
    (`~/Agents` cannot be read for the first-use import), each saying what
    to do.

- Desktop: the TUI's leader. Alt+O on Linux and Windows, ⌃\ on macOS, then
  one key from the TUI's own table: `k` or Space the command palette, `1` `2`
  `3` Instances, Souls and Capabilities, ↑/↓ the terminal of the roster row
  before or after, ←/→ the tabs, `z` focus mode, `w` close the tab, `|` `-`
  the splits, Tab and `x` the split's groups, `X` `R` `S` `D` Stop, Restart,
  Start and Retire, `n` `N` spawn, `/` the filter, `o` the workspace
  switcher, `?` the shortcuts and Esc the instance roster. It works from a
  terminal too: there the leader pressed twice sends the program what the
  chord sends (Alt+O is ESC o, ⌃\ is 0x1c). While it waits, a panel at the
  bottom of the main area lists the keys that apply now. `m` (move a tab to
  the other group) has nothing to act on in the Desktop and is left out. A
  test holds the Desktop's table to the TUI's, so the two cannot drift apart
  ([Desktop keyboard](../../packages/desktop/docs/desktop-keyboard.md#the-leader)).
- Desktop: the TUI's plain keys in the sidebar. With focus in the sidebar,
  `1` `2` `3`, `w`, `/`, `r`, `z`, `c`, `[` `]`, `|` `-`, `X` `D` `S` `R`,
  `n` `N` and `?` do what they do in the TUI, each rebindable in the
  shortcuts editor; on a roster row `k` `j` `g` `G` `h` `l` and
  PageUp/PageDown move through the tree
  ([Sidebar keys](../../packages/desktop/docs/desktop-keyboard.md#sidebar-keys)).
- Desktop: help leads with the leader. The shortcuts editor opens on a
  Leader group, the leader's chord and then one row per key after it, which
  its search finds (`alt+o k`), then the sidebar keys. The sidebar footer
  starts with the leader's chord and "commands", a button that starts it.

## Changed

- **The Desktop's switcher lists this computer's deployments from the
  kernel's list,** `oats deployments`
  ([#1390](https://github.com/awebai/oats/issues/1390)), and no longer looks
  inside `~/Agents`.
  - **Under "On this computer"** a window with no workspace shows the
    deployments on that list that are not open, beside the saved ones.
  - **A row that can't be opened says why:** missing (the folder is gone, or
    its volume isn't mounted), not a deployment any more, or can't be checked.
  - **Remove** beside a row takes it off the list, and off the Desktop's saved
    workspaces when it is one. Nothing on disk changes. From the keyboard:
    Right Arrow, then Enter.
  - **Every deployment the Desktop opens is listed:** an add, an onboarding,
    and the deployment it was launched on. A failure is a notification, and
    the deployment stays open.
  - **Once, at the first launch,** the Desktop moves its own list of recently
    added workspaces and its saved workspaces onto the list, then renames
    `workspace-recents.json` to `workspace-recents.imported.json`. It reads
    recents for nothing else.
  - **With an older oats,** which has no such list, the switcher shows the
    saved workspaces and says "This oats can't list this computer's
    deployments. Update oats." See [OATS Desktop](../desktop.md#opening-a-workspace).

- Desktop: the command palette (⌘K / Ctrl+Shift+K) now opens on its first
  row, the top of the list, which its last-focus order makes the most recently
  focused path. With a query it opens on the first match. It no longer opens on
  the agent you were on before, which was often a row in the middle of the
  list (#1391).

- Desktop: none of the existing default shortcuts changes. A shortcut you set
  yourself that now shares its chord with the leader or a sidebar key is kept
  as it is, and the shortcuts editor shows the clash until you rebind or reset
  one side.

- **`oats tui` is one sidebar and the main area, with no header and no
  footer.** An agent's open terminal now spans every row, and zoomed (`z`)
  it has the whole screen. The sidebar starts with the workspace's name and
  what the view holds of other machines. A deployment's state and reason,
  the note of a one-deployment view and the line after an open stand under
  it. The three views follow as an accordion, each with its key: the open
  one's heading with its list under it, and with no instances
  `No agents yet: n spawns one`. A short cheat sheet comes last: the
  leader, the palette, what `Enter` does now, spawn, help and quit; the
  leader's hint, the palette and the help name the other keys. On a narrow
  sidebar a row's name keeps its cells ahead of its word. The filter field
  and a kept filter stand on the open view's heading. The counts and the
  time of the read have left the screen. The help shows that time at its top, with how many rows were
  withheld. From 80 columns the switcher, the palette, the spawn prompt, the
  help and the confirmations cover the main area, and the sidebar stays
  beside them. Under 80 columns they cover the whole screen, with their keys
  on their first row, as the detail does
  ([docs/tui.md](../tui.md#what-it-shows)).
- **The leader is `Alt+O` on Linux and Windows.** `Ctrl+\` was a stretch on
  most keyboards and needs AltGr on many layouts. macOS keeps `Ctrl+\` for
  now. `open.detachKey` in `tui.json` still names another key, `C-\`
  among them. `Alt+O` counts as the leader only when it arrives as one
  keypress: an `Esc` then `o` typed as two keys reaches the agent unchanged.
  The leader pressed twice now types it into the terminal that has the
  focus, and the leader then `Esc` gives the list the focus. The cheat
  sheet and the help name keys as people read them: `Alt+O`, `Ctrl+K`,
  `Enter` ([docs/tui.md](../tui.md#the-leader)).
