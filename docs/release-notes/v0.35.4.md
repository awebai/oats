# OATS 0.35.4

## Fixed

- **A Desktop workspace never waits silently on "Reading the deployment…",
  and a folder that is not a deployment never drops the open ones**
  (awebai/oats#461). With three or more deployments open, the third and later
  ones were never read: the server started every deployment's reads at once
  past the observer's two-read bound, and kept the refused ones on their
  first "pending" forever. That is also why an empty deployment (no souls,
  no instances) listed third never loaded; an empty answer is an
  observation, shown as no instances. Deployments are now read two at a
  time, each one every cycle. A launch from a folder that is not a
  deployment (a parent such as `~/Agents` as the cwd or `--dir`), at a
  moment when no saved deployment could be opened, saved that folder as the
  whole open set; only deployments are saved now, and the saved set is
  never replaced with nothing. Add workspace → Browse… on a folder without
  `oats-local.yaml` is refused with an explanation and lists the
  deployments in it (or the one it is inside) as one-click adds; setting up
  a new deployment there is a secondary action. A workspace the Desktop's
  server does not serve, or does not answer for within 45 s, shows an
  error naming it, with Retry and Re-add workspace. Behaviour change in
  the Desktop's own server: an explicit `?ws=` it does not serve (any id)
  on `/api/panel` and `/api/agents` is now 404 `E_WORKSPACE_NOT_SERVED`
  instead of the first workspace's answer.

- **After upgrading from a version before 0.35.3, restart once a tmux
  server that a Finder-launched Desktop started earlier** (awebai/oats#468).
  Such a server keeps launchd's PATH for the sessions it starts. Restart it once to pick up the
  new PATH. Restarting it ends the sessions in it, so do it when no instance
  is running.
