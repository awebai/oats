# OATS v0.22.6

A resource-safety patch after the first full team rollout exhausted the
machine: record capture runs one pass per root, the Desktop app runs once,
and `--help` never executes a command. Plus the oats.aweb 1.10.3 pin.

## Record capture: one pass per root

Hook-triggered capture passes, one per agent event across every live agent,
used to overlap, each opening the multi-gigabyte search index. A capture pass
now takes a per-root lock directory (`<root>/.capture.lock`). A second pass
finding it skips at once and the next pass catches up, since reconciliation
is idempotent. The lock is never stolen: a live, dead, unknowable or
still-initializing holder all refuse the pass, and the refusal names the
holder's pid, start time and liveness together with the exact operator
recovery (verify the pid is gone, remove the lock directory with the printed
shell-safe command, rerun). A killed pass therefore needs one explicit
cleanup, which is the accepted trade against any automatic reclaim protocol.

An indexing-enabled pass reconciles the index even when it appended nothing,
so turns left by append-only passes (`--sessions-only --no-index --quiet`,
the recommended hook form from `capture --install-hint`) become searchable at
the next plain pass.

## Desktop runs once

A repeated launch of OATS Desktop no longer starts a second backend, viewer
set and window. The secondary process exits before any startup work, and the
running app restores and focuses its existing window (waiting for its own
startup to finish first). Switching workspaces stays with the validated
switcher inside the running window.

## `--help` never executes

`oats <command> --help` (and `-h`) prints usage for every kernel builtin and,
for capability commands, answers from the manifest without running the
capability executable. Previously several commands ran with `--help` as an
argument.

## Bundled: oats.aweb 1.10.3

The join wait after spawn is 120 s (`OATS_AWEB_JOIN_TIMEOUT_MS`), a join that
completes server-side after the client timed out is recovered instead of
leaving a bound alias behind, retirement reads the alias from the home's
`.aw/workspace.yaml`, and on aw 1.36.1 `aliasReusable` reflects the server's
`alias_released_reason` truthfully (1.10.2).
