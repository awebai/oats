# OATS 0.27.2

## Fixed

- **Retiring a worktree instance whose repository excludes paths locally.**
  Retire refused with `E_WORK_PRESERVATION_FAILED` ("recovered Git
  index/status disagreed with the source") when the repository ignored a path
  only through its local rules: the common Git directory's `info/exclude`, or
  a `core.excludesFile` set in the repository's config. The recovery clone had
  neither, so such a path was ignored (`!!`) in the source but untracked, or
  absent for an empty directory, in the clone. Preservation runs before the
  retire hooks and `--force` does not bypass it, so the instance could not be
  retired and its identities were never revoked. The recovery now carries
  those patterns into its own `.git/info/exclude` (nested repositories too),
  and `recovery.json` lists them under `excludes`
  (`[{ repo, kind, path }]`).
  When a recovery's status still disagrees, the refusal now **names the
  differing rows** from both sides, for example
  `.scratch/ (source !!, recovery absent)`: the first 10, then
  `; and N more`. Under `--json` they are in
  `details.statusDisagreement` (`{repo, rows: [{path, source, recovery}],
  total}`; see [desktop-cli-api.md](../desktop-cli-api.md)).
  **On an older kernel:** remove the disposable paths that
  `git -C <home>/work status --porcelain --ignored=matching` lists as `!!`
  before retiring.

## Known limitations

- **Status-affecting repository config is not carried yet.** A source
  repository with `core.fileMode=false` and a mode-only change is clean in the
  source but ` M` in the recovery clone, so retire still refuses. The refusal
  now names those rows. Workaround: restore the file modes, or commit them,
  before retiring.

## Documentation

- `oats retire --force` does **not** skip work preservation
  ([souls-and-instances.md](../souls-and-instances.md#retire)).
