# OATS 0.27.2

## Fixed

- **Retiring a worktree instance whose repository excludes paths locally.**
  Retire refused with `E_WORK_PRESERVATION_FAILED` ("recovered Git
  index/status disagreed with the source") when the repository ignored a path
  only through its local rules: the common Git directory's `info/exclude`, or
  a `core.excludesFile` set in the repository's config. The recovery clone had
  neither, so such a path was ignored (`!!`) in the source but untracked, or
  absent for an empty directory, in the clone. Preservation runs before the
  retire hooks and `--force` does not bypass it, so the instance could not be
  retired and its identities were never revoked. The recovery now carries
  those patterns into its own `.git/info/exclude` (nested repositories too),
  and `recovery.json` lists them under `excludes`
  (`[{ repo, kind, path }]`).
  When a recovery's status still disagrees, the refusal now **names the
  differing rows** from both sides, for example
  `.scratch/ (source !!, recovery absent)`: the first 10, then
  `; and N more`. Under `--json` they are in
  `details.statusDisagreement` (`{repo, rows: [{path, source, recovery}],
  total}`; see [desktop-cli-api.md](../desktop-cli-api.md)).
  **On an older kernel:** remove the disposable paths that
  `git -C <home>/work status --porcelain --ignored=matching` lists as `!!`
  before retiring.

- **Retiring a worktree instance whose repository changes how status reads
  its files.** The recovery clone probed its own settings and lacked the
  common Git directory's `info/attributes`. A repository with, for example,
  `core.fileMode=false` and a mode-only change was clean in the source but
  ` M` in the clone, so retire refused. The recovery now takes the source's
  `core.fileMode`, `core.ignoreCase`, `core.precomposeUnicode`,
  `core.symlinks`, `core.autocrlf` and `core.eol` (set, or unset where the
  source leaves them unset) and its `info/attributes`, nested repositories
  included. `recovery.json` lists them under `statusConfig`
  (`[{ repo, kind: "config", key, value } | { repo, kind: "info/attributes", path }]`).

## Known limitations

- The bundled oats.okf is still 2.1.5 (its harvest answers one `deprecated-runtime-name` warning per spawn; harmless). oats.okf 2.1.6 follows in a later patch.

- **A `core.attributesFile` or filter driver set in the repository's own
  config is not carried** into a recovery. Merging its patterns would change
  their precedence, and a pointer would tie the recovery to a host file. Such
  a repository can still make retire refuse, and the refusal names the rows.
  Workaround: commit or restore the files it re-reads before retiring.

## Documentation
