# OATS 0.59.0

2026-10-16

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says: a 0.58 Desktop refuses a 0.59.0 CLI. The
  0.59.0 Desktop accepts OATS CLIs `>=0.26.0 <0.60.0`.

- **The official catalog moves three pins:** oats.framework 1.12.0 → 1.12.2,
  oats.okf 5.2.0 → 5.2.1 and oats.aweb 1.27.3 → 1.28.0 (see Provider
  updates). oats.engineering 1.10.0, oats.cloning 1.0.1, oats.authoring
  1.0.3, oats.jira 1.0.1, oats.linear 1.0.1 and oats.apps 1.0.0 are
  unchanged. A deployment takes them by changing its pins and running
  `oats sync`. Only new spawns use them.

- **With oats.aweb 1.28.0, a host that needs the wake broker** (a Codex
  home, `delivery: session`, or a join) installs it once with
  `oats aweb wake install`. Run it from the host's own login session (on
  macOS, at the desktop), not over ssh.

- **`oats tui`: the back key is now the leader, pressed twice to go back to
  the list.** `Ctrl+\` (`open.detachKey` in `tui.json`) pressed once in a
  terminal waits for a command key; pressed again it gives the focus to the
  list, as one press did up to 0.58.0. A `tui.json` whose `open.detachKey` is a
  key an action has is now refused: give one of the two another key. See
  Added and Changed ([#855](https://github.com/awebai/oats/issues/855)).

## Added

- **`retire` on status rows: whether a retire of the home is running,
  cannot be told, failed or was interrupted** (feature `status-retire-state`,
  [#1247](https://github.com/awebai/oats/issues/1247)). `oats status --json`
  instance rows carry `retire: {state, since, self, code?, message?}` while a
  retire of the home is running, scheduled or owed, and no such key
  otherwise. It is read only from the files beside the home: the self-retire
  marker (`self: true`) with its completion process and its result file, or,
  without a marker, the home's claim held by an `oats retire` (`self:
  false`). `state` is `running`, `unknown` (liveness cannot be read),
  `failed` (with the result's kernel `code` and its one-line `message`) or
  `interrupted` (the completion process is gone). `since` is always an
  instant (the recorded time, else the file's modification time), and
  `code` and `message` are strings or absent, never `null`. Status still takes no
  claim, removes no file and signals no process. `retirePending` keeps its
  meaning. Remote roster rows relay `retire` only when the host's row has
  it, checked by the same rule, and drop a value that fails it. A client
  reads the field only when `oats version --json` lists
  `status-retire-state`: an older kernel never carries it
  ([`retire`](../desktop-cli-api.md#row-retire)).

- `oats session inspect --json` reports the agent window's `size: { cols, rows }`
  in cells when present, including through `--server`. The dimensions come
  from the same tmux call as the pane identity and are omitted for absent or
  dead terminals. `oats version --json` advertises `session-inspect-size`, so
  viewers can discover support before opening a PTY at that size (#1285).

- **`oats tui` has a leader key, so every action is reached by keys from
  every focus** ([#855](https://github.com/awebai/oats/issues/855)). The
  leader is `Ctrl+\` (`open.detachKey` in `tui.json`), then one plain key:
  `k` or `Space` the palette, `1` to `3` the views, `Up`/`Down` the
  previous or next instance's terminal, `z` zoom, `w` close the terminal,
  `X`/`R`/`S`/`D` the acts, `/` filter, `o` workspaces, `?` help, and `Esc`
  or the leader again the list. In a terminal the leader is still the one
  key taken from the agent, now twice to go back to the list. A key that
  comes in the same read as the leader cancels it, so a paste never runs a
  command. See [the TUI page](../tui.md#the-leader).
- **A palette, as the Desktop's ⌘K:** the leader then `k`, or `Ctrl+K` in
  the list, opens one input over the instances that can be opened (the
  most recently opened or shown in the run first), the views, the selected
  instance's acts, and workspaces, refresh and help, filtered as you type
  with the Desktop's match. Choosing an instance shows its tab, or opens it
  in a new one. See [the TUI page](../tui.md#the-palette).

- **`oats tui` lists the open workspace's souls**
  ([#855](https://github.com/awebai/oats/issues/855)). `2`, or the leader
  then `2`, shows the Souls view: one row per soul with its colour, a count
  of its instances on this machine, and `!` for a soul a spawn here would
  refuse. The detail beside it says where the soul comes from and where it
  works, which harness a spawn would use, its teams, its capabilities and
  its instances here. `i` (or `Enter` in the detail) shows those instances
  in the Instances view, filtered by that soul; `Esc` clears the filter.
  The list is the OATS Desktop's, read with `oats souls` only once the view
  is first shown, and again only when the workspace changes, or with `r`.
  The palette lists the souls once they are read. `tui.json` has a new
  action, `soul-instances` (default `i`). See
  [the TUI page](../tui.md#the-souls-view).

- **`oats tui` spawns an agent on this machine**
  ([#855](https://github.com/awebai/oats/issues/855)). `n` (or the leader
  then `n`) opens a picker of the open workspace's souls; `N` spawns
  another of the selected instance's soul. The preview is the OATS
  Desktop's, read with `oats spawn <soul> --preview --json`: the name, the
  home, where it works, the harness and model and where they were chosen,
  the team and the worktree setup, with the launch-prompt policy, the
  warnings and the modules folded to one row each. `Tab` moves between
  Spawn, the name (the instance's `--purpose`), the parent and the folds;
  `Enter` on Spawn applies exactly the decision on screen, through the
  shared apply, and a pasted `n` and `Enter`s never spawn. When the agent
  is created and started its terminal opens beside the list; any other
  outcome is said in the Desktop's words, with what to do next, and an
  outcome that is not known is checked once with `C`. One spawn runs at a
  time; spawning on another machine, or with another harness, model or a
  task, stays `oats spawn`. The palette lists Spawn an agent and Spawn
  another. `tui.json` has three new actions, `spawn` (default `n`),
  `spawn-another` (`N`) and `spawn-check` (`C`). See
  [the TUI page](../tui.md#spawning-an-agent).

- **`oats tui` splits its panel in two groups**
  ([#855](https://github.com/awebai/oats/issues/855)). The leader then `|`
  splits it side by side, and the leader then `-` one above the other (`|`
  and `-` alone in the Instances view). The open tabs stay in the first
  group; the second starts empty, says `Enter on an agent opens it here`,
  and an agent opened then opens in it. Each group has its own strip and
  shown tab, both shown tabs are drawn, and a rule separates them. The
  leader then `Tab` goes to the other group, the leader then `m` moves the
  shown tab there, and the leader then `x` closes an empty group; closing a
  group's last tab gives the other the whole panel. Each group needs 40
  columns side by side or 8 rows one above the other, and the four tabs
  are counted across both. `tui.json` has five new actions: `split-right`
  (default `|`), `split-down` (`-`), and `group-next`, `tab-move` and
  `group-close`, which have no key of their own by default. See
  [the TUI page](../tui.md#splits).

- **`oats tui` opens up to four terminals at a time, as tabs**
  ([#855](https://github.com/awebai/oats/issues/855)). The panel's top row
  is the tab strip: each tab's agent in the order it was opened, the shown
  one in reverse while it has the focus and bold otherwise, and `•` (`*` in
  ASCII) after a hidden tab whose agent wrote since it was last shown. With
  one tab the row reads as before. `[` and `]` in the Instances view, or
  the leader then `Left`/`Right` from any focus, show the tab before or
  after, without wrapping; showing a tab selects its row in the list and
  leaves the focus where it was. Opening an instance that has a tab shows
  that tab. The palette opens with the second recent instance selected
  when the first is the shown tab's, as the Desktop's does. `tui.json` has
  two new actions, `tab-previous` (default `[`) and `tab-next` (`]`). See
  [the TUI page](../tui.md#tabs).

## Changed

- **A retire with a large work tree is about twice as fast
  ([#1247](https://github.com/awebai/oats/issues/1247)).** On a Linux
  laptop (btrfs on dm-crypt), the retire of a home holding about 400 MiB in
  37,000 files under `work/` took 18–30 s and now takes 10–17 s. Every
  recovery copy is still written and verified before the retire hooks run,
  and every safety rule is kept.
  - **Cold reads in parallel.** A digest reads its files one at a time, and
    a tree outside the page cache read at about 40 MB/s: the copy of a
    clone just made by a reflink, or a `node_modules/` not read for a
    while. A few worker threads now read the next files ahead of it. No
    digest value changes, including those of baselines older kernels wrote,
    and no error changes. The verification still reads the copy's own bytes
    back.
  - **One read per state.** A worktree's untracked and ignored digest and
    its bytes are taken from one read of each file, both before the hooks
    and after them.
  - **A directory instance's pre-hook copy no longer reads its source a
    second time.** A file changed before the copy read it still refuses the
    retire before any hook runs. A file changed during the copy, after it
    was copied, used to refuse the retire. It is now preserved, verified,
    under `after-hooks/`, as a worktree's work already was
    ([souls-and-instances.md](../souls-and-instances.md)).

- **Desktop and TUI: the instance list is in name order**
  ([#1262](https://github.com/awebai/oats/issues/1262)). The sidebar, the
  command palette and the TUI's list order instances by name, each bundle by
  its top instance. Starting or stopping an instance no longer moves it, and
  running instances are no longer gathered at the top.

- **OATS Desktop accepts an `oats` CLI 0.59.x.** Its band is now
  `>=0.26.0 <0.60.0`. 0.59 adds no new gate on the band: the Desktop reads
  the `retire` field on status rows where it is present (feature
  `status-retire-state`).

- **`oats tui`: the header starts with the workspace's name**, with no `oats` title,
  and the Souls and Capabilities views are no longer dim: `2` and `3`, or
  the leader then `2`/`3`, show what each will hold and what to run until
  then.
- **`oats tui`: the footer is one row of keys from the first column**, with no rule
  above it, and names `C-\ commands` first in every focus. The `1-3 views`
  hint is gone: the header names the views.
- **`oats tui`, a quieter list:** a row is its state mark and its name, the harness
  and the state in words moved to the detail, a folded row says `+n`, a
  machine's heading is its name, with the time of its read only when it
  differs from the header's, and with a terminal open the list keeps 30
  columns. A saved route to an instance its machine no longer has reads
  `gone from <machine>`, as the Desktop says it, not `unknown`.
- **`oats tui`: `tui.json` is refused when `open.detachKey` is a key an action has**,
  since the leader is read as a key in the list too: `C-l` is `Ctrl+L`,
  `C-k` is `Ctrl+K`, `C-j` is `Enter`. Give the action another key, or the
  leader another key.

- **A hidden tab in `oats tui` no longer costs CPU while its agent
  prints** ([#855](https://github.com/awebai/oats/issues/855)). Its first
  output marks the tab as before. Its pane is then paused for `oats tui`
  (tmux's `refresh-client -A '%<pane>:pause'`) until the tab is shown
  again, when it is drawn from the pane's current screen. Measured with a
  hidden agent printing without pause, `oats tui` takes about 0.4% of a
  core instead of 11%, and its private tmux server 9% instead of 14%. The
  same holds while another view or an overlay covers the panel.

- **Opening another agent's terminal in `oats tui` no longer closes the
  one that was open.** It opens in a new tab after the shown one. With four
  tabs open nothing closes by itself: the line says
  `4 terminals are open; close one with C-\ w.` Closing a tab (`c`, or the
  leader then `w`) shows the tab to its right, else the one to its left;
  closing the last one gives the right side back to the detail. A tab whose
  viewer ends by itself closes, hidden or shown, with its line; a hidden
  one's end leaves the shown tab and the focus as they were. Opening
  another workspace closes every tab, and the agents keep running.

## Fixed

- **Desktop and `oats tui`: a retire in progress no longer shows as failed;
  it reads Retiring…** ([#1247](https://github.com/awebai/oats/issues/1247)).
  An instance being retired read **Retire didn't finish** while its retire
  was still running, as if it had failed. Its row now reads **Retiring…**
  while the retire runs, while OATS cannot tell whether the process holding
  it still runs, and from the moment you send a retire until the roster has
  been read after its answer. With an OATS that does not report a retire's
  state, a pending retire reads **Retiring…** too. A retiring row offers no
  start, stop, restart or open; Retire stays reachable but out of the way
  (in the Desktop's row menu, on the TUI's key). A self-retire whose
  completion failed reads **Retire failed**, with OATS's own message and
  code through the display filter, and one whose completion was lost reads
  **Retire didn't finish**; both offer Retire to finish it. See
  [Stopping and retiring](../desktop.md#stopping-and-retiring) and
  [held rows](../tui.md#held-rows).

- **Desktop and TUI: a bundle keeps its place when its instance gains or
  loses children** ([#1262](https://github.com/awebai/oats/issues/1262)).
  An instance that spawns its first child no longer jumps to the top of the
  list with its new bundle: it stays where it was, with the child under it,
  and it stays there when its last child goes.

- **`oats tui` no longer loses a terminal's exit status on tmux built
  with libutempter** ([#1277](https://github.com/awebai/oats/issues/1277)).
  With Ubuntu's or Debian's tmux, a viewer that exited as its pane closed
  could be left unreaped by tmux. The terminal then closed ten seconds
  later, with "ended without saying why" where its own line belonged: for
  example "could not be opened", with what the viewer printed under it.
  While a terminal waits for its status, `oats tui` now has tmux reap its
  children once a second (`run-shell true` on its private server), so the
  terminal closes within a second or two with its status.

## Provider updates

- **oats.aweb 1.28.0: `oats aweb wake install` puts the host wake broker in
  place** ([#1224](https://github.com/awebai/oats/issues/1224)). The catalog
  and this workspace pin `oats.aweb: v1.28.0`.
  - `oats aweb wake install|status|uninstall` (with `--plan`) writes, checks
    and removes a per-user systemd or launchd unit that runs `aw wake run`.
    It recognises only its own unit: a hand-written one is refused
    (`E_WAKE_UNIT_CONFLICT`, with the steps to retire it).
  - Readiness adds the warning `claude-channel-mode-default` (a Claude home
    in development channel mode because `claudeChannelMode` is unset) and a
    soul-scope broker check: a soul with `delivery: session` or a join fails
    readiness while no broker runs.
  - `/oats-host-delivery` (oats.setup 2.6.1, oats.framework 1.11.1 and later)
    teaches it. The floor is unchanged (OATS >=0.52.0).
  - A deployment gets it by pinning `oats.aweb: v1.28.0` and running
    `oats sync`; only new spawns use it. Install the broker from the host's
    own login session (on macOS, at the desktop).

- **oats.okf 5.2.1: faster spawn checks** ([#1246](https://github.com/awebai/oats/issues/1246)).
  The catalog and this workspace pin `oats.okf: v5.2.1`. Its spawn hook primes
  only the bases a soul owns or reads, and checks a usable cached commit
  offline first. A node or owner mismatch on a cache that is due gets one
  bounded normal resolution before it refuses, so a new accepted node is
  never rejected because of an old cache. One `git cat-file --batch` replaces
  one process per blob in accepted-tree validation. Measured on #1246: an
  expired cache 1088 → 561 ms, a cached revalidation 3175 → 1047 ms. The
  harvest duty, inject and skills of 5.2.0 are unchanged, and so is the
  floor (OATS >=0.49.0). A deployment gets it by pinning
  `oats.okf: v5.2.1` and running `oats sync`; only new spawns use it.
- **oats.framework 1.12.1, oats.core 2.6.2: `/oats-operate` says how to read
  an agent window's size** ([#1285](https://github.com/awebai/oats/issues/1285)).
  `oats session inspect --json` reports `size: { cols, rows }` where the
  kernel lists `session-inspect-size` in `oats version --json`; the skill
  names that check, and that a `--server` inspect needs it on the host.
  Instruction text only; the floors are unchanged. A deployment gets it by
  pinning `oats.framework: v1.12.1` and running `oats sync`. Instances already
  running keep the skills they were spawned with.
- **oats.framework 1.12.2, oats.setup 2.7.1: `/oats-onboarding` pins
  `oats.okf` 5.2.1** ([#1246](https://github.com/awebai/oats/issues/1246)).
  Its knowledge-operations card names and pins the catalog's OKF release.
  Instruction text only; the floors are unchanged. A deployment gets it by
  pinning `oats.framework: v1.12.2` and running `oats sync`.
