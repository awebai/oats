# OATS v0.24.9 — readiness pins, side-effect-free spawn preview (API 2), process-group safety, Desktop Readiness view

Kernel/Pi/Desktop **0.24.9**. Tag `v0.24.9` → the commit carrying these notes;
the version-bump commit lands after the tag. Consumers gate on `oats version
--json` `features[]` names and API integers — never on the version.

## Kernel

- **Spawn preview API 2** (feature `spawn-preview-2`, `spawnPreviewApi: 2`).
  API 1 previews **wrote before they returned** — a refused child spawn appended
  an event to the parent, a Herdr backend could be started, an unknown soul
  could be imported from an importable def — and nothing bound a later spawn to
  the previewed decision. API 2: a preview touches nothing, success or refusal
  (proven by a byte-identical deployment tree); `spawn --agents-root <abs>`
  binds the exact root with no fallback and the preview echoes `subject` as
  given; `decision {instance, home, branch, base, revision}` + `spawn
  --expect-decision <rev>` refuses **`E_DECISION_STALE`** with the fresh
  decision on any drift (no auto-suffix, no silent re-base, nothing created);
  every native probe shares one bounded preflight budget and is process-group
  killed on timeout (`preflight {status, budgetMs, elapsedMs}`). **Gate on API
  2 — API 1 is the pre-fix marker.**
- **Readiness pins** (`oats readiness`): `configured` is *effective* activation
  (a capability declared for the soul but disabled is a fail that says so);
  data-only capabilities (skills/inject, no commands/hooks/env) report trust
  **not-applicable** — the inspect row carries `health.executableSurface`;
  every item is typed (`capability {id, level, scope}`, `origin {kind,
  target}`) and `summary.byCapability[]` regroups the same items with
  `ownReady` vs `ready` (never ready under a `summary.subjectBlockers[]` item
  such as unknown membership); `subject.selector` echoes the arguments as given,
  byte-exact; an unreadable member document is `unknown`, not not-applicable;
  `readiness --home <captured>` refuses `E_UNSUPPORTED_MODE`; `--agents-root`
  documented. **Signature verification** (feature `readiness-verify`) is
  bounded custody: one budget per read, process-group kill, cleanup on
  SIGINT/SIGTERM/SIGHUP, `GIT_CONFIG_GLOBAL=/dev/null`, https/ssh only, a closed
  `signature.failure.code` — never stderr.
- **Process-group safety (high).** Bounded-custody code killed a child's
  process group on timeout with `process.kill(-child.pid)`; a **failed** spawn
  (binary missing → `ENOENT`) reports `pid: 0`, and `kill(-0)` signals the
  caller's own process group — `oats readiness --verify-signatures` without
  `git` would have SIGKILLed the operator's shell/tmux/Desktop backend. One
  guarded helper now refuses non-positive PIDs at every kill site.
- **OKF 2.1.3** mirrored and pinned in the official catalog: per-cause `check`
  reasons, a named remedy when a soul has no `okf.json` (was a raw ENOENT from
  the required spawn hook), retired drained sources switch their `okf-<id>` job
  off.

## Desktop

- **Readiness** (frame 09/04): Workspace header entry and first-run
  invitation; the quartet from `oats readiness` with items, remedies (display
  only), *View policy*, *Skip for now* (presentation only). Verify signatures
  and Enrol are shown unavailable with the exact reason until their contracts
  land. Effective-readiness section per scope on the Capabilities view.
- **Normalized route classification**: one classifier decides every specialized
  IPC route from the normalized pathname — dot-segment, percent-encoded,
  backslash, tab and CRLF aliases can no longer skip a route's frame/epoch
  guard.
- Spawn modal: kernel **preview** (API 2) for the instance name, home, worktree,
  branch and resolved base — *Suggest* asks the kernel for its default
  candidate; preview-only choices block legacy submission rather than being
  dropped. Apply companion, attach-knowledge, auto-PR and branch enumeration are
  named follow-ups, not parity-done.

## Upgrade

`npm i -g @awebai/oats@0.24.9`, then `oats doctor`. Desktops on an older CLI
show the new controls as unavailable until the CLI advertises them.
