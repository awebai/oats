# OATS v0.24.4 — provider reasons cross the wire; one request file for both commands

Kernel/Pi/Desktop **0.24.4**. Provider releases that declare the new manifest fields (OKF 2.1.2, aweb 1.11.1) require this version.

- **The kernel no longer discards the provider's reason.** A provider's `error.message` (and a non-ready `check`'s `result.problems[].message`) crosses the binding wire when it is byte-equal to a fixed reason the provider declares in manifest `binding.reasons`, or to the kernel's compatibility list for aweb 1.11.0 and OKF 2.1.2. It is surfaced as the problem's `message` beside `slot`, `capability` and `origins`; anything else is dropped and the kernel template is used. No interpolation, operator values or paths ever cross.
- **`binding.reasons` and `binding.keys` manifest fields** (optional). `reasons`: 1–64 unique printable-ASCII strings of at most 200 characters, no braces; an invalid declaration refuses. `keys`: a provider's owned operator-binding keys, exact names or trailing-dot namespaces (`stores.`), shape-validated only in this release. Providers must still ignore keys they do not own. Earlier kernels reject manifests carrying these fields, so declaring providers require `>=0.24.4`.
- **`inspect --request` accepts `prepare`'s fields.** `operator`, `launch`, `helperLaunches`, `mode` and `allowLocalPaths` are accepted, not evaluated, and listed under `ignored`; `--emit-prepare-request` carries them through. The same request file is now valid for both commands.
- **The CLI renders the problem `key`** (for example `/bindings/messaging/responsibleHuman`) beside its message.

Known limit: OKF 2.1.1 and aweb 1.11.0 cannot be prepared together (OKF validated messaging's `wider` as a store locator); OKF 2.1.2 fixes it.
