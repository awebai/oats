# OATS v0.22.10

One Desktop defect an operator meets in the sidebar: the instance actions
control was a native select that did not behave like the rest of the app.

## Sidebar instance actions: an app-styled button and popover

Each instance row's actions control (Harvest knowledge, Retire instance) was
a native `<select>` labelled with an ellipsis. It rendered with the
platform's own look, opened as a native menu, and its keyboard and focus
behaviour did not match the app's other controls. It is now an app-styled
button that opens a popover. The menu opens from the keyboard or pointer and
moves focus into its items. Escape and choosing an action close it and return
focus to the button; clicking outside also dismisses it.

Safety is unchanged. The per-instance pending guard still holds: while a
harvest or a retirement is in flight for an instance, every control for that
instance stays disabled until the operation reports, so a second click
cannot start a duplicate operation, and a roster refresh while an operation
is pending re-renders the control still disabled. A remote instance with no
saved route on this machine still has its actions disabled with the same
explanation.

Nothing else changes: no kernel, session start, start dialog or record
schema change. Tag v0.22.9 and everything it shipped stand.
