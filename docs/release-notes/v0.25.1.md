# OATS v0.25.1 — workspace-model fix round

Kernel/Pi **0.25.1**. Consumers gate on `oats version --json` `features[]`
names and API integers, never on the version.

**No API change.** `workspaceApi: 2`, every other API integer and the
`features[]` list are those of [0.25.0](v0.25.0.md). Every item below is a
correctness, security or documentation fix to the 0.25.0 workspace model.

## Kernel

- **A running instance's soul no longer changes under it.** Souls are fetched
  into an immutable per-commit cache `agents/<name>/souls/<commit12>/`;
  `agents/<name>/soul` is an atomically swapped pointer to the current commit,
  and each home links its own commit's directory. A 0.25.0 layout is migrated
  in place on first use.
- **SSH remotes are fetched over SSH.** The fetch URL honours the ref as
  written (`git@…` / `ssh://` → SSH, `https://` → HTTPS, bare `git:` → HTTPS
  unless `remoteOptions.transport: ssh`). A private repo is no longer probed
  over HTTPS and silently degraded to the standalone view, and the standalone
  fallback reports the host failure that triggered it.
- **Package approval is re-verified at spawn.** The executables digest is
  recomputed at the locked commit; a mismatch is `E_PACKAGE_UNAPPROVED {
  reason: "digest-mismatch" }`.
- **Annotated tags are peeled**: results, locks and `instance.json` record
  the commit, never a tag object.
- **`work: workspace` spawns on a v2 deployment**, with `./work` as the
  deployment directory.
- **Operator-level capability commands from the deployment.** `oats <ns>
  <cmd> … --soul <name>` outside a home resolves as a spawn of that soul,
  fetches the module into `<deployment>/.oats/modules/<cap>@<commit12>/` and
  dispatches there (for example `oats okf init` before any instance exists).
  Without `--soul` it is `E_BAD_ARGS`; an unknown namespace is
  `E_UNKNOWN_COMMAND`.
- **Slot `none` empties the slot**, dropping any capability the workspace
  defaults contributed for that layer; only a capability the soul itself
  declares beside `none` is `E_SLOT_CONFLICT`.
- **Absolute-path refusal applies only to ref and path fields**; team
  descriptions and the messaging payload may contain `/`-rooted text.
- **One unsafe deep entry no longer blanks a member's souls.**
- **Listing failures are classified**: a `maxBuffer` overflow is not reported
  as `timeout`, and an unclassified listing failure is a discovery problem row
  (`E_REMOTE_UNREADABLE { reason: "unknown" }`) instead of an abort.
- **The revision splits declarations from payload**: `revision =
  hash(declRevision, payloadRevision)`, and a preview can report `changed
  since: declarations | payload | both`.

## Documentation

- The [rebuild guide](https://github.com/awebai/oats/blob/bdd7e55e1b798a97b8b5486001d7c17e522792a7/docs/rebuild-to-v2.md) covers moving `agents/<name>/soul` to `souls/<name>`, OKF
  2 owner re-registration (a fresh `state-dir`), and an `oats-local.yaml`
  example with `settings.oats.aweb.delivery` and `settings.oats.okf`;
  unlabelled souls receive the messaging base payload only.
- Every `pi` launch a 0.25 kernel performs starts the harness normally,
  classic 0.24 homes included. `oats session recompose` is
  `E_UNSUPPORTED_MODE` for module homes; `session-recompose` stays advertised
  for classic homes.
- The reference docs no longer present the 0.24 model as live, and
  [knowledge.md](../knowledge.md) documents operator-level `oats okf … --soul
  <x>` from the deployment.

## Known limitations

- A deployment without `oats-local.yaml` still spawns through the classic
  compose path, which reads `yolo` and `launch-configs` from an
  `oats-config.yaml` chain above a deployment.
- Readiness (`readinessApi: 1`) is still produced by the 0.24 tier.
- OKF 2.1.3 pins a soul's owner per soul path, so per commit; a per-soul
  harvest opt-out is not available.
- `oats-local.yaml` has no `transport:` key.
