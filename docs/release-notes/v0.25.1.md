# OATS v0.25.1 — workspace-model fix round

Kernel/Pi **0.25.1**. Tag `v0.25.1` → the commit carrying these notes; the
version-bump commit lands after the tag. Consumers gate on `oats version --json`
`features[]` names and API integers — never on the version.

**No API change.** `workspaceApi: 2`, every other API integer and the
`features[]` list are exactly those of [0.25.0](v0.25.0.md). Every item below
is a correctness, security or documentation fix found by the team review of
the 0.25.0 workspace model; the normative record is the "0.25.1 fix round"
section of `docs/design/2026-09-23-workspace-module-contracts.md` and the
matching clarifications in
`agents/oats-expert/soul/knowledge/decisions/workspace-model-v2.md`.

## Kernel

- **M1 (high) — a running instance's soul no longer changes under it.** Souls
  are fetched into a per-commit cache `agents/<name>/souls/<commit12>/`
  (immutable); `agents/<name>/soul` is an atomically swapped pointer to the
  current commit; each home links its own commit's directory. A 0.25.0 layout
  is migrated in place on first use. OKF's path-pinned owner stays valid per
  instance.
- **M2 — SSH remotes are fetched over SSH.** The canonical repo key is
  unchanged; the fetch url honours the ref as written (`git@…`/`ssh://` → SSH,
  `https://` → HTTPS, bare `git:` → HTTPS unless `remoteOptions.transport:
  ssh`). A private repo is no longer probed over HTTPS and silently degraded to
  the standalone view; the standalone fallback now reports the host failure
  that triggered it.
- **M3 (high) — package approval is re-verified at spawn.** `resolveSoul`
  recomputes the executables digest over the package tree at the locked commit
  and refuses `E_PACKAGE_UNAPPROVED { reason: "digest-mismatch" }` when it
  differs from the approved one; one shared `executablesDigestAt` serves
  `sync` and `resolve`.
- **M4 — annotated tag OIDs are peeled.** `observeRemote` records the peeled
  commit, never a tag object, in results, locks and `instance.json`.
- **B2 — `work: workspace` spawns on a v2 deployment.** `./work` is the
  deployment directory (the one holding `oats-local.yaml`); no branch recorded;
  the remedy names `oats-local.yaml`.
- **B3 — operator-level capability commands from the deployment.**
  `oats <ns> <cmd> … --soul <name>` outside a home resolves exactly as a spawn
  of that soul, fetches the module into `<deployment>/.oats/modules/<cap>@<commit12>/`
  and dispatches there with the soul's merged payload (`oats okf init` before
  any instance exists). `--soul` absent → `E_BAD_ARGS`; unknown namespace →
  `E_UNKNOWN_COMMAND`.
- **L1 — slot `none` empties the slot.** A soul's `knowledge|messaging|tasks:
  none` drops any layer-bearing capability the workspace defaults contributed
  for that layer; only a layer-bearing capability the soul itself declares next
  to `none` is `E_SLOT_CONFLICT`.
- **L2 — absolute-path refusal is scoped to ref/path fields.** Team
  descriptions and the opaque messaging payload may contain `/`-rooted text.
- **L3 — one unsafe deep entry no longer blanks a member's souls.** Depth
  filtering precedes the entry-name safety check.
- **L4 — listing failures are classified.** `maxBuffer` overflow is not
  reported as `timeout`; an unclassified git listing failure becomes a
  discovery problem row (`E_REMOTE_UNREADABLE { reason: "unknown" }`) instead
  of an abort.
- **L6 — revision splits declarations from payload.** `revision =
  hash(declRevision, payloadRevision)`; decision binding unchanged; preview can
  report `changed since: declarations | payload | both`.

## Documentation

- **M5 — rebuild guide gaps closed** (`docs/rebuild-to-v2.md`): the tracked
  `git mv agents/<name>/soul souls/<name>` step and the tests that enumerate
  soul paths; OKF 2 owner re-registration (fresh `state-dir` for a rebuilt
  deployment, the old one frozen custody); `oats-local.yaml` example with
  `settings.oats.aweb.delivery` and `settings.oats.okf` `state-dir` +
  `bindings-file`; unlabelled souls receive the messaging base payload only;
  per-soul memory-harvest opt-out is not available in OKF 2.1.3 (an OKF 2.1.4
  item).
- **L7 — decision 13 reach.** Every `pi` launch a 0.25 kernel performs starts
  the harness normally, classic 0.24 homes included (rebuild guide §0,
  `conventions.md`). `oats session recompose` is `E_UNSUPPORTED_MODE` for
  module homes; `session-recompose` stays advertised for classic homes
  (`desktop-cli-api.md`).
- **L8 — v1 no longer presented as live** in `schedules.md`, `conventions.md`,
  `implementation.md`, `execution-targets.md`, `desktop.md`,
  `desktop-succession.md`, `integrations.md`, `migration-from-oas.md`
  (a 0.24.x procedure), `desktop-cli-api.md` (readiness producers are the 0.24
  tier), `knowledge-migration.md` (`state-dir` is required; four settings) and
  `knowledge.md` (operator-level `oats okf … --soul <x>` from the deployment).

## Known follow-ups (unchanged from 0.25.0 unless noted)

- The classic (no `oats-local.yaml`) spawn path still runs the pre-v2 compose;
  `composeInstance` still reads `yolo` / `launch-configs` from an
  `oats-config.yaml` chain when one sits above a deployment.
- The readiness quartet (`readinessApi: 1`) is still produced by the 0.24 tier
  observers; re-basing it on `spawn --preview` / `sync` / `workspace status` is
  a named follow-up.
- OKF 2's owner pin is per soul path (hence per commit under M1); re-basing it
  on the owner identity is an OKF 2.1.4 item, as is a per-soul harvest opt-out.
- `oats-local.yaml` `transport:` (M2's per-machine SSH default) needs a schema
  addition before it can be written.
