# OATS 0.35.2

## Fixed

- **A capture pass runs in bounded memory, whatever the record's size**
  (awebai/oats#456). On a host with a 2.6 GB turn record, the periodic pass
  (`capture.mjs` under `--max-old-space-size=256`) died within seconds every
  time it ran. Each death left a dead-owner capture lock, the cause of #437.
  The pass loaded whole files:
  - the first append to a stream parsed its whole journal;
  - the aw dedupe read the whole aw journal into a set of ids;
  - every changed comm log was read whole (a log over 512 MB failed even
    with a large heap);
  - a lost session offset re-read the whole journal and transcript;
  - a session's new lines were all collected before any was appended.

  Each is now streamed. On a 1.1 GB synthetic record the same pass peaks at
  160 MB resident instead of about 2 GB. A host whose capture job was turned
  off can turn it back on: the first pass after a long gap captures the
  backlog in bounded memory.
