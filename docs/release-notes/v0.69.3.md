# OATS 0.69.3

Unreleased

0.69.3 fixes `oats tui` killing the host's systemd user manager, and every
agent with it, when it ended at the wrong moment. It also fixes a terminal
left open on macOS, and pins oats.engineering 1.16.0.

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says. The 0.69.3 Desktop accepts OATS CLIs
  `>=0.26.0 <0.70.0`.
- **The keeper fix is in the CLI** (`oats tui`). The danger is an `oats tui`
  that ends while its private server is still starting. Until a Linux host
  with systemd has the 0.69.3 CLI, let `oats tui` finish opening before you
  quit it, and don't run it where something may kill it as it starts.
- **Package moves:** the official catalog pins oats.engineering 1.16.0
  (Provider updates, below). A deployment takes it with `oats sync`.

## Fixed

- **`oats tui` can no longer kill your session's systemd user manager.** When `oats tui` ends, a keeper kills its private tmux server. The keeper took its server to be the parent its shell saw when it started. If the server had already ended by then, that parent was `systemd --user` on a systemd host, so an `oats tui` killed at the wrong moment could SIGKILL the user manager and every process under it, every agent of the host included. The keeper now kills only the server that tmux names in the keeper's own `TMUX`, and only while that server is still its parent; in any doubt it kills nothing ([awebai/oats#1615](https://github.com/awebai/oats/issues/1615); [What it reads, and what it runs](../tui.md#what-it-reads-and-what-it-runs)).

- **`oats tui` on macOS closes a terminal whose viewer a signal ended.** tmux on macOS names the signal (`kill`, `hup`) where Linux's gives its number, and `oats tui` read only a number or an upper-case name, so on a Mac such a tab could stay open with nothing left in it. It now reads both ([awebai/oats#1613](https://github.com/awebai/oats/issues/1613); [What it reads, and what it runs](../tui.md#what-it-reads-and-what-it-runs)).

## Provider updates

- **oats.engineering 1.16.0: who sets the "same work" flag.** The catalog and
  this workspace pin `oats.engineering: v1.16.0`; the floor is unchanged.
  - An expert spawns its developers with `--same-work`
    (`/coordinate-developers`), a developer its reviewer
    (`/run-the-review-loop`), and a lead expert the domain experts it spawns
    as its children for its effort (`/coordinate-experts`).
  - A maintainer launches its leads without it (`/launch-work`): each effort
    is the lead's own. An expert spawned `--relation unrelated` gets no flag.
  - The skills use the flag, and `oats instance same-work`, only on a kernel
    whose `oats version --json` lists `instance-same-work` (OATS 0.69.2 and
    later); on an older one the spawn leaves it out.
- **Upgrade:** `oats sync` locks it. New spawns get it, and a stopped home
  moves to it with `oats instance upgrade`. On OATS 0.69.2 or later, an expert
  marks a developer it started before with
  `oats instance same-work <developer> on`.
