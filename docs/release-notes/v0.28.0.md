# OATS 0.28.0

Package souls, triggers, okf 3.0.0 remote knowledge consult, and the Workspace v4 Desktop.

## Added

- **Package souls** (feature `package-souls`). A package may ship souls
  (`souls: ["souls/<name>", …]` in `oats-package/oats-package.json`), versioned
  by the same `packages:` pin as its capabilities. `oats sync` locks each
  soul's digest (`E_PACKAGE_INTEGRITY { why: "souls" }` on drift) and `oats
  souls` lists them with `kind: "package"`. Spawn one as `<package>/<soul>`
  (`oats spawn oats.okf/knowledge-maintainer`), or by its bare name when
  unique; an ambiguous bare name is `E_SOUL_AMBIGUOUS`, naming each qualified
  form. It resolves like any soul, is verified against the lock at spawn,
  homes in `agents/<package>--<soul>/` (its agent name in `oats status`), and
  shows as `moved` once the package pin moves. Two packages whose ids differ
  only by `.` and `-` that ship a same-named soul are an `E_SOUL_AMBIGUOUS`
  problem, and neither spawns. See [packages.md](../packages.md#package-souls).

- **Triggers** (feature `triggers`): event-driven spawns. When a GitHub pull
  request event (`opened`, `reopened`, `ready_for_review`, `labeled`,
  `synchronize`, filtered by `labels` and `base`) matches, a new instance of a
  soul is spawned with a templated task. Triggers are stored in
  `oats-schedules.json`, polled with the host's `gh` by the schedule tick (no
  daemon or webhook), and delivered at least once, bounded by `concurrency.max`
  and `perKey`. A PR's title and body never reach the task. Commands: `oats
  trigger add | list | show | enable | disable | remove | test | status`;
  `oats trigger test` checks gh auth, permissions, the soul and what would
  fire, and spawns nothing. The instance gets the event as
  `OATS_TRIGGER_EVENT_FILE` (via `oats spawn --trigger-event <file>`) and
  records `instance.json.trigger`; `spawn.teams` becomes the messaging
  capability's `join=`. Packages may ship trigger templates. See
  [schedules.md](../schedules.md#triggers).

## Fixed

- **`--flag=value` is read.** Kernel commands silently ignored the inline
  form (`oats spawn dev --harness=claude` spawned the default harness). It is
  now read exactly as `--flag value`; an empty `--flag=` or a value on a switch
  (`--yolo=false`) is `E_BAD_ARGS`. A capability command's own flags are
  forwarded as typed. See [desktop-cli-api.md § Flags](../desktop-cli-api.md#flags).
  **On an older kernel:** use the spaced form.
- **`oats-local.yaml` `souls.disabled` is enforced at spawn**
  (`E_SOUL_DISABLED`). An entry is a bare or a qualified soul name.

## oats.okf 3.0.0 (catalog pin and bundled mirror)

The official catalog pins `oats.okf` to `v3.0.0`; the bundled copy is its byte
mirror. It declares `oats >=0.26.0`.

- **Knowledge is consulted remotely**: `oats okf bases`, `index`, `cat --base
  <alias> <path>`, `ls`, `links` and `search` read the soul's knowledge at the
  accepted state. A Git base is served from one host-wide partial clone,
  refetched once older than `consult-max-age` (default 300 s; `--fresh` always
  refetches); a failed fetch serves the cache with `stale: true`. The new
  `okf-consultation` skill teaches instances to run `oats okf index` at the
  start of every task.
- **BREAKING: no `./knowledge/` in homes.** Read
  `oats okf cat --base <alias> <path>` instead of
  `<home>/knowledge/bases/<alias>/…`. A `./knowledge/` left by a 2.x spawn is
  ignored and reported by `oats okf inspect` as `legacy-local-view`.
- **BREAKING: `oats okf refresh` is `E_REMOVED`.** `oats okf read --path`
  still works as an alias of `cat`.

## Desktop

- **Workspace v4 redesign** (#206): Setup, Souls, Capabilities and the soul
  and capability pages are rebuilt. Facts the kernel does not report yet are
  left out rather than guessed.
- **Soul team labels** reach the Souls grid (#208).

## Upgrading

- **okf 3.0.0 is breaking for anything that read `<home>/knowledge/`.** Use
  `oats okf cat`. Existing homes keep their old view, unused.
- **Package souls and triggers are additive.** Nothing changes until a
  package declares `souls:`/`triggers:`, or you add a trigger.
