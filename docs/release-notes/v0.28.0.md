# OATS 0.28.0

Package souls, triggers, okf 3.0.0 remote knowledge consult, and the Workspace v4 Desktop.

## Added

- **Package souls** (feature `package-souls`). A package may ship souls as
  well as capabilities: `souls: ["souls/<name>", …]` in
  `oats-package/oats-package.json`, each an ordinary soul directory
  (`soul.yaml`, `AGENTS.md`, `skills/`). One pin in the workspace's
  `packages:` versions both, so a package soul never drifts the way an
  `external:` commit pin can. See [packages.md](../packages.md#package-souls).
  - `oats sync` locks each soul's `name`, `path` and `digest` in the package's
    lock entry and checks them again on the next sync
    (`E_PACKAGE_INTEGRITY { why: "souls" }`). A soul without `soul.yaml` or
    `AGENTS.md` is `E_PACKAGE_MANIFEST`. A lock written by an earlier kernel
    has its `souls` filled in on the next sync.
  - `oats souls` lists them with `kind: "package"`, `package`, `version` and
    `qualifiedName`; `oats sync` and `oats workspace status` list each
    package's `souls`.
  - Spawn one by its qualified name `<package>/<soul>`
    (`oats spawn oats.okf/knowledge-maintainer`), or by its bare name when that
    is unique. A bare name shared by several souls is `E_SOUL_AMBIGUOUS`, which
    now names each qualified form (`details.qualified`); a member soul's is
    `<member name>/<soul>`.
  - A package soul resolves like any soul: workspace and team defaults apply,
    `off` and `<slot>: none` work, its `team:` labels must be declared, and
    `from: here` means its own package at the locked commit.
  - The spawn fetches the soul at the locked commit and verifies it against the
    lock's digest (`E_PACKAGE_INTEGRITY { why: "soul-digest" }`). It homes in
    its own agent directory `agents/<package>--<soul>/`
    (`agents/oats-okf--knowledge-maintainer/`), its agent name in `oats status`
    and `OATS_AGENT`, so a member soul of the same bare name never shares its
    directory or roster row. `instance.json.workspace.soul` records `name`,
    `qualifiedName` and `package: { id, version, commit, digest, path }`, and
    the soul id is `package:<id>#<soul>`. `oats status` shows the soul as
    `moved` once the package pin moves. Two packages whose ids differ only by
    `.` and `-` (`a.b`, `a-b`) and that ship a same-named soul would share an
    agent directory: that is an `E_SOUL_AMBIGUOUS` problem in `oats sync` and
    `oats souls`, and neither spawns.

- **Triggers** (feature `triggers`): event-driven spawns. A trigger says
  "when a GitHub pull request event matches, spawn a new instance of this soul
  with this task, in these teams". It is stored beside the schedules
  (`kind: "trigger"` in `oats-schedules.json`) and evaluated by the same host
  tick; there is no daemon or webhook. See
  [schedules.md#triggers](../schedules.md#triggers).
  - The source `github.pull_request` is polled with the host's `gh` at the
    trigger's `poll` interval (at least 1m). Events: `opened`, `reopened`,
    `ready_for_review`, `labeled`, `synchronize`, filtered by `labels` and
    `base`.
  - Each event fires once: its key is recorded only after a successful spawn,
    so a failed spawn is retried on the next poll. Delivery is at least once: a
    tick that dies between the spawn and recording its key spawns the event
    again (held while the first instance is live, under the default `perKey: 1`). `concurrency.max` and
    `perKey` bound the live instances of the trigger and of one PR.
  - The purpose and task are templated from `{repo} {number} {url} {event}
    {headSha} {trigger}` only; a PR's title and body never reach the task.
    `spawn.teams` becomes the messaging capability's `join=`. The instance gets
    the event as `OATS_TRIGGER_EVENT_FILE` (`<home>/.oats/trigger-event.json`)
    and records `instance.json.trigger`.
  - `oats trigger add (--file | --from <package>:<template> --set …) | list |
    show | enable | disable | remove | test | status`, all with `--json`.
    `oats trigger test` checks gh auth and where its credential comes from
    (warning when the host timer cannot reach it, such as a shell-only
    `GH_TOKEN`), the repository and your push/maintain/admin permissions on it,
    the soul, the teams, and what would fire now, and spawns nothing.
    `oats schedule list` counts the triggers it does not list.
  - A package may ship trigger templates (`triggers: [{ id, file }]` in
    `oats-package.json`).
  - `oats spawn --trigger-event <file>` is how a trigger hands the event to the
    spawn.

## Fixed

- **`--flag=value` is read.** Every kernel command ignored the inline form
  silently: `oats spawn dev --harness=claude` spawned the default harness,
  and `--name=x`, `--runtime=x`, `--dir=x` and `--server=x` were dropped the
  same way. A kernel command now reads `--flag=value` exactly as
  `--flag value`, with the same validation. The value is everything after the
  first `=`. Two inline forms are refused with `E_BAD_ARGS`: an empty
  `--flag=`, and a value on a switch. `--yolo=false` is refused and never
  turns yolo on. A capability command's own flags are its provider's: they
  are forwarded exactly as typed, and the kernel reads only its dispatch flag
  (`--soul`) in either form. `oats capture`, `recall` and `setup` parse their
  own arguments, as before. See
  [desktop-cli-api.md § Flags](../desktop-cli-api.md#flags).
  **On an older kernel:** use the spaced form.

- **`oats-local.yaml` `souls.disabled` is enforced at spawn.** It was documented
  as "not run on this machine", but only counted souls in the `oats sync`
  report. A listed soul is now refused with `E_SOUL_DISABLED { name,
  qualifiedName, entry }`. An entry is a bare name (every soul of that name) or
  a qualified name (`oats.okf/knowledge-harvester`, `<member>/<soul>`).

## oats.okf 3.0.0 (catalog pin and bundled mirror)

The official catalog now pins `oats.okf` to `v3.0.0` (tag object `ad2349c7`,
commit `76f7ccdb`). The copy bundled in this package is its byte mirror. The
package declares `oats >=0.26.0`.

- **Knowledge is consulted remotely.** An instance reads its soul's knowledge
  at the accepted state through new commands: `oats okf bases`, `index`,
  `cat --base <alias> <path>`, `ls`, `links` and `search`. A Git base is served
  from one host-wide partial clone per base, and a read refetches the accepted
  branch once the cached commit is older than the `consult-max-age` setting
  (seconds; default 300; `0` refetches on every read). `--fresh` always
  refetches. If the fetch fails, the read is served from the cache, with
  `stale: true` and the reason in its receipt.
  A directory base is read in place. The new `okf-consultation` skill and the
  okf injection teach instances to run `oats okf index` at the start of every
  task.
- **BREAKING: no `./knowledge/` in homes.** A spawn records the accepted
  resolution and materializes no `./knowledge/` directory or view. Anything
  that read `<home>/knowledge/bases/<alias>/…` reads
  `oats okf cat --base <alias> <path>` instead.
- **BREAKING: `oats okf refresh` is `E_REMOVED`.** There are no per-instance
  views to refresh.
- **`oats okf read --path` still works** in 3.0.0, as an alias of `cat`.
- **Older homes:** a `./knowledge/` a 2.x spawn left in a home is not touched.
  3.0.0 ignores it, and `oats okf inspect` reports it as
  `legacy-local-view`.
- The memory-harvest worker soul no longer ships a `CLAUDE.md -> AGENTS.md`
  symlink (npm drops symlinks, and the kernel composes each home's
  `CLAUDE.md`). The mirror check (`scripts/check-okf-mirror.mjs`) no longer
  requires one; any symlink a future release ships is mirrored and verified
  as before.

## Desktop

- **Workspace v4 redesign** (#206): the Workspace area (Setup, Souls, Capabilities, the soul and capability pages) is rebuilt to the Workspace v4 design. Facts the kernel does not report yet are left out rather than guessed; the Setup screen no longer names kernel files.
- **Soul team labels** reach the Souls grid (#208).

## Tests and CI

- A home's resolved view (`resolvedFromHome`) carrying the slot rows its
  spawn recorded (`layers`, since 0.26.0 layers-from) is now pinned. Before,
  no test caught reverting it to `{}`.
- CI runs the suite in six parallel shards (`node --test --test-shard`), plus a gate job with the old check name. Main runs no longer cancel each other.

## Upgrading

- **okf 3.0.0 is breaking for anything that read `<home>/knowledge/`.** Use `oats okf cat`. Existing homes keep their old view, unused.
- **Package souls and triggers are additive.** Nothing changes until a package declares `souls:`/`triggers:`, or you add a trigger.
