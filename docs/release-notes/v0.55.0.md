# OATS 0.55.0

2026-10-14

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says: a 0.54.0 Desktop refuses a 0.55.0 CLI.

- **The first capture after the upgrade takes longer.** It reconciles the
  existing journals, resets the search index and rebuilds it from them, in
  one synchronous pass that can take minutes on a large record; later passes
  read only what is new. See Fixed
  ([#1108](https://github.com/awebai/oats/issues/1108)).

- **A script that reads `oats server roster --json`** no longer sees
  `E_ROSTER_BUDGET` or `bounds.skipped`: every server is probed, and one
  that does not answer reports its own `E_SSH` timeout. See Removed
  ([#1117](https://github.com/awebai/oats/issues/1117)).

- **The official catalog's versions in this release** are oats.framework
  1.10.0, oats.okf 5.0.5, oats.aweb 1.27.2 and oats.engineering 1.10.0: see
  Provider updates. Pin what your workspace uses, then run `oats sync`.
  Running instances keep what they were spawned with; new spawns get the new
  versions, so a standing maintainer gets oats.engineering 1.10.0's lane
  rules only by being re-spawned. The same holds for oats.okf 5.0.5: an
  instance spawned before the pin keeps its old frozen-remote guard (and
  still fails with `E_OWNER` on a host that rewrites Git URLs) and its old
  proposal brief until it is re-spawned.

## Changed

- **The Desktop accepts OATS CLIs `>=0.25.8 <0.56.0`.** The compatibility band
  admits 0.55. Upgrade the CLI and the Desktop together: a 0.54.0 Desktop
  refuses a 0.55.0 CLI. No new gate on the band. `oats tui` runs the kernel it
  ships with and is held to the same band.

## Fixed

- Capture streams transcript content, stores per-input cursors and journal IDs on
  disk, and indexes only new journal bytes in bounded transactions ([#1108](https://github.com/awebai/oats/issues/1108)).
  Background input logs share an append-only assumption: an edit to an old
  aweb-log line is no longer picked up merely because the log grows. Use
  `capture --reset-cursors [--source aw|cc|pi|codex]` to request reprocessing.
  Detected native-transcript prefix changes are set aside before appending, to
  preserve v0.53.0 downgrade/re-upgrade compatibility. Restore the prefix and
  use `capture --retry-set-aside`, or exclude the source through the existing
  ignore list (which also excludes its later turns). `capture --health` reports
  these inputs. This changes capture algorithms; it introduces no service
  schedule, record-size policy, or bounded-runner guarantee. Content buffers and
  caches are bounded apart from the largest record; sorted path/root metadata
  and explicit receipt inventories can still grow with input counts. The first
  capture after upgrade reconciles existing journals and rebuilds the index,
  with substantial per-input/per-stream synchronous commit cost still unresolved.
  Refused aweb entries are counted and consumed; reset source cursors to retry
  them. Snapshot and receipt scratch stays on the record-root volume, with
  conservative cleanup of proven abandoned allocations under the capture lock.

- Capture health reads current set-aside issues, including direct library calls,
  while command snapshots retain their historical run fields. Reading an existing
  capture database requires read-only SQLite support (Node 22.12+/23.2+; prefer
  22.13+ on 22.x without an experimental flag). Unsupported runtimes, schemas,
  WAL databases and unavailable readers fail closed; normal capture's runtime
  floor is unchanged.

- **A server that can't be reached no longer hides the others.** The remote
  roster (`oats server roster`, the Desktop's view of other machines) probes
  every registered server at once, each within its own deadline. A server
  that is switched off now costs only its own entry, which shows that it
  timed out (`E_SSH`, `ssh to <host> timed out: no answer within <n> s`), and
  the servers registered after it are read as usual. Before, the probes ran
  one after another against one 45 s budget. Four registrations on one
  offline host could use the budget up, and the servers after them were
  never asked ([#1117](https://github.com/awebai/oats/issues/1117)).
- **Retry on a remote window reads the servers again.** In the Desktop, the
  roster's **Retry** on a window with a deployment on another machine now
  reads the servers at once, or waits for the read already running, before it
  shows the roster. Before, it showed the last read's result until the next
  background read, 10 s later
  ([#1117](https://github.com/awebai/oats/issues/1117)).

## Removed

- **`E_ROSTER_BUDGET` and `bounds.skipped`** in `oats server roster --json`.
  Every group is probed, so no group is reported as not reached any more, and
  `bounds` is `{budgetMs, perTargetTimeoutMs, elapsedMs}`. `--budget` stays,
  as the deadline of the whole answer, which caps each probe's `--per-target`
  allowance
  ([the roster](../desktop-cli-api.md#the-remote-roster-oats-server-roster---json)).

## Provider updates

- **oats.okf 5.0.5** (from 5.0.3; 5.0.4 is included).
  - **A host's Git URL rewriting no longer breaks Git bases**
    ([oats-okf#76](https://github.com/awebai/oats-okf/issues/76), 5.0.4). A
    host whose global or system Git config routes a bound repository through
    `url.<base>.insteadOf` or `pushInsteadOf` (a deploy key on an ssh alias,
    for example) failed every okf call with `E_OWNER`. The frozen-remote
    guard now resolves the binding's `repository` with the host's own
    rewrites and compares that with the clone's fetch and push URLs; the
    binding stays as written. A rewrite in the clone's own config, a changed
    origin or a `pushurl` is still refused, and URLs compare byte for byte.
  - **One harvester at a time** (5.0.5). A working instance writes one
    proposal per checkpoint, with claims only for the nodes its soul owns,
    and spawns one knowledge harvester at a time, none while `oats status`
    still lists its last one ([the flow](../knowledge.md)). Instruction text
    only; it reaches instances spawned after the pin.
  - The official catalog, the reference workspace and the generated mirrors
    take published `v5.0.5` at `73b85020e52b8584cb15f153a39712f900e69918`.
    Compatibility remains OATS 0.29.0 or later.
- **oats.aweb 1.27.2:** the `/oats-aweb` skill's etiquette points to
  `/oats-token-saving` (oats.core 2.6.0, in OATS 0.54.0) for whether to send,
  to whom and how long, and keeps how to send
  ([#1103](https://github.com/awebai/oats/issues/1103)). Instruction text
  only; both floors are unchanged (OATS 0.52.0, aw 1.36.33). The catalog,
  the reference workspace and `mirrors/oats-aweb` take published `v1.27.2`
  at `f82cebe299562b38188f3373fa09a89b50d5f868`; the mirror's tree equals
  the tag's.
- **oats.engineering 1.10.0: maintainers work in lanes**
  ([#1103](https://github.com/awebai/oats/issues/1103),
  [oats-engineering#14](https://github.com/awebai/oats-engineering/pull/14)).
  The official catalog, the reference workspace and the generated mirrors
  (`mirrors/oats-developer`, `mirrors/oats-code-review`,
  `mirrors/oats-engineering-expert`, `mirrors/oats-maintainer`) take published
  `v1.10.0` at `944470be71a96299ae4a1cfb7df0fba94a592899`; each mirror's tree
  equals the tag's. Instruction text only: no skill is added or removed, and
  the requirement is unchanged (OATS 0.30.0 or later). `oats.maintainer` and
  `oats.engineering-expert` change; the other two capabilities only change
  version. What changes:
  - **Each maintainer holds a lane.** The peers' agreement becomes a written
    lane map: what each lane covers, its maintainer and its second reader,
    the label a PR shows its lane with, the hold label, and who owns the next
    release. A maintainer's state file holds its own lane only; the forge is
    the one copy of a PR's state.
  - **Every PR gets one second reader, asked once,** at the head the lane's
    maintainer approved. This replaces every peer reviewing every PR and
    re-binding its verdict at every head.
  - **Intake no longer sweeps on every wake:** a full sweep at session start,
    after a compaction and at least weekly; on a wake, the event alone.
  - **Peers message each other for five things** (a second read, a hold that
    must stop work in flight, the release plan, a lane changing hands, a
    request that belongs to the peer's lane), and send no notice before or
    after a merge or a tag. A hold is a label on the forge, and the merge step
    reads it.
  - **The merging maintainer brings a branch up to date itself;** the verdicts
    carry when the PR's own change is unchanged and CI is green. When the
    default branch moved since CI ran, it runs the affected test files on a
    trial merge first.
  - **Experts hand over to one maintainer,** the one whose lane the work is
    in, and leave the branch alone after the hand-over.
  - **To adopt it:** peer maintainers rewrite their agreement as a lane map
    (`/cross-review-peer`), create the lane labels and the hold label, and
    drop each other's PRs from their state files. A maintainer alone has
    nothing to do. Pin `oats.engineering: v1.10.0` and run `oats sync`.
    Running instances keep what they were spawned with; new spawns pick
    1.10.0 up after `oats sync`. A standing maintainer gets the new rules
    only by being re-spawned, not by a sync or a session restart: hand its
    lane over first (`/cross-review-peer`, "A lane changes hands").
