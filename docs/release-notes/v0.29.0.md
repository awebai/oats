# OATS 0.29.0

## Added

- **Workspace triggers and schedules** (feature `automations`). A trigger or
  schedule can be declared in Git in any confirmed member and shared with the
  team: `oats-triggers/` or `*.oats-trigger.yaml`, and `oats-schedules/` or
  `*.oats-schedule.yaml`. It is named `<member>/<id>`; a machine's own ones
  are `local/<id>`. Each file names `runsOn` (the host that runs it) and
  `owner` (the GitHub account it acts as); a host runs it only when `runsOn` is
  its new `oats-local.yaml` `host.name` and its `gh` is logged in as `owner`.
  `oats trigger|schedule disable <member>/<id>` stops one on this host without
  a commit. `oats sync` snapshots them and the host tick refreshes the
  snapshot every ten minutes (`oats automations refresh`). `oats trigger|schedule
  add … --workspace <member>` writes the file. See
  [schedules.md](../schedules.md#workspace-triggers-and-schedules) and
  [desktop-cli-api.md](../desktop-cli-api.md) for the list rows.
- **Desktop facts** (feature `desktop-facts`): additive fields the Desktop's
  Workspace view shows instead of deriving them, on `oats inspect --soul`,
  `oats souls`, `oats capabilities`, `oats workspace status` and `oats status`
  (`--json`). Among them: each capability's `composedFrom` and the defaults a
  soul turned off, a soul's spawn defaults and whether it is `spawnable` here,
  member clones, the lock, newer package versions, file locations, and an
  instance's `startedAt`, `modelFrom` and `identityAddress`. See
  [desktop-cli-api.md](../desktop-cli-api.md#desktop-facts-feature-desktop-facts-oats-0290).
- **`oats schedule test <id>`**: where a schedule runs, whether its soul
  resolves, and when it is next due. It spawns nothing.
- **`launchConfig`** on a trigger's `spawn` and on a spawn schedule: the
  running host's launch configuration to start the soul with.
- `oats trigger status --json` rows add `nextDue`, `concurrency` and
  `liveCount`; `oats trigger test --json` `wouldFire` items add `repo`.
- **`OATS_SETTINGS_ORIGINS`** beside `OATS_SETTINGS`, for every hook,
  capability command and readiness probe: where each leaf of the payload came
  from (`manifest-default`, `workspace`, `soul`, `host`, `spawn`), also
  recorded in `instance.json`.

## Changed

- **oats.framework 1.3.0 pinned** (covering 1.2.0, 1.2.1 and 1.3.0): the
  setup-admin skills in oats.setup 2.1.0 and oats.core 2.1.0, OKF knowledge
  operations in onboarding (oats.setup 2.1.1), and `knowledge-theory-expert`
  as a package soul with oats.knowledge-theory 1.1.0. Pin
  `oats.framework: v1.3.0` and run `oats sync`.
- **A local trigger's id is `local/<id>`** in `oats trigger` rows, its state
  and a triggered instance's `instance.json`. Every verb still accepts the
  bare id.

## Removed

- **BREAKING: capability-defined agents.** A manifest's `agents:` is refused
  at resolution (`E_CAPABILITY_AGENTS_REMOVED`), naming the replacement: a
  **package soul** (`oats spawn <package>/<name>`) or a member soul. `oats spawn
  <name>` no longer falls back to a module's agent (`E_SOUL_UNKNOWN`). Homes
  spawned earlier for one stay listed, may be a `--parent`, and retire.
  - OKF's harvester is an oats.okf 4.0.0 package soul; the post-commit
    `reviewer` is `oats.dev/reviewer` (oats.dev 1.1.0, beside oats.review
    1.3.0), spawned as `oats-dev-reviewer-<short-sha>`; and
    `knowledge-theory-expert` is an oats.framework 1.3.0 package soul.
  - The reviewer's harness and model now come from the spawner's launch
    configuration (it was pinned to pi, gpt-5.6-sol).

## Fixed

- A package soul's derived instance name is checked and de-duplicated as the
  name the home gets; an over-long purpose is `E_INSTANCE_NAME_INVALID` with
  `details.maxPurpose`.
- A spawn that loses a race for the same instance is `E_PLACEMENT_TAKEN`
  (it was `E_SPAWN_FAILED`).
- Disabled-here messages name the per-kind key (`triggers.disabled`,
  `schedules.disabled`).

## Desktop

- **Schedules and Triggers tabs** on the automations contract: rows grouped by
  where they run, workspace and local items together, a detail page per item
  with its prompt, runs, placement verdict and test result. The old Schedules
  read path is gone.
- The soul page and an instance's soul tab tag why each capability is there
  (`workspace`, `team · <label>` or `soul`) and list the defaults turned off.
- Module drift names versions ("moved 2.1.5 → 2.2.0").
- The Desktop accepts OATS CLIs `>=0.25.8 <0.30.0`.

## Upgrading from 0.28

> **0.29.0 and oats.okf 4.0.0 move in lockstep.** Kernel 0.29.0 refuses
> oats.okf ≤3.x (it declares a capability agent), and oats.okf 4.0.0 requires
> kernel 0.29.0. A deployment on okf 3.x stays on kernel 0.28 until it moves
> its pins, then upgrades in one sitting:

1. **Upgrade the kernel**: the npm package, the pi adapter and the Desktop, all
   0.29.0.
2. **Move the pins** to `oats.okf: v4.0.0`, `oats.dev: v1.1.0`,
   `oats.framework: v1.3.0`.
3. **Run `oats sync`.**

Between steps 1 and 3, any soul that composes oats.okf ≤3.x (every soul with
oats.okf in its knowledge slot), oats.dev 1.0.x or oats.framework ≤1.2.x is
refused with `E_CAPABILITY_AGENTS_REMOVED`. Harvest is off by default in okf
4.0.0; switch it on with `oats okf setup --harvest on`. Homes spawned earlier
keep loading their recorded modules.

## oats.okf 4.0.0 (catalog pin and bundled mirror)

The official catalog pins `oats.okf` to `v4.0.0`; the bundled copy is its
byte mirror.

- **BREAKING:** requires `oats >=0.29.0` (`E_CAPABILITY_INCOMPATIBLE` on an
  older kernel), and the `okf` and `memory-harvest` skills are gone.
- **Three capabilities:** `oats.okf` (the knowledge slot), `oats.okf-harvest`
  and `oats.okf-maintenance`. A soul with `oats.okf` in its knowledge slot gets
  the `okf-consultation` and `okf-instance-knowledge` skills and the inject.
- **The harvester is a package soul**, `oats.okf/knowledge-harvester`,
  spawned by `oats okf run-source` / `harvest` as `okf-harvester-<run>`. It
  stays alive in the `okf` team until its PR is merged or closed.
  `oats.okf/knowledge-maintainer` is the second soul, and the trigger template
  `harvest-review` watches labelled harvest PRs.
- **`harvest: on|off`** (default off) is a host switch
  (`oats okf setup --harvest on|off`); a soul can only opt out
  (`knowledge: { harvest: off }`).
- **`oats okf read` is removed** (`E_REMOVED`); use `oats okf cat --base
  <alias> <path>`.
