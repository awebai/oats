# OATS 0.39.0

## Changed (breaking)

- **The Desktop accepts OATS CLIs `>=0.25.8 <0.40.0`**, so it runs against
  this release's kernel. Install the CLI and the Desktop 0.39.0 together: the
  Desktop 0.38.x refuses a 0.39 CLI.

## Added

- **oats.aweb 1.21.0: `oats aweb connect <server-id>` gives a deployment on
  another machine its messaging** (awebai/oats#517). After `oats server
  connect` has created the workspace's deployment on a registered server, one
  command from the local deployment gives that deployment membership in its
  default team. It runs through the kernel's capability route
  (`oats aweb … --server <id>`) and reports its steps (`aw`, `invite`, `join`,
  `readiness`) in the server-connect status vocabulary, with every runnable
  remedy in backticks. It checks aw on the host and installs it with
  `--install-aw`. It mints a hosted invite from this deployment's root for the
  host's default team; nothing is minted when the host is already a member.
  It joins on the host with `oats aweb setup --join <label> --invite-stdin`,
  then checks again. On this machine and in transit the invite token exists
  only in memory and on the routed command's stdin; on the host,
  `aw id team accept-invite` takes it as an argument, so it is visible in the
  host's process list while that call runs. The join half works on its own: `setup --invite-stdin`,
  `setup --install-aw [--aw-version <v>]` and `setup --check-only --json`.
  `setup --join` also recovers a per-team root left connected but unrecorded
  by an interrupted join.
