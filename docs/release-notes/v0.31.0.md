# OATS 0.31.0

## Changed

- **New tmux instances open in the tmux session `oats-agents`, not
  `pi-agents`.** Running instances are unaffected: a home launched before 0.31
  keeps the `pi-agents` session it recorded, `session start` and `restart` put
  it back there, a self-retire kills its recorded window, and `oats status` and
  the Desktop read each home in its recorded session. To keep new instances in
  `pi-agents`, add one line to the deployment's `oats-local.yaml`:

  ```yaml
  session: { tmuxSession: pi-agents }
  ```

  `OATS_TMUX_SESSION` also sets it, and `PI_AGENTS_TMUX_SESSION` is still
  honoured, read when the spawn runs. `oats inspect --json` reports the session
  a new spawn would open in as `session`.
- **Routed ssh calls share one connection per host and notice a dead link.**
  Every `--server` call, `server roster` and `session attach --server` runs
  ssh with `ControlMaster=auto`, `ControlPath=~/.oats/ssh/%C` and
  `ControlPersist=60`, plus `ServerAliveInterval=15` and
  `ServerAliveCountMax=3`. The probe, the command and an attached viewer
  ride one authenticated connection. A viewer whose link dies ends within
  about 60 s with a message naming the command to reattach, instead of
  hanging. These options override any `Control*` settings for the host in
  `~/.ssh/config`. When the control socket path would not fit the 104-byte
  limit or has characters ssh reads as syntax, or `~/.oats/ssh` is not
  private to you, calls run with connection sharing off
  (`ControlPath=none`) and the command warns once per server
  ([servers.md](../servers.md#connections)).
- **The version probe is asked once per process** per server and target.
- A server too old for `oats session` is refused with the tmux command for
  the instance's recorded session and window, not a fixed `oats` session.
- **oats.aweb 1.17.3** (catalog and workspace pin, and the bundled mirror).
  Session-delivery guidance matches aw 1.36.15's host wake broker: it
  presents either a line naming what is waiting or the full mail/chat event,
  and recovery after an uncertain crash, compaction or restart goes by exact
  message id (`aw mail show --message-id <id> --json`) or paged
  `aw mail inbox --show-all --json` with `--cursor`. A resident grant's
  `renew: launch` re-registers the wake broker with the new grant, and grant
  seats start with `aw whoami`.

## Added

- **Any instance on a server is controllable from here, whoever spawned it.**
  `retire --server` and the routed `session` commands (inspect, attach,
  start, restart, upload), `inspect`, `operation` and `launch-config` reach
  an instance with no saved route by `--home`, or by a name the server's
  roster lists once. A name two homes share there is refused with
  `E_AMBIGUOUS`, listing the homes. Roster rows gain `addressable`, and
  `savedRoute` is information only ([servers.md](../servers.md#run-there)).
- **The Desktop's reads and lifecycle plans route to the instance's
  machine.** `readiness`, `instance events`, `instance git`, `instance diff`,
  `instance stop --plan|--apply` and `retire --plan` (and its guarded apply)
  take `--server <id>`; the host's kernel does the work, Git included, and
  its envelope is relayed unchanged. A host that does not advertise the
  feature is refused with `E_REMOTE_INCOMPATIBLE` before anything is sent.
  `version --json` lists them in `remote`: `readiness`, `instance-events`,
  `instance-git`, `lifecycle-plans`
  ([desktop-cli-api.md](../desktop-cli-api.md#routed-reads-and-plans)).
- **Remote roster rows carry the host's facts.** `oats server roster --json`
  instance rows relay `identity`, `identityAddress`, `teams`, `startedAt`,
  `createdAt`, `model`, `runtimeState`, `parentInstance`, `siblingInstance`,
  `relation`, `relativeTo` and `spawnOrigin` from the host's `status --json`,
  `null` where the host does not supply them
  ([desktop-cli-api.md](../desktop-cli-api.md#the-remote-roster-oats-server-roster---json)).
- **A remote terminal in the Desktop reconnects after a lost link.** A
  viewer that ssh ends with exit 255 keeps its tab and scrollback, goes
  inert, and re-attaches with backoff (1, 2, 4, 8, 15 s, then every 30 s),
  with **Reconnect now** to try at once. It stops with the reason when the
  server says the session is gone or refuses the attach, or after four
  attempts in a row in which this computer's `oats` gave no answer
  ([desktop.md](../desktop.md#remote-terminals)). Reconnecting never touches
  the agent on the server.

## Fixed

- **`oats status` reads liveness from each instance's recorded tmux socket**,
  not the caller's `$TMUX` server. Outside the agents' tmux (every `status
  --server` over ssh, cron, a plain terminal) running instances read
  `running: false`, and a row on the default server could read `true`. Now
  `running` agrees with `session inspect`; a recorded server that cannot be
  read gives `running: null` with `runtimeState: "unreachable"` (#347).
- **`session attach --server` exits 255 when ssh fails before the viewer
  opens** (the version probe, or resolving a name through the host's roster),
  as it does when ssh fails under the viewer; it exited 1, so a caller that
  reconnects on 255 gave up on a flapping link. Every other refusal still
  exits 1. An ssh failure now names the host: `ssh to <host> failed: …`
  (#349).
- **An `E_SSH` envelope says when ssh never started.** A routed `--json`
  command whose ssh could not be run on this machine (not installed, not
  executable) answers `E_SSH` with `error.details: {"sshStarted": false}`, so
  a caller can stop retrying; a failed link carries no details, as before.

## Removed

- **Herdr.** tmux is the only session backend; cross-machine work goes over
  ssh routing (`--server`), which never used Herdr. Nothing is migrated
  silently: everything that meets Herdr refuses with `E_HERDR_REMOVED`, whose
  message says what to do.
  - `oats spawn --backend herdr` or `--herdr-socket` (local, or routed with
    `--server`, refused before the server is contacted) and `oats server add
    --herdr`: remove the flag, or use tmux. `--backend tmux` is still accepted,
    and `oats version --json` advertises `sessionBackends: ["tmux"]`.
  - A schedule's `backend: herdr` or a trigger's `spawn.backend: herdr`: the
    message names the file and key; remove it, or use tmux. A stored local job
    that names it is reported invalid and never runs.
  - `session inspect`, `attach`, `input`, `start`, `restart` and `instance
    stop` on an instance opened in Herdr: retire it (`oats retire <name>`) and
    spawn a new instance; it opens in tmux. `oats status` lists such an
    instance with `running: null`, `runtimeState: "unsupported"` and the
    refusal as `runtimeError`, and never fails because of it.
  - `oats retire` of an instance opened in Herdr works without Herdr. When a
    process still works in its home it refuses, naming the pids: stop its
    Herdr pane (for example `herdr --session oats server stop`), then retire.
  - A server registration or saved route that records `herdrPath` still
    loads; the field is ignored.

  An idle Herdr server that OATS started (session `oats`) is not OATS state;
  stop it with `herdr --session oats server stop`.
