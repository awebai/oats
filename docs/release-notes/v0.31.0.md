# OATS 0.31.0

## Changed

- **New tmux instances open in the tmux session `oats-agents`, not
  `pi-agents`.** Running instances are unaffected: a home launched before 0.31
  keeps the `pi-agents` session it recorded, `session start` and `restart` put
  it back there, and `oats status` and the Desktop read each home in its
  recorded session. To keep new instances in `pi-agents`, add one line to the
  deployment's `oats-local.yaml`:

  ```yaml
  session: { tmuxSession: pi-agents }
  ```

  `OATS_TMUX_SESSION` also sets it, and `PI_AGENTS_TMUX_SESSION` is still
  honoured.
- **A host chooses its session backend in `oats-local.yaml`.** The new
  `session.backend: tmux | herdr` is the backend of a spawn without
  `--backend`, Desktop and schedule spawns included. The order is `--backend`,
  then `session.backend`, then the `OATS_SESSION_BACKEND` environment variable,
  then tmux. Nothing changes for a deployment that sets neither. Feature
  `session-backend-config`: the spawn result, the spawn preview and the
  `launched` event name the deciding layer as `backendFrom` (`flag`, `local`,
  `env` or `default`). Known limit: a `--no-launch` spawn on Herdr cannot be
  started later with `session start` (it records no Herdr server), so a
  Herdr host's no-launch spawns and schedules should pass `--backend tmux`.
- **`oats status` reads each Herdr server once.** Liveness for Herdr homes
  takes one `herdr api snapshot` per server per call, not one per instance, so
  `status` costs the same however many Herdr instances there are.
