# OATS v0.24.0 — retained execution first cut

Kernel, Pi adapter and Desktop **0.24.0**: the first cut of retained (captured)
execution.

## Official OKF pairing

The catalog pins **oats.okf 2.1.0** (tag `v2.1.0`, `oats-package` source path),
which requires **OATS >=0.24.0**. Do not pair it with an installed 0.23.x kernel.

## Source-complete preparation and retained execution

- `oats prepare --request` accepts one bounded, nonsecret JSON input validated
  by the shared strict reader. Source, deployment, work target and
  workspace/standalone context stay distinct; inherited current config never
  fills missing source authority. Executable approvals remain explicit.
- Fresh onboarding detects existing managed state without deleting it. A
  replaced deployment or work directory requires reinspection; this is a
  point-in-time check, not a lock against concurrent writers.
- Captured instructions, resources, source identity and provider bindings stay
  usable from retained bytes after the source is removed.
- Captured primary and helper start and restart use the retained selections. A
  helper launches through its exact source helper edge. Uncertain same-ID state
  is held rather than redispatched; failure receipts, pending allocations,
  native history and cleanup obligations are preserved.
- Provider execution keeps generic invocation, same-owner binding and opted-in
  source-receipt inputs separate; missing or invalid transport never falls back
  to legacy authority.

## Backends and the Pi profile

tmux and Herdr share the native path. Herdr supports exact protocols 20 and 22;
an unknown protocol is refused, never negotiated or replaced by tmux.

The Pi target in this cut is explicit print-mode retained execution, not full
interactive or plugin parity. An absent or incomplete session-directory witness
or required runtime, bridge or plugin contribution is a refusal.

Harness authentication is unchanged: the already-authenticated harness keeps
its native profile, credentials and model configuration. OATS adds no auth-file
selector, credential inspection or copying, or substitute profile.

## Desktop compatibility

Desktop accepts released CLI versions `>=0.22.0 <0.25.0` over Desktop CLI API
v1; prereleases, wrong API versions and failed probes are refused. Optional
execution and remote capabilities are advertised separately; version acceptance
grants none of them. Desktop does not cover captured-instance UI, Herdr 0.9
terminal attachment, or captured scheduling, retirement and recovery. macOS
builds are ad-hoc signed, not notarized.

## Limits of this release

- No automatic in-place migration, old-state deletion or role-library adoption.
- Unsupported managed, plugin, bridge or interactive profiles are held. Git
  knowledge delivery is PR-only.
- Captured retirement, wake and recovery are not supported in this release; do not
  strip selectors, use a private fallback, or delete an uncertain home. Keep old
  sessions, identities, work and receipts.
- Backend or model success does not qualify private aweb messaging.

Adopt through a new explicit deployment or source request against the installed
public contract.
