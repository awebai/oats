# OATS v0.22.0

OATS v0.22.0 is the first release under the OATS name. The framework release
includes `@awebai/oats@0.22.0`, `@awebai/oats-pi@0.22.0`, and OATS Desktop
0.22.0.

The version sits above every release of the OAS line (`@oas-framework/oas`
0.21.2 was the latest). This release includes the OAS 0.20.1, 0.21.1, and
0.21.2 corrections; it does not include the OAS 0.21.0 remote catalog fetch.

## The rename: OAS is now OATS

Everything previously published as **OAS** (`@oas-framework/oas`,
`@oas-framework/pi`, OAS Desktop) continues as **OATS** (`@awebai/oats`,
`@awebai/oats-pi`, OATS Desktop). The rename is a clean break: the kernel
recognizes no `oas-*` file name, no `oas:` config key, and no `oas.*`
capability id.

Deployments created by OAS must migrate:

```bash
oats migrate --from-oas --dry-run --dir <scope>   # full plan, touches nothing
oats migrate --from-oas --dir <scope>             # convert this scope
```

Each scope converts in one transaction (file names, the `oas:` key, capability
ids, then the guided package conversion to `lockfileVersion: 2`). Any failure
restores the original bytes; a second run is a no-op. Executable trust is
re-earned after conversion. See
[migration from OAS](https://github.com/awebai/oats/blob/v0.22.0/docs/migration-from-oas.md).

`oats doctor` names un-migrated OAS scopes with the remedy, and every
`oats migrate` form exits nonzero on them. Migration was verified against OAS
0.20.x; OAS 0.21.x scopes may lock the OAS v2.0.0 package line, which the OATS
catalog does not carry, so run the dry run first.

The 0.18 upgrade guarantee (existing v1 locks keep working) applies to
OATS-named scopes only, never to OAS-named deployments.

## Corrections ported from OAS

- **Own-property config handling.** Config parsing and diagnostics ignore
  inherited `Object.prototype` properties; YAML keys named `__proto__` are
  refused with `unsafe-config-key`.
- **Internal annotations cannot arrive from disk.** Underscore-prefixed engine
  annotations are stripped from every manifest and soul read.
- **Config writes fail closed.** Values or keys that would change the shape of
  a written config are refused with `unsafe-config-value` or
  `unsafe-config-key`. `oats init` and the first `oats use` or `oats type add`
  in a fresh scope refuse a directory basename that cannot be stored as one
  YAML scalar.
- **Typed CLI failures.** `unsafe-config-key`, `unsafe-config-value`, and
  `E_NO_CONFIG` render as one `oats:` line or one `--json` envelope.
  Configless `oats use` reports `E_NO_CONFIG` with the `oats init --raw` remedy.
- **Scope-exact doctor and trust.** `oats doctor` and trust judge each artifact
  against the lock of the scope that installed it, ending false `invalid-lock`
  and orphan reports.
- **Desktop parity.** The Desktop deployment reader accepts and refuses the
  same lock shapes as the kernel.
- **Package payloads are not deployment scopes.** Bare `oats install` and
  `oats migrate --official --recursive` skip config templates under a package
  manifest.

## The turn record: `oats capture | recall | setup`

The kernel carries the turn record: Claude Code, Pi, and Codex sessions plus
aw mail and chat logs, captured as content-addressed turns in append-only
journals and searchable with provenance.

```bash
oats setup            # install capture hooks and a background watcher
oats capture          # one reconciliation pass (--watch, --status, --install-hint)
oats recall <query>   # full-text search with provenance
```

The v1 format specification and conformance vectors ship in the package
(`packages/record/docs/`, `packages/record/test/vectors/`).

## Contract changes

- `oats migrate --dry-run --json` on a scope with visible OAS files returns
  `ok: false` with code `oas-scope-unmigrated`.
- `oats doctor --json` gains `oasScopes`, `oasRemedy`, and per-package
  scope-exact rows; the exit code stays 0.
- Guided migration plan rows gain `migratesTo`, applied rows `migratedTo`;
  all seven ids published by OAS 0.20 are mapped.
- New typed failures `unsafe-config-key`, `unsafe-config-value`, and
  `E_NO_CONFIG`.
- `oats init` and first-write commands refuse unstorable directory basenames.

## Desktop

OATS Desktop 0.22.0 accepts a kernel with `desktopApi: 1` in
`>=0.22.0 <0.23.0`, probing `@awebai/oats`. The old OAS Desktop and this CLI
cannot see each other, so upgrade both together. macOS builds are ad-hoc
signed, not notarized; see [the Desktop guide](../desktop.md).

## Also

- The kernel ships a `LICENSE` file (MIT).
- Root `npm test` runs the Desktop suites when their dependencies are
  installed and otherwise prints the install command.
- The OAS 0.21.0 remote official catalog is not included; OATS resolves the
  bundled catalog only.

## Install

```bash
npm install -g @awebai/oats@latest
pi install npm:@awebai/oats-pi@latest
```

Install matching kernel and adapter versions.
