# OATS v0.24.11 — retirement recovery: kernel-owned fields only, nothing re-blessed after launch

Kernel/Pi/Desktop **0.24.11**. Tag `v0.24.11` → the commit carrying these
notes; the version-bump commit lands after the tag. **Upgrade from 0.24.10 —
it can lose an agent's early home bytes at retire.**

## Fix

0.24.10 (PR84) made a fresh keyed spawn retire clean by re-hashing the **whole
home** after the kernel's own post-spawn writes (completion marker, wake
record). That re-stamp ran after the tmux launch, so anything the agent wrote
in the launch→completion interval — `STATE.md`, notes — was blessed into the
retirement baseline and **not recovered** at retire. Found by the Desktop
engineer's exact-source inert analysis of the merged fix.

Now the re-stamp is gone. The baseline fingerprint hashes the root
`instance.json` with exactly the kernel-owned post-spawn fields
(`spawnCompleted`, `wake`) removed. Kernel writes never read as the agent's
changes; **nothing else in the home is ever re-blessed**; there is no
observation of the home after launch. Regression: authored bytes written at
launch are recovered under `changed instance-home bytes` with the bytes
intact; a plain keyed spawn still retires with `workRecovery: null`.

Rule recorded for the framework: the retirement baseline may account only for
bytes the kernel can *prove* it wrote — never for what it *observes* after the
agent may have started.
