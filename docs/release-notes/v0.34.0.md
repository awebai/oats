# OATS 0.34.0

## Added

- **`oats capabilities show <name>`** (feature `capability-show`,
  `capabilityShowApi: 1`). It answers what one capability of the catalog
  ships: its inject text exactly as committed, and each skill, enumerated as
  a spawn enumerates it, with its SKILL.md description and its files with
  their sizes. `--file <path>` returns the text of one file the show lists
  (the inject or a skill file) and refuses any other file of the capability.
  The rows are `oats capabilities`'s own (`--member <repoKey>` or `--package
  <id>` picks one when names collide, and `--max-age` is accepted), and the
  reads take the trust path spawn takes: a member at the row's commit, a
  package at its locked commit after spawn's lock check (`E_PACKAGE_INTEGRITY`),
  always through the remote cache, never a working clone. Every text and
  description is untrusted repository content: render it as plain text or
  through a sanitising Markdown renderer. The Desktop's capability page reads
  it ([desktop-cli-api.md](../desktop-cli-api.md#oats-capabilities-show)).
  `oats capabilities --json` is unchanged; an unknown word after
  `oats capabilities` is now `E_BAD_ARGS`. A skill path with a `.git`
  component, which a spawn's fetch refuses, now gives `skills: null` on that
  catalog row too.

- **The Desktop's capability page shows what a capability ships.** A new
  *Contents* section, between *Provides* and *Used by*, lists the injected
  instructions and every skill's files on the left and shows the selected
  file on the right: Markdown rendered (a SKILL.md's front matter as a small
  table), other text as highlighted code. A relative link to another listed
  file opens it in place. The content is untrusted repository text, so no raw
  HTML, script or image is rendered. The section reads `oats capabilities
  show` (feature `capability-show`) and needs this release's CLI; with an
  older one it says so and reads nothing. Remote workspaces show it later
  ([desktop-file-viewer.md](../../packages/desktop/docs/desktop-file-viewer.md#rendering-rendererviewsmarkdownmjs)).
  *Provides* above it is now one compact card, with every skill, command and
  hook as its own chip.

## Changed

- **The Desktop's Instance tab says how an instance works in one sentence.**
  "Where it works" becomes **Work**: the work mode's tile and a sentence,
  for example "Works in its own worktree of oats, on branch main." or "Has its
  own folder, not tied to one repository". Folder and Home move into a closed
  **Paths** disclosure, each with Copy. The ahead/behind counts stay on the
  Developer tab. **Messaging & Teams** shows the instance's **Messaging ID**
  with Copy, then its **Teams**, introduced as the messaging teams its soul is
  allowed to join.

- **The Desktop accepts OATS CLIs `>=0.25.8 <0.35.0`**, so it runs against
  this release's kernel. Install the CLI and the Desktop 0.34.0 together: the
  Desktop 0.33.x refuses a 0.34 CLI.

## Fixed

- **`oats status` and `oats workspace status` answer within 12 s of remote
  work, even under load.** Each git call they made had its own 30 s limit, and
  a read could wait up to 11 minutes behind another process fetching the same
  remote, so the Desktop's 30 s limit could end them (`E_CLI_TIMEOUT`). Now
  every remote step of these two reads gets what is left of a 12 s budget: a
  member not read by then is a `cannot-read` row (`… (timeout)`) and its git is
  ended, and the command still answers. A workspace definition not read by then
  fails as an unreadable one does today (`reason: "timeout"`). Another
  process's write to the remote cache is waited for only as long, never taken
  over. Spawn, sync and the other verbs are unchanged.
