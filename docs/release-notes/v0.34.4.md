# OATS 0.34.4

## Fixed

- **A worktree spawn branches from the member commit it observed, not from
  the clone's stale local branch** (awebai/oats#445). When a member clone
  (`clones:`, the convention path or `--repo`) was a human's checkout or a
  shared reference, `oats spawn` cut the instance branch from whatever that
  clone had checked out, often far behind the head the spawn had just
  resolved the soul at, and nobody was told. Now:
  - the branch starts at the commit the spawn observed for its decision. The
    spawn fetches that commit by id into the clone, from the remote that names
    the soul's repository;
  - the clone's own branches, remote-tracking refs and work tree are never
    moved;
  - a commit that cannot be fetched refuses the spawn with
    `E_REMOTE_UNREADABLE`, naming the clone and the commit. Nothing is created
    and nothing falls back to the clone's branch;
  - the spawn result states the start point: `base: <oid> (observed head of
    <repo>)` in text and `base: {ref, oid}` in `--json`. `instance.json`
    records it too.

  `--base <ref>` still names an explicit start point in the clone, and a
  `--repo` that is not a clone of the soul's repository still starts at its
  `HEAD`.

- **A retire whose hook reports incomplete cleanup leaves the worktree as it
  was** (awebai/oats#444). The worktree used to be moved or removed before
  the home was quarantined, so its git admin entry could be gone by the time
  the retry needed it. The retry's work inspection then failed, and the hook
  that asked to be retried could never run again. Now:
  - the home is quarantined before any worktree step: the worktree, its admin
    entry and the branch stay exactly as they were. `retire --json` reports
    `retention: null` and `worktreeRemoved: false`, and `rollbackIncomplete`
    says `git worktree <path>: kept for the retry; outstanding: …`;
  - the retry does the worktree step only once nothing else is outstanding:
    retain by default, remove with `--discard-worktree` or `--delete-branch`.
    Only a failed spawn's quarantine that owes the worktree removes it;
  - `--force` removes the home regardless, so it does the worktree step first
    and leaves no admin entry pointing into a removed home;
  - a work directory whose admin entry is gone is reported as incomplete, the
    hooks still run, and the directory is never removed. `--force` refuses it
    (`E_WORK_PRESERVATION_FAILED`) until you move it out or delete it by hand.
    Upgrade before forcing: an older kernel's `--force` still removes such
    a directory along with the home.

- **The spawn's fetch of its base reads remote names safely** (follow-up to
  #445): the remote is passed after `--end-of-options`, so a remote whose
  name reads like an option is never taken as one, and remote urls are read
  NUL-separated (`git config -z`), so a newline in one url cannot forge
  another remote.
