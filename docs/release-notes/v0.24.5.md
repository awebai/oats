# OATS v0.24.5 — four small fixes

Kernel/Pi/Desktop **0.24.5**. No contract, schema or authority change.

- **Retirement recovers a worktree on the branch it actually has.** Recovery used the spawn-time branch from `instance.json`, so a worktree that had switched branches could not be retired by the normal path. Recovery now reads the branch from the worktree while it exists (a detached HEAD recovers at its exact commit), falls back to the recorded branch only when the worktree is gone, and records the difference in `recovery.json` (`branchDrift`). Fail-closed behavior is unchanged.
- **Captured launch: `ifInstalled` runtime rows are not hard blocks, and refusals are attributed.** A `requires` row marked `ifInstalled: true` (a version floor for an optional package) was treated as mandatory, so a Pi launch with aweb `delivery: session` could never publish a resolution. Such rows are now satisfied by absence. Remaining hard rows refuse with an ordinary preparation problem (`slot`, `capability`, `runtime`, `package`, and the manifest's `install` text).
- **Helper-injection refusal is attributed.** A capability that ships an `inject` without a `helperInjection` policy yields a preparation problem naming that capability, with `origins`.
- **`oats onboard --workspace` uses the workspace's catalog.** The bundled `package-catalog.json` is a snapshot at the kernel's tag and lags later `oats.framework` releases, so onboarding a current workspace edition refused as `integrity-drift`. Onboarding now reads the workspace repository's `package-catalog.json` at the observed revision; the bundled entry is the fallback and `OATS_PACKAGE_CATALOG` still overrides. The result reports `catalog.origin`, and a drift refusal names both integrities.
