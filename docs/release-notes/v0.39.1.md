# OATS 0.39.1

## Changed

- **oats.aweb 1.21.1: a Claude Code start says that it will wait at Claude
  Code's development-channels confirmation** (awebai/oats-aweb#44). Under
  `delivery: channel`, Claude Code loads the `aweb-channel` plugin with
  `--dangerously-load-development-channels`, because the plugin is not on
  Claude Code's approved channel list. Claude Code then stops at its "Loading
  development channels" confirmation before the session starts, and waits
  until someone answers it in the instance's terminal. Unattended starts
  (Desktop starts and restarts, automations, successors) waited there with
  nothing saying so. Now:
  - every spawn or start that adds the flag carries the warning
    `channel-dev-confirmation` once;
  - `oats readiness` reports it, without changing the status, for a home
    whose last start was Claude Code under `channel`.

  Nothing answers the confirmation on the human's behalf. Launch arguments
  and settings are unchanged. `--channels` registers only plugins on Claude
  Code's approved list; for a plugin not on it, Claude Code prints a startup
  warning and the channel does not register. That list is Anthropic's
  default, or a Team/Enterprise organization's managed
  `allowedChannelPlugins`, which replaces the default and requires
  `channelsEnabled: true`.

## Fixed

- **`oats readiness` no longer fails package souls on membership**
  (awebai/oats#533). A package soul (`oats.okf/knowledge-maintainer`,
  `oats.engineering/code-reviewer`, …) failed its `member` check with
  "member <its package's repository>: not a member of the workspace", and the
  remedy asked to list the package's repository in `members:`. A package
  soul is trusted through the workspace's `packages:` pin, never through
  membership (see [the non-collapse rule](../workspaces.md#member-tier-vs-package-tier-the-non-collapse-rule)).
  Its `member` item is now `package <package>/<soul>`. It passes when the
  package is declared and locked, ships the soul at the locked commit, and
  the soul's copy matches its digest: for `--soul`, the copy a spawn would
  link against the lock; for `--home`, the home's copy against the digest it
  recorded, and the lock against that same digest while it still pins the
  same commit. A mismatch fails with `E_PACKAGE_INTEGRITY`. Member and
  external souls are unchanged. Spawn already applied this rule.
