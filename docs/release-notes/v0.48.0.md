# OATS 0.48.0

## Added

- **Conditional team default and mapping-only add (#771), feature
  `teams-conditional-default`.** `oats teams default <label> --if-absent`
  sets the local default only where the deployment has no effective default;
  `--expect <label0>` only where the effective default (local, or inherited
  from the workspace) is `<label0>`. A failed condition is
  `E_TEAM_DEFAULT_MISMATCH {expected, observed}` and writes nothing.
  `oats teams add <label> --team <id> --no-default` writes the mapping without
  touching `defaultTeam`; the same label and id already declared is reuse
  (`changed: false, reused: true`). `E_TEAM_EXISTS` also carries `observed:
  {label, team, from}`. Every `oats teams` write holds
  `<deployment>/.agents/locks/local.lock`, so the later of two racing
  conditional writes sees the earlier one and refuses with
  `E_TEAM_DEFAULT_MISMATCH`; a lock still held after 5 s is `E_LOCAL_BUSY`,
  with nothing written. `teamsApi`
  stays 2: the `oats teams --json` shape is unchanged. Callers check the
  feature before passing the flags, because older kernels ignore them, and
  there `--if-absent` is an unconditional set.

## Changed

- **`oats teams` refuses flags it does not take.** Each form (`oats teams`,
  `add`, `remove`, `default`) answers an unknown flag with `E_USAGE {flag}`,
  naming it and the usage, before anything is read or written. Before, they
  were ignored. `--server` on `oats teams` is now refused too: teams has never
  been routed to a server. A script that passes stray flags must drop them.

- **The workspace pins oats.framework 1.8.0 and oats.engineering 1.9.0.**
  The official catalog resolves bare `oats.framework` versions to
  `oats-framework/v1.8.0` (oats.support 1.0.0, the support desk role), and
  `oats.engineering` to `v1.9.0`. That adds oats.maintainer's
  `/support-maintainer` skill: a maintainer that serves the support desk's
  tickets. The capability mirrors under `mirrors/` are regenerated from the
  v1.9.0 tag and their trees equal the tag's. Running instances keep what
  they were spawned with; new spawns pick these up after `oats sync`.

- **The workspace and official catalog pin oats.aweb 1.23.2.** The generated
  `mirrors/oats-aweb` payload equals the provider v1.23.2 tag tree. This adds
  verified LOCAL join mapping/default readback and explicit LOCAL identity
  selectors at launch and preview (1.23.1), and GLOBAL grant metadata that
  records the app snapshot from each successful native mint receipt: Comms
  labels it as the at-spawn snapshot, inspect shows the current recorded
  metadata, and preview warnings say whether it is retained or unknown
  pending renewal (1.23.2). That snapshot is not a live app acceptance. Existing captured homes
  do not adopt the changes automatically; this pin does not perform sync,
  restart or live acceptance.

- **oats.apps 1.0.0 is a new official package.** It exports `oats.folio` and
  `oats.library`, additive guidance capabilities for the aweb Folio and Library
  apps (`aw >=1.36.26`; OATS 0.47.0 or later), and the catalog aliases both
  ids to the package. The generated `mirrors/oats-folio` and
  `mirrors/oats-library` equal the v1.0.0 tag's payload trees. The workspace
  adds `awebai/oats-apps` as a member (its expert soul `oats-apps-expert`) and
  pins `oats.apps: git:github.com/awebai/oats-apps@v1.0.0`: an installed CLI
  resolves bare versions through the catalog it shipped with, and 0.47.0's has
  no `oats.apps`, so the pin goes bare once every deployment's CLI carries
  this entry. No soul selects either capability yet, and no workspace default
  is added.
