# OATS 0.41.0

## Changed

- **The framework workspace has a separate maintainer soul.** The new
  `oats-maintainer` soul is the OATS maintainer: direction, the roadmap,
  architecture coherence, routing work to experts, review, merge and releases.
  It composes `oats.maintainer` and carries the OATS-only `/oats-pr-review` and
  `/git-tag-release` skills. `oats-expert` stays an expert, the generalist that
  leads cross-area work, coordinates the domain experts and reports to
  `oats-maintainer`. The other souls send direction, contract decisions and
  merges to `oats-maintainer`, and read its knowledge node
  (`oats/oats-maintainer`, which holds what the `oats-expert` node held).
  - The `oats` knowledge store's main must declare the `oats-maintainer`
    node before this reaches a deployment: souls that read or own it fail
    their knowledge check with `E_CONFIG unresolved node:
    oats/oats-maintainer` against a base without it.
  - Operators: `oats sync`, then spawn `oats-maintainer` for maintainer work.
    Running instances keep what they were spawned with.
- **Desktop terminals keep text readable (#602).** Desktop terminals now keep
  text at least 4.5:1 against its background, so coloured text written for
  another palette (a grey meant for a dark terminal, shown in White) stays
  readable. The built-in palettes' colours on the terminal background are
  unchanged; text on a coloured background may be drawn lighter or darker than
  the program asked.
- **Desktop can match this computer's theme (#602).** A fourth theme choice,
  **This computer**, shows Desktop's chrome and every terminal in the theme of
  the computer that runs Desktop. On an Omarchy computer that is the current
  Omarchy theme, followed when it changes, with no restart. Elsewhere it is
  Dark or White by the system's appearance. Text colours taken from the host
  are adjusted where needed to stay at least 4.5:1 on Desktop's surfaces; a
  terminal's 16 colours are the host's own. If the host's theme cannot be
  read, Desktop shows Dark or White and says so. A theme you chose does not
  change: choose **Theme: This computer** in the command palette, or cycle to
  it with the theme button.
  - On Linux, This computer is the default: a Desktop where no theme was ever
    chosen starts in This computer (the computer's Omarchy theme, or the
    system's light or dark appearance where there is none) instead of White.
    That includes an existing install where the theme was never changed. If
    you chose White at any time, it stays White. Choose another theme with the
    theme button or the palette, and it stays. On other platforms the default
    is still White.
- **Desktop's Remove has one choice, the worktree.** Remove no longer offers
  to delete a branch: retirement leaves branches to the operator, and the
  kernel refuses the flag. The dialog's one choice is **Also delete the
  worktree**, and it says "Remove never deletes a branch." A home left by a
  failed spawn that still owes its branch stays incomplete while that branch
  exists, and Remove can no longer complete it: check the branch and delete it
  with Git, then remove the home again.

## Upgrade

**Retirement no longer deletes branches.** What to do:

- **`oats retire --delete-branch` is refused** with `E_BAD_ARGS` before
  anything happens: no child or session is stopped, no hook runs, nothing is
  written. Retire without it; the branch is left in the repository. Inspect it
  there and delete it with Git if it is no longer wanted. Scripts that pass the
  flag must drop it. A self-retire an older OATS recorded with the flag is
  completed with the branch and the worktree left, and its `retired` event says
  so.
- **A home a failed spawn left that still owes its branch** stays incomplete
  while that branch exists, with the item `the branch the failed spawn created
  is left: OATS does not delete it. Inspect it and delete it with Git if it is
  not wanted, then retry`. The item names no branch; the CLI prints it on the
  next line (the receipt's `retention.recordedBranch`, or the `branch` in the
  retained home's `instance.json` when the worktree step did not run). While
  Git cannot show the branch gone, the item is `git branch <b>: could not
  verify whether it still exists (…)`. Delete the branch with Git, then retire
  again.
- **A worktree whose branch has no commit yet:** `oats retire
  --discard-worktree`, or a retire that has work to copy, on such a worktree
  refuses with `E_WORK_INSPECTION_FAILED` and removes nothing. Make a commit,
  switch the worktree to a branch that has one, or remove the worktree with
  Git; then retire again.
- **A worktree Git refuses to read without your own `safe.directory`**
  (typically one owned by another user) now refuses a retire that has work to
  preserve or that removes the worktree, with `E_WORK_INSPECTION_FAILED`. A
  plain retire of such a worktree with nothing to preserve retains it under a
  `detached-unknown` name, without its branch in the receipt. Retire as the
  owner, or with Git's ownership check satisfied for that path.

## Fixed

- **A retire keeps what only the worktree has.** The recovery a retire writes
  of a worktree is proven against the commit the worktree has checked out, and
  is checked out at that commit on the worktree's own branch (detached, when
  the branch's name is not one OATS carries). A clean worktree whose HEAD is
  detached at a commit no ref of the repository reaches is preserved in a
  recovery before `--discard-worktree` removes it, also when a retire hook made
  that commit. HEAD is read again immediately before the worktree is removed:
  if it moved since the retire's last inspection, the worktree is not removed
  and the retire stops with `E_WORK_PRESERVATION_FAILED`; the home and the
  worktree are kept, and so is any recovery the retire wrote.

- **A stopped instance's harness mark is readable in Solarized (#602).** In
  the Desktop's roster, the harness mark of a stopped instance was drawn at
  4.0:1 in Solarized, under the 4.5:1 the rest of the app keeps. It is now
  4.7:1. The mark's block is slightly lighter in White and Solarized and
  slightly darker in Dark.
- **Desktop no longer hangs when the Omarchy colours file is replaced while it
  is read (#602, #612).** On a computer with an Omarchy theme, Desktop reads
  the theme's colours file at start and each time a window gets focus,
  whichever theme is chosen. It could hang there if the file was replaced by
  something that is not a regular file (a named pipe, for example) while it was
  being read. It now opens the file without blocking and checks what it opened.
- **Review threads reach an agent whose session is not on the default tmux
  server (#602).** Sending a pull request's review threads to an agent's
  terminal from the Desktop now uses the tmux socket the instance records, as
  the Desktop's terminals do. Before, the paste always went to the default tmux
  server, so for an instance that records another socket it answered that the
  paste failed. An instance that records no socket is pasted to as before.
- **The Desktop names a retire refused at inspection.** When `oats retire`
  refused a local instance with `E_WORK_INSPECTION_FAILED`, the Remove dialog
  said "The lifecycle CLI is unavailable.", although the CLI had answered. It
  now says: "Retirement was refused: the instance's home or work could not be
  inspected. The home is kept; its session may already have been stopped, and
  earlier retirement steps may have run." The outcome is still reported as
  unknown, because the kernel can refuse after it stopped the children and the
  session and ran the retire hooks. For an instance on a server the same
  sentence replaces that headline, above the host's own message in Details.
  For a local refusal the CLI's own message, which names the path and the
  remedy, is in Details too (next entry). Part of
  [#601](https://github.com/awebai/oats/issues/601).
- **The Desktop shows the kernel's own message when a local Stop or Remove
  fails.** The dialog said only its own sentence for the error code; the
  message the CLI answered with was dropped. It is now in the dialog's
  **Details**, as the code and the message, under that sentence, as it already
  was for an instance on a server. It is shown only when the installed CLI
  answered with an error and the Desktop has a sentence for its code: a
  timeout, an unreadable answer or an unknown code shows none. Closes
  [#601](https://github.com/awebai/oats/issues/601).
- **The Desktop shows a kernel or host message as one plain line.** In the
  Details of a refusal (Stop and Remove, the Git panel, Activity, readiness),
  line feeds, the Unicode line and paragraph separators and tabs are collapsed
  into single spaces. The C1 control characters, the bidirectional embedding,
  override and isolate characters, the zero-width space, the word joiner, the
  byte order mark and tag characters are each replaced by U+FFFD, the
  replacement character. A message that holds a carriage return, DEL or
  another ASCII control character other than tab and line feed (a message
  with Windows line endings, for example), or that looks like a credential,
  is withheld whole as `[Detail withheld]`, as before. A long message is cut
  at 2048 characters. For readiness, the message is no longer in the "Couldn't
  refresh" line's tooltip, which keeps the Desktop's sentence and the error
  code; it stays in Details. In the Git panel a failed read's message, which
  could span several lines, is now one line.
- **A tmux server started from the Desktop gets your environment, not the
  Desktop's (#602).** A tmux server started from the Desktop (by a spawn or a
  start, or by opening a terminal) no longer carries the Desktop's own runtime
  settings. They made Electron programs started from an agent's pane run as
  Node, and on the AppImage they pointed library and data paths into the
  Desktop's mount, which exists only while that Desktop runs. Every program
  the Desktop starts (the `oats` CLI, `tmux`, `gh`, the login shell that
  resolves `PATH`) now gets your environment without them. One change in a
  diagnostic: `probePath` in the backend's `GET /api/cli` answer no longer
  lists the AppImage's own entries. A tmux server that was already running
  keeps the environment it was started with (#616). Known limits are in the
  Desktop README.
- **The Desktop builds a view's failure placeholder as text.** A tab whose
  view fails to load or to mount shows the same words, built without markup.
- **`oats retire` no longer refuses a launched instance only because its
  tmux socket file is missing.** After a reboot that cleared tmux's socket
  directory, tmux answers `error connecting to <socket> (No such file or
  directory)` for the socket the instance's session was recorded on, and
  retire refused with `E_RUNTIME_QUIESCE_FAILED`. Retire now goes on when the
  recorded server cannot be reached because its socket file is missing and no
  process on the host works in the instance's home (any process whose working
  directory is in the home, not only the harness). A tmux server keeps running
  when its socket file is removed, so when a process still works in the home,
  or the process scan (`lsof`) cannot run or does not complete, retire refuses
  as before and the message says which. Such a server recreates its socket
  when its process is sent `SIGUSR1`. The check needs `lsof`: on a host
  without it, a retire whose recorded socket file is missing is still refused,
  and the message says that `lsof` is missing; install it, then retire. The
  scan counts only when `lsof` completed: one that was cut off (a timeout, too
  much output, a signal) is no longer read as "no process", here, for a home
  without its session receipt and for a home opened in Herdr; those retires
  are refused. A window that is still running, or a server that cannot be read
  for another reason, is refused as before.
  [#620](https://github.com/awebai/oats/issues/620).

## Removed

- **Three unused routes of the Desktop's local server.**
  `GET /api/session/<instance>` (a capture of the instance's terminal),
  `POST /api/keys/<instance>` (keys or a paste typed into it) and
  `POST /api/interrupt/<instance>` (Ctrl-C) are gone. Nothing in the Desktop
  used them: its terminals attach to the instance's session directly. They
  ran `tmux` without the socket an instance records, so for an instance on
  its own tmux server they would have reached another one. Each path now
  answers as any unknown route does (`404`, `not found`).
  `GET /api/chat/<instance>` is unchanged. Closes
  [#609](https://github.com/awebai/oats/issues/609).
