# OATS 0.41.0

## Changed

- **The framework workspace has a separate maintainer soul.** The new
  `oats-maintainer` soul is the OATS maintainer: direction, the roadmap,
  architecture coherence, routing work to experts, review, merge and releases.
  It composes `oats.maintainer` and carries the OATS-only `/oats-pr-review` and
  `/git-tag-release` skills. `oats-expert` stays an expert, the generalist that
  leads cross-area work, coordinates the domain experts and reports to
  `oats-maintainer`. The other souls send direction, contract decisions and
  merges to `oats-maintainer`, and read its knowledge node
  (`oats/oats-maintainer`, which holds what the `oats-expert` node held).
  - The `oats` knowledge store's main must declare the `oats-maintainer`
    node before this reaches a deployment: souls that read or own it fail
    their knowledge check with `E_CONFIG unresolved node:
    oats/oats-maintainer` against a base without it.
  - Operators: `oats sync`, then spawn `oats-maintainer` for maintainer work.
    Running instances keep what they were spawned with.

## Fixed

- **The Desktop names a retire refused at inspection.** When `oats retire`
  refused a local instance with `E_WORK_INSPECTION_FAILED`, the Remove dialog
  said "The lifecycle CLI is unavailable.", although the CLI had answered. It
  now says: "Retirement was refused: the instance's home or work could not be
  inspected. The home is kept; its session may already have been stopped, and
  earlier retirement steps may have run." The outcome is still reported as
  unknown, because the kernel can refuse after it stopped the children and the
  session and ran the retire hooks. For an instance on a server the same
  sentence replaces that headline, above the host's own message in Details.
  For a local refusal the CLI's own message, which names the path and the
  remedy, is in Details too (next entry). Part of
  [#601](https://github.com/awebai/oats/issues/601).
- **The Desktop shows the kernel's own message when a local Stop or Remove
  fails.** The dialog said only its own sentence for the error code; the
  message the CLI answered with was dropped. It is now in the dialog's
  **Details**, as the code and the message, under that sentence, as it already
  was for an instance on a server. It is shown only when the installed CLI
  answered with an error and the Desktop has a sentence for its code: a
  timeout, an unreadable answer or an unknown code shows none. Closes
  [#601](https://github.com/awebai/oats/issues/601).
- **The Desktop shows a kernel or host message as one plain line.** In the
  Details of a refusal (Stop and Remove, the Git panel, Activity, readiness),
  line breaks and tabs are collapsed into single spaces, and control
  characters, bidirectional formatting characters, the zero-width space, the
  word joiner, the byte order mark and tag characters are withheld: each is
  shown as U+FFFD, the replacement character. A message that looks like a
  credential is still withheld whole, as before. A long message is cut at 2048
  characters. The message is no longer in the "Couldn't refresh" line's
  tooltip, which keeps the Desktop's sentence and the error code; it stays in
  Details. In the Git panel a failed read's message, which could span several
  lines, is now one line.
