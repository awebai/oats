# OATS 0.41.0

## Added

- **A capability can declare the home state it owns:
  `retirement.disposable.home`**
  ([#410](https://github.com/awebai/oats/issues/410)). The meaning is:
  provider-owned state that is not the instance's work, left in place until
  the home is removed, and not copied to recovery. A provider declares the
  top-level entries of the instance home that hold its own state, such as an
  identity directory with a signing key:

  ```json
  "retirement": { "disposable": { "home": [".aw", ".oats-aweb", ".aweb-identity", ".aweb-identity-*"] } }
  ```

  Each entry is one hidden top-level name (`.name`) or a prefix
  (`.prefix-*`, every top-level entry whose name starts with the text before
  `*`). Matching entries are left out of the home fingerprint, the home copy
  and its verification, so a change to them alone causes no copy. Exclusion
  means "not copied" and nothing more: the entries stay in the home until the
  home is removed, retire hooks still see them, and an incomplete cleanup
  keeps the home with them. The receipt names what was left out in
  `workRecovery.notCopied` (`[{scope, path, owner}]`: names and owners only),
  and the summary prints `not copied: .aw, .oats-aweb (oats.aweb)`. A
  capability that declares nothing has its home state copied, once. This
  kernel reads the field. See
  [capabilities](../capabilities.md#manifest).

## Changed

- **One retire writes one recovery**
  ([#480](https://github.com/awebai/oats/issues/480),
  [#544](https://github.com/awebai/oats/issues/544)). A retire whose hooks
  changed the home or the work wrote a second recovery directory with a full
  copy of both. It now adds to the recovery it already wrote, and copies again
  only the part that changed:

  ```text
  <recovery>/
    recovery.json
    home/               the home before the retire hooks
    repo/ or work/      the work before the retire hooks
    after-hooks/
      home/             the home again, only if a hook changed home bytes
      repo/ or work/    the work again, unless it is proven unchanged
  ```

  The work is copied again unless it is proven unchanged: in worktree mode
  by what a work copy holds beside the files (status, branch and commit,
  index entries and resolve-undo records, an operation in progress, tags, stash, exclude rules and
  status settings, for the worktree and for each nested repository) and by
  the bytes of its files. A status with the same rows is not taken as proof, so a retire
  hook that rewrites a file that was already modified has its bytes
  preserved, whether or not it also writes the home
  ([#600](https://github.com/awebai/oats/issues/600)). For that proof a
  retire reads the worktree's files once before the hooks, when there is
  something to preserve, and at most once more after them. A tag or a stash
  made in the worktree's repository while the hooks run causes one more
  work copy.
  A snapshot that holds the home only also gets the work under
  `after-hooks/` when the hooks did not move it but something beyond the
  home is there to preserve after them. The home is not
  copied again because the work is: the kernel's own records in it
  (`.oats-events.jsonl`, the `.oats-stop*.json` and `.oats-restart.json`
  receipts, `.oats-agents-md.*.previous`, `.claude/settings.json`, and the
  `spawnCompleted` and `wake` fields of `instance.json`) are as of the
  pre-hook snapshot unless the home itself was copied again.

  Each part under `after-hooks/` is whole and verified, verified
  before the home is removed; `after-hooks/home/` exists only when the
  home's own bytes moved. The pre-hook snapshot is never rewritten. An
  instance that had nothing to preserve before the hooks still gets its one
  recovery after them, with no `after-hooks/`. `recovery.json` gains `phase`:
  `"before-hooks"` when the pre-hook snapshot is written, `"complete"` once
  the post-hook check has concluded. A retried retire, after incomplete
  cleanup or after a refused or interrupted attempt, writes its own recovery
  and never touches an earlier one; a directory left at `before-hooks` is a
  complete, verified pre-hook snapshot. The summary prints one "has been
  preserved" block, with what was copied from the home and an `after the
  retire hooks: … copied again under after-hooks/` line when it applies. See
  [souls and instances](../souls-and-instances.md#retire).
- **A socket, a FIFO or a device file in a worktree refuses the retire.**
  In worktree mode, when a retire has something to preserve before its
  hooks run, it now reads the whole worktree, and an entry that is not a file, a directory or a
  symbolic link cannot be read or copied. Git prints no status row for such
  an entry. Before, a retire refused it only inside a directory Git reports
  as ignored, or when it copied the work; a retire that preserved only the
  home went through. Now it refuses with `E_WORK_INSPECTION_FAILED` before
  any retire hook runs: no recovery was written and nothing was deleted,
  however often it is retried. The message names the entry and says what to do: safely stop
  the process or resource that owns it, or move the entry elsewhere, then
  retry (it may be a live endpoint, so the advice is not to delete it).
  `--json` keeps the code; the `message` field is the new sentence, also for
  the cases that were already refused. The retire has already stopped the
  session of a launched instance by then: the instance's session is
  stopped, the instance is not retired, and its home is kept; the message
  says so. To continue, deal with the entry and run
  `oats retire <instance>` again, or start the session again in the same
  home with `oats session start --home <abs>`. A self-retire (`--self`) is
  refused the same way by its detached completion, which records the
  refusal beside the home; after that only `oats retire <instance>`
  continues, and `oats session start` refuses until it has. Only
  `--self --keep-dir` refuses with the session still running. When a retire hook leaves such an
  entry behind, the hooks have run: the retire refuses
  (`E_WORK_INSPECTION_FAILED`, or `E_WORK_PRESERVATION_FAILED` when the hook
  also moved the Git state) and the home, the work and the recovery written
  before the hooks are kept.
- **An exclude or attributes file that cannot be read refuses the retire.**
  A retire now reads, at every inspection, the files a work copy carries of
  the Git configuration: the file `core.excludesFile` names, `info/exclude`,
  `info/attributes` and the stash's log, in the worktree's repository and in
  each nested one. One that exists but cannot be read (it is a directory, or
  permission is denied) refuses the retire with `E_WORK_INSPECTION_FAILED`,
  naming the file, at the first inspection: no recovery was written, nothing
  was deleted, and the retire has not stopped the session. That includes a retire with nothing to
  preserve; before, only a retire that copied the work read these files.
- **Two retires that already refused now refuse with another error code.**
  A worktree that the retire copies before its hooks (it has work to
  preserve) and that holds an entry that is not a file, a directory or a
  symbolic link was refused with `E_WORK_PRESERVATION_FAILED`, when the copy
  met the entry. It is now refused earlier, when the worktree is read, with
  `E_WORK_INSPECTION_FAILED`; the message names the entry's path and says
  what to do. (A worktree that holds a repository inside a nested
  repository is copied without that read, and keeps
  `E_WORK_PRESERVATION_FAILED`.) And a worktree with a nested repository whose Git state cannot
  be read was refused with `E_WORK_PRESERVATION_FAILED`, when the copy asked
  that repository for its commit. It is now refused at the first
  inspection, with `E_WORK_INSPECTION_FAILED`: no recovery was written,
  nothing was deleted, and the retire has not stopped the session; the
  message names the repository. The home is kept in all of them.
- **`oats retire --json` no longer emits `workRecoveries`.** The receipt has
  one `workRecovery`, which keeps `path`, `classes`, `bytes`, `outputs` and
  `repoCopy` and gains `home` (what was copied from the home), `notCopied`
  and `afterHooks: {home, work}` (which parts are under `after-hooks/`).
  A reader that consumes the receipt should read `workRecovery`, and keep
  accepting `workRecoveries[]` from an older kernel on a server. The
  Desktop's reader of the receipt is unchanged. See
  [the CLI API](../desktop-cli-api.md#retire).
- **`oats retire <instance> --plan` says what a retire would copy.** Two
  `notes` are added: where changed home files are copied, with the declared
  entries that are not copied, and whether the work is copied too (worktree
  and directory modes). No other key changes, and `planRevision` is
  unaffected.
- **The Desktop accepts OATS CLIs `>=0.25.8 <0.42.0`**, so it runs against
  this release's kernel; the Desktop 0.40.x refuses a 0.41 CLI.
- **A forced removal past incomplete cleanup no longer leaves a copy of
  declared state in recovery.** `oats retire <instance> --force` on a home
  whose cleanup cannot finish removes the home after preserving its work.
  Entries declared in `retirement.disposable.home` go with the home; the
  recovery holds no copy of them.
- **A malformed `retirement` is refused where the manifest is read.** Member
  discovery (`E_WORKSPACE_SCHEMA`), package manifests (`E_PACKAGE_MANIFEST`)
  and the kernel loader refuse the same manifest with the same JSON pointer.
  `retirement` must contain a `disposable` map with only `home` and `work`,
  each an array of strings. A `home` entry must be one hidden top-level name
  (`^\.[A-Za-z0-9_][A-Za-z0-9._-]*$`) or a prefix
  (`^\.[A-Za-z0-9_][A-Za-z0-9._-]*-\*$`). Refused: anything else (`notes`,
  `.aw/keys`, `.a*`); an exact name that is `.oats`, `.agents` or `.claude`,
  or that starts with `.oats-events`, `.oats-stop`, `.oats-restart`,
  `.oats-rollback`, `.oats-agents-md`, `.oats-start` or `.oats-attachments`
  (the entries the kernel itself writes in a home); and a prefix that starts
  with `.oats-`. An exact name such as `.oats-aweb` is allowed. The published
  [manifest schema](../capability-manifest.schema.json) states the same
  rules.

  **This is stricter than before for `home`.** Before this release `home`
  entries were not checked against a grammar; an entry outside the grammar
  now refuses the whole manifest. For a home whose module copy
  (`<home>/.oats/modules/<capability>/oats.json`) carries such an entry, the
  commands that load the home's module manifests stop: starting or
  restarting its session, and capability commands run from the home.
  `oats inspect` reports it as a `module-manifest-invalid` problem instead of
  failing. Retiring such a home still works, because retire runs the hooks
  recorded in `instance.json` at spawn and does not load the manifests. No
  capability shipped in this repository declares `retirement`.

## Notes

- **Instances spawned before the upgrade retire with one copy, and still
  copy provider state.** The declaration is recorded at spawn in the home's
  retirement baseline, and retire reads it from there only. A home spawned
  before its capability declared the entries gains no exclusion from a
  package update: its home is copied whole, once. An instance spawned after
  the capability declares them leaves them out.
- Existing recovery directories are not read, listed or deleted by this
  release.
