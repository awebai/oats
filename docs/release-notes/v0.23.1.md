# OATS v0.23.1 — external OKF v2 integration

This patch integrates the published **oats.okf 2.0.0** Git package, tagged at
`4b6d861ce44e5662303e150cc85095d0eb00d7e7`, following the published OATS 0.23.0
prerequisite. The checked-in mirror records verified remote tag/object and
payload provenance. Updating OATS alone does not change existing exact locks,
activate capabilities, migrate knowledge or install a host timer.

## External OKF v2 integration

The framework mirror follows the standalone package's **only exported
capability**, `oats-package/capabilities/oats-okf/`. OATS >=0.23.0 supplies the
generic directory-work and public capture/recall/CLI boundaries; OKF uses no
private kernel imports. V0.23.1 prepares the framework catalog for OKF 2.0.0,
without changing an existing deployment's exact lock or activation.

This is a **breaking capability upgrade**, independently versioned from the
framework patch:

- Explicit absolute `bindings-file` settings, external Git/directory bases,
  `soul/okf.json` owner declarations and accepted `okf-base.json` node metadata.
- Index-first immutable reader views, with an instructional no-write boundary,
  not an OS sandbox or new ACL. `owns` routes responsibility and `reads` selects
  starting context; every configured base remains discoverable/readable.
- Durable per-source notes **and full record windows**, frozen destinations,
  independent directory workers and source jobs that survive home retirement.
  Final capture must certify custody before the source home can disappear.
- Git delivery is PR-only, with verified native commit/push/PR receipts and
  separate merge-visible acceptance. Plain-directory delivery uses cooperative
  locks, baseline comparison, a recoverable publication journal and validated
  receipts, without Git/gh. Multi-base delivery is not a distributed transaction.
- Working agents capture; service workers judge. No automatic edits to soul
  skills, direct accepted-base edits by readers or attached source-branch
  promotion commits.

## Inspection and complete pipe output

The v2 inspection surface restores labeled live `STATE.md`, `log.md` and sorted
Markdown notes alongside durable processing receipts. Home-pointer and instance
identity checks prevent a retired, missing, reused or unverified home from
supplying another source's live documents. `liveMemory` reports availability,
reason and observation time; durable bindings, registered view receipts and
scheduler diagnostics remain available independently.

Inspection keeps its explicit **256 KiB per-document preview**, with
`truncated`/original `bytes` metadata. The complete JSON envelope drains stdout,
including large documents and receipts. Provider `read` returns full Markdown;
record transport retains full returned evidence, not an inspection preview.
Descriptor-selected `read`/`refresh` always writes new immutable views under
source state, never the invoking repository or a deleted/replacement home.

Regression qualification must retain behavioral coverage, including large
piped documents, live identity failures, durable inspection after disappearance,
external view placement and full native record backlog. Scaffold tests establish
layout/custody, not that a model learned.

## Git distribution, not an npm payload shortcut

Users acquire `oats.okf` through the catalog's exact Git payload and explicitly
review/trust executable surfaces. The npm bundled mirror is **not a
self-contained Git distribution**: npm omits the worker soul's tracked
`CLAUDE.md -> AGENTS.md` symlink. Do not synthesize source aliases, weaken
integrity rules or advertise copying that mirror as a complete package.

The optional `oats.knowledge-theory` catalog entry uses the already published
**v0.23.0** source (package 1.0.0), avoiding a forward reference to an unpublished
tag. The current Git source additionally contains the 1.0.1 authoring-reference
patch, available through an explicit v0.23.1 Git source after publication.
Its payload stays in the repository's `oats-package/` Git subtree,
not the kernel npm tarball. It exports authoring resources and
`knowledge-theory-expert`, without a knowledge-layer binding, mandatory runtime
injection or OKF dependency. Canonical references and copied local curriculum
must stay synchronized. Acquisition alone activates nothing.

## Migration and verification

Follow [the v1 preservation and cutover guide](../knowledge-migration.md):
inventory active writers, preserve legacy knowledge/state/cursors, provision
empty owned nodes, stage and deliver through the provider, confirm acceptance,
then deliberately cut over owner declarations and existing sources. Old
watermarks are evidence, not v2 processing proof. No automatic migration deletes
legacy material or leaves a knowledge symlink in the soul.

Qualification includes the standalone suite against the actual published
minimum kernel, strict byte/mode/symlink mirror verification, framework regression
and installed-tarball Git acquisition probes. Iterative independent review
covered custody, interrupted publication, source retirement and rejected-PR
recovery. Separate real Pi learning after source/transcript deletion and actual
GitHub PR merge/reconciliation/fresh-view acceptance were verified; scripted
transport and model-learning evidence are kept distinct.

The normal tag-driven release still gates npm publication on all tests and
Desktop build/smoke legs. Live deployment and explicit knowledge cutover remain
separate operations, not side effects of package acquisition.

commands, custody and recovery boundaries.
