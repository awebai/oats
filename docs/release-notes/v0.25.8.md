# OATS 0.25.8

## Fixed

- **Desktop: quotes are escaped in attribute contexts** (#139). The views share
  one escaper (`escapeHtml`) for element content and attribute values.

- **The roster reports an instance where it actually is.** `oats status`
  reports each instance at the directory the kernel enumerated
  (`<soul dir>/instances/<name>`), under that directory's name. An
  `instance.json` whose `home` or `instance` disagrees no longer relocates or
  renames the instance; the disagreeing values appear only as the diagnostics
  `recordedHome` / `recordedInstance`. Before this, a hostile or corrupted
  `instance.json` could make every consumer that acts on `home` (retire,
  `inspect --home`, the Desktop's file roots) target a path outside the
  deployment. Found by the Desktop engineer in Phase F slice F1.

## Added

- **Team facts for workspace-model hooks** (human decisions 2026-09-24:
  `oats.aweb` is the messaging default; teams are seamless). A workspace
  deployment has no classic `team:` block, so lifecycle hooks of a workspace
  spawn now receive: `OATS_TEAM_SCOPE` = the deployment directory;
  `OATS_TEAM_ID` = the messaging slot's merged payload `team` (workspace base ⊕
  `byTeam[<soul team>]` ⊕ soul ⊕ host ⊕ spawn), **empty when no shared team is
  mapped — meaning "personal"**; and new `OATS_TEAM_LABEL` (the soul's team
  label), `OATS_WORKSPACE_NAME` and `OATS_WORKSPACE_KEY` (canonical repository
  key), so a messaging provider can derive a personal team per person per
  workspace deterministically. Classic deployments are unchanged.
- **Desktop F2: Capabilities, Sources, sync and approval, onboarding** (#143).
  The Workspace view gains a Capabilities table (Capability | Status | Used
  by, from `oats capabilities --json`, filtered by team and source) and a
  Sources tab. It can run `oats sync` and approve pending packages: the Desktop
  admits an approval only when its (id, version, executables digest) exactly
  match the latest sync report it holds, and refuses a mismatch with
  `E_APPROVAL_STALE`. A picked folder that isn't yet a workspace can be
  onboarded through single-use offers held by the main process. The 0.24
  Deployment inventory and Workspace readiness blocks are removed.
- **Desktop: design parity with Redesign v3 and brand artwork** (#137, #128).
  The Desktop F1 deployment model on kernel JSON (#126) is included too.
- **`oats.aweb` is the workspace messaging default** (#140, human decision).
  The onboarding skill makes messaging setup its own step before the first
  spawn (#141).
- **The onboarding next-step hint names `oats-operator-expert`** (#134).
- **Phase D:**
  - The OATS repository hosts a workspace-model workspace (D2, #127).
  - `oats-operator-expert` and `integrations-expert` souls, with the experts' instructions on the workspace model (D3, #129).
  - `oats.core` and `oats.setup` rewritten for the workspace model (D4, #133).
