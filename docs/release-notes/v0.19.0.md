# OATS v0.19.0

One release built from one tag: `@awebai/oats@0.19.0`,
`@awebai/oats-pi@0.19.0`, and **OATS Desktop 0.19.0** in this GitHub Release.

This release introduces distribution packages, exact OATS-managed instance
curricula, canonical instance homes, and package config profiles.

## Distribution packages

An OATS package is the acquisition, integrity, update, and review unit above
independently targetable capabilities. Git and catalog sources default to the
contained `oats-package/` directory; `#<path>` selects another directory (`#.`
for the repository root), and a local path names the exact package root.

Lock v2 records source, exact commit, selected path, integrity, dependency
closure, exported capabilities, and per-capability executable approvals. Bare
`oats install` restores the exact locked graph; updating is explicit
(`oats update <package-id>`). Acquisition installs and hashes only the selected
payload subtree; root `.git` metadata appearing later inside a managed artifact
is treated as source drift and invalidates trust. See
[Distribution packages](../packages.md).

## Package config profiles

Packages may ship reference `oats-config.yaml` profiles. Adoption is explicit
and writes an editable local snapshot:

```bash
oats init --package <package-source> [--config <profile>] --dir <workspace>
oats install --dir <workspace>
```

Package updates never rewrite an adopted config. Missing host commands and
runtime packages remain a separate consent decision; plans show every ordered
step before anything executes, and spawn verifies required runtime packages but
never installs them.

## Exact instance curriculum and canonical homes

The scoped config cascade determines each soul's complete OATS-managed skill and
instruction set. Missing, untrusted, duplicate, or uncontained active resources
fail closed. Resources are composed into `<instance-home>/.agents/skills/`
(linked from `.claude/skills`) and `AGENTS.md` (linked from `CLAUDE.md`). Pi
suppresses ambient skills, context files, and prompt templates; Claude Code
keeps the operator's native settings, skills, plugins, MCP, hooks, and memory.

Instance homes live under the soul-owning repository's primary checkout, even
when spawn runs from a linked worktree. Every runtime and hook receives the
absolute `OATS_INSTANCE_HOME`; lifecycle commands run in the home, repository
work happens in `<instance-home>/work`.

## Required hooks and runtime requirements

Capability spawn hooks may declare `required: true`; a failing required hook
fails the spawn. If compensation cannot finish, OATS keeps a quarantine that
`oats retire` retries before deleting the home (`--force` remains available).
Requirement consent supports runtime-scoped Pi packages and Claude plugins.

## Compatibility with 0.18 installations

Existing v1 locks, installed official capabilities, activation, and trust keep
working; no migration is forced. `oats migrate --official --recursive
[--dry-run] --dir <team-root>` is included but held in this release because the
official package catalog was not yet published; `oats doctor` explains that the
legacy capabilities remain supported.

## OATS Desktop

Desktop accepts CLI versions `>=0.18.0 <0.20.0` (Desktop CLI API v1). It also
includes cluster-aware agent navigation, persistent terminal groups, Quick Open
for souls, runtime-scoped model suggestions, and improved spawn readiness
handoff.

Installers: macOS arm64 and x64 (DMG + ZIP), Linux x64 (AppImage + DEB). macOS
builds are ad-hoc signed, not notarized; first launch may need right-click →
**Open**. Verify assets with `SHA256SUMS.txt` and the build-provenance
attestations. Windows and Linux arm64 are not supported.

## Install or update

```bash
npm install -g @awebai/oats@0.19.0
pi install npm:@awebai/oats-pi@0.19.0
```

Keep the kernel, Pi adapter, and Desktop on matching versions.
