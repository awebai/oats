# OATS 0.51.0

Unreleased

## Added

- **`oats session attach --detach-key <key>`: a key that leaves the viewer
  (#856).** A viewer sets no tmux prefix and a locked key table, so every key
  reaches the agent and nothing on the keyboard leaves it. A caller may now
  name one key that detaches its own viewer, on the local form and with
  `--server`. The agent's window and every other viewer are untouched, and
  the agent never receives that key while this viewer is attached. Nothing
  changes for a caller that names none: a plain attach still has no keyboard
  exit, the tmux prefix included, and is left by closing the terminal.
  - **The key** is `C-` with a letter other than `h`, `i` and `m` or one of
    `\ ] ^ _`, `M-` with a lowercase letter or a digit, or `F1` to `F12` with
    at most one of `C-`, `M-`, `S-`. Anything else is `E_BAD_ARGS` before any
    tmux or ssh call. The suggested key is `C-\`, written `--detach-key
    'C-\'`; `F12` where `\` needs AltGr.
  - **Exit status 20** when the viewer was left by the key. 0 (the viewer
    ended without the key) and 1 (a refusal, or tmux failing under the
    viewer) are unchanged, and so is ssh's own 255 on the routed form. 20 is
    nonzero, so `set -e`, an `&&` chain and tmux's `remain-on-exit failed`
    treat a leave by the key as a failure.
  - **While the pane is scrolled back**, tmux's copy mode reads its own key
    table first: a key copy mode binds (`C-e`, for example) detaches only
    once the mode is left. `C-\` and `F12` are unbound in tmux's default
    copy-mode tables (3.7c) and detach from there.
  - **Feature `session-attach-detach-key`** in `oats version --json`, and so
    in `oats status --json` and each `oats server roster --json` group's
    `probe.features`. Gate on it and never try: a kernel without the feature
    ignores the flag and opens a viewer with no exit. A routed attach sends
    the flag only to a host that advertises the feature, and probes for it
    under `--print` too. A host without it is refused here with
    `E_REMOTE_INCOMPATIBLE`, exit 1, nothing else sent; its `details` are
    `{"feature":"session-attach-detach-key"}`.

  See [Inspect, input and
  attach](../execution-targets.md#inspect-input-and-attach) and
  [servers.md](../servers.md#run-there).

## Fixed

- **Retire: one retire of an instance at a time (#863).** Two `oats retire`
  of the same instance, started moments apart from two sessions, both ran to
  completion: two recovery copies, and every capability's retire hook ran
  twice, at the same time. A retire hook releases things that exist once (a
  messaging identity, a scheduled job). A retire now holds the instance's
  claim from the moment it has resolved the home until it ends, and any other
  retire of that instance is refused at once with `E_LIFECYCLE_BUSY` (exit 1),
  before it stops a session or a child, writes a recovery, runs a hook or
  changes a file of the home: `a retire of <name> is already running (pid
  <pid>, since <at>); nothing was done — wait for it to finish`. This holds
  for a plain retire, a guarded apply with any idempotency key, `--self` and
  its detached completion, and `--server`; `--force` does not bypass it, and
  `--plan` is unchanged. `details` is `{instance, home, lock, pid, since}`.
  - **A scheduled `--self` counts.** From the moment a self-retire is
    scheduled until its completion has ended, every other retire of the
    instance is refused the same way (`a retire of <name> is already
    scheduled …`, `details.lock` the pending marker). The marker
    `.oats-retire-pending-<instance>.json` now records the completion process
    (`completionPid`, `completionStart`). A completion that failed or died
    refuses nothing: `oats retire <instance>` retries it, as before. A second
    `--self` still answers `alreadyScheduled: true`.
  - **The claim file** is
    `<agents>/<agent>/instances/.oats-retirement/claims/<instance>.lock`,
    beside the homes, and names its holder by pid and start time. A retire
    that ends leaves none. A retire that was killed leaves its file until
    that name is retired again: the next retire takes the claim over, because
    its holder is verifiably gone. The file is safe to remove by hand once
    its pid is gone.
  - **A host that cannot read a process's start time** (no `/proc`, and `ps`
    failing): a retire could not hold its claim verifiably there, so it is
    now refused with `E_LIFECYCLE_BUSY`, and the message says what could not
    be read. Likewise a claim or a pending marker whose holder's start cannot
    be read is never taken for gone: the refusal names the pid, the file and
    the way out (check that pid by hand; if it is not an `oats retire`,
    remove the file, then retry).
  - **One changed answer.** `--self --keep-dir` runs the retire in the
    calling process, so it is refused while a `--self` completion is pending.
    On a home opened in Herdr (removed in 0.31.0), where `--self --keep-dir`
    is deferred like a plain `--self`, a second one inside that window
    therefore answers `E_LIFECYCLE_BUSY` where it answered
    `alreadyScheduled: true`.

  The claim orders retires only: `oats instance stop`, `oats session start`
  and `oats worktree add` against a retire in flight are unchanged (#866). See
  [Retire](../desktop-cli-api.md#retire).
