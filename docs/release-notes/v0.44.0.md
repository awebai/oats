# OATS 0.44.0

## Changed

- **A team label is at most 64 characters**
  ([#726](https://github.com/awebai/oats/issues/726)). Both
  `oats-workspace.yaml` and `oats-local.yaml` now refuse a longer label. The
  refusal is `E_WORKSPACE_SCHEMA`, and the message names the label and the
  64-character limit. `oats teams add` and a trigger's `spawn.teams` apply
  the same bound.
  - **Who this breaks:** a workspace or deployment with a label over 64
    characters. The Desktop could never show such a label: it refused the
    whole readiness answer.
  - **What to do:** shorten the label, in `teams:`, `defaultTeam:` and
    `souls:`.

  See [Teams](../desktop-cli-api.md#teams).

## Fixed

- **Readiness clips long item text**
  ([#725](https://github.com/awebai/oats/issues/725)). An item's `reason`,
  `remedy` and kernel `problems[].message` are at most 1000 characters,
  clipped with `…`. Before, a long remote error made the Desktop refuse the
  whole readiness answer. One example is the workspace discovery error in
  the member and package-soul items. A provider's own `result` is still
  relayed verbatim.
