# OATS v0.22.17

Two corrections found by installed acceptance of 0.22.16, nothing else.

## oats.okf 1.6.1

A provider view larger than one pipe buffer arrived cut at 65536 bytes
with exit 0 when the kernel's operation runner or a Desktop read it: the
provider wrote its envelope and exited at once, and on macOS Node writes
to a pipe asynchronously. Every answer now leaves the provider whole
before it exits. The catalog pins v1.6.1; scopes on 1.6.0 keep working
for small views until their owners run
`oats update oats.okf --to v1.6.1 --dir <scope>` and re-trust. The
kernel's runner is unchanged; the regression covers a 128 KiB view
through an actual pipe, directly and through `oats operation run`, and a
300 KiB view from any provider.

## Desktop

Workspaces added at runtime survive an app restart: the opened set is
persisted on its own (not the recent-suggestion store), restored and
re-validated at startup with absent paths skipped and aliases collapsed,
and a backend is reused only when it covers every restored workspace. A
failed persistence write keeps the previous set and reports the failed
add.
