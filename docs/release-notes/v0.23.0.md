# OATS v0.23.0

This kernel release adds generic directory work and more reliable record
capture, the prerequisites for capability-owned external knowledge. It does
**not** migrate existing knowledge or select a new knowledge integration. The
bundled `oats.okf` and official catalog pin remain **1.6.1**.

## Independent directory work

`work: directory` creates an instance-owned ordinary `work/` directory. It does
not require a Git repository, branch, worktree, or fabricated commit. Existing
Git work modes retain their semantics. A capability can use directory workers
for non-Git knowledge custody without making its storage model a kernel policy.

Directory lifecycle checks reject a replaced, missing or symlinked work root
before launch, and preserve retryable cleanup obligations when compensation
cannot finish. Hooks receive the running kernel's CLI path. Generic scheduled
commands no longer inherit another instance's source identity.

## Evidence capture and recall

Record capture distinguishes completed work from skipped, held, incomplete and
failed attempts. Capture verifies attributed native transcript identity,
honors native storage roots and recorded launch environments, and includes
supported nested Claude subagent transcripts. Uncertain discovery, unreadable
or replaced sources, incomplete tails and lock failures are not certified as
complete evidence. Large piped recall responses drain stdout before exiting.
Managed starts now preserve independent, execution-time native record-location
history, so a later observer's environment cannot silently redirect capture.
History survives retirement and is not a knowledge bundle. Older or standalone
sessions without that authority fail closed on `capture --home`; an operator
can explicitly use `oats capture --current-roots --home <home>` to inventory the
currently configured roots, but that does not certify all historical locations.

These are evidence-preservation guarantees, not a claim that a model has learned
from the captured records.

## Optional knowledge-theory authoring resources

`oats.knowledge-theory` 1.0.0 is an optional **Git-distributed OATS package**
in this repository's self-contained `oats-package/` subtree. It exports
`knowledge-theory-expert` and the `knowledge-capability-authoring` skill with
the complete local reference curriculum. The kernel npm tarball ships public
docs and the CLI, but **excludes** this optional payload entirely. npm omits
symlinks; a partial copy without the canonical source alias is not a supported
package. Acquisition does not synthesize aliases or relax integrity semantics.

Acquire it through the normal Git package route and explicitly opt in for an
author soul:

```bash
oats install git:github.com/awebai/oats@v0.23.0 --dir /path/to/scope
oats use oats.knowledge-theory --soul <author-soul> --dir /path/to/scope
```

The default Git package root is `oats-package/`; acquisition locks the resolved
commit and alone activates nothing. This release has no catalog pin for the
package.

The package has no knowledge-layer binding, mandatory injection, runtime hook,
command or dependency on OKF. Authors may adopt, adapt or replace the reference
model. Each selected knowledge capability owns its runtime, reader/capture,
judgment and delivery instructions. No framework ACL layer is added.

Canonical references are published under
[the authoring guide](../knowledge-capability-authoring.md) and
[the reference model](../knowledge-reference/model.md), with byte-identical
copies in the Git-packaged skill. Installed instances read those local copies,
not a source checkout or mutable network documentation. Git transport preserves
the tracked source `CLAUDE.md -> AGENTS.md`; generated instances receive their
own canonical alias through the unchanged normal composition path.

## Packaging and compatibility

Kernel, Pi adapter and Desktop versions are aligned at 0.23.0, including both
lockfiles. Desktop still uses CLI API v1; its accepted kernel band is widened
to `>=0.22.0 <0.24.0`, retaining support for released 0.22.x kernels.
