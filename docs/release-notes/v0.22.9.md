# OATS v0.22.9

A stopped instance can be started again in its existing home, from the CLI
and from Desktop, with the model chosen at that moment; Desktop's running
status and terminal attachment follow each instance's saved tmux socket.

## Start a stopped instance in its existing home

`oats session start --home <absolute-home> [--model <id>] [--json]` runs the
instance's persisted launch command again in the same home: same identity,
worktree, notes and launch environment, no spawn hooks, no new home. The
command runs in the recorded tmux session on the recorded socket, or on the
recorded Herdr server. A fallback shell with no harness descendant and a dead
pane restart in that exact pane; a missing window opens again; a tmux server
lost to a reboot is recreated on the recorded socket path. A live harness is
refused (`E_SESSION_RUNNING`), a state that cannot be established is refused
(`E_SESSION_UNKNOWN`, including permission failures, which are not treated as
absence), and a quarantined home or one whose self-retirement is in progress
is refused (`E_INSTANCE_RETIRING`). Nothing is started by any refusal.

`--model` replaces the recorded model for this and later starts. The kernel
re-renders the persisted command through a parser of the exact shapes spawn
generates; an existing `--model` value is replaced in place, otherwise the
pair is inserted after the harness binary, and every other token, including
capability launch environment and arguments, is kept byte for byte. A command
OATS did not generate, a duplicate or valueless `--model`, or a preference
whose provider prefix is incompatible with the recorded runtime is refused
rather than rewritten or silently defaulted. A runtime model id is passed
through to the harness as given; the kernel does not validate it against a
catalog. Omitting the model keeps the recorded one.

The start opens a new harness conversation from the instance's saved briefing
(`TASK.md`) and the instance resumes from its own `STATE.md`, as its
knowledge protocol prescribes. It is not a native conversation resume.

## Recovery and the duplicate guard

Every observation a start makes happens under a per-home lock, so two starts
of one home (a double click, two clients) serialize instead of both seeing
"stopped" and allocating twice (`E_SESSION_START_BUSY`). The independent
lifecycle receipt and the instance metadata are updated in that order, the
receipt keeping its home and work fingerprints so a later retire still
preserves everything changed since the original spawn.

A per-launch receipt carrying a launch id and the actual target is written
before the harness is launched (a Herdr start allocates its empty pane first)
and is retained for the launch's lifetime, including after the metadata is
recorded. The command wrapper writes a matching exit marker only when the
saved command returns, so a start that observes only shells without that
marker sees a launch still starting up, or a transient child such as the
briefing being read, and refuses rather than mistaking it for a fallback
shell; no background watcher or polling is involved. A start that launched
but could not record its metadata leaves the receipt in place, and the next
start reconciles it before the ordinary metadata check: a present target is
recorded and adopted, an exited one is reconciled and restarted, and an
unobservable target refuses and keeps the receipt. Recovery is idempotent
through the launch id recorded in the metadata, so an attempt already
recorded is not counted again. Every field of the receipt, the command, the
model, the id, the timestamp and the target, is validated before any
authority or metadata is touched; a malformed receipt refuses and is kept
unchanged. A running adopted target never has a newly requested model applied
silently; that start is refused and says so.

## Desktop: start with model choice, and saved-socket status

A stopped instance's sidebar row and hierarchy popover offer Start, which
opens a same-home dialog showing the existing runtime, host and home, with an
optional model (blank keeps the recorded one). The dialog re-checks status
before submitting, converts a running instance to Open terminal, and blocks
explicitly on an unknown state, an old CLI or a remote without a route. It
calls only the kernel command above and waits for the roster to show the
instance before opening its saved terminal target. When the launch returns
but the harness is not observed running, the dialog says the instance may
have exited and offers a status refresh before any retry, instead of
assuming the roster is merely late.

Status now reads each instance's saved tmux socket, session and window, and
sees a harness running under its launcher shell; a dead pane or fallback
shell is stopped and an observation error is unknown, never a guess. The
terminal transport carries that saved socket end to end (preflight, viewer,
PTY attachment, resource identity and cleanup), so two instances with the
same window name on different sockets are distinct and input never lands in
the wrong one. Viewer sessions left behind by a crash are reclaimed on the
default server at startup and on each saved socket when a terminal is next
opened there.

## Remote hosts

`oats session start --server <id> (--instance <name> | --home <abs>)
[--model <id>]` routes over the saved route and runs the same command on the
execution host. The kernel's version probe advertises `session-start` in its
features and remote lists; the local side reads the server's version probe
and refuses before the remote start, so nothing is mutated on a host whose
kernel does not advertise it. A remote host needs this release installed
there first.

## Limitation

A never-launched legacy Herdr home has no saved server endpoint; starting it
refuses with that reason and does not fall back to tmux.
