# OATS v0.22.9

A stopped agent can be started again in the home it already has, from the
Desktop app or the CLI, optionally on a different model. Its terminal status
and its terminal itself now follow the tmux socket each instance was launched
on, instead of assuming the default one.

## Start a stopped instance in its existing home

    oats session start --home <absolute-home> [--model <model>] [--json]

The instance keeps its home, its identity, its work tree and its notes. No new
home is scaffolded, no spawn hook runs, and nothing about the identity is
touched: the persisted launch command is simply executed again, in the tmux
session and window the instance already records, on the socket it records, or
on its Herdr server.

**This is a new conversation, not a resumed one.** The harness starts fresh and
reads the instance's saved briefing and state, the same way it did at spawn.
Nothing restores the previous transcript, and no runtime's native
conversation-resume is involved.

What counts as stopped is now decided by what is actually running rather than
by whether a pane exists. A window whose harness has exited, leaving a fallback
shell, is stopped and can be started in that same pane; so is a dead pane, and
so is a machine whose tmux server is gone after a reboot, where the server is
recreated on the same socket path. A live harness refuses with the instance
named. A state that cannot be established refuses too, and says why: an
unreadable status is not an absence, and starting on that assumption is how two
harnesses end up in one home.

## Choosing a model for the next start

`--model` applies to this launch and is recorded, so it persists for later
starts. Omitting it, or leaving the Desktop field blank, keeps whatever the
instance already records.

The model is placed by re-rendering the persisted launch command rather than by
editing its text: the command is parsed into the exact token grammar OATS
writes at spawn, the model option is replaced or inserted immediately after the
binary, and every other token is re-emitted byte for byte, so capability
environment variables, launch flags and the task prompt expression are
untouched. A command that does not match that grammar is refused, with the
offset, instead of being rewritten by guesswork. A model the recorded runtime
cannot use is refused before anything starts.

## Terminal status and attachment follow the saved socket

Instances launched on their own tmux socket, which is every instance an OATS
deployment spawns with a non-default session, previously reported as stopped in
Desktop because the roster only ever asked the default tmux server. They now
report correctly, and the terminal you open attaches through that same saved
socket: the preflight, the viewer session, the linked window, the attached
process and the cleanup all address it. Terminals are also identified by
socket, so two instances with the same session and window name on different
sockets are two different terminals and can no longer be confused for one
another.

## Recovery, and one start at a time

A start that allocated a session but failed before recording it leaves a
receipt naming the session it really created. The next start reconciles that
receipt before anything else, adopts the session rather than allocating a
second one, and refuses if the recorded session cannot be observed, keeping the
receipt rather than discarding the only evidence of it.

Concurrent starts of the same home are refused: the whole operation, including
every observation it acts on, happens under a per-home lock, so two clicks or
two clients cannot both conclude that an instance is stopped. A home whose
retirement is still running is refused as well, rather than being relaunched
into a teardown that is about to remove it.

## Remote instances

The same start works over a saved server route with `--server <id>`. The host
must be running a kernel that advertises the `session-start` feature; Desktop
and the CLI check that first and refuse with an explicit message rather than
failing at the end of the operation.

## Known limitation

An instance created with `--no-launch` on a Herdr backend has no saved server
endpoint, so there is nothing to start it on. That case is refused explicitly
and is not silently started on tmux instead.
