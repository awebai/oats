# OATS 0.37.0

## Added

- **The Desktop opens one window per workspace** (awebai/oats#481). Each
  workspace has at most one window, titled with its name (a workspace on a
  server: `name — server`). Choosing a workspace in the switcher shows it in the
  current window, or brings its own window to the front when it has one.
  Each workspace in the switcher has an **Open in new window** button
  (keyboard: Right Arrow then Enter, or ⌘Enter / Ctrl+Enter). On macOS,
  **File → New Window** (⌘⇧N) opens a window with no workspace that asks you
  to choose one, and ⌘\` cycles the windows; on Linux and Windows the command
  palette has **Window: new window**, with no default chord. Quitting and
  relaunching brings every window back with its size and place; a window
  whose workspace isn't served at launch stays remembered until you close it
  while it is served. Launching the app again with `--dir <deployment>`
  brings that deployment's window to the front, adding the deployment if
  needed. An unfocused window re-reads its instance list at the server's
  blurred cadence (30 s). A window's requests always carry its own
  workspace: one the server doesn't serve is refused with
  `E_WORKSPACE_NOT_SERVED`, never answered with another workspace's data.
  Window positions are kept in `windows.json` in the app's data folder.

## Fixed

- **Launch hooks no longer have side effects under a preview, or before a
  start's preflight has passed** (awebai/oats#500). A launch hook may register
  a home with its provider; oats.aweb's registers it with the host wake
  broker. But `oats launch-config preview`, which Desktop's start dialog
  calls for running homes, ran every hook for real. A start refused by
  preflight, including a start of a home that was already running, had also
  run them. Previewing a running Claude home with another harness could
  therefore change how that live session is woken.

  Launch hooks now run twice per start. The first run is a preview, with
  `OATS_LAUNCH_PREVIEW=1` in the hook environment (a new, additive hook
  environment variable), and its contribution drives the preflight and the
  rendered command. The real run, without the flag, comes only once every
  check has passed, and before a restart stops the running harness. A
  preview runs only the first pass. A hook must change nothing under the
  flag and return the same contribution either way. If the real run's
  contribution differs, the start is refused with `E_LAUNCH_PREPARATION`
  and nothing is stopped or started. The kernel never passes on an
  `OATS_LAUNCH_PREVIEW` inherited from the environment.

  **Provider authors:** honour `OATS_LAUNCH_PREVIEW`, and expect your launch
  hook to run twice per start (docs/capabilities.md). oats.aweb 1.18.1 does.
