# OATS 0.60.0

2026-10-16

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says: a 0.59 Desktop refuses a 0.60.0 CLI. The
  0.60.0 Desktop accepts OATS CLIs `>=0.26.0 <0.61.0`.

- **`running` in a status row now means the harness is running**
  ([#364](https://github.com/awebai/oats/issues/364)). A window left at its
  fallback shell after Stop reads `running: false`, `runtimeState: "shell"`;
  before, it read `true` because the window existed. A script or tool that
  reads `oats status --json` to see whether an agent is running now gets the
  answer the lifecycle commands give. See Changed.

- **The official catalog moves two pins:** oats.framework 1.12.2 → 1.12.3
  and oats.aweb 1.28.0 → 1.29.0 (see Provider updates). The other packages
  are unchanged. A deployment takes them by changing its pins and running
  `oats sync`. Only new spawns use them.

## Added

- **`oats tui` lists the open workspace's capabilities**
  ([#855](https://github.com/awebai/oats/issues/855)). `3`, or the leader
  then `3`, shows the Capabilities view, which until now was a placeholder:
  the capabilities in the OATS Desktop's sections (Workspace owned, Repo
  owned, Packages), grouped by repository or package, each with its layer.
  The detail beside it says what the capability is, where it comes from,
  the skills, commands and hooks it provides, and the souls that use it,
  each with how many of its instances here carry it and how many of those
  are on an older version. In the detail, `Up`/`Down` mark a soul and
  `Enter` shows it in the Souls view. The list is the Desktop's, read with
  `oats capabilities` only once the view is first shown, and again only
  when the workspace changes, or with `r`. The palette lists the
  capabilities once they are read. See
  [the TUI page](../tui.md#the-capabilities-view).

## Changed

- **`oats status` reports whether the harness is running**
  ([#364](https://github.com/awebai/oats/issues/364)). After Stop leaves a
  fallback shell, the row reads `running: false` with `runtimeState: "shell"`,
  even though its tmux window remains. A live harness remains running, and an
  unreadable session remains unknown. Pane reads are batched per socket and
  session.

- **OATS Desktop accepts an `oats` CLI 0.60.x.** Its band is now
  `>=0.26.0 <0.61.0`. 0.60 adds no new gate on the band: a status row's
  `running: false` with `runtimeState: "shell"` for a window at its fallback
  shell is what the Desktop's own terminal probe already reports for a local
  row, and a server's rows now read the same way.

- **`oats tui` polish** ([#855](https://github.com/awebai/oats/issues/855)).
  The footer names `[/] tab` while two tabs or more are open. The help's
  Marks section lists the soul mark `■` (`#` in ASCII) and a refused soul's
  `!`. A split one above the other joins the list's bar with `├` (`+` in
  ASCII).

## Fixed

- **`r` in the `oats tui` Souls view keeps the souls when the read fails**
  ([#1301](https://github.com/awebai/oats/issues/1301)). In 0.59.0, `r`
  forgot the souls before reading them again, so a read that failed left
  only the failure. Now the souls stay listed while `r` reads, and a read
  that fails keeps them under a heading that says it failed, as the
  Capabilities view does. See [the TUI page](../tui.md#the-souls-view).

- **`oats tui`: a package soul's instances are its own in the Souls view**
  ([#855](https://github.com/awebai/oats/issues/855)). In 0.59.0 the Souls
  view counted no instances for a soul that comes from a package, and `i`
  on it listed none: the view did not match the name its instances carry,
  `<package>--<soul>`. Its row now counts its instances on this machine,
  `i` lists them in the Instances view, and its detail names them. See
  [the TUI page](../tui.md#the-souls-view).

## Provider updates

- **oats.framework 1.12.3, oats.core 2.6.3: `/oats-operate` says what
  `running` means** ([#364](https://github.com/awebai/oats/issues/364)).
  From OATS 0.60.0, a status row's `running` is the harness's liveness: a
  window left at its fallback shell after Stop reads `running: false`,
  `runtimeState: "shell"`. The skill dates the rule, since an older kernel
  still reports such a window as running. Instruction text only; the floors
  are unchanged. A deployment gets it by pinning `oats.framework: v1.12.3`
  and running `oats sync`.

- **oats.aweb 1.29.0: the agent status publisher.** The catalog and this
  workspace pin `oats.aweb: v1.29.0`.
  - `oats aweb health enable | status | disable | publish` publishes, once a
    minute, a signed status for every agent of the deployment to aweb:
    whether it can be reached (`yes`, `degraded`, `no` or `unknown`), why
    not, and who fixes it. It is opt-in and host-only
    (`settings.oats.aweb.health` in `oats-local.yaml`), runs in the
    deployment directory, never inside an instance, and needs aw 1.36.38 to
    publish (checked before anything is sent). `disable` clears every
    designation it made.
  - `/oats-aweb`: on macOS, `oats aweb wake install` runs from the desktop
    login, not over ssh.
  - The floors are unchanged (OATS >=0.52.0, aw >=1.36.33). A deployment
    gets it by pinning `oats.aweb: v1.29.0` and running `oats sync`; only
    new spawns use it. The provider's reference is its
    `docs/health-publisher.md`.
