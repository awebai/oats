# OATS 0.33.0

## Added

- **`oats spawn <soul> --preview --max-age <seconds>`** (feature
  `spawn-preview-max-age`). A preview reuses member heads this machine
  observed at most that many seconds ago, as the read verbs do since 0.32.0,
  so a warm preview asks no remote. With the flag the preview's JSON carries
  the read verbs' `observation {observedAt, reused, localRevision}` block;
  without it the preview is unchanged. The decision still covers the heads
  the preview used: an apply with `--expect-decision` observes live and
  refuses `E_DECISION_STALE` when a reused head has moved, and a re-preview
  then shows the new head. The apply refuses `--max-age` (`E_BAD_ARGS`), and
  the refusal message of every form that refuses the flag now lists
  `spawn --preview` among the read forms.

## Changed

- **OATS fetches only what it reads from a remote** (awebai/oats#384). A
  commit comes with its trees and its files up to 64 KiB; a larger file is
  fetched when a read or a module needs it. The first spawn from a large
  workspace host downloads megabytes instead of its whole tree (tsm: 13 MB in
  3 s, instead of 2.4 GB in 6.5 minutes). A server that cannot serve partial
  fetches (a default `git daemon`, an old self-hosted git), or a local git
  older than 2.45, gets whole trees as before, with one `oats: warning` per
  repository.

- **oats.engineering 1.4.0** (catalog and workspace pin, and the bundled
  mirrors): the developer's loop REQUIRES loading `/understand-the-spec` and
  `/execution-strategy` before implementation.

- **oats.aweb 1.17.5** (catalog and workspace pin, and the bundled mirror;
  1.17.4 and 1.17.5): a faster spawn and retire. The spawn hook mints the identity with one
  `aw init --join-from` instead of `aw team invite` + `aw team join` +
  `aw init`, so the invite token no longer appears in any argv. The aw floor
  check stops at `aw version`'s version line instead of waiting on its GitHub
  update check. Retire deletes by workspace id, with `aw wake deregister`
  running at the same time. Measured spawn hook: 7.72 s to 4.62 s mean
  (awebai/oats-aweb#31). Hook output, compensation and the aw floor (1.36.13)
  are unchanged. The mint now has one 120 s budget where three calls had
  about 210 s; raise `OATS_AWEB_JOIN_TIMEOUT_MS` on a slow network. Since the
  hook no longer holds the invite token, 1.17.5 always records the alias it
  requested and warns, without quoting the reply, when aw reports another
  (awebai/oats-aweb#32).

- **Pressing Spawn (Cmd-Enter) closes the spawn dialog at once.** The spawn
  completes in the background: a pending row ("Spawning…") appears in the
  sidebar roster where the instance will stand, and is replaced in place by
  the real row once the roster reports it. Outcomes arrive as notifications:
  "<name> spawned" with Open, what didn't finish for a partial or incomplete
  spawn (with View schedules for a wake that wasn't saved), and, for a
  refused or failed spawn, the reason with **Reopen spawn**, which restores
  the whole draft. An unknown outcome keeps the row, reading "Outcome
  unknown", with Check result. Prepare reuses the dialog's fresh preview
  instead of reading it again, and the kernel's `--expect-decision` still
  refuses a decision that changed. Dialog previews use `--max-age 60` when the
  CLI supports it (feature `spawn-preview-max-age`)
  ([desktop-spawn-preview.md](../../packages/desktop/docs/desktop-spawn-preview.md#background-spawn-the-dialog-closes-on-spawn)).

- **The spawn dialog never waits on the preview while you edit.** The last
  preview stays visible while it updates, Spawn stays pressable, and answers
  are reused for 60 s (#378).

- **Core capabilities and Capabilities read as one system** on the soul page,
  the capability page, the instance inspector and the spawn preview. Every
  core row says why it's there, including a slot the soul empties or that has
  no default. The capability page opened from a soul gains a "Why" row.
  Workspace › Capabilities lists Repo owned before Packages (#377).

- **The Desktop accepts OATS CLIs `>=0.25.8 <0.34.0`**, so it runs against
  this release's kernel. Install the CLI and the Desktop 0.33.0 together: the
  Desktop 0.32.x refuses a 0.33 CLI.

- **Unattended claude and codex launches** (awebai/oats#341,
  [souls-and-instances.md](../souls-and-instances.md#unattended-launches-folder-trust)).
  - Every codex launch passes `-c check_for_update_on_startup=false`, so
    Codex's update prompt no longer blocks it.
  - Codex does not apply a trusted parent to the folders below it. When
    `~/.codex/config.toml` trusts the deployment or an ancestor, a codex
    launch now trusts its new home for that session; the file is never
    written.
  - A claude or codex spawn whose home is not covered by the operator's
    one-time trust of the deployment warns `the <harness> session will stop
    at its folder-trust prompt: trust <deployment> once (…)`. `oats readiness`
    reports the same as a `harness-trust` item in `checks.configured` (not
    required).

## Fixed

- **Codex sessions see their instance** (awebai/oats#342). Codex can run tool
  commands under its shared app-server daemon, without the session's
  environment, so `oats aweb roster` inside Codex asked for `--soul`.
  - A codex launch now sets the instance environment for tool commands with
    `shell_environment_policy.set`: `OATS_INSTANCE`/`OATS_INSTANCE_HOME`, the
    capabilities' launch environment (`AWEB_IDENTITY_HOME`, `AWEB_DELIVERY`)
    and the launch configuration's literals.
  - It also sets `PATH` with the home's `.oats/bin` first. The user's login
    shell may put its profile's entries ahead of it.
  - A capability command with no home in its environment finds the home from
    its working directory.

- The partial-fetch tests now pass on a host whose git is older than 2.45
  (awebai/oats#389). The kernel already fell back to whole trees there; the
  tests now read the kernel's own git probe:
  - on an older git they assert that fallback (whole trees, one warning per
    repository);
  - they skip the partial-cache mechanics that cannot happen there, and name
    why;
  - under CI, an older git fails those tests instead.

- **A killed fetch no longer leaves a remote cache unusable** (awebai/oats#386).
  OATS ends git with SIGTERM first, so git removes its own lock files, and
  SIGKILL only after a grace. A lock left by a git killed earlier is removed
  once it is older than the longest fetch, with an `oats: warning` naming it.
  A younger one is never removed: the error names the file and says it is
  safe to remove once no oats or git process is running.

- **Processes making the first fetch from one remote at once all succeed**
  (two spawns, two Desktop previews). Every write to a cache takes a
  per-cache lock: a live holder is waited for, a dead one's lock is reclaimed,
  and the cache repo appears whole. A failure to write the local cache is now
  reported as `E_REMOTE_UNREADABLE` with the new reason `cache`, never as
  `network`.

- Fetching a commit into the remote cache may take 10 minutes instead of 30 s, so
  the first spawn from a large workspace host no longer fails with `cannot read
  remote … (timeout)`; the timeout error names the fetch and the elapsed time
  (awebai/oats#362).
