# OATS 0.44.2

## Added

- **`oats souls` rows say what each soul composes.** Each row of
  `oats souls --json` carries `capabilities`: the capabilities its
  resolution composes, keyed like `oats capabilities` rows (`name`, `kind`,
  `repoKey` or `package`), each with `from` (`soul` or `workspace`). A soul
  that does not resolve has `null`. The Desktop uses it to say which souls
  use a capability, including ones no live instance carries. Feature
  `souls-capabilities`; `soulsApi` is unchanged. See
  [`oats capabilities` and `oats souls`](../desktop-cli-api.md#oats-capabilities---dir---json--capabilitiesapi-1--oats-souls---dir---json--soulsapi-1).

## Fixed

- **An operator soul may empty its knowledge and tasks slots.** Operator
  coverage (readiness and doctor) excluded a soul that composes `oats.setup`
  when it emptied any slot the workspace fills, so a setup soul with
  `knowledge: none` or `tasks: none` left permanent warnings: its teams
  uncovered, and `operator-soul-missing` naming it ("not usable here: …
  slot-none") when it was the only one. Only `messaging: none` now excludes
  it, so an operator stays reachable. The items' shape and codes are
  unchanged. See
  [Operator coverage items](../desktop-cli-api.md#operator-coverage-items).
