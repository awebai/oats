# OATS 0.34.3

## Fixed

- **A capture that is killed no longer blocks every later capture**
  (awebai/oats#437). A capture pass killed mid-pass (a hook timeout, or
  okf's 60 s bound) left the record root's capture lock behind, and every
  later `oats capture` skipped. Retires that needed a final capture then
  failed. Now:
  - the next pass reclaims a lock whose recorded owner is dead on this host,
    under a guard, and says so on stderr;
  - a live or unknown owner, an initializing lock and another host's lock
    are never touched;
  - locks written by earlier kernels, which do not record the host, count as
    this host's, so a stale lock already on disk clears on the next pass.
