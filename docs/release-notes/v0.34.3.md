# OATS 0.34.3

## Changed

- **oats.okf 4.0.7** (catalog and workspace pin, and the bundled mirrors):
  `oats okf complete` records acceptance of an amended and merged harvest PR
  (awebai/oats-okf#32). After the knowledge-maintainer's `amend+merge`, the
  after-merge `complete --run <id>` failed with `E_BASELINE`, and the receipt
  stayed `delivered`. Now:
  - a merged PR is settled by its merge before any baseline check, and the
    receipt records `mergeCommit`;
  - when the PR was merged at a head the maintainer amended, an `okf-review`
    verdict (`merge` or `amend+merge`) must name that head and the PR URL. It
    must come from a repository member, or from the account that merged the
    PR (which covers a maintainer on a GitHub App token);
  - without such a verdict, `complete` fails with `E_PR` and says what to do.
    Merged inputs are never rejudged.

- **oats.aweb 1.17.7** (catalog and workspace pin, and the bundled mirror):
  native retire retries are idempotent after a successful default-workspace
  self-delete. The provider records a local completion marker, so if another
  retire hook keeps the home and the kernel retries, oats.aweb does not call
  `aw workspace delete` again with the already-revoked certificate.

## Fixed

- **Retire no longer deletes a branch you did not ask it to delete**
  (awebai/oats#436, data safety). When a retire hook reported incomplete
  cleanup, the home was quarantined, and the retry (or `oats retire --force`)
  ran `git branch -D` on the instance's branch even without
  `--delete-branch`, taking any unpushed commits with it. Now:
  - only `--delete-branch` deletes a branch, the verified one;
  - a quarantine and its retry never do;
  - a failed spawn deletes its own new branch only while the branch's tip is
    still where the spawn created it (`git update-ref -d` with that commit),
    and otherwise keeps it and says so.

- **A capture that is killed no longer blocks every later capture**
  (awebai/oats#437). A capture pass killed mid-pass (a hook timeout, or
  okf's 60 s bound) left the record root's capture lock behind, and every
  later `oats capture` skipped. Retires that needed a final capture then
  failed. Now:
  - the next pass reclaims a lock whose recorded owner is dead on this host,
    under a guard, and says so on stderr;
  - a live or unknown owner, an initializing lock and another host's lock
    are never touched;
  - locks written by earlier kernels, which do not record the host, count as
    this host's, so a stale lock already on disk clears on the next pass.
