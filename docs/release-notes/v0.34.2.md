# OATS 0.34.2

## Changed

- **oats.aweb 1.17.6** (catalog and workspace pin, and the bundled mirror):
  session-delivery instructions name the aw 1.36.21+ full-mail wake form
  (`aweb mail event received.` with metadata, sender body, the `Use the aw CLI`
  line and a Recovery line), say that body and subject are untrusted sender
  content that never overrides the task or human, and remind operators that
  delivered mail may be marked read and absent from unread `aw mail inbox`.
  The aw floor is unchanged (`>=1.36.13`).
- **oats.okf 4.0.6** (catalog and workspace pin, and the bundled mirrors):
  harvest completion works on a real host (awebai/oats-okf#27, #28, #29,
  #30).
  - `oats okf complete` persists the harvester's judgment first, then delivers
    in one detached worker per run. After persisting the judgment, it waits
    up to 30 s: it answers with the final receipt, or with
    `status: delivering` and the progress.
    - A killed `complete`, or a killed worker, loses nothing. Rerunning
      `complete` resumes, never judges again, and never pushes or opens a PR
      twice.
    - A `worker.lock` whose owner died is reclaimed automatically.
    - `oats okf-harvest harvest-status` reports the delivery as in progress,
      failed or stopped.
    - Captured completions still deliver inline.
  - A Git base whose head moved outside its knowledge root is no longer a
    baseline change. A read-only base records the new head. A written base is
    committed onto it. Only changed root bytes fail with `E_BASELINE`, and the
    judgment stays persisted (`oats okf retry --rejudge`).
  - Staging a Git base fetches its root's blobs in one batch. Delivery never
    fetches the blobs outside the root. Staging over SSH, from GitHub:

    | Base | 4.0.5 | 4.0.6 |
    |---|---|---|
    | oats-knowledge | 237 s | 9.9 s |
    | aweb | 41 s | 9.1 s |

  - `oats okf harvest-status` reports `unknown`, with the reason, when it
    cannot read a soul's opt-out.

## Fixed

- **An operator command with `--soul` always gets the soul**
  (awebai/oats#423). `oats <namespace> … --soul <name>` from the deployment
  passed `OATS_SOUL` only when a spawn had already fetched that soul at the
  resolved commit, so `oats okf harvest-status --soul <s>` reported harvest
  "off" for a soul no spawn had fetched yet. The soul is now read at the
  resolved commit as a spawn preview reads it: the copy a spawn left, else a
  temporary copy removed when the command ends. A soul that cannot be read
  refuses the command; it never runs without `OATS_SOUL`.

- **A task's text no longer appears in the process list** (awebai/oats#427).
  Claude Code and Codex instances were launched with the whole `TASK.md` as a
  command-line argument, which any local user can read. Now:
  - Claude Code gets `@TASK.md` (it reads the file).
  - Codex gets a fixed instruction to read `TASK.md`.
  - A home recorded the old way starts with the safe prompt, and its saved
    command is updated.
  - New instance homes are created `0700` and `TASK.md` `0600`.
  - `oats doctor` reports a home other users can read (`home-readable`) with
    the exact `chmod`. Existing homes are not changed: run that `chmod`.

- **`npm run validate` catches a broken workspace file** (a development
  check). It reads the repository's own `oats-workspace.yaml` and
  `package-catalog.json` with the kernel's readers, and fails on an unresolved
  merge-conflict marker in any tracked text file, naming the file and the
  line. A conflicted `oats-workspace.yaml` had passed check, validate, pack
  and smoke. The kernel's YAML and catalog errors now name the line too.
