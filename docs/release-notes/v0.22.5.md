# OATS v0.22.5

A small release: the knowledge package 1.5.1 pin, a way to move a pinned
package lock from the CLI, and the operating records from the first team
rollouts.

## Bundled: oats.okf 1.5.1

`harvest-runtime` chooses the harness that runs the memory harvester (pi,
claude or codex; default pi), so a host authenticated for one harness need
not authenticate another. No harness gets a vendor default: with no
`harvest-model` set, the harvester inherits the harness's own configured
model; `harvest-model` remains the way to pin a cheaper one. The promotion
instructions exclude secrets, credentials and verbatim third-party message
content from promotion. `okf harvest` warns instead of respawning when a
plan's window boundaries did not move since the previous harvester was
spawned.

## Move a pinned package lock

`oats update <package> <package>@<ref>` or `oats update <package> --to <ref>`
moves a catalog-sourced lock to another published ref through the same
transactional update (closure validation, lock replace, approvals
invalidated, then `oats trust`). A plain `oats update <package>` keeps an
explicit selector, as before, and `--to` without a package is refused rather
than falling through to the kernel self-update (`oats update` with no
package).
