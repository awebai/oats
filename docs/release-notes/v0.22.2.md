# OATS v0.22.2

OATS now launches native Codex, supports Herdr alongside tmux, and routes
agent lifecycle commands to registered SSH servers. This release also adds
record-fed harvesting and lets agents finish their own retirement.

## Native runtimes and one permission setting

Choose Pi, Claude Code or Codex when creating or spawning an agent. Codex
uses its native CLI, instructions and skill discovery. Unknown runtimes are
rejected before provisioning.

Set `yolo: true` in a scope's `oats-config.yaml`, override it in a soul, or
use `oats spawn --yolo` / `--no-yolo`. Desktop offers the same launch choice.
Codex receives `--yolo` and a launch-local trust setting for the generated
home; Claude receives `--dangerously-skip-permissions`. Pi is unchanged.
With no setting, OATS leaves native permission policy in place.

## Persistent terminals and SSH execution

Use `--backend tmux|herdr` at spawn. The instance's saved session receipt
identifies its execution; inspect, input, attach and retirement use that
original target. Closing a viewer leaves the agent running.

`oats session inspect|input|attach --home <absolute-home>` provides the
harness-neutral terminal interface. Input sends literal text and Enter;
submission is not proof that the agent processed a message.

Register an existing SSH host with `oats server add`, then use `--server`
on spawn, status, retire and session inspect/attach. Saved routes keep
retirement and attachment available if a registration changes. SSH retains
responsibility for keys and host verification. Desktop includes a server
selector and the remote terminal adapter; remote roster projection remains
a follow-up, so use the CLI to attach to a remote instance in this release.

Live checks covered native Codex launch and subsequent terminal input on
both local backends. A real remote Claude session accepted input through
the Desktop terminal helper, survived viewer closure, and ended its viewer
on retirement. Herdr roster checks include public IDs beyond the ninth
workspace. These checks do not establish reboot recovery.

## Learning and retirement

The official `oats.okf` 1.5.0 capability can feed harvest from an instance's
captured turns even when it wrote no notes. It selects that home's sessions,
reads bounded windows, and advances its watermark over the supplied record.
Notes-based harvesting remains supported. Record commands require Node 22.5
or later on the execution host.

`oats retire --self` records retirement intent and starts detached completion.
Completion stops the runtime before releasing capability resources and
removing the home. Failed cleanup remains visible and recoverable through
status. The roster also stops treating retirement bookkeeping directories
as instances. Retiring an instance whose work tree is large no longer fails with
`git ENOBUFS` during work preservation: every git call on the retirement path
now runs with a buffer far above Node's 1 MiB default (found on a real
~9,500-file tree).

## Package versions and remaining work

The catalog pins `oats.okf` v1.5.0 and `oats.aweb` v1.9.0. The latter updates
native Codex's messaging instructions; its Pi and Claude channel delivery
is unchanged. Native Codex has no automatic aweb delivery in this release.

The aweb host wake broker, session-delivery capability glue, retained-identity
handover and supported standing-seat reboot recovery are still being
completed. Hosted temporary aliases also remain non-reusable until aweb's
certificate-retirement fix ships; use fresh purpose names. A configured
team or successful spawn does not mean its standing agents have migrated.
