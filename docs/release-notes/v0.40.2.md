# OATS 0.40.2

## Added

- **Unconfirmed spawn and operation failures carry structural evidence**
  ([#548](https://github.com/awebai/oats/issues/548)). Incomplete keyed spawns
  and failed spawn compensation set `error.details.unconfirmed: true`; the
  operation wrapper promotes a provider's literal true marker while retaining
  its complete envelope. Completed compensation stays unmarked. Existing
  text fallbacks and scheduler slot/reconcile behavior remain during this
  additive migration; older copied providers are not upgraded by this change.

## Fixed

- **Schedule registry reads are lock-free and do not mutate state**
  ([#579](https://github.com/awebai/oats/issues/579)). Status and other readers
  use coherent atomic-file snapshots, including during registry writes. Legacy
  cap migration is projected in memory and persisted only by locked mutations,
  with a one-slot restoration notice on stderr. Invalid stored schedule caps
  now refuse instead of silently increasing capacity; explicit CLI cap options
  can repair them. Old hand-set and implicit ones cannot be distinguished, nor
  can current kernels identify a one reintroduced by an older writer sharing
  the registry; stop mixed-version writes and explicitly set the desired cap.
  Shared directory locks wait through transient owner publication/removal within
  their retry deadline without stealing locks.
- **OATS Desktop: "Needs input" shows on a remote instance, and a withheld
  note reads as the reason.** Desktop hid every remote claim: a remote roster
  row carries no `runtimeState`, and Desktop read "not reported" as "not
  running" (#582). An unreported state no longer hides the claim; a row
  reported stopped, unreachable or unsupported, or one whose server did not
  answer, still shows none. When a claim's note holds a link or text such as
  `token: …`, Desktop does not show it. The row's description, the terminal
  tab's title and the hover card now show the reason in words, such as "Asked
  you a question", where they showed "[Detail withheld]" (#584). The activity
  view still marks such a note as withheld, and `oats status` prints it in
  full.
- **A remote instance's "needs input" reaches the roster**
  ([#582](https://github.com/awebai/oats/issues/582)). `oats server roster`
  built a remote row from a fixed list of facts and dropped the host's
  `waitingOnYou`. A row now carries it when, and only when, the host's kernel
  reports it: a row from a host before 0.40.0, and a saved route the host did
  not list, have no such key, so "not reported" stays distinct from `null`
  ("no claim"). The value passes the kernel's read rule again on this side;
  anything that is not a claim is `null`. See
  [the remote roster](../desktop-cli-api.md#the-remote-roster-oats-server-roster---json).
- **"Needs input" in a deployment addressed through a symlink**
  ([#583](https://github.com/awebai/oats/issues/583)). A home there has two
  spellings: `oats status --dir <symlink>` addressed it lexically, while a
  started or restarted session carries the real path. Event rows are keyed by
  the home, so the session's claims never showed on status, a restart did not
  void a claim written under the other spelling, and a clear through one
  spelling found nothing. Rows are now stored and matched under the home's
  real path, whichever spelling a writer or reader uses, and both spellings
  use one workspace log, the deployment's own `.agents/events`. Answers keep
  the spelling they were asked in: the `home` in `oats instance events --json`
  (the top-level field and each row's) and in the `oats instance waiting` and
  `oats instance attention` answers is the home as the caller addressed it.
  Deployments not reached through a symlink see no change.

  Rows an earlier kernel wrote under the lexical spelling are not rewritten
  and not matched: after the upgrade they are foreign, counted in
  `integrity.foreignRows`. In a symlinked deployment that means:
  - a claim that was live under the lexical spelling (a session that was
    spawned and never restarted) stops showing. It shows again only when it
    is made anew: at the agent's next permission prompt, question or
    `oats instance attention`. A restart starts a new session with no claim;
  - a claim that stayed set because its restart was recorded under the real
    path is gone, not stuck;
  - the rows a started or restarted session wrote under the real path are
    read now. They cannot show a stale claim: such a session wrote its clears
    and its session boundaries under the real path too.
- **oats.core 2.4.1: the Claude Code emitter no longer speaks for another
  instance** ([#584](https://github.com/awebai/oats/issues/584)). Its hook
  script took the home from `$OATS_INSTANCE_HOME`. A Claude process that
  loaded one home's `.claude/settings.json` while carrying another instance's
  environment (a nested `claude -p`, a `claude -p` started with its working
  directory in another home, a pane that inherited the variables) set and
  cleared that other instance's claim, and its `Stop` and `SessionEnd` clears
  could erase a real one. The launch hook now writes the home's real path
  into each hook command, and the script acts only when `$OATS_INSTANCE_HOME`
  names that home, through any spelling; otherwise it does nothing. Ships in
  oats.framework 1.6.1 (compatibility unchanged; catalog and workspace pin
  `oats-framework/v1.6.1`): a workspace's `oats.framework: v1.6.1` resolves
  to that tag through the official catalog, and a workspace pinned to v1.6.0
  keeps oats.core 2.4.0 until it moves the pin and syncs. A home picks it up
  at its next spawn. See [capabilities](../capabilities.md).
- **A waiting row whose time is not a date is no claim**
  ([#584](https://github.com/awebai/oats/issues/584)). The reader validated a
  stored claim's producer, reason and message but passed its time through.
  And `oats help` lists `[--dir <d>]` for `oats instance waiting`.
- **Catchable scheduler-supervisor shutdown cleans up its owned child group**
  ([#580](https://github.com/awebai/oats/issues/580)). SIGINT, SIGTERM and SIGHUP
  enter the existing bounded TERM/KILL cleanup once, preserving observed child
  exit evidence and treating interrupted envelopes as unconfirmed. The group
  is checked when its leader exits and never signalled again after it is seen
  empty, reducing but not eliminating process-group ID reuse races. Escaped
  sessions and unrecoverable supervisor deaths such as SIGKILL/OOM remain
  outside that cleanup guarantee; no receipt means no proven child exit, so
  the unknown attempt and host slot remain pending reconciliation.
- **Workspace schedule opt-outs and named trust accept 100-character IDs**
  ([#581](https://github.com/awebai/oats/issues/581)). Host configuration now
  accepts the full schedule name limit in `schedules.disabled` and
  `automations.trust`, so enabling/disabling and trusting schedules with
  41–100-character IDs works through the CLI and workspace placement checks.
  Trigger definitions and `triggers.disabled` retain their 40-character limit;
  member syntax, allowed characters and uniqueness rules are unchanged.

## Changed

- **Session input restores single-paste, single-Enter terminal semantics**
  ([#562](https://github.com/awebai/oats/issues/562)). Corrects 0.39.4's
  screen-derived extra Enters and `enter-not-taken` refusal after successful
  terminal commands. Pre-Enter settling remains, with a shared monotonic
  2-second observation budget; at most two read-only post-Enter looks share
  1 second. Each probe and sleep is limited by its remaining budget.
  `submitted: true` reports terminal-operation success; `verified` reports
  display change only, and false never authorizes retry. Neither proves model
  acceptance, pending draft state or absence of effects. Command errors and
  authority checks are unchanged; busy-pane submission, exactly-once delivery
  and generic-error retry uncertainty are not solved by this correction.
