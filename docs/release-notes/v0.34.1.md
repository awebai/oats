# OATS 0.34.1

## Changed

- **Reading a remote's current head takes one round trip instead of two.**
  `oats spawn` (preview and apply) and the read verbs ask each workspace
  member for its head with Git's protocol v0, which returns the whole ref list
  in one request, where protocol v2 takes two. On a 6-member deployment the
  live phase of a spawn preview went from 0.77 s to 0.49 s (median of 5). Tags
  and branches are read as before. If your Git configuration sets
  `protocol.version`, OATS uses it as set. A remote whose ref list is over
  4 MiB is read with protocol v2 from then on (remembered in the remote
  cache). A remote that times out under v0 fails as before and is read with
  v2 for the next 7 days; a read ended by the 12 s budget of `oats status` or
  `oats workspace status` is not counted as the remote's timeout. One that
  fails under v0 for another reason than an
  authentication refusal, a missing repository or the local cache is read
  again with v2. Each case is one `oats: warning`. What a read observes is
  unchanged, and an apply still observes every member live. Known limit: the
  4 MiB bounds what OATS keeps, not what Git downloads, so a remote with a
  larger ref list transfers it once before OATS switches to protocol v2.
- **oats.engineering 1.5.0** (catalog and workspace pin, and the bundled
  mirrors): developers keep each dynamic workflow under 10 agents and ask
  their human for permission first for more. Within the cap they run
  workflows without asking where the harness allows it; where it requires the
  human's opt-in (Claude Code's workflow tool does), they use a standing
  opt-in the human configured, or ask once per task.
- **The `oats-setup-admin` soul has knowledge and is harvested.** It drops
  `oats.developer` and `knowledge: none` and takes the workspace's oats.okf
  knowledge slot, owning the new `oats/oats-setup-admin` node (the judgement
  of administering a workspace's config, never deployment state) and reading
  the operator, expert and kernel nodes. This reverses the 0.29.1 opt-out:
  deployment specifics are kept out of the base at promotion, by the node's
  charter and the reviewed harvest PR, instead of by not harvesting the soul.
  It needs `oats/oats-setup-admin` in the bound `oats` base
  (awebai/oats-knowledge#51); new instances only.
