# OATS 0.63.0

Unreleased

## Upgrade

- **Install the Desktop first and the CLI second,** as
  [Upgrading](../upgrading.md) says: a 0.62 Desktop refuses a 0.63.0 CLI. The
  0.63.0 Desktop accepts OATS CLIs `>=0.26.0 <0.64.0`.

- **The official catalog moves oats.framework 1.13.1 → 1.13.2** (oats.core
  2.6.4, see Provider updates). The other packages are unchanged. A
  deployment takes it by moving its `oats.framework` pin and running
  `oats sync`. Only new spawns use it.

## Added

- `oats session inspect --json` reports `running` on every successful result,
  advertised as `session-inspect-running`. Wherever inspect answers, it is the
  liveness `oats status --json` reports for the row, by the same rule over the
  same pane observation: `true` for a live harness, behind a wrapper shell included, and `false` for
  a fallback shell, an absent or dead pane, a missing home or a home that never
  launched. `state` and its enum are unchanged, and a failed observation is
  still an error, never `false`; that includes a tmux server that is gone,
  which status reads as `running: false` and inspect answers with
  `E_SESSION_UNAVAILABLE`. `running` is activity at the session
  endpoint, not health, readiness, busy or idle, or proof of which executable
  runs. `--server` relays the execution host's answer; an older host's answer
  has no `running`. See
  [inspect, input and attach](../execution-targets.md#inspect-input-and-attach) (#1346).
- `E_RUNTIME_AUTHORITY_MISMATCH` (instance metadata that disagrees with the
  independent session receipt, from a session command or `oats retire`) carries
  `details.fields`: which of `launched`, `tmux.session`, `tmux.window` and
  `tmux.socket` differ, never their values. A missing or invalid receipt is
  still `E_RUNTIME_ENDPOINT_UNKNOWN`, without fields, and every refusal still
  happens before any pane or process is read (#1346).

## Changed

- A retire that refuses because the worktree recovery copy disagrees with the
  source (`E_WORK_PRESERVATION_FAILED`, `worktree recovery verification
  disagreed with the source`) now says where. `details.recoveryDisagreement`
  lists up to 20 escaped relative paths, each with a fixed kind (`missing`,
  `extra`, `type`, `mode`, `link-target`, `file-content`), and the message
  names the first 5. The refusal is still decided by the exact digest
  comparison, and nothing else changes: no hook runs, nothing is deleted and
  the staged copy is removed as before. The report is read afterwards, from
  the source and the copy as they are then, so it is a diagnosis, not a
  verdict. Its search is bounded (entries, bytes read and 5 seconds) and says
  when it stopped early. No content, link target or absolute path is
  reported. See [the retire errors](../desktop-cli-api.md#retire) (#1360).

- **OATS Desktop accepts an `oats` CLI 0.63.x.** Its band is now
  `>=0.26.0 <0.64.0`. 0.63 adds no new gate on the band: the Desktop does
  not read `running` on `session inspect --json` or the mismatch's
  `details.fields`, and it already reads a `launched` event's
  `launchConfig: null` as no configuration (#1367).

## Fixed

- A `session start|restart` that selects the bare harness from a home
  recorded with a named configuration (for example `--launch-config none
  --harness codex` on a home started with a claude configuration) now records
  `launchConfig: null` everywhere. The launch itself, `instance.json` and the
  command's answer already said so. But the session's `launched` event and the
  restart receipt (`.oats-restart.json` `next.launchConfig`) named the earlier
  configuration. So did the `launched` event an adoption records for a start
  whose metadata write failed. Each now takes the name from the recipe the
  start launched, its pending receipt's for an adoption. Only a receipt
  without a recipe still falls back to the recorded one. Selection is
  unchanged: `--launch-config none` is the bare harness, as
  [launch configurations](../configuration.md#launch-configurations) say.
  This is the kernel half of #1345. The provider's delivery for the selected
  harness is tracked separately.

- SIGTERM or SIGINT now stops a capture pass cooperatively, where the worker was
  killed at once before. The supervised pass starts no further worker, asks the
  current worker to stop at its next unit boundary through the lock owner
  record, and kills and reaps the worker if it has not stopped after a 5-second
  grace, capped by the pass's deadline. The worker writes its own
  `failed`/`interrupted` receipt and keeps its committed counts and the previous
  `lastSuccess`. A killed worker leaves its `running` receipt, which the next
  pass records as interrupted. The worker also catches a signal sent to the
  caller's whole process group (Ctrl-C, `timeout`, a service manager), so it
  is not killed mid-unit. An interrupted run's failure message now reads
  "Capture execution was interrupted.", for a stop and for a later recovery
  alike. The lock is released and the command exits 1.
  `capture --home`, `--file` and `--reset-cursors` still run in the calling
  process. They now stop at their safe points (before and after taking the
  lock, before each format's batch, before the index update, and after the
  work before answering), answer their
  existing `failed` receipt with `capture interrupted by SIGTERM` and a
  confirmed `appended`, release the lock and exit 1. Discovery, a format's
  batch and the index update cannot be preempted, so a signal waits for the
  segment it arrived in. See
  [stopping capture](../../packages/record/docs/capture-service.md#stopping-capture-and-the-lock-owner-record) (#1347).
- The capture lock's `owner.json` now says who took it: `command`, `caller`
  (`entry` and `trigger`) and `ppid`. These are fixed labels and process facts,
  never argv or environment. They are diagnostic only. Records from earlier
  releases are read and reclaimed exactly as before (#1347).

- The index update after `capture --home` or `--file` now skips streams it can
  prove current. A stream is skipped when its validation checkpoint names the
  journal's current version and its search cursor agrees with that checkpoint.
  A skipped stream takes no stream lock, no validation and no `capture.db`
  connection of its own. The pass opens `capture.db` once instead of twice per
  stream, so an unchanged record no longer costs two lock cycles and two
  database opens for every stream. Work now follows the streams that changed
  and their new bytes. Backlog from `--no-index` passes, streams changed by
  other writers, and missing or inconsistent evidence are still validated
  under the stream lock, and a stale union still resets and is rebuilt. See
  [the index update](../../packages/record/docs/capture-service.md) (#1348).

- A retire's recovery copy now keeps each symbolic link's own mode. The copy
  recreated a link with its exact target but the platform's default mode,
  while the verification digest holds the link's mode, so on macOS a worktree
  whose ignored dependency tree has links of another mode (for example
  `node_modules/.bin` links at 0700) was refused with "worktree recovery
  verification disagreed with the source". The link is now given its source's
  mode with lchmod, on the link itself, never on its target. Where the
  platform cannot set a link's mode and the new link's differs, the copy is
  refused rather than verified against another digest, and no target
  changes. Spawn's copies of skills and the other recovery copies use the
  same copier. See
  [what a recovery copy carries](../souls-and-instances.md#retire) (#1360).

## Provider updates

- **oats.framework 1.13.2, oats.core 2.6.4: `/oats-operate` reads inspect's
  `running`** ([#1346](https://github.com/awebai/oats/issues/1346)). From OATS
  0.63.0 (feature `session-inspect-running`), the skill says what `running` on
  `oats session inspect --json` means: activity at the session endpoint, not
  health or readiness. A failed inspect is an error, never `running: false`.
  Without the field, `state: unknown` on a successful result reads as running.
  Text only: the capability's floor (`compatibility.oats`) is unchanged.
