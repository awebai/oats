# OATS 0.43.1

## Changed

- **Proportional setup and operation guidance** ([#689](https://github.com/awebai/oats/pull/689)).
  Instructions distinguish requested outcomes from workflow defaults, select
  relevant reads, retain one accountable executor and reuse accepted evidence
  and authorization without serial permission or ACK rounds. The rule against
  hand-editing `instance.json`, `oats-lock.json`, `oats-local.yaml` and `.oats/`
  remains in force; a specific host intervention is not a general captured-state
  repair procedure. Principal/work preservation, truthful provenance and
  outward-action authority remain required. This changes guidance, not commands
  or runtime contracts, and introduces no composition or adoption mechanism.

## Fixed

- **A drag in an OATS Desktop terminal selects text, as in a native
  terminal** ([#672](https://github.com/awebai/oats/issues/672)). Every drag
  in a terminal tab went to tmux's copy mode, so the copy depended on your
  tmux copy-mode bindings, OSC 52 and a clipboard write that failed silently.
  The selection vanished on release and the copy often never arrived. Now a
  plain drag, in every local and remote terminal tab and with no modifier,
  leaves a selection that stays after release. A double-click selects a
  word, a triple-click a line. This holds for Claude Code and Codex panes,
  before and after wheel scrolling, and after a tab is closed and reopened.
  - **Copying happens when you copy, not on release:** ⌘C or Edit › Copy on
    macOS, **Ctrl+Shift+C** on Linux and Windows (`terminal.copySelection`, a
    new keymap action you can rebind), and right-click › Copy everywhere.
    With nothing selected, Ctrl+Shift+C does nothing and sends nothing to the
    program. Ctrl+C still interrupts it. If the clipboard refuses the text,
    a notification says so. Copies trim trailing spaces at line ends, as
    native terminals do.
  - **A drag selects what is on screen.** To select older output, wheel up
    first, then select.
  - **Programs in panes no longer receive mouse clicks or drags from the
    Desktop, only the wheel.** Wheel scrollback is unchanged: on a pane that
    doesn't use the mouse, wheel up scrolls back through tmux's history and
    wheel down to the bottom leaves it, and a program that uses the mouse
    (Codex) still gets the wheel. No tmux option, key table or binding
    changed.
  - **The terminal selection is now clearly visible in every theme.** Its
    fill holds 3:1 against the terminal's background and selected text 4.5:1
    against the fill, in White, Solarized, Dark and This computer. The fill
    was as faint as 1.12:1 in White, and This computer's selection colour is
    moved until it passes.
  - On Linux, a drag also sets the primary selection (untrimmed), and
    middle-click pastes it (one bracketed paste), as in other Linux
    terminals.
  - **`oats session attach` in your own terminal is not changed.** There
    tmux keeps the mouse for wheel scrollback, so a plain drag is tmux's copy
    mode, which copies on release. That copy reaches the clipboard only
    through OSC 52 when your terminal allows it (an iTerm2 setting;
    Terminal.app has none), or through your own tmux copy binding. For your
    terminal's own selection, hold Option while dragging (iTerm2, Ghostty,
    Terminal.app) or Shift (most others). See
    [Copy from a terminal](../desktop.md#copy-from-a-terminal).
