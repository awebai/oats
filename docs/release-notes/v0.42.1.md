# OATS 0.42.1

## Changed

- **Remote roster rows carry the local row's work, repository, branch,
  model-from, soul and module drift facts**
  ([#675](https://github.com/awebai/oats/issues/675)). A remote instance
  row (`oats server roster --json`, and the Desktop's remote roster) now
  relays `work`, `repo`, `branch`, `modelFrom`, `soul` and `modules` from
  the host's own `oats status --json` row, with the same names and meaning
  as on a local row. `soul` and `modules` are the host's own drift
  observation, relayed as it answered; nothing is recomputed on this side,
  and `repo` is the host's path. Each is always present, `null` from a host
  that doesn't report it (an older host, a fact it never recorded, or a saved
  route the host no longer lists). See
  [the remote roster](../desktop-cli-api.md#the-remote-roster-oats-server-roster---json).

## Fixed

- **The context panel shows the soul and teams of an instance on a server**
  ([#675](https://github.com/awebai/oats/issues/675)). The Soul tab and the
  Messaging & Teams list were empty for an instance on a registered server.
  They now read through the server by the instance's home, as the soul page
  does, and say "Reading from <server>…" while they wait. The Soul tab's
  header shows the soul's description from the server's roster. The Work
  card, the "model from" line and the "older build" chip show the facts the
  server relays. When a part can't be shown, it says why and what to update:
  this computer's OATS when it can't route the read or doesn't relay the
  facts, the server's OATS when it lacks the feature or doesn't report them.
  A server's other refusals show its code and message, as the rest of the
  panel does.
