# OATS 0.33.1

## Changed

- **The Desktop names an OATS cache problem, and keeps the roster through an
  unreadable remote.** When the kernel can't read a remote
  (`E_REMOTE_UNREADABLE`), the sidebar roster keeps the instances it last
  observed instead of going empty. A cache problem (`details.reason: "cache"`)
  reads "Couldn't refresh instances · OATS cache problem · observed <age>",
  with the kernel's message in full (it names the lock file or the process
  holding it, and the remedy) and Retry. With nothing observed yet, the failed
  state shows that message. A network failure or a timeout reads "Couldn't
  reach <host> · showing what was read <age>", with the raw code behind
  Details. Only the reason and the host of the remote cross to the window,
  never paths or pids
  ([desktop-cli-api.md](../desktop-cli-api.md#workspace)).

## Fixed

- **A background spawn never fails silently, and a soul can't be spawned
  twice at once** (awebai/oats#383). While a spawn of a soul is in flight,
  opening Spawn for it shows the press disabled with "A spawn of <soul> is in
  progress" and a link to its pending row; it re-enables when the spawn
  settles. After a window reload, a spawn whose outcome wasn't known yet comes
  back as a pending row and its outcome is reported, a failure included; Reopen
  spawn then restores the soul and the name. Quitting the Desktop mid-spawn
  still loses an unreported failure
  ([desktop-spawn-preview.md](../../packages/desktop/docs/desktop-spawn-preview.md#background-spawn-the-dialog-closes-on-spawn)).
