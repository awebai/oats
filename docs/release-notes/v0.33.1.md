# OATS 0.33.1

## Changed

- **Reading a remote's current head takes one round trip instead of two.**
  `oats spawn` (preview and apply) and the read verbs ask each workspace
  member for its head with Git's protocol v0, which returns the whole ref list
  in one request, where protocol v2 takes two. On a 6-member deployment the
  live phase of a spawn preview went from 0.77 s to 0.49 s (median of 5). Tags
  and branches are read as before. If your Git configuration sets
  `protocol.version`, OATS uses it as set. A remote whose ref list is over
  4 MiB is read with protocol v2 from then on (remembered in the remote
  cache). A remote that times out under v0 fails as before and is read with
  v2 for the next 7 days. One that fails under v0 for another reason than an
  authentication refusal, a missing repository or the local cache is read
  again with v2. Each case is one `oats: warning`. What a read observes is
  unchanged, and an apply still observes every member live. Known limit: the
  4 MiB bounds what OATS keeps, not what Git downloads, so a remote with a
  larger ref list transfers it once before OATS switches to protocol v2.

- **`oats spawn` checks Claude Code's plugins while it reads the workspace.**
  The `claude plugin list --json` probe that verifies a soul's required
  plugins starts when the command starts, instead of after the remotes are
  read, and is used only when the spawn then selects exactly that executable
  and environment; otherwise it is ended and the probe runs as before. A probe
  that fails, times out or prints something else gives the same answer as
  before, and it never outlives the command. With both changes, the same
  deployment reaches a spawn's first capability hook in 0.96 s instead of
  1.85 s (median of 5).
