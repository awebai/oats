# OATS 0.33.1

## Fixed

- **`oats status` and `oats workspace status` answer within 12 s of remote
  work, even under load.** Each git call they made had its own 30 s limit, and
  a read could wait up to 11 minutes behind another process fetching the same
  remote, so the Desktop's 30 s limit could end them (`E_CLI_TIMEOUT`). Now
  every remote step of these two reads gets what is left of a 12 s budget: a
  member not read by then is a `cannot-read` row (`… (timeout)`) and its git is
  ended, and the command still answers. A workspace definition not read by then
  fails as an unreadable one does today (`reason: "timeout"`). Another
  process's write to the remote cache is waited for only as long, never taken
  over. Spawn, sync and the other verbs are unchanged.
